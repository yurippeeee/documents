# 00. 目次と学習の進め方

> **この編の狙い.**
>
> Arm PSA Certified APIs（PSA Crypto / Secure Storage / Attestation）を、
> 「**どの関数を、どの順で、どんな引数で呼ぶか**」に重心を置いて説明する。
> 公式仕様書は関数の辞書であり、この編はその辞書を引けるようになるための読み物である。

## 前提

- C 言語が読める（ポインタ、構造体、`goto cleanup` のパターン）
- 暗号の用語（AES、SHA-256、ECDSA）を聞いたことはあるが、中身は知らなくてよい。必要な分は各章で説明する
- 組み込み（マイコン）の経験があると 15・16 章が読みやすいが、PC 上の Mbed TLS だけでも 01〜14 章は試せる

## 章の構成

| 部 | 章 | 内容 |
|---|---|---|
| **I. 作法** | 01 PSA とは何か | 仕様・認証・実装の関係。コードが動く 2 つの場所 |
| | 02 API の共通作法 | `psa_status_t`、初期化、定数の作り方、出力バッファ、操作オブジェクト |
| | 03 鍵と属性 | type / bits / usage / algorithm / lifetime / id |
| | 04 鍵の作成と破棄 | import / generate / export_public_key / destroy。バイト列の形式 |
| **II. 操作** | 05 乱数とハッシュ | 鍵を使わない操作。分割処理の状態遷移 |
| | 06 MAC | HMAC / CMAC、タグの切り詰め |
| | 07 対称暗号 | CTR / CBC、IV の扱い、単独で使わない理由 |
| | 08 AEAD | GCM / CCM / ChaCha20-Poly1305、ノンス管理 |
| | 09 署名と検証 | ECDSA / EdDSA / RSA、hash 版と message 版、署名の形式 |
| | 10 鍵導出 | HKDF / PBKDF2、SECRET・SALT・INFO |
| | 11 鍵合意 | ECDH、一時鍵、認証との組み合わせ |
| **III. 保存と証明** | 12 永続鍵とライフタイム | 揮発 / 永続、場所、鍵 ID の設計 |
| | 13 セキュアストレージ | ITS / PS の 4 関数、何をどこに置くか |
| | 14 アテステーション | トークンの取得と中身、検証側の仕事 |
| **IV. 実装** | 15 Mbed TLS での実装 | 設定、`PSA_WANT_*`、エントロピー源、ドライバ |
| | 16 TF-M での実装 | SPE / NSPE、ベニア、ビルド、クライアント ID |
| | 17 実践パターン | 7 つの要件を呼び出し列に翻訳 |
| | 18 落とし穴とチェックリスト | エラー逆引き、設計の落とし穴、扱わなかった API |

## 読み方の提案

- **最短経路（API を今すぐ使う）**: 02 → 03 → 04 → 05 → 08 → 09 → 17
- **設計を任された**: 03 → 09 → 10 → 11 → 12 → 13 → 17 → 18
- **TF-M に載せる**: 01 → 12 → 13 → 14 → 16
- **すでに Mbed TLS の旧 API を使っている**: 02 → 03 → 15（4 節の橋渡し）→ 18

各章末の「仕様書に逃がす」は、めったに使わない関数の名前と参照先だけを並べている。読み飛ばしてよい。

## 表記

- 関数・定数・型は `psa_import_key()` のように等幅で示す
- エラーコードは `PSA_ERROR_NOT_PERMITTED` のように定数名で示し、初出で数値も併記する
- コードは Crypto API 1.1〜1.3、Mbed TLS 3.6 / TF-PSA-Crypto 1.0、TF-M 2.x を前提にしている。古い資料の `psa_key_handle_t` / `psa_open_key()` は使わない
