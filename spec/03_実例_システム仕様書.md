> **この章で扱う問い.**
> [01 章](01_システム仕様書の書き方.md)では、システム仕様書に何をどの形で書くかを一般論で示した。この章では、その型で書いた温湿度ロガーのシステム仕様書 LG-SYS-001 版 1.0 を、初めから終わりまで示す。

### 1.3 用語

**表 1-4 用語**

| 用語 | 意味 |
|---|---|
| **ロガー** | この文書が対象とする、電池で動く温湿度ロガーの本体 |
| **アプリ** | ロガーと通信して、設定・読み出し・時刻合わせをするスマートフォンのアプリケーション |
| **例のスマートフォン** | 性能を確かめるときに使うスマートフォン。機種は LG-TST-001 で決める |
| **記録** | 1 回の測定の結果（温度・湿度）を、時刻と、そのときの状態を表す印（**状態の印**）と一緒に、1 件にまとめて保存したもの。状態の印は、警報の印・時刻未設定の印・電池少の印・測定異常の印（この表の下の行）の総称（SR-F03） |
| **記録の間隔** | 記録しているときに、測定して記録を保存する時間の間隔（SR-F02） |
| **記録の容量** | ロガーが保存できる記録の件数（SR-F04） |
| **容量に達したときの動作** | 記録の件数が記録の容量に達した後の動作。「上書き」は最も古い記録から上書きして記録を続け、「記録を止める」はそれ以上記録しない（SR-F05） |
| **警報の上限**・**警報の下限**・**警報の印** | 記録の温度が警報の上限より高いか、警報の下限より低いとき、その記録に警報の印を付ける。上限・下限に等しいときは付けない（SR-F10） |
| **確認の操作** | 警報の印の付いた記録を読み出した利用者が、確かめたことをアプリで入れる操作（SR-F11） |
| **警報の表示** | 確認の操作をしていない警報の印がある間、LED で続ける表示。確認の操作で止まる（表 3-5） |
| **時刻未設定の印** | 電池を入れてから最初に時刻を合わせるまでに保存した記録に付ける印。この記録の時刻は正しくない（SR-F09） |
| **電池少の印** | 電池の残りが少ないと判定した後に保存した記録に付ける印（SR-F13） |
| **測定異常の印** | 温度か湿度を測れなかった記録に付ける印。測れなかった値は記録に入れない（形式は LG-ICD-001） |
| **短押し**・**長押し** | ボタンを押して 1 秒未満で離すこと・3 秒以上押し続けること（SR-U01） |
| **主のモード**・**通信の状態** | ロガーが同時にとる 2 つの状態。主のモードは記録に、通信の状態はアプリとの通信に関わる（表 3-2） |
| **接続の受付** | アプリからの接続を受け付けること。短押しから 2 分間だけ行う（SR-U06） |
| **読み出し** | アプリが記録を受け取ること。全部の記録を受け取る**全部の読み出し**と、前回の読み出しの後に保存された記録だけを受け取る**差分の読み出し**がある。前回の読み出しは最後まで終えた読み出しを指し、途中で接続が切れた読み出しは含めない（SR-F07） |
| **記録の消去** | 保存したすべての記録を消すこと（SR-S01） |
| **PIN** | ロガーごとに決めた 6 桁の数字。設定の変更と記録の消去に要る（SR-S01） |
| T・A・I・D | 検証の方法の記号。試験（T）・解析（A）・検査（I）・実演（D） |

ロガーに固有の言葉は、この表で 1 回だけ定義し、ほかの所では定義どおりの意味でだけ使う。例えば「上限を超える」が上限ちょうどを含むかを決めておかないと、8.0 °C の記録に警報の印を付けるかどうかが、設計する人と試験する人で割れる（[01 章 4 節](01_システム仕様書の書き方.md#要求文の書き方-1-文-1-要求-数値と条件-検証の方法)）。

| 境界 | ロガーの本体だけを対象にし、利用者・アプリ・電池・周囲の環境（測る・耐える）との 6 つのやり取りを、コンテキスト図と外部インタフェースの一覧で決める |
| 動作モード | 主のモード（停止中・記録中・電池切れ）と通信の状態（通信なし・接続の受付中・接続中）を分け、2 つの状態遷移表の全部のマスを埋める。警報と電池少はモードではなく、記録の印と表示である |
| LED の表示 | 開始・停止・状態の応答と、警報・電池少・記録中・通信中の表示（電池切れでは点けない）。周期の表示は 30 秒ごとに 1 つだけで、重なったときは優先順位の低い表示を省く。どの 2 つの表示も、色と回数で見分けられる |
| 機能の要求 | SR-F 18 件・SR-U 7 件・SR-I 3 件。1 つの ID に 1 つの要求で、数値・条件・境目・許容差を書き、理由・出典・優先度・検証の方法を付ける。容量は件数で書く（記録の間隔 10 分で 365 日、1 分で 36.5 日） |
| 機能以外の要求 | SR-P 6 件・SR-W 4 件・SR-E 4 件・SR-R 5 件・SR-S 2 件・SR-C 2 件。電池寿命には使い方の条件（警報の表示と電池少の表示が無いことも含む）を付け、精度は温度の範囲ごとに境目まで決める |
| 検証の方法 | 試験 41 件・解析 5 件・検査 4 件・実演 1 件。要求の ID の順に ST-001〜ST-051 を 1 つずつ振り、試験の無い要求を無くす。合否の基準は要求文の数値と境目の定義から決まる |

次章では、この仕様書を入力にして、ロガーの設計書 LG-DES-001 を示す。要求の ID を設計の要素（DS-）と、この章の ST の番号に結び、SR-W02 の使い方の条件で電池寿命を見積もる。
