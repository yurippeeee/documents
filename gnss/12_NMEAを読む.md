# 12. NMEA を読む — 文の形式とチェックサム

> **この章で扱う問い.**
> 10 章 4 節では、GNSS モジュールが位置・時刻・衛星の状態を文字の行にして UART で出すことと、その 1 秒あたりのバイトの数を見た。この章では、その行の形を決めた規格を読み、マイコンの C のプログラムで、1 文字ずつ届く行を確かめながら数値に直す。
>

## 1. NMEA 0183 — 文の形

### 文字の行が並んだもの

船の航海の機器（GNSS の受信機・測深器・自動操舵の装置など）の間でデータを受け渡すために、米国の海洋電子機器協会（NMEA、National Marine Electronics Association）が決めた規格を **NMEA 0183** という。規格は、文字の行の形と、電気の形・速さ（基本は 4800 bit/s）を決めている。GNSS モジュール（以下、モジュール）の多くは、行の形を借りて、[10 章 4 節](10_モジュールの回路.md#通信の端子-uart-i2c-spi-と電圧)の UART を製品ごとの速さ（例のモジュールは 9600 bit/s）で使って、位置・時刻・衛星の状態を出す。NMEA 0183 で、1 つのまとまった情報を書いた 1 行の文字の列を**文**（sentence、センテンス）という。例のモジュールが UART で送るバイトを、ASCII の文字として読むと、次の図のようになる（6 章・7 章の東京の例で、1 秒に 1 回出す 1 回分。文の値は例。2 節）。

```fig
e12_stream
```

文は $ で始まり、CR と LF（行の終わりを表す 2 つの制御文字。0x0D と 0x0A）で終わる。その間には、ASCII の表示できる文字（0x20〜0x7E）だけを使い、決まった順の値をカンマで区切って書く。区切りに使う $・カンマ・* と CR・LF は、値の中には現れない。1 回分の文の長さ（$ から LF まで）の和が、[10 章 4 節](10_モジュールの回路.md#通信の端子-uart-i2c-spi-と電圧)のデータ量（1 秒に 1 回出すとき）になる。

バイトの流れには、どこからどこまでが 1 つのまとまりかを示す印が無い（[組み込み通信シリーズ 3 章 1 節](../comm/03_フレーミングと誤り検出.md#バイトの流れには切れ目がない)）。NMEA 0183 では $ が文の頭の印で、値の中に現れないので、受ける側は、文の途中から受け始めても、文字を取りこぼしても、次の $ で文の頭を見つけ直せる。

### 文の形 — 話者 ID・文の種類・欄・チェックサム

1 つの文は、次の図のように分かれる。$ の直後の 2 文字は、文を出した機器の種類を表し、**話者 ID**（talker ID）という。GNSS の受信機では、どの衛星系で求めた値かを表し、複数の衛星系をまとめて使った値には GN を使う。この章では、$ と * の間の文字を、文の「中身」と呼ぶ。

```fig
e12_anatomy
```

文の種類（2 節）ごとに、欄の数と並びが規格で決まっている。この章では、話者 ID と文の種類を書いた欄を 0 番として、欄を順に番号で呼ぶ（4 節のコードの `f[0]`, `f[1]`, …）。話者 ID の書き方は、規格の版とモジュールで違う（BeiDou の GB と BD など）。$P で始まる文は、モジュールの作り手が独自に決めた文で、欄の意味は製品による。

規格では、1 つの文の長さは、$ から LF までで 82 文字以下とされている。$・*・チェックサムの 2 桁・CR・LF の 6 文字を除くと、中身は 76 文字以下になる。

## 2. 主な文 — GGA・RMC・GSA・GSV

1 節の 7 つの文のうち、位置と時刻を使う機器が主に読むのは GGA と RMC で、衛星の状態を見るときに GSA と GSV を読む（VTG と GLL は、GGA と RMC の値の一部を別の文にしたもの）。どの文も、時刻は UTC（協定世界時。14 章）で書く。この節の例の文は、東京（1 章の例の点。楕円体高 40 m）の受信機が、6 章・7 章の 8 つの GPS の衛星（時刻 0）で測位したとして作った（時刻と日付は例の値）。

### GGA — 測位の結果

時刻・緯度・経度・測位の品質・使った衛星の数・HDOP・高さを 1 つにまとめた文を **GGA** という（global positioning system fix data。GPS 以外の衛星系にも使う）。6 番の欄は、位置が求まったかと、どの方法で求めたかを、1 桁の数で表す。この値を**測位の品質**（fix quality）という。0 は位置が求まっていないことを表すので、受ける側は、0 のときの緯度・経度を使ってはならない（6 節）。

```fig
e12_gga
```

GGA の高さの欄は、楕円体高ではなく標高である（[6 章 6 節](06_位置を解く.md#緯度-経度-高さへ-座標の変換)）。受信機が求めるのは楕円体高なので、モジュールは、中に持つジオイドのモデル（全地球の粗いもの。製品による）でその場所のジオイド高を求め、楕円体高から引いて標高の欄に書き、ジオイド高も隣の欄に書く。したがって、楕円体高は 2 つの欄の和（例で 3.3 + 36.7 = 40.0 m）である。

### RMC — 時刻・日付・速さ

時刻・データの状態・緯度・経度・速さ・進む向き・日付をまとめた文を **RMC** という（recommended minimum の略。航法の機器が最低限出すよう勧められた値の組）。4 つの文のうち、日付は RMC にしか無い。2 番の欄（状態）が V（警告）のときは、位置を使ってはならない。速さは、[6 章 5 節](06_位置を解く.md#速度を求める-ドップラーから)で求めた速度の、水平の成分の大きさを、ノットで書いたものである。

```fig
e12_rmc
```

### GSA と GSV — 使った衛星と、見えている衛星

位置の計算に使った衛星の番号（12 個まで）と、PDOP・HDOP・VDOP（[7 章 4 節](07_誤差とDOP.md#dop-衛星の並びが誤差を広げる)）を書いた文を **GSA** という（DOP and active satellites）。見えている衛星ごとに、番号・仰角・方位角・C/N0 を書いた文を **GSV** という（satellites in view）。GSV は 1 つの文に 4 機までしか書けないので、見えている衛星が多いときは、いくつかの文に分けて出す。GPS の衛星の番号は PRN 番号（[2 章 2 節](02_衛星の信号.md#拡散符号-1023-チップの擬似雑音)）で、ほかの衛星系の番号の付け方は版とモジュールによる（例: GLONASS は 65〜96）。

```fig
e12_gsa
```

```fig
e12_gsv
```

GSV には、見えていても位置の計算に使わない衛星も書かれる。仰角マスク（[7 章 3 節](07_誤差とDOP.md#マルチパス-反射した電波が混ざる)）より低い衛星や、信号が弱くて追尾できない衛星（C/N0 の欄が空になる）である。どの衛星を使ったかは GSA で分かる。

## 3. チェックサム — 排他的論理和で誤りを見つける

### 中身の文字の排他的論理和

UART の線の上の雑音で、ビットが反転することがある。NMEA 0183 の文は、各バイトにパリティを付けない 8N1（[組み込み通信シリーズ 2 章 2 節](../comm/02_UART.md#uart-のフレーム-スタートビット-データ-パリティ-ストップビット)）で送るので、文ごとに検査の値を付けて誤りに気づく。文の中身（$ と * の間の全部の文字。$ と * は含めない）の ASCII の値の、ビットごとの排他的論理和を 16 進 2 桁で書いたものを、NMEA 0183 の**チェックサム**という。送る側（モジュール）が計算して * の後に付け、受ける側は、届いた中身から同じ計算をして、付いてきた値と比べる。バイトの和を使うチェックサムも多い（[組み込み通信シリーズ 3 章 5 節](../comm/03_フレーミングと誤り検出.md#チェックサム-バイトを足す)）が、NMEA 0183 は排他的論理和を使う。

2 つのビットの排他的論理和は、2 つが違えば 1、同じなら 0 である（C の `^`）。バイトの排他的論理和は、これを 8 つのビットの位置ごとに行う。したがって、多くのバイトの排他的論理和の各ビットは、そのビットの位置にある 1 の数が奇数なら 1、偶数なら 0 になる。

```fig
e12_xor
```

### 1 文字の誤りは必ず見つかる

1 つの文字が化けたとき、チェックサムが必ず変わることを示す。

**方針**: 排他的論理和は、順番を変えても結果が同じで、同じ値を 2 回とると 0 になる。これを使い、化けた後に計算した値を、化ける前のチェックサムと、化けた分に分ける。

**導出**: 中身の文字を $`a_1, a_2, \ldots, a_n`$、排他的論理和を $`\oplus`$ と書くと、チェックサムは $`S = a_1 \oplus a_2 \oplus \cdots \oplus a_n`$ である。$`k`$ 番目の文字が $`a_k'`$ に化けたとき、反転したビットの位置に 1 を立てた値を $`e = a_k \oplus a_k'`$ とする。$`a_k \oplus e = a_k \oplus a_k \oplus a_k' = 0 \oplus a_k' = a_k'`$ なので、受ける側が計算する値は

$$
S' = a_1 \oplus \cdots \oplus (a_k \oplus e) \oplus \cdots \oplus a_n = S \oplus e
$$

である（順番を入れ替えて、$`e`$ を最後に回した）。$`S' = S`$、つまり $`S \oplus e = S`$ なら、両辺に $`S`$ を $`\oplus`$ すると $`e = 0`$ になり、どのビットも反転していないことになる。文字が化けたなら $`e \ne 0`$ なので、$`S' \ne S`$ である ∎

### 見逃す誤り

いくつかの文字が化けたとき、チェックサムが合ってしまうのはどんな場合かを調べる。

**方針**: 前の導出を、化けた文字がいくつかある場合に広げ、受ける側が計算する値が $`S`$ に戻る条件を求める。

**導出**: $`m`$ 個の文字が化け、それぞれの化けた分を $`e_1, e_2, \ldots, e_m`$ とする。前の導出と同じく、化けた分を最後に回すと、受ける側が計算する値は $`S' = S \oplus e_1 \oplus e_2 \oplus \cdots \oplus e_m`$ である。前の導出の終わりと同じく両辺に $`S`$ を $`\oplus`$ すると、$`S' = S`$ になるのは、$`e_1 \oplus e_2 \oplus \cdots \oplus e_m = 0`$ のときで、そのときに限る。

- 2 つの文字の、同じ位置のビットが反転したとき: $`e_1 = e_2`$ なので、$`e_1 \oplus e_2 = e_1 \oplus e_1 = 0`$ である。反転が 0 から 1 か、1 から 0 かによらない。
- 2 つの違う文字 $`a_j`$ と $`a_k`$ が入れ替わったとき: 化けた分は $`a_j \oplus a_k`$ と $`a_k \oplus a_j`$ で等しいので、やはり排他的論理和は 0 である。

どちらの誤りでも、チェックサムは合う ∎

例の GGA の緯度の欄で確かめる。

```fig
e12_miss
```

位置が 66.6 km 違っても、チェックサムは合う。バイトの和のチェックサムも、入れ替わりと、2 つのバイトの同じビットが逆の向きに反転する誤りを見逃す（[組み込み通信シリーズ 3 章 5 節](../comm/03_フレーミングと誤り検出.md#チェックサム-バイトを足す)）が、排他的論理和は同じ向きの反転も見逃す。CRC（[同じ節](../comm/03_フレーミングと誤り検出.md#crc-割り算の余り)）ならどちらにも気づくが、NMEA 0183 の形は変えられない。受ける側は、チェックサムに加えて、値の範囲（5 節）と、前の位置からの飛び（15 章）で確かめる。

## 4. C で解析する — 1 文字ずつ読む状態機械

### 状態と遷移

UART で届いたバイトは、割り込みでリングバッファ（[組み込み通信シリーズ 4 章 3 節](../comm/04_割り込みDMAリングバッファ.md#リングバッファ)。GNSS での大きさの決め方は 15 章）にためられ、プログラムはそこから 1 文字ずつ取り出す。1 つの文がそろうまで待つ書き方では、その間ほかの仕事ができないので、1 文字ごとに呼ばれ、その文字を処理したらすぐに戻る関数にする。そのためには、文のどこまでを受けたかを、呼ばれるたびに覚えておく必要がある。手順を状態・イベント（状態を変えるきっかけ）・遷移・動作で表した状態機械（[組み込み通信シリーズ 5 章 1 節](../comm/05_状態機械とタイムアウト.md#手順を状態と遷移で表す-状態機械)）で書く。ここでは、イベントは「1 文字が届いた」で、その文字の種類で遷移が決まる。

```fig
e12_fsm
```

$ は値の中に現れないので、どの状態でも、$ が来たら新しい文の頭とし、それまで受けていた文は途中で切れたものとして捨てる。中身の文字は、ためながら排他的論理和をとるので、* が来たときにはチェックサムを計算し終わっている。中身が 76 文字を超えたら捨てるのは、* や CR LF を取りこぼして次の文とつながったものに早く気づくためと、文字をためる配列をはみ出さないためである。

### C のコード

型と、16 進の 1 桁を読む関数を次に示す。

```c
#define NMEA_MAX    82                 /* $ から CR LF までの最大の長さ（規格の値とされる） */

enum nmea_state  { ST_WAIT, ST_BODY, ST_CK1, ST_CK2, ST_END };
enum nmea_result { NMEA_NONE,          /* 文の途中（まだ何も起きていない） */
                   NMEA_OK,            /* 文が 1 つそろい、チェックサムが合った */
                   NMEA_ERR_SUM,       /* チェックサムが合わない */
                   NMEA_ERR_LONG,      /* 長すぎる */
                   NMEA_ERR_FORM,      /* 形が違う（* の前に CR が来た、など） */
                   NMEA_ERR_CUT };     /* 文の途中で次の $ が来た */

struct nmea_rx {
    enum nmea_state st;                /* いまの状態 */
    char buf[NMEA_MAX];                /* $ と * の間の中身（* が来たら '\0' で終える） */
    int len;                           /* buf にためた文字の数 */
    uint8_t sum;                       /* ためた文字の排他的論理和 */
    uint8_t got;                       /* * の後に届いたチェックサムの値 */
};

static int hexval(char c)                  /* 16 進の 1 桁の値（大文字・小文字の両方）。それ以外は −1 */
{
    if (c >= '0' && c <= '9') return c - '0';
    if (c >= 'A' && c <= 'F') return c - 'A' + 10;
    if (c >= 'a' && c <= 'f') return c - 'a' + 10;
    return -1;
}
```

状態機械は、1 文字を受け取って結果を返す関数 `nmea_feed` である。

```c
enum nmea_result nmea_feed(struct nmea_rx *r, char c)
{
    int h;
    if (c == '$') {                                    /* どの状態でも、$ で新しい文を始める */
        enum nmea_result res = (r->st == ST_WAIT) ? NMEA_NONE : NMEA_ERR_CUT;
        r->st = ST_BODY; r->len = 0; r->sum = 0;
        return res;                                    /* 途中だった文は捨てる */
    }
    switch (r->st) {
    case ST_WAIT:                                      /* $ を待つ間は読み捨てる */
        return NMEA_NONE;
    case ST_BODY:                                      /* 中身: * まで、ためながら XOR をとる */
        if (c == '*') { r->buf[r->len] = '\0'; r->st = ST_CK1; return NMEA_NONE; }
        if (c < 0x20 || c > 0x7E) break;              /* * より前に CR・LF などが来た */
        if (r->len >= NMEA_MAX - 6) { r->st = ST_WAIT; return NMEA_ERR_LONG; }
        r->buf[r->len++] = c;
        r->sum ^= (uint8_t)c;
        return NMEA_NONE;
    case ST_CK1:                                       /* チェックサムの上の桁 */
        if ((h = hexval(c)) < 0) break;
        r->got = (uint8_t)(h << 4); r->st = ST_CK2;
        return NMEA_NONE;
    case ST_CK2:                                       /* チェックサムの下の桁 */
        if ((h = hexval(c)) < 0) break;
        r->got |= (uint8_t)h; r->st = ST_END;
        return NMEA_NONE;
    case ST_END:                                       /* CR は読み飛ばし、LF で終わる */
        if (c == '\r') return NMEA_NONE;
        if (c != '\n') break;
        r->st = ST_WAIT;
        return (r->got == r->sum) ? NMEA_OK : NMEA_ERR_SUM;
    }
    r->st = ST_WAIT;                                   /* 形の誤り: 次の $ まで読み捨てる */
    return NMEA_ERR_FORM;
}
```

`hexval` が小文字も受け付けるのは、規格では大文字とされているチェックサムを、小文字で出す機器もあるからである。チェックサムの無い文は、* の前に CR が来るので、形の誤りとして捨てる（モジュールの文には、ふつうチェックサムが付いている。省いた文も受ける必要があるときは、この扱いを変える）。

### 欄に分ける

チェックサムが合った文は、カンマで欄に分ける。カンマを文字列の終わり（`'\0'`）に書き換え、各欄の頭を指すポインタを並べる。空の欄も 1 つの欄として残すのが要点である（6 節）。`uart_read` と `use_position` は、この章で仮に置く関数で、`nmea_gga` は 5 節で作る。

```c
int nmea_split(char *s, char *f[], int max)            /* 空の欄も 1 つの欄として残す */
{
    int n = 0;
    f[n++] = s;
    for (; *s != '\0'; s++) {
        if (*s != ',') continue;
        if (n == max) return -1;                       /* 欄が多すぎる */
        *s = '\0';                                     /* , を文字列の終わりに変え */
        f[n++] = s + 1;                                /* 次の欄はその次の文字から */
    }
    return n;
}

int uart_read(void);                          /* 仮に置く関数: 受けたバイト（0〜255）を返す。無ければ −1 */
void use_position(const struct gga *g);       /* 仮に置く関数: 位置を使う側へ渡す */

static struct nmea_rx rx;                     /* 初めは ST_WAIT（= 0） */
uint32_t n_bad;                               /* 捨てた文の数 */

void gnss_poll(void)                          /* 主のループから何度も呼ぶ */
{
    int c;
    struct gga g;
    while ((c = uart_read()) >= 0) {
        enum nmea_result res = nmea_feed(&rx, (char)c);
        if (res == NMEA_OK) {
            if (nmea_gga(rx.buf, &g) && g.quality > 0 && g.has_pos)
                use_position(&g);             /* GGA で、位置が出ているときだけ */
        } else if (res != NMEA_NONE) {
            n_bad++;                          /* 壊れた・切れた・長すぎる文 */
        }
    }
}
```

`n_bad` は、壊れた文が増えていないかを見張るのに使う（取りこぼしの見つけ方は 15 章）。

## 5. 数値に直す — 緯度経度・時刻・測位の品質

### 度分形式と、float では足りない理由

NMEA 0183 の緯度・経度は、度の整数の部分と、分（1 度の 60 分の 1。小数を含む）を続けて、1 つの数のように書く。この書き方を**度分形式**という。緯度は度が 2 桁（ddmm.mmmm）、経度は 3 桁（dddmm.mmmm）で、分の小数の桁の数は製品による。度に直すには、分を 60 で割って度に足す（3540.86000 は 35 + 40.86/60 = 35.681°）。

```fig
e12_float
```

C の float（32 ビットの浮動小数点）は、有効な桁が 2 進で 24 桁しかない。128 以上 256 未満の数は $`2^7 \times 1.xxx`$（小数点の後に 2 進で 23 桁）と表されるので、最後の桁の重みは $`2^7 \times 2^{-23} = 2^{-16}`$ で、刻みは 1.53 × 10⁻⁵ 度になる。東京の経度（139.767°）では、東西に 1.38 m である。文が分の小数 5 桁（緯度で 1.85 cm）まで書いてきても、float に入れるとその細かさを失う。double（64 ビット）なら足りるが、浮動小数点の計算の回路を持たないマイコンでは、計算をソフトウェアで行うので遅い。そこで、10⁻⁷ 度を 1 とした整数（固定小数点。[組み込み通信シリーズ 3 章 6 節](../comm/03_フレーミングと誤り検出.md#小数を送る-固定小数点)）に直す。経度の 180° でも 1.8 × 10⁹ で、32 ビットの符号付き整数（最大 2 147 483 647）に収まる。

### 整数に直す式

度分形式の文字の列から、10⁻⁷ 度を 1 とした整数を、浮動小数点を使わずに求める式を導く。

**方針**: 分の小数を 6 桁にそろえて、分を 10⁻⁶ 分を 1 とした整数 $`m_6`$ で表す。10⁻⁷ 度が 10⁻⁶ 分の何倍かを求めて、度の整数の部分に足す。

**導出**: 度の整数の部分を $`d`$、分を $`m`$ [分] とすると、角度は $`d + m/60`$ [度] である。10⁻⁷ 度を 1 とした整数 $`v`$ にするには 10⁷ を掛けて、$`v = 10^7 d + 10^7 m/60`$ である。$`m = 10^{-6} m_6`$ を代入すると

$$
\frac{10^7 m}{60} = \frac{10^7 \times 10^{-6} m_6}{60} = \frac{10\,m_6}{60} = \frac{m_6}{6}
$$

なので、$`v = 10^7 d + m_6/6`$ である。C の整数の割り算は小数を切り捨てるので、割る数 6 の半分の 3 を足してから割ると四捨五入になり、$`v = 10^7 d + (m_6 + 3)/6`$ の誤差は 0.5 × 10⁻⁷ 度以下である ∎

例の緯度と経度で、この式の手順をたどると、次の図のようになる。

```fig
e12_dm
```

```c
int nmea_dm_e7(const char *s, char hemi, int maxdeg, int32_t *out)
{
    int32_t ip = 0, m6 = 0, deg, v;                    /* ip: 小数点より前、m6: 分を 1e-6 分の単位で */
    int nd = 0, k;
    while (*s >= '0' && *s <= '9') {                   /* 小数点より前（ddmm・dddmm） */
        if (++nd > 5) return 0;
        ip = ip * 10 + (*s++ - '0');
    }
    if (nd < 3) return 0;                              /* 空の欄、または分の 2 桁が無い */
    deg = ip / 100;
    if (deg > maxdeg || ip % 100 >= 60) return 0;
    if (*s == '.') s++;
    for (k = 0; k < 6; k++) {                          /* 分の小数を 6 桁にそろえる（足りない桁は 0） */
        m6 *= 10;
        if (*s >= '0' && *s <= '9') m6 += *s++ - '0';
    }
    while (*s >= '0' && *s <= '9') s++;                /* 7 桁目から後は捨てる */
    if (*s != '\0') return 0;                          /* 数字でない文字がある */
    m6 += (ip % 100) * 1000000;                        /* 分の整数の部分を足す */
    v = deg * 10000000 + (m6 + 3) / 6;                 /* 1e-7 度 = 6e-6 分（四捨五入） */
    if (v > maxdeg * 10000000) return 0;
    if (hemi == 'S' || hemi == 'W') v = -v;
    else if (hemi != 'N' && hemi != 'E') return 0;
    *out = v;
    return 1;
}
```

分が 60 以上、度が 90（経度は 180）を超える、などの値は誤りとして返す。ただし、3 節の入れ替わり（35°04.86′）のように範囲の中に収まる誤りは、この確かめでも見つからない。分の小数を 4〜7 桁にした文と、Python の有理数で計算した 2 万あまりの値で、結果が一致することを確かめた。

### 時刻と測位の品質

時刻の欄 hhmmss.ss（UTC）を、その日の 0 時からの ms に直し、測位の品質・衛星の数・HDOP・高さと一緒に構造体に入れる関数を示す（数の欄を 10 の何乗倍かした整数に直す `nmea_fix` は、`nmea_dm_e7` と同じ考え方なので中身を省いた）。

```c
struct gga {
    int32_t t_ms;                      /* UTC（14 章）の 0 時からの時間 [ms]。無ければ −1 */
    int quality, nsat;                 /* 測位の品質・使った衛星の数 */
    int has_pos, has_alt;              /* 位置・高さの欄があったか */
    int32_t lat, lon;                  /* 緯度・経度 [1e-7 度] */
    int32_t hdop_c;                    /* HDOP × 100（無ければ −1） */
    int32_t alt_mm, sep_mm;            /* 標高・ジオイド高 [mm] */
};
int nmea_fix(const char *s, int dec, int32_t *out);    /* "3.3", dec = 3 → 3300。空の欄や数でなければ 0 */

int32_t nmea_time_ms(const char *s)                    /* hhmmss.ss → その日の 0 時からの ms。誤りは −1 */
{
    int32_t v[3], ms = 0, w = 100;
    int k;
    for (k = 0; k < 3; k++, s += 2) {                  /* 時・分・秒（2 桁ずつ） */
        if (s[0] < '0' || s[0] > '9' || s[1] < '0' || s[1] > '9') return -1;
        v[k] = (s[0] - '0') * 10 + (s[1] - '0');
    }
    if (*s == '.')                                     /* 秒の小数（ms より細かい桁は捨てる） */
        for (s++; *s >= '0' && *s <= '9'; s++, w /= 10) ms += (*s - '0') * w;
    if (*s != '\0' || v[0] > 23 || v[1] > 59 || v[2] > 60) return -1;   /* 秒の 60 はうるう秒（14 章） */
    return ((v[0] * 60 + v[1]) * 60 + v[2]) * 1000 + ms;
}

int nmea_gga(char *body, struct gga *g)                /* GGA の中身を数値に直す。GGA でなければ 0 */
{
    char *f[NMEA_FIELDS];
    int32_t q = 0, ns = 0;
    int n = nmea_split(body, f, NMEA_FIELDS);
    if (n < 15 || strlen(f[0]) != 5 || strcmp(f[0] + 2, "GGA") != 0) return 0;
    g->t_ms = nmea_time_ms(f[1]);                      /* 時刻が無ければ −1 */
    nmea_fix(f[6], 0, &q);                             /* 測位の品質（空なら 0 のまま） */
    nmea_fix(f[7], 0, &ns);
    g->quality = (int)q; g->nsat = (int)ns;
    g->has_pos = nmea_dm_e7(f[2], f[3][0], 90, &g->lat) && nmea_dm_e7(f[4], f[5][0], 180, &g->lon);
    if (!nmea_fix(f[8], 2, &g->hdop_c)) g->hdop_c = -1;          /* HDOP × 100 */
    g->has_alt = nmea_fix(f[9], 3, &g->alt_mm) && nmea_fix(f[11], 3, &g->sep_mm);
    return 1;
}
```

`NMEA_FIELDS` は欄の数の上限（例では 24）である。`f[0] + 2` は話者 ID の 2 文字を飛ばした文の種類なので、GP でも GN でも同じ関数で読める。例の GGA を `nmea_gga` に通すと、次の図の値になる。

## 6. 落とし穴 — 空の欄・桁・時刻のずれ

### 空の欄

C の標準関数 `strtok` は、区切りの文字が続くとき、その間の空の文字列を返さずに飛ばす。空の欄のある文を `strtok` で分けると、空の欄より後ろの欄の番号が全部ずれる。

```fig
e12_strtok
```

位置が出ている間の GGA には、空の欄が終わりの近くにしか無いので、`strtok` でも正しく読めてしまい、試験で見つけにくい。4 節の `nmea_split` のように、カンマごとに必ず 1 つの欄を作る。

### 桁の数と、版で増えた欄

同じ値でも、製品と規格の版によって、桁の数と欄の数が違う。

```fig
e12_versions
```

規格は、版（2.x・3.x・4.x）を重ねるたびに、文の後ろに欄を足してきた。どの版の文を出すかはモジュールと設定（13 章）による。したがって、欄は頭からの番号で読み、後ろに知らない欄が増えていても読み飛ばし、欄が足りないときは「無い」として扱う。桁の数も決め打ちせず、数字が続く限り読む（5 節の関数はそうなっている）。

### 位置が出ていない間と、UTC の時刻

電源を入れてから位置が出るまで（TTFF の間）も、モジュールは文を出し続ける。

```fig
e12_nofix
```

位置が出ていない間の位置の欄は、空か、製品によっては前に求めた値である。時刻の欄も、衛星から時刻を受け取るまでは、空か、モジュールの中の時計の値（製品による）になる。したがって、位置と時刻は、測位の品質が 1 以上で、RMC の状態が A のときだけ使う（どの品質から、どの HDOP までなら使ってよいかの判断は 15 章）。

時刻は UTC なので、日本の時刻にするときは 9 時間を足し、日付の繰り上がりも扱う。GGA には日付が無いので、同じ時刻の RMC の日付と組み合わせる（同じ時刻の文を 1 組にまとめる処理は 15 章）。
