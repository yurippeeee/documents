# 24. 総合演習 — GNSS ロガーを設計する

> **この章で扱う問い.**
> 1〜23 章で、衛星の信号と受信機の仕組み、回路と基板、プログラム、精度を上げる方法、ノイズ対策と筐体、評価の方法をそろえた。最後のこの章では、それらの道具を 1 つの機器に通して使い、電池で動き、位置と時刻を記録するロガー（例）を、仕様から評価まで設計する。新しい理論はほとんど無く、各節で、どの章の道具を使ったかを示す。
>
> この章では次の 3 つの問いに答える。
>
> 1. ロガーの仕様を、どんな項目と数値で書き、各項目の値を、どの章の道具で見積もるのか。
> 2. 回路・基板・筐体・ファームウェアを、どの順に決め、各段で何を計算して確かめるのか。
> 3. 精度を上げる方法をどう選び、設計が仕様を満たすかを、どう判定して仕上げるのか。
>

## 2. 回路と部品を選ぶ

### 回路の構成

この節では、3・8・9・10 章の道具で部品を選び、次の図の回路にする。

```fig
e24_block
```

アンテナは、右旋円偏波のパッチアンテナにする。直線偏波のチップアンテナは、右旋の電波を受けると 3 dB 損する（[8 章 2 節](08_アンテナ.md#右旋円偏波-衛星の電波の向きとマルチパス)）。SAW フィルタは、5 節で受けることにする GLONASS（1602 MHz 付近）と BeiDou（B1I 1561.098 MHz）も通す帯域（1559〜1606 MHz。例）のものにする。1PPS は使わない。ロガーが記録に付ける時刻は、組の時刻の欄で足りるからである（4 節）。

### C/N0 を見積もって LNA の要否を決める

仰角 30° の衛星を 3 章 3 節の例のアンテナ（仰角 30° で約 −1 dBi）で受ける電力は、[3 章 1 節](03_信号の強さとCN0.md#衛星から届く電力-約-−130-dbm)の回線計算（EIRP 26.4 dBW・大気 0.5 dB）で −128.6 dBm である。雑音の電力スペクトル密度は、9 章 1 節のフリスの式で求めたシステム雑音温度 $`T_\mathrm{sys}`$ から $`N_0 = k_\mathrm{B}T_\mathrm{sys}`$ で決まる。このように見積もった設計の値が、仕様の値（や、目安のしきい値）をどれだけ上回るかを**余裕**（マージン）という。精度や TTFF のように、小さいほど良い項目では、仕様の値が設計の値をどれだけ上回るかを余裕とする。LNA の有無と置き場所を変えて、4 行目の余裕を比べる。

```fig
e24_lna
```

LNA を入れると C/N0 は 5.4 dB 上がる。LNA が無いと、SAW フィルタの挿入損失と受信用のチップの増幅器の雑音が、そのまま $`T_\mathrm{sys}`$ に足される（[9 章 3 節](09_LNAとフィルタ.md#フィルタの置き場所-lna-の前か後か)）ので、余裕は 1.0 dB しか無く、3 節で足す線と筐体の損失と、部品のばらつきで割ってしまう。したがって、9 章の例の並び（LNA → SAW フィルタ）にする。LNA の電流は、モジュールと一緒に入れ切りするので、平均では小さい（4 節）。

LNA の前の線（50 Ω のマイクロストリップ線路）の損失は、雑音指数にそのまま足される（[11 章 4 節](11_RFの基板設計.md#部品の置き方-アンテナ-lna-フィルタ-モジュール)）ので、LNA と SAW フィルタはアンテナのすぐ外に置く。充電の回路は、スイッチング周波数 2 MHz が L1 C/A の帯域の幅 2.046 MHz より低いので、どれかの高調波が必ず帯域に入る（[20 章 3 節](20_妨害とノイズの源.md#高調波が-gnss-の帯域に落ちる)）。そのため、電源の区画の端に置き、アンテナから離す。電池と USB の端子の金属は、地板の裏と基板の端に置く（[22 章 4 節](22_筐体とアンテナの置き方.md#地板とアンテナの向き)）。

### 筐体とアンテナ

筐体は ABS の樹脂で、アンテナの上は厚さ 2 mm、パッチとの隙間は 1 mm にする（例）。樹脂がアンテナの近くに来るので、22 章 2 節の離調のモデルで、共振周波数のずれと L1 での軸比を見積もる。

```fig

```

L1 の S11 は −20.9 dB でよく合って見えるが、軸比は 5.4 dB に悪くなる。整合の回路では軸比は戻らない（22 章 2 節）ので、筐体に入れたときに合うよう、共振を 5 MHz 上げたアンテナを選ぶ。選んだ後は、筐体に組んだ状態で S11 を測り、谷の中心が L1 に来ていることを確かめる（[8 章 6 節](08_アンテナ.md#整合と測り方-反射とリターンロス)）。

### 15 章の部品に足すもの

ファームウェアは、12〜15 章の部品を名前と型を変えずに使い、記録と電源の管理を足す（次の図）。この節のコードは、15 章のコードと同じファイルに置き、15 章の `sm`（測位の状態）と `ep`（組）をそのまま使う。


まず、この章で仮に置く関数、ロガーの状態、1 件の記録の形を宣言する（ブロック A）。

```c
void gnss_power(int on);                      /* 仮に置く関数: モジュールの主の電源を入れる・切る（10 章 6 節の順番で） */
int  cfg_step(uint32_t now);                  /* 仮に置く関数: 13 章 6 節の手順で設定を確かめる。終われば 1 */
int  gnss_stop(uint32_t now);                 /* 仮に置く関数: 13 章 5 節の停止の命令を送り、ACK か時間切れで 1 */
int  uart_next_baud(void);                    /* 仮に置く関数: 次の通信の速さに変える（13 章 3 節）。全部試したら 0 */
void flash_write(uint32_t addr, const void *p, uint32_t n);   /* 仮に置く関数: フラッシュに書く */

#define TU_MS     60000u                      /* 記録の間隔 [ms]（1 節の仕様の例） */
#define TU_MAX    1800000u                    /* 起きる間隔の上限 30 分（15 章 5 節） */
#define WAIT_TXT  2000u                       /* 文を待つ上限 [ms]（15 章 5 節） */
#define WAIT_FIX  45000u                      /* 電源を入れてから測位を待つ上限 [ms]（15 章 5 節） */
#define LOG_SIZE  (8u * 1024u * 1024u)        /* フラッシュ 8 MB（例の値） */

enum lg_state { LG_SLEEP, LG_WAIT_TXT, LG_CONFIG, LG_WAIT_FIX, LG_STOP };
struct logger {
    enum lg_state st;
    uint32_t t_wake, t_on, t_st, iv;          /* 次に起きる時刻・電源を入れた時刻・今の段に入った時刻・間隔 [ms] */
    int got;                                  /* この回に記録したか */
    uint32_t addr, n_wake, n_fail;            /* 次に書くアドレス・起きた回数・位置が出なかった回数 */
} lg = { LG_SLEEP, 0, 0, 0, TU_MS, 0, 0, 0, 0 };

struct log_rec {                              /* 1 件の記録（32 B） */
    uint32_t gps_s;                           /* 組の GPS 時刻: 1980-01-06 からの秒（14 章 1 節） */
    int32_t  lat, lon;                        /* 緯度・経度 [1e-7 度]（12 章 5 節） */
    int32_t  alt_mm, sep_mm;                  /* 標高・ジオイド高 [mm] */
    uint16_t ms, hdop_c, on_ds;               /* 秒の端数 [ms]・HDOP × 100・起きてから記録まで [0.1 s] */
    uint8_t  nsat, state, leaps, flags;       /* 衛星の数・測位の状態・うるう秒の数・印 */
    uint8_t  ck[2];                           /* フレッチャーのチェックサム（13 章 2 節） */
};
typedef char log_rec_is_32[sizeof(struct log_rec) == 32 ? 1 : -1];   /* 32 B でないと翻訳の誤り */
```

15 章 4 節で仮に置いた `use_epoch` の中身として、使ってよい組（`USE_OK`）を 32 B の記録にしてフラッシュに書く（ブロック B）。時刻は、組の時刻の欄（GGA と RMC の時刻と、RMC の日付）を 15 章 4 節の `epoch_gnss_ns` で GPS 時刻に直した値で、組を受け終えたマイコンの時刻は使わない。受け終えた時刻には位置の遅れ（[13 章 3 節](13_バイナリプロトコルと設定.md#設定-出力-更新レート-通信速度)。例で 0.27 s）が入るからである（[14 章 6 節](14_時刻と1PPS.md#時刻を付けて記録する)）。うるう秒の数も記録に残し、13 章 2 節の `bin_sum`（フレッチャーのチェックサム）を付けて、読み出したときに壊れていないかを確かめる。

```c
void use_epoch(const struct epoch *e, enum fix_state st, enum use_why w)   /* 15 章 4 節で仮に置いた関数 */
{
    struct log_rec r;
    if (w != USE_OK || lg.st != LG_WAIT_FIX || e->r.date < 0 || lg.addr + sizeof r > LOG_SIZE) return;
    r.gps_s = (uint32_t)(epoch_gnss_ns(e, LEAPS) / 1000000000);   /* 組の時刻の欄から（届いた時刻は使わない） */
    r.ms = (uint16_t)(e->t_ms % 1000);
    r.lat = e->g.lat; r.lon = e->g.lon; r.alt_mm = e->g.alt_mm; r.sep_mm = e->g.sep_mm;
    r.hdop_c = (uint16_t)e->g.hdop_c; r.nsat = (uint8_t)e->g.nsat;
    r.on_ds = (uint16_t)((now_ms() - lg.t_on) / 100);
    r.state = (uint8_t)st; r.leaps = LEAPS; r.flags = 0;
    bin_sum((const uint8_t *)&r, 30, r.ck);  /* 13 章 2 節: 読み出したときに壊れていないか確かめる */
    flash_write(lg.addr, &r, sizeof r);
    lg.addr += sizeof r;
    lg.got = 1;
}
```

8 MB には 262 144 件が入り、60 s ごとに 24 時間記録しても 182 日分である（8 行目）。

電源の管理は、15 章 5 節の状態機械を、そのまま `logger_step` にする（ブロック C）。起きるたびに `ep.t_ms` を −1 にするのは、前の回の組の時刻と比べて、時刻の飛び `n_gap`（15 章 4 節）を数えないためである。位置が出ないときは、次に起きるまでの間隔を 2 倍ずつ延ばす（15 章 5 節）。

```c
void logger_step(uint32_t now)                /* 主のループで、gnss_poll の後に呼ぶ */
{
    switch (lg.st) {
    case LG_SLEEP:
        if ((int32_t)(now - lg.t_wake) < 0) return;          /* まだ起きる時刻ではない */
        gnss_power(1);
        lg.t_on = lg.t_st = now; lg.got = 0; lg.n_wake++;
        ep.t_ms = -1;                                        /* 前の回の組を持ち越さない */
        lg.st = LG_WAIT_TXT; break;
    case LG_WAIT_TXT:                                        /* 正しい文が来ると sm は文なしを出る */
        if (sm.st != FS_NODATA) lg.st = LG_CONFIG;
        else if (now - lg.t_st > WAIT_TXT) {                 /* 来ない: 次の通信の速さを試す */
            lg.t_st = now;
            if (!uart_next_baud()) lg.st = LG_STOP;
        }
        break;
    case LG_CONFIG:
        if (cfg_step(now)) lg.st = LG_WAIT_FIX;
        break;
    case LG_WAIT_FIX:                                        /* use_epoch が記録すると got が立つ */
        if (lg.got || now - lg.t_on > WAIT_FIX) { lg.st = LG_STOP; lg.t_st = now; }
        break;
    case LG_STOP:
        if (!gnss_stop(now)) break;
        gnss_power(0);                                       /* 信号を L にしてから主の電源を切る */
        if (lg.got) lg.iv = TU_MS;                           /* 位置が出た: 初めの間隔に戻す */
        else { lg.n_fail++; lg.iv = (lg.iv > TU_MAX / 2) ? TU_MAX : 2 * lg.iv; }   /* 出ない: 2 倍に */
        lg.t_wake += lg.iv;
        if ((int32_t)(now - lg.t_wake) > 0) lg.t_wake = now; /* 長く起きていた: すぐ次へ */
        lg.st = LG_SLEEP; break;
    }
}
```

主のループは、`gnss_poll` と `logger_step` を呼び、眠っている段では RTC の割り込みまでマイコンを止める（ブロック D）。

```c
void board_init(void);                        /* 仮に置く関数: 時計・UART・RTC・フラッシュの初めの設定 */
void mcu_sleep_until(uint32_t t);             /* 仮に置く関数: RTC の割り込みで時刻 t に起きるまで止まる */

int main(void)
{
    board_init();
    for (;;) {
        gnss_poll();                          /* 15 章 4 節: 届いた文を組にし、状態機械と判断に渡す */
        logger_step(now_ms());
        if (lg.st == LG_SLEEP) mcu_sleep_until(lg.t_wake);   /* 眠っている間は 2 µA */
    }
}
```


起きてから記録まで 4.15 s かかるのは、15 章 3 節の状態機械が、位置のある組が 3 回続いてから 3D に上がり、`fix_judge` がそれまで使ってよいとしないからである。ホットスタートの TTFF 2 s の後に 2 s 待つ分だけ、モジュールは追尾中の電流を流す。ウォームスタートでは記録まで 32.15 s かかるので、測位を待つ上限（15 章 5 節の 45 s）はこれより長くなければならない。短いと、エフェメリスを受け直す前に電源を切るので、次の回もウォームスタートになり、屋外でも記録できない。

### 1 日の電荷と電池の持ち時間

13 章 5 節で、周期的に起きる省電力モードの平均の電流を求めた式は、毎回同じ周期で起きて位置が出るとした。例の 1 日では、屋内で位置が出ない回と、外に出た後のウォームスタートが加わるので、試験と同じ規則で 1 日に起きる回を全部数え、2 節の表の電流を掛けて足す。

```fig

```

1 日に 44.0 mAh を使い、2000 mAh の電池は 45.4 日持つ（9 行目の仕様は 30 日以上）。最も大きいのは、屋内で 45 s 探して止める回の 21.6 mAh で、屋外の記録の 18.8 mAh より大きい。起きる間隔を延ばさないと、屋内で 60 s ごとに 45 s 探し続けて 3.9 日しか持たない。延ばす代わりに、屋内から外に出た後、最初の記録まで最大 30 分待つ（例の 1 日では、12:15 に外に出てから 15.5 分）。

単独測位のまま精度を上げるには、衛星系を増やして DOP を下げる（[13 章 4 節](13_バイナリプロトコルと設定.md#衛星系と動きのモデルを選ぶ)）。

4 つの衛星系を受けると、開けた空の R95 は 3.6 m になり、通りの中でも 99 % の時間で位置が解ける（GPS だけでは、通りの中の衛星が未知数より少なく、一度も解けない）。その代わり、10 章 4 節の例の文をそのまま出すと、1 回 999 B になり、9600 bit/s では送り切れない（負荷率 104 %）。ロガーが使うのは GGA と RMC だけなので、13 章 3 節の設定で出す文をこの 2 つにしぼり、1 回 141 B（14.7 %）にする。1 秒ごとに連続で記録しても、受け取るのは 1 回分の 141 B で、15 章 2 節の 1024 B のリングバッファに収まる（7 行目）。
