# 14. 時刻と 1PPS — GNSS で時計を合わせる

> **この章で扱う問い.**
> GNSS の受信機は、位置と一緒に自分の時計のずれも求めるので、正確な時計にもなる（1 章 3 節）。10 章では、受信機が秒の変わり目を知らせる 1PPS の端子を、12 章では、文の時刻の欄が UTC で書かれることを見た。この章では、受信機が知った時刻を、マイコンの時計と、センサのデータに移す。
>
> この章では次の 3 つの問いに答える。
>
> 1. GNSS の時刻は、ふだん使う UTC の日付と時刻と、どう違うのか。週番号と週の中の秒から日付と時刻を求めるには、何に気を付けるのか。
> 2. 1PPS のパルスは何を知らせ、どれだけ正確なのか。どのパルスが何時何分何秒の頭かを、どう知るのか。パルスの時刻の誤差は、何から来るのか。

## 1. GNSS の時刻 — GPS 時刻・UTC・うるう秒

### UTC・うるう秒・GPS 時刻

世界の時計が基準にしている時刻を **UTC**（Coordinated Universal Time、協定世界時）という。UTC の 1 秒は、世界の多くの原子時計（1 章 2 節）で決めた長さで、進み方は一定である。一方、地球の自転は揺らぎながら少しずつ遅れるので、原子時計の秒を数えるだけでは、時刻が太陽の動きから離れていく。そこで UTC は、地球の自転で決まる時刻との差が 0.9 s を超えないように、必要なときに 1 秒を足す。この 1 秒を**うるう秒**という。うるう秒は、6 月か 12 月の最後の 23 時 59 分 59 秒の後に、23 時 59 分 60 秒として入る（規格では 1 秒を抜くこともできるが、書いた時点まで行われたことはない）。

GPS の衛星の時計がそろえてある基準の時刻を **GPS 時刻**という。GPS 時刻は、1980 年 1 月 6 日 0 時（UTC）を 0 とし、うるう秒を足さずに秒を数え続ける。そのため GPS 時刻は、1980 年から入ったうるう秒の数だけ、UTC より進んでいる。書いた時点（2026 年）では、2016 年 12 月 31 日の終わりに入ったうるう秒を最後に、18 s である（次の図）。

```fig
e14_leap
```

うるう秒を入れるかどうかは、半年ほど前に決まって発表される。2022 年の国際度量衡総会は、遅くとも 2035 年までに、地球の自転との差の上限を広げて、うるう秒を入れないようにすることを決めた（具体的なやり方は、書いた時点で検討中）。受信機は、GPS 時刻と UTC の差と、次のうるう秒の予告を、航法メッセージのサブフレーム 4 の 1 つのページで受け取る（[2 章 5 節](02_衛星の信号.md#航法メッセージ-軌道と時計の情報)）。全部のページの一巡は 12.5 分なので、電源を入れてからしばらくは差をまだ受け取っておらず、その間の UTC は、受信機が前から持っている値で計算されることがある（製品による）。受信機の中の計算は途切れない GPS 時刻で行い、人に見せる時刻と NMEA の文の時刻（12 章）は、差を引いた UTC で出す。

### 週番号と週の中の秒

GPS 時刻は、日付ではなく週で数える。1980 年 1 月 6 日（日曜日）0 時から数えた週の数を**週番号**といい、その週の始まり（日曜日の 0 時。GPS 時刻）からの秒を**週の中の秒**（TOW、time of week）という。1 週は 7 × 86 400 = 604 800 s なので、週の中の秒は 0〜604 799 の値をとる（[2 章 6 節](02_衛星の信号.md#信号の時間の構造-チップ-符号の周期-ビット-フレーム)の HOW は、週の中の秒を 6 s 単位で数えた値である）。日付と時刻から週番号と週の中の秒を求めるには、うるう秒の数を足してから、1980 年 1 月 6 日からの日数を 7 で割る。逆は、秒に直してから、うるう秒の数を引いて日数に分ける（次の図。例の時刻は 10 章・12 章の例の文の時刻）。

### 週番号の一巡

L1 の C/A 符号の航法メッセージは、週番号を 10 bit で送るので、1023 の次は 0 に戻る。週番号が 0 に戻ることを**週番号の一巡**という。1024 週は約 19.6 年で、一巡は 1999 年 8 月 22 日と 2019 年 4 月 7 日（どちらも GPS 時刻の 0 時）に起き、次は 2038 年 11 月 21 日である（次の図。日付は Python で計算した）。

```fig
e14_week
```

10 bit の値だけでは、何回目の一巡の中にいるかが分からない。そこで受信機は、作った時期などの基準の週から 1024 週の間にいるとみなして、本当の週番号に直す。基準から 1024 週を過ぎると日付を誤り、2019 年 4 月には、一部の古い受信機が日付を 19.6 年前に戻した。新しい形式の航法メッセージ（L2C・L5 の CNAV）は、週番号を 13 bit（8192 週、約 157 年）で送る。

日付と時刻と、週番号と週の中の秒の間の変換を C で書く。うるう秒の数は、航法メッセージから受け取った値を引数で渡す。

```c
struct utc { int y, mo, d, h, mi, s; };            /* 日付と時刻（UTC） */
static const uint8_t MDAYS[12] = {31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31};
static int is_leap(int y) { return (y % 4 == 0 && y % 100 != 0) || y % 400 == 0; }
static int mdays(int y, int m) { return MDAYS[m] + (m == 1 && is_leap(y)); }   /* m は 0〜11 */

/* GPS 時刻（週番号・週の中の秒）と、そのときの GPS−UTC の秒数 leaps から、UTC の日付と時刻を求める */
void gps_to_utc(int week, int32_t tow, int leaps, struct utc *u)
{
    int64_t s = (int64_t)week * 604800 + tow - leaps;  /* 1980-01-06 0 時（UTC）からの秒（UTC の数え方） */
    int32_t days = (int32_t)(s / 86400) + 5, sod = (int32_t)(s % 86400);   /* +5: 1980-01-01 からの日数に */
    int y = 1980, m = 0;
    while (days >= 365 + is_leap(y)) { days -= 365 + is_leap(y); y++; }
    while (days >= mdays(y, m)) { days -= mdays(y, m); m++; }
    u->y = y; u->mo = m + 1; u->d = days + 1;
    u->h = sod / 3600; u->mi = sod / 60 % 60; u->s = sod % 60;
}

/* UTC の日付と時刻と leaps から、GPS 時刻の週番号と週の中の秒を求める（1980-01-06 以後） */
void utc_to_gps(const struct utc *u, int leaps, int *week, int32_t *tow)
{
    int32_t days = u->d - 1 - 5;                       /* 1980-01-06 からの日数（まず月の中の分） */
    for (int y = 1980; y < u->y; y++) days += 365 + is_leap(y);
    for (int m = 0; m < u->mo - 1; m++) days += mdays(u->y, m);
    int64_t s = (int64_t)days * 86400 + u->h * 3600 + u->mi * 60 + u->s + leaps;
    *week = (int)(s / 604800);
    *tow = (int32_t)(s % 604800);
}
```

```c
/* 10 bit の週番号 wn10 を、基準の週 ref（例: ファームウェアを作った週）から 1024 週の中の週番号に直す */
int week_unroll(int wn10, int ref)
{
    int w = (ref & ~1023) + wn10;                      /* ref と同じ一巡の中の候補 */
    if (w < ref) w += 1024;                            /* ref より前なら、次の一巡 */
    return w;
}
```

`gps_to_utc` と `utc_to_gps` は、1980 年から 2123 年までの 4 万通りの値で、Python の日付の計算と一致した。`week_unroll` は、基準の週から 1023 週後までの全部の組（73 万通り）で正しい週番号を返し、基準の週 2400（2026 年 1 月 4 日の週）なら 2045 年 8 月 19 日まで正しい。うるう秒の 1 秒の間（23 時 59 分 60 秒）は、この関数では表せない（6 節）。

ほかの衛星系の時刻は、[1 章 5 節](01_GNSSとは何か.md#座標と時刻-地球中心の座標-緯度経度-gnss-の時刻)の図のとおりである。Galileo とみちびきの時刻は、GPS 時刻と秒の数をそろえてあり、BeiDou の時刻は 2006 年 1 月 1 日からうるう秒を足さずに数えるので GPS 時刻より 14 s 遅れ、GLONASS の時刻は UTC に 3 時間を足したもので、うるう秒も入る。系の間には、ほかに数 ns〜数十 ns の差がある（代表値）。複数の衛星系を使う受信機は、この差を、航法メッセージで配られる値で直すか、衛星系ごとに時計のずれの未知数を足して、位置と一緒に求める。

## 2. 1PPS — 秒の頭を知らせるパルス

### 立ち上がりが表すもの

受信機（10 章の GNSS モジュール）は、擬似距離から、位置と一緒に受信機の時計のずれを求める（[1 章 3 節](01_GNSSとは何か.md#受信機の時計のずれ-4-つ目の衛星が要る理由)）。ずれが分かれば、受信機の時計のどの読みが GNSS の時刻の秒の変わり目にあたるかが分かるので、その瞬間に 1PPS（周期 1 s のタイムパルス）を立ち上げる。GPS 時刻と UTC の差は整数の秒なので、どちらの秒の頭も同じ瞬間で、違うのはその秒の名前だけである（次の図の (a)）。どちらの時刻に合わせるかや、パルスの幅・どちらの縁を秒の頭にするかは、設定で選べる製品が多い（[13 章 3 節](13_バイナリプロトコルと設定.md#設定-出力-更新レート-通信速度)）。

立ち上がりの時刻の誤差は、受信機が求めた時計のずれの誤差である。[7 章 4 節](07_誤差とDOP.md#dop-衛星の並びが誤差を広げる)の TDOP は、擬似距離の誤差の標準偏差に掛けると、時計のずれを距離に直した値の誤差の標準偏差になる倍率だったので、時刻の誤差の標準偏差は、光の速さ $`c`$ で割って

$$
\sigma_t = \frac{\mathrm{TDOP}\times\sigma_\mathrm{UERE}}{c}
$$

である。7 章の東京の 8 つの衛星（TDOP 0.79）と誤差の予算（UERE 3.99 m）では、$`\sigma_t`$ = 0.79 × 3.99 m ÷ $`c`$ = 10.5 ns になる（図の (b)）。これは、擬似距離の誤差が衛星ごとに独立だとした見積もりで、製品の資料では、代表値で数十 ns（製品による）とされることが多い。

```fig
e14_meaning
```

位置が分かっている所に置き、位置を固定して時刻だけを求める受信機（時刻の専用の受信機に多い。製品による）は、未知数が 1 つになるので、時刻の誤差がさらに小さい。電源を入れてから位置が出るまでは、パルスを出さないか、秒の頭に合っていないパルスを出す（[10 章 5 節](10_モジュールの回路.md#1pps-とタイムパルス)）。

### どのパルスが何秒の頭か

パルスには、何時何分何秒の頭かという情報が無い。それは、パルスの前後に届く文の時刻で知る。多くの製品は、秒の頭で測った結果を、計算が終わってから文にして出すので、文の時刻の欄は、その文の直前のパルスの秒を表す（次の図の (a)）。マイコンは、パルスの瞬間をタイマで記録し（3 節）、次に届いた GGA か RMC の時刻を、その記録に名前として付ける。

```fig
e14_label
```

この付け方は、文の位置の遅れ（位置を求めた時刻から、その文を受け終わるまでの時間。[13 章 3 節](13_バイナリプロトコルと設定.md#設定-出力-更新レート-通信速度)）が 1 秒を超えると、1 秒ずれる（図の (b)）。10 章 4 節の例の文を 9600 bit/s で 1 秒に 2 回出すと（更新レート 2 Hz）、負荷率が 130 % なので、位置の遅れは 1 秒に 0.30 s ずつ増えていく（13 章 3 節）。したがって、位置の遅れが 1 秒より十分短いこと（負荷率が 100 % より十分小さいこと）を確かめ、パルスとパルスの間に、時刻がちょうど 1 秒進んだ文が 1 つずつ届くことを確かめながら付ける。文を捨てる製品では、名前の付かないパルスができる。次のパルスの時刻を、パルスの前に予告するメッセージを出す製品もある（図の (c)）。文を受け取りながら、同じ時刻の文を 1 組にまとめてパルスと対応させる実装は、[15 章 4 節](15_組み込みでの実装.md#時刻とデータをそろえる)で扱う。

下の図で、出す文・ボーレート・更新レート・文が出始めるまでの遅れを変えて再生すると、どのパルスに何秒の名前が付くかと、名前を付け誤る条件を確かめられる。

## 3. マイコンの時計を合わせる — タイマで捕まえる

### インプットキャプチャ

マイコンのタイマは、クロック（この章の例では 10 MHz）の刻みを数え続けるカウンタである。カウンタが数えている値を、端子の立ち上がりの瞬間に、回路が別の場所（捕獲の値を入れるレジスタ）へ写して残す仕組みを**インプットキャプチャ**（入力の捕獲）という。写すのは回路なので、その後の割り込みの処理がいつ動いても、残った値は立ち上がりの瞬間のものである。割り込みの処理の中でカウンタを読むと、ほかの割り込みや処理を待った時間だけ遅れた値になり、その遅れは毎回違う（次の図）。OS のティック（[OS シリーズ 8 章 1 節](../freertos/08_ティックとタイムスライス.md#ティック-os-にとっての時間)）や、ティックで動くソフトウェアタイマ（[15 章 1 節](../freertos/15_ソフトウェアタイマ.md#3-つの-タイマ-の違い)）では、刻みがさらに粗い。

```fig

```

端子の信号は、回路の中でクロックにそろえてから写すので、製品によっては 1〜2 カウントの一定の遅れが加わる（クロックにそろえる理由は[組み込み回路シリーズ 12 章 3 節](../circuit/12_タイミング.md#メタステーブル-準安定状態)）。

### 1 秒を数える — 水晶の周波数の誤差

隣り合う 2 つのパルスの捕獲値を $`C_{k-1}`$・$`C_k`$（$`k`$ はパルスの番号）とすると、差 $`C_k - C_{k-1}`$ は、本当の 1 秒の間にタイマが数えた数である。周波数の相対的な誤差は、100 万分の 1 を単位にして表すことが多い。この単位を **ppm**（parts per million）という。1 ppm = 10⁻⁶ で、時計なら 1 秒に 1 µs、1 日に 86.4 ms のずれにあたる。マイコンの水晶の周波数の、名目の値からの相対的な誤差を $`r_\mathrm{m}`$、タイマの名目の周波数を $`f_\mathrm{tim}`$、パルスの周期を $`T_\mathrm{p}`$ = 1 s とすると、1 秒の数は $`f_\mathrm{tim}T_\mathrm{p}(1 + r_\mathrm{m})`$ なので

$$
r_\mathrm{m} = \frac{C_k - C_{k-1}}{f_\mathrm{tim}T_\mathrm{p}} - 1
$$

である。$`r_\mathrm{m}`$ は、マイコンの時計が 1 秒あたりに進みすぎる時間で、[6 章 5 節](06_位置を解く.md#速度を求める-ドップラーから)の時計のドリフトと同じ量である（数え方の比べは[電源と周辺の制御シリーズ 8 章 1 節](../periph/08_センサをつなぐ.md#パルスを測る時間)）。

32 bit のカウンタは、10 MHz なら 2³² カウント（429.5 s）で一周して 0 に戻る。差を符号なしの 32 bit で計算すれば、一周をまたいでも正しい（次の図の (a)。理由は[組み込み通信シリーズ 5 章 3 節](../comm/05_状態機械とタイムアウト.md#一周するカウンタと-期限の比較)と同じ）。

```fig
e14_count
```

1 つの捕獲値は 1 カウントまでの誤差を持つので、1 秒の差から求めた $`r_\mathrm{m}`$ は ±0.1 ppm の誤差を持つ。$`N`$ 秒離れた 2 つの捕獲値の差を使えば、途中の誤差は打ち消し合い、誤差は $`N`$ 分の 1 になる（図の (b)）。捕獲の割り込みと、差から周波数の誤差を求める関数を示す。`timer_capture()` は、捕獲の値を入れるレジスタを読む、この章で仮に置く関数である。

```c
#define F_TIM 10000000                     /* タイマの名目の周波数 [Hz]（例: 10 MHz） */
#define NS_PER_COUNT 100                   /* 1 カウントの名目の時間 [ns] */

static volatile uint32_t g_cap;            /* 割り込みが書き、主の処理が読む */
static volatile uint8_t g_cap_new;
void pps_capture_isr(void)                 /* 1PPS の立ち上がりの捕獲で呼ばれる割り込み */
{
    g_cap = timer_capture();               /* 立ち上がりの瞬間のカウント（仮に置く関数） */
    g_cap_new = 1;
}

/* 2 つの捕獲値から、間の秒数 *nsec と、マイコンの水晶の周波数の誤差 [10^-9] を求める */
int32_t rate_ppb(uint32_t c0, uint32_t c1, int *nsec)
{
    uint32_t d = c1 - c0;                  /* カウンタが一周をまたいでも正しい（2^32 カウント未満） */
    int n = (int)((d + F_TIM / 2) / F_TIM);   /* 何秒分か（パルスが抜けても、いちばん近い整数） */
    *nsec = n;
    if (n == 0) return 0;
    return (int32_t)(((int64_t)d - (int64_t)n * F_TIM) * 1000000000 / ((int64_t)n * F_TIM));
}
```

図の例の捕獲値で 20 000（20 ppm）を返し、パルスが 2 つ抜けた 3 秒分の差でも、3 秒と 20 ppm を返すことを確かめた。

### PI 制御で時計を合わせる

$`r_\mathrm{m}`$ が分かれば、マイコンの時計の進み方を直せる。しかし、$`r_\mathrm{m}`$ は温度で変わり、捕獲値の誤差も含む。そこで、パルスのたびに時計のずれを測り、周波数の補正を少しずつ直す。マイコンの時計の、$`k`$ 番目のパルスの瞬間の読みから、そのパルスの GNSS の時刻を引いた差を、マイコンの時計のずれといい、$`\delta t_\mathrm{m}[k]`$ と書く。周波数の補正を $`\hat r[k]`$ とし、$`k`$ 番目から次のパルスまでは、時計の進み方を $`1 - \hat r[k]`$ 倍にする。補正は、ずれに比例する P 動作と、ずれの和に比例する I 動作を足した PI 制御（[制御工学シリーズ 10 章 1 節](../control/10_PID制御.md#p-動作-偏差に比例した操作量)・[2 節](../control/10_PID制御.md#i-動作-偏差をためて定常偏差を消す)）で決める。

$$
\hat r[k] = K_\mathrm{P}\,\delta t_\mathrm{m}[k] + K_\mathrm{I}T_\mathrm{p}\sum_{j=0}^{k}\delta t_\mathrm{m}[j]
$$

$`K_\mathrm{P}`$ [1/s] と $`K_\mathrm{I}`$ [1/s²] は、比例ゲインと積分ゲインである（次の図）。

```fig
e14_loop
```

このループが、ずれを 0 に収めるゲインの範囲と、収まる速さを求める。

**方針**: 2 つのパルスの間にたまるずれを式にし、2 つの時刻の式の差をとって和を消し、$`\delta t_\mathrm{m}`$ だけの漸化式にする。解を $`z^k`$ の形で探し、$`z`$ が満たす 2 次方程式の 2 つの根が、どちらも大きさ 1 より小さい条件と、根の大きさで決まる 1 秒ごとの縮み方を求める。

**導出**: $`k`$ 番目から次のパルスまでの本当の $`T_\mathrm{p}`$ の間に、補正した時計は $`(1 + r_\mathrm{m})(1 - \hat r[k])T_\mathrm{p} \approx (1 + r_\mathrm{m} - \hat r[k])T_\mathrm{p}`$ 進む（積 $`r_\mathrm{m}\hat r`$ は、例の 20 ppm で 4 × 10⁻¹⁰ と小さいので省く。省いた分も I 動作が直す）。したがって

$$
\delta t_\mathrm{m}[k+1] = \delta t_\mathrm{m}[k] + (r_\mathrm{m} - \hat r[k])T_\mathrm{p}
$$

である。この式の $`k`$ を 1 つ進めた式から、もとの式を引く。$`r_\mathrm{m}`$ は一定なので消え、$`\hat r[k+1] - \hat r[k] = K_\mathrm{P}(\delta t_\mathrm{m}[k+1] - \delta t_\mathrm{m}[k]) + K_\mathrm{I}T_\mathrm{p}\,\delta t_\mathrm{m}[k+1]`$ を代入して整理すると

$$
\delta t_\mathrm{m}[k+2] = (2 - K_\mathrm{P}T_\mathrm{p} - K_\mathrm{I}T_\mathrm{p}^2)\,\delta t_\mathrm{m}[k+1] - (1 - K_\mathrm{P}T_\mathrm{p})\,\delta t_\mathrm{m}[k]
$$

となる。$`\delta t_\mathrm{m}[k] = z^k`$ を代入して $`z^k`$ で割ると、$`f(z) = z^2 + pz + q = 0`$、$`p = -(2 - K_\mathrm{P}T_\mathrm{p} - K_\mathrm{I}T_\mathrm{p}^2)`$、$`q = 1 - K_\mathrm{P}T_\mathrm{p}`$ である（この $`z`$ は[制御工学シリーズ 15 章 5 節](../control/15_サンプリングと離散化.md#z-変換と離散時間の極)の $`z`$ と同じもの）。根を $`z_1`$・$`z_2`$ とすると、どんな初めの値からも $`\delta t_\mathrm{m}[k] = A_1 z_1^k + A_2 z_2^k`$ の形になるので、ずれが 0 に収まるのは $`|z_1| < 1`$ かつ $`|z_2| < 1`$ のときである。

根が共役な複素数のとき、$`f(z)`$ は実数の上では 0 にならず正なので $`f(1) > 0`$・$`f(-1) > 0`$ で、根の積が $`q = z_1 z_2 = |z_1|^2`$ なので、根が大きさ 1 より小さい条件は $`q < 1`$ である。根が実数のとき、上に開いた放物線 $`f(z)`$ は 2 つの根の間でだけ負になる。$`f(1) > 0`$ かつ $`f(-1) > 0`$ なら、$`1`$ も $`-1`$ も根の間に無いので、2 つの根は、両方が $`-1`$ と $`1`$ の間にあるか、両方が同じ側の外にある。後の場合は $`q = z_1 z_2 > 1`$ である。したがって、どちらの場合も、条件は $`f(1) > 0`$・$`f(-1) > 0`$・$`q < 1`$ の 3 つである。$`f(1) = 1 + p + q = K_\mathrm{I}T_\mathrm{p}^2`$、$`f(-1) = 1 - p + q = 4 - 2K_\mathrm{P}T_\mathrm{p} - K_\mathrm{I}T_\mathrm{p}^2`$ なので、ループが安定な範囲は

$$
K_\mathrm{P} > 0,\qquad K_\mathrm{I} > 0,\qquad K_\mathrm{I}T_\mathrm{p}^2 < 4 - 2K_\mathrm{P}T_\mathrm{p}
$$

である。根が複素数のとき、2 つの根の大きさは等しく $`|z_1| = |z_2| = \sqrt{q} = \sqrt{1 - K_\mathrm{P}T_\mathrm{p}}`$ なので、$`|\delta t_\mathrm{m}[k]| \le (|A_1| + |A_2|)(1 - K_\mathrm{P}T_\mathrm{p})^{k/2}`$ である。振れ幅は 1 秒ごとに $`\sqrt{1 - K_\mathrm{P}T_\mathrm{p}}`$ 倍になり（$`K_\mathrm{I}`$ によらない）、1/100 になるまでの秒数 $`n`$ は、$`(1 - K_\mathrm{P}T_\mathrm{p})^{n/2} = 1/100`$ を解いて $`n = 2\ln 100/\{-\ln(1 - K_\mathrm{P}T_\mathrm{p})\}`$ である ∎

この章の例のゲイン $`K_\mathrm{P}`$ = 1/4 s⁻¹、$`K_\mathrm{I}`$ = 1/32 s⁻² では、根は 0.859 ± j0.107（複素数）で、振れ幅は 1 秒に $`\sqrt{0.75}`$ = 0.866 倍、1/100 になるまで $`2\ln 100/(-\ln 0.75)`$ = 32 s である。$`K_\mathrm{I}`$ は、振れの周期だけを変える。$`K_\mathrm{I}`$ = 0 の P 動作だけでは $`f(1) = 0`$、つまり根の 1 つが 1 になり、ずれは $`r_\mathrm{m}/K_\mathrm{P}`$ = 80 µs に止まって消えない（I 動作が無いと定常偏差が残るのと同じ）。周波数の補正が 0 の所から始めた（20 ppm の段差を受けた）ときの応答を、次の図に並べる。

```fig

```

例のゲインでは、6 s 後に最大 53 µs になったずれが、振れ幅 0.866 倍ずつの包絡線の中で 0 に向かう（Python のシミュレーションと、下の C のコードをホストで動かした値が一致した）。実際には、2 つ目のパルスまでの 1 秒の数で $`r_\mathrm{m}`$ を測って、I の分の初めの値にすれば、この過渡は起きず、残るのは $`r_\mathrm{m}`$ が後から変わったときの過渡（1 ppm の段差なら、最大 2.7 µs）である。

```c
struct mclock {
    uint32_t cap;                          /* 前のパルスの捕獲値 */
    int64_t t_ns;                          /* そのときのマイコンの時計の読み [ns] */
    int64_t r_ppb;                         /* 周波数の補正 r̂ [10^-9] */
    int64_t sum_ns;                        /* 測ったずれの和 [ns]（I の分） */
    int n;                                 /* 受けたパルスの数 */
};

/* タイマの値が c のときの、マイコンの時計の読み [ns] */
int64_t mclock_now(const struct mclock *m, uint32_t c)
{
    int64_t d = (int64_t)(uint32_t)(c - m->cap) * NS_PER_COUNT;   /* 前のパルスからの名目の時間 */
    return m->t_ns + d - d * m->r_ppb / 1000000000;                /* 補正 r̂ の分だけ遅らせる */
}

/* パルスごとに呼ぶ。cap: パルスの捕獲値、gnss_ns: そのパルスの GNSS の時刻 [ns]（文から知る。2 節） */
void mclock_pps(struct mclock *m, uint32_t cap, int64_t gnss_ns)
{
    if (m->n == 0) {
        m->t_ns = gnss_ns;                 /* 初めのパルス: 時刻を合わせる */
    } else if (m->n == 1) {                /* 2 つ目: 1 秒の数で r_m を測り、I の分の初めの値にする */
        int nsec;
        m->r_ppb = rate_ppb(m->cap, cap, &nsec);
        m->sum_ns = 32 * m->r_ppb;
        m->t_ns = gnss_ns;
    } else {
        int64_t t = mclock_now(m, cap);
        int64_t err = t - gnss_ns;         /* マイコンの時計のずれ δt_m [ns] */
        m->sum_ns += err;
        m->r_ppb = err / 4 + m->sum_ns / 32;   /* PI: K_P T_p = 1/4、K_I T_p^2 = 1/32 */
        m->t_ns = t;                       /* 時刻は飛ばさず、周波数だけを直す */
    }
    m->cap = cap;
    m->n++;
}
```

時刻は、GPS 時刻の始まりからの ns を 64 bit の整数で持つ（double にすると、2026 年の値では刻みが 256 ns に粗くなる）。10 MHz のカウンタを模して、カウンタが一周する所を含めて動かすと、周波数の誤差の 0 から 20 ppm への段差で最大 53.35 µs（6 s 後）、20 ppm から 21 ppm への段差で最大 2.67 µs になり、Python のシミュレーションと一致した。

下の図で、水晶の周波数の誤差・2 つのゲイン・パルスの時刻の誤差を変えて、ずれの収まり方と、安定な範囲の中の位置を確かめられる。

## 4. 1PPS の誤差 — 量子化と鋸歯状の誤差

### 刻みでしか出せない

受信機は、秒の頭がいつかを ns より細かく計算できても、パルスは、中のクロック（例: 48 MHz、1 周期 $`T_\mathrm{q}`$ = 20.8 ns）の刻みでしか出せない。そこで、秒の頭にいちばん近い刻みでパルスを立ち上げる（例）。連続した値を決まった刻みの値に丸めることを量子化といい、丸めたために生じる誤差を**量子化誤差**という。ここでは、パルスを出した刻みの時刻から、本当の秒の頭を引いた差 $`q_k`$ である。

受信機の発振器（TCXO）の周波数の誤差を $`r_\mathrm{rx}`$、クロックの周波数を $`f_\mathrm{q} = 1/T_\mathrm{q}`$ とする。1 秒ごとの量子化誤差がどう並ぶかを求める。

**方針**: $`k`$ 番目の秒の頭が、刻みを数えて何番目の位置（実数）にあるかを、整数の部分と端数に分ける。端数だけが量子化誤差を決める。

**導出**: 秒の頭 0 が刻みの $`x_0`$ 番目にあるとする。本当の 1 秒の間に刻みは $`f_\mathrm{q}T_\mathrm{p}(1 + r_\mathrm{rx})`$ 回あるので、秒の頭 $`k`$ は $`x_k = x_0 + kf_\mathrm{q}T_\mathrm{p}(1 + r_\mathrm{rx})`$ 番目にある。$`f_\mathrm{q}T_\mathrm{p}`$ は整数（例で 48 000 000）なので、$`x_k`$ の端数は $`x_0 + k f_\mathrm{q}T_\mathrm{p}r_\mathrm{rx}`$ の端数に等しい。$`\nu`$ を $`f_\mathrm{q}T_\mathrm{p}r_\mathrm{rx}`$ の端数（0 以上 1 未満）とすると、$`x_k`$ の端数は $`x_0 + k\nu`$ の端数である。いちばん近い刻みは $`x_k`$ を四捨五入した番目なので、刻みの間隔をほぼ $`T_\mathrm{q}`$ として

$$
q_k = T_\mathrm{q}\,\bigl(\mathrm{round}(x_k) - x_k\bigr)
$$

で、$`q_k`$ は $`-T_\mathrm{q}/2`$ から $`T_\mathrm{q}/2`$ の間にある。$`x_k`$ の端数が 1 秒ごとに $`\nu`$ ずつ増えるので、$`q_k`$ は 1 秒ごとに $`\nu T_\mathrm{q}`$ ずつ減り、$`-T_\mathrm{q}/2`$ を下回ると $`T_\mathrm{q}/2`$ の側へ跳ぶ ∎

```fig
e14_quant
```

この形の誤差を**鋸歯状の誤差**（sawtooth error）という。形は $`\nu`$ だけで決まる（次の図）。$`\nu`$ が 0 に近いほど、跳ぶまでの $`1/\nu`$ 秒が長くなり、ちょうど 0 なら同じ値にとどまって、何秒平均しても誤差が減らない。TCXO の周波数は温度でゆっくり変わるので、$`\nu`$ も時間とともに変わり、同じ受信機でも形が入れ替わる。


### 補正値 — 次のパルスの誤差の予告

受信機は、$`q_k`$ をパルスを出す前に計算できるので、次のパルスの量子化誤差を、パルスの前にメッセージで知らせる製品がある（時刻を扱う製品に多い。形式・単位・符号は製品による。例: ps の単位の整数）。この値を**量子化誤差の補正値**という。受ける側が、捕獲したパルスの時刻から補正値を引けば、鋸歯状の誤差は消え、残るのは 2 節の解の誤差になる。

パルスの時刻の誤差を、源ごとに並べる（次の図）。

```fig

```

ケーブルの遅れ（アンテナのケーブルの中を電波が進む時間）と、捕獲の半カウント（捕獲値は立ち上がりの前に最後に数えた値なので、平均で半カウント早い）は、いつも同じ向きの一定の誤差なので、測っておき、3 節の `mclock_pps` に渡す GNSS の時刻を直す。一方、10 MHz の捕獲の刻みは鋸歯状の誤差より大きいので、補正値を引いても刻みの分が残る。補正値が生きるのは、ns の刻みで捕獲できるとき（速いタイマや、時間の間隔を測る専用の回路）である。マイコンの捕獲でも同じことが起き、3 節の例の 20.0 ppm では 1 秒の数 10 000 200 の端数が 0 なので、捕獲の刻みの誤差は毎秒同じ値にとどまり、PI のループで平均しても消えない。

## 5. 時計を保つ — 衛星が見えない間

### ずれは周波数の誤差 × 時間で増える

トンネルや建物の中で衛星が見えなくなると、受信機は時刻を求められず、1PPS も止まる（製品によっては、中の TCXO で数えたパルスを出し続け、その間はその印を付ける）。基準の時刻が届かない間、それまでに覚えた周波数の補正で時計を進め続けることを**ホールドオーバー**という。PI の補正のうち、P の分はパルスごとの捕獲値の誤差をそのまま含むので、ホールドオーバーの間は、ずれの和で決まる I の分だけを周波数の補正に使う。

**方針**: 最後のパルスの後に残る周波数の誤差を $`r_\mathrm{res}`$ として、1 秒ごとに進みすぎる時間を積み上げる。許せるずれの上限 $`E`$ に届くまでの時間を求める。

**導出**: 補正した時計は、本当の 1 秒の間に $`1 + r_\mathrm{res}`$ 秒進むので、最後のパルスから時間 $`t`$ の後のずれは $`\delta t_\mathrm{m}(t) = \delta t_0 + r_\mathrm{res}t`$ である（$`\delta t_0`$ は最後のパルスのときのずれ）。$`|\delta t_0|`$ が $`E`$ より十分小さければ、ずれが $`E`$ に届くまでの時間は $`t_\mathrm{h} = E/|r_\mathrm{res}|`$ である。温度が変わって、周波数の誤差が一定の速さ $`\dot r`$ で変わるときは、1 秒ごとの進みすぎ $`r_\mathrm{res} + \dot r t`$ を積分して、$`\delta t_\mathrm{m}(t) = \delta t_0 + r_\mathrm{res}t + \dot r t^2/2`$ となる ∎

補正しない 20 ppm の水晶は、1 日に 1.7 s ずれる（10 章 3 節の RTC と同じ）。3 節の例のゲインで、パルスの時刻の誤差が 30 ns のとき、I の分で覚えた周波数の誤差は 0.0014 ppm（標準偏差。Python のシミュレーションとデモで確かめた）で、温度が変わらなければ長く保てる。しかし、水晶の周波数は温度で変わる。補償しない水晶は、使う温度の範囲で ±10〜30 ppm 変わり（[4 章 2 節](04_受信機の中.md#rf-フロントエンド-増幅-フィルタ-周波数変換)）、TCXO（例: 0.05 ppm/°C）でも、10 °C 変われば 0.5 ppm である（次の図）。

```fig
e14_hold
```

### 温度が変わるとき

衛星が見えなくなるのは、屋外から建物や車の中へ入ったときが多く、そのとき温度も変わる。TCXO の温度が 10 分ほどかけて 10 °C 上がると、周波数の誤差が増えていく間は、ずれは時間の 2 乗に近い形で増え、その後は 0.5 ppm の傾きで増える（次の図）。

```fig
e14_temp
```

したがって、ホールドオーバーで保てる時間は、時計の発振器と、衛星が見えない間の温度の変わり方で決まる。長く保つ必要があれば、TCXO で時計を刻み、温度の変わりにくい所に置く。衛星が見えている間に、測った温度と補正の関係を覚えておき、見えない間は温度で補正を変える方法もある（例）。眠っている間は、RTC（[10 章 3 節](10_モジュールの回路.md#バックアップ電源-ホットスタートのために)、[電源と周辺の制御シリーズ 7 章 2 節](../periph/07_眠らせ方と起こし方.md#起こすもの-rtc-ピン-周辺の割り込み)）で時刻を数え続け、起きたら 1PPS で合わせ直す。

パルスが来ない間も、カウンタが一周する（10 MHz・32 bit で 429.5 s）前に、3 節の `cap` と `t_ns` を今の値に進めておく。進めないと、符号なしの差が一周を数え損なう。

## 6. 時刻を付けて記録する

### センサのデータの時刻

センサの値を測った時刻を、その値の**タイムスタンプ**という（[組み込み通信シリーズ 15 章 3 節](../comm/15_クラウドとつなぎ続ける.md#件の形-通し番号とタイムスタンプ)と同じ意味）。センサが、測り終えたことを知らせる端子を持っていれば、それを 1PPS と同じタイマの別の捕獲の入力につなぐ（センサの出力の形は[電源と周辺の制御シリーズ 8 章 1 節](../periph/08_センサをつなぐ.md#センサの出力の形)）。測った瞬間の捕獲値 $`C_\mathrm{s}`$ を、前後のパルスの捕獲値 $`C_k`$・$`C_{k+1}`$ と比べると、パルス $`k`$ の GNSS の時刻を $`t_k`$ として

$$
t_\mathrm{s} = t_k + \frac{C_\mathrm{s} - C_k}{C_{k+1} - C_k}\,T_\mathrm{p}
$$

である（次の図）。2 つのパルスの間を、その 1 秒に本当に数えた数で比例に割り振るので、水晶の周波数の誤差は打ち消される。次のパルスを待たずに付けるときは、3 節の `mclock_now(C_s)` を使う。

```fig
e14_interp
```

文が届いた時刻をタイムスタンプにしてはならない。文が届くのは、測った時刻（秒の頭）より 0.1〜1 s ほど後で、その遅れは文の長さと送る速さで変わる（2 節）。

### 記録に残すもの

記録する時刻は、途切れず、同じ値が 2 回現れない GPS 時刻にする。UTC には 23 時 59 分 60 秒が入り、1970 年 1 月 1 日からの秒（コンピュータで多く使う数え方）は、うるう秒を数えないので同じ値が 2 秒続く（1 節の図）。うるう秒の数を一緒に残せば、後でいつでも UTC に直せる。さらに、その時刻がどれだけ確かか（まだ合わせていない・1PPS に合わせている・ホールドオーバーの間）と、ずれの見積もり（5 節の $`r_\mathrm{res}t`$）を残す（次の図）。

```fig
e14_record
```

レコードの形とリングバッファでの扱いは[バイナリ解析シリーズ 12 章 3 節](../binary/12_ログとリングバッファ.md#バイナリログのレコードを読む)、ためたデータに時刻を付けて送る考え方は[組み込み通信シリーズ 15 章 3 節](../comm/15_クラウドとつなぎ続ける.md#件の形-通し番号とタイムスタンプ)で扱っている。受信の処理の中で 1PPS と文の時刻を対応させる実装の全体は 15 章、時刻の精度を測る方法は 23 章で扱う。

## 7. まとめ

| 項目 | 内容 |
|---|---|
| UTC・うるう秒 | 原子時計の秒で進み、地球の自転との差が 0.9 s を超えないように 1 秒を足す時刻／足す 1 秒（6 月か 12 月の終わりの 23:59:60）。2035 年までにやめる方針が決まっている |
| GPS 時刻 | 1980 年 1 月 6 日 0 時（UTC）から、うるう秒を足さずに数える時刻。UTC より 18 s 進んでいる（書いた時点。2017 年 1 月から）。差と次のうるう秒の予告は航法メッセージで届く |
| 週番号・週の中の秒（TOW） | 1980 年 1 月 6 日からの週の数／週の始まり（日曜日 0 時、GPS 時刻）からの秒（0〜604 799）。例: 2026-11-11 09:27:50 UTC は週 2444、293 288 s |
| 週番号の一巡 | 10 bit の週番号が 1024 週（約 19.6 年）で 0 に戻ること（1999-08-22・2019-04-07、次は 2038-11-21）。基準の週から 1024 週の中にあるとみなして直す |
| 1PPS の意味と精度 | 立ち上がりは、受信機が求めた GNSS の時刻の秒の頭。GPS 時刻と UTC で同じ瞬間。誤差 $`\sigma_t = \mathrm{TDOP}\times\sigma_\mathrm{UERE}/c`$（例 10.5 ns）、製品の資料で数十 ns（代表値） |
| パルスと秒の対応 | パルスの後に届く文（GGA・RMC）の時刻が、そのパルスの秒（多くの製品）。文の位置の遅れが 1 秒を超えると 1 秒ずれる |
| インプットキャプチャ | 端子の立ち上がりの瞬間のカウンタの値を、回路が別の所へ写して残す仕組み。割り込みの遅れに左右されない |
| ppm・周波数の誤差 | 100 万分の 1（1 秒に 1 µs、1 日に 86.4 ms）。$`r_\mathrm{m} = (C_k - C_{k-1})/(f_\mathrm{tim}T_\mathrm{p}) - 1`$。差は符号なしの引き算で一周をまたげる。$`N`$ 秒の差なら誤差は $`N`$ 分の 1 |
| PI の時計合わせ | $`\hat r[k] = K_\mathrm{P}\delta t_\mathrm{m}[k] + K_\mathrm{I}T_\mathrm{p}\sum\delta t_\mathrm{m}[j]`$。安定は $`K_\mathrm{P} > 0`$・$`K_\mathrm{I} > 0`$・$`K_\mathrm{I}T_\mathrm{p}^2 < 4 - 2K_\mathrm{P}T_\mathrm{p}`$。振れ幅は 1 秒に $`\sqrt{1 - K_\mathrm{P}T_\mathrm{p}}`$ 倍（例 0.866 倍、1/100 まで 32 s）。P だけではずれが残る |
| 量子化誤差・鋸歯状の誤差 | 秒の頭をクロックの刻みに丸めた誤差（±$`T_\mathrm{q}/2`$。例 ±10.4 ns）／1 秒の刻みの数の端数 $`\nu`$ で形が決まる鋸の歯の形の誤差。$`\nu = 0`$ では平均しても消えない |
| 量子化誤差の補正値 | 受信機がパルスの前に知らせる、次のパルスの量子化誤差。引くと鋸歯状の誤差が消える。捕獲の刻みが粗いと生きない |
| 一定の誤差 | ケーブルの遅れ（3 m で 15.2 ns）・捕獲の半カウント（50 ns）は測って引く |
| ホールドオーバー | 衛星が見えない間、覚えた周波数（I の分）で時計を進めること。ずれは $`\delta t_0 + r_\mathrm{res}t + \dot r t^2/2`$。20 ppm で 1 日に 1.7 s、TCXO で 10 °C 変わると 1 時間に 1.5 ms（例） |
| タイムスタンプ | 値を測った時刻。$`t_\mathrm{s} = t_k + (C_\mathrm{s} - C_k)/(C_{k+1} - C_k)\,T_\mathrm{p}`$。文が届いた時刻は使わない。GPS 時刻・うるう秒の数・時刻の状態を残す |

この章では、GNSS の時刻を、マイコンの時計とデータに移した。次の章では、12〜14 章の部品（文の解析・設定・時刻）を、受信の割り込み・リングバッファ・状態の管理とあわせて、1 つのファームウェアに組む。
