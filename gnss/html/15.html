Chapter 15

組み込みでの実装 — 受信・解析・状態の管理

この章で扱う問い. 12〜14 章では、モジュールが出す文を 1 文字ずつ確かめて数値に直し（12 章）、設定を送って確かめ（13 章）、1PPS でマイコンの時計を合わせた（14 章）。この章では、これらの部品をマイコンの中で 1 つのファームウェアに組み、文を取りこぼさずに受け、位置を使ってよいかを決め、電源を管理し、記録した文で確かめる。

この章では次の 3 つの問いに答える。

  1. UART に届くバイトを、割り込みとリングバッファでどう受け取り、リングバッファはどれだけの大きさにすればよいのか。
  2. 測位の品質・衛星の数・HDOP・位置の古さから、位置を使ってよいかを、時間の流れの中でどう決めるのか。同じ時刻の文と 1PPS を、どう 1 組にそろえるのか。
  3. 起動・待機・再開の手順をどう組み、組んだファームウェアが誤りの混ざった入力でも正しく動くことを、どう確かめるのか。

答えの道具は、届くバイトの数の最大を数える式、状態機械とタイムアウト、時刻の欄で文をまとめる規則、そして記録した文を同じコードに流す試験である。

1. 全体の構成 — 受信・解析・利用

割り込みと主のループに分ける

12 章 4 節では、UART で届いたバイトを uart_read で 1 文字ずつ取り出し、gnss_poll の中で文を切り出した。uart_read は、受信の割り込みでためたバイトを取り出す関数として、仮に置いたものだった。この章では、その割り込みから、位置を使う側までを 1 つのファームウェアに組む。マイコンが普段実行している無限のループを、以下、主のループという。割り込みが書き、主のループが読む受け渡しの場所には、決まった大きさの配列を輪のように使い、書く位置と読む位置を別々に進めるリングバッファを使う（作り方と大きさは 2 節）。全体の構成を次の図に示す（節の番号は、その部分を扱う所）。

2. 受信 — 割り込み・DMA・リングバッファ

リングバッファで主のループへ渡す

リングバッファの書く位置を head、読む位置を tail という（仕組みは組み込み通信シリーズ 4 章 3 節）。同じ節の struct ring と ring_put・ring_get（大きさ RB_SIZE は 2 のべき乗）をそのまま使い、受信の割り込みと、12 章で仮に置いた uart_read の中身を書く。uart_hw_ で始まる関数は、同じ章の 2 節と同じく、この章で仮に置く関数（UART のレジスタを読む）である。

static struct ring urx;                        /* UART の受信: 割り込みが書き、主のループが読む */
volatile uint32_t n_rxerr, n_drop, rb_max;     /* UART の誤り・満杯で捨てたバイト・最大の埋まり */

void gnss_rx_isr(void)                         /* UART の受信の割り込み: 読む・入れる・数えるだけ */
{
    while (uart_hw_rx_ready()) {
        if (uart_hw_rx_errors()) n_rxerr++;    /* オーバーランなどの印（読むと消える） */
        if (!ring_put(&urx, uart_hw_read())) n_drop++;   /* 満杯: 新しいバイトを捨てて数える */
        uint32_t used = urx.head - urx.tail;
        if (used > rb_max) rb_max = used;      /* 大きさが足りているかを、実機で確かめるため */
    }
}

int uart_read(void)                            /* 12 章 4 節で仮に置いた関数の中身 */
{ uint8_t b; return ring_get(&urx, &b) ? b : -1; }

head を書き換えるのは割り込みだけ、tail を書き換えるのは主のループだけで、データを書いてから head を、読んでから tail を進める（ring_put・ring_get の中の順番）。head・tail・データの配列には volatile を付け、32 bit の添字は 32 bit のマイコンでは 1 つの命令で読み書きされる（途中で割り込まれない）ので、割り込みを止めずに共有できる（同じ章の 4 節。8 bit のマイコンでは、添字を 8 bit にするか、読む間だけ割り込みを止める）。3 つの数えも、書くのは割り込みだけである。満杯のときに捨てたバイトを含む文は、チェックサムが合わなくなる（どこで失ったかの見分け方は 4 節）。

大きさを決める — 処理の遅れの間に届くバイトの数

主のループがリングバッファを空にしてから、次に読むまでの最長の時間を、処理の遅れ \(t_\mathrm{p}\) という（記録の書き込みなどで延びる）。組み込み通信シリーズ 4 章 5 節では、大きさを「届く速さ × 処理の遅れ」で見積もった。GNSS のモジュールは、文を 1 回分ずつまとめて送り、その後は休む（1 節の図）ので、この見積もりは処理の遅れが長いと大きくなりすぎる。届き方に合わせて数える。

方針: 処理の遅れ \(t_\mathrm{p}\) の間にリングバッファに入るバイトの数の最大を \(n(t_\mathrm{p})\) とする。まず短い時間 \(\delta\) の間に入る数の最大を求め、それを使って、1 回分の最初のバイトが入る直前に空にした場合が最も多いことを示してから、その場合の数を数える。

導出: モジュールは、更新の間隔 \(T_\mathrm{u}\) ごとに、1 回分の \(N_\mathrm{B}\) バイトを続けて送る（13 章 3 節。負荷率は 100 % 以下とする）。8N1 ではボーレート \(R_\mathrm{B}\) の線で 1 バイトに \(10/R_\mathrm{B}\) の時間がかかり、1 バイトは受け終えた時点でリングバッファに入る。したがって、入る時刻は 1 回分の中では \(10/R_\mathrm{B}\) ごとに並び、1 回分は \(t_\mathrm{tx} = 10N_\mathrm{B}/R_\mathrm{B}\) の間に入り終え、残りの \(T_\mathrm{u} - t_\mathrm{tx}\) は何も入らない。この並びが \(T_\mathrm{u}\) ごとに繰り返す。長さ \(\delta\)（\(0 < \delta < T_\mathrm{u}\)）の間に入る数は、入る時刻の間隔がどこでも \(10/R_\mathrm{B}\) 以上なので、\(\lceil R_\mathrm{B}\delta/10\rceil\)（\(R_\mathrm{B}\delta/10\) 以上の最小の整数）を超えない。2 回分にまたがるときは、前の回の \(j\) 番目から後の回の \(i\) 番目までの時間 \(T_\mathrm{u} + (i - j)\cdot 10/R_\mathrm{B}\) が \(\delta\) 以下で、\(\delta < T_\mathrm{u}\) なので \(i < j\) となり、入る数 \((N_\mathrm{B} - j + 1) + i\) は \(N_\mathrm{B}\) を超えない。1 回分の最初のバイトが入る直前から数えれば、ちょうど \(\min(N_\mathrm{B}, \lceil R_\mathrm{B}\delta/10\rceil)\) 入るので、これが長さ \(\delta\) の間に入る数の最大である。

次に、長さ \(t_\mathrm{p}\) の数える区間の頭を、1 回分の最初のバイトが入る直前から \(\delta\) だけ後にずらす（並びが \(T_\mathrm{u}\) ごとに繰り返すので、どの位置もこう表せる）。頭で数えなくなる数は上の最大で、終わりで新たに数える数は長さ \(\delta\) の間に入る数なので、それを超えない。したがって、1 回分の最初のバイトが入る直前から数えた場合が最も多い。この場合、\(t_\mathrm{p}\) を \(T_\mathrm{u}\) で割った商を \(k\)、余りを \(t_\mathrm{r} = t_\mathrm{p} - kT_\mathrm{u}\) とすると、\(k\) 回分の \(kN_\mathrm{B}\) バイトが全部入り、残りの \(t_\mathrm{r}\) の間に、上と同じく \(\min(N_\mathrm{B}, \lceil R_\mathrm{B}t_\mathrm{r}/10\rceil)\) 入るので

\[ n(t_\mathrm{p}) = kN_\mathrm{B} + \min\!\left(N_\mathrm{B},\ \left\lceil\frac{R_\mathrm{B}\,t_\mathrm{r}}{10}\right\rceil\right),\qquad k = \left\lfloor\frac{t_\mathrm{p}}{T_\mathrm{u}}\right\rfloor \]

である。リングバッファの大きさ RB_SIZE は、\(n(t_\mathrm{p})\) 以上の 2 のべき乗にする ∎

10 章の例（9600 bit/s・1 Hz・626 B。\(t_\mathrm{tx}\) = 0.652 s）で、主のループが記録の書き込みなどで最長 0.3 s 読まないとき（例の値）を、次の図に示す。

\(t_\mathrm{p}\) が \(T_\mathrm{u}\) より短ければ \(k\) = 0 で、\(n\) は 1 回分の 626 B を超えない。10 章 4 節の「1 回分を取りこぼさずに受ける」は、1 回分が入る 1024 B を取れば、1 秒より短いどんな処理の遅れでも満たされる。一方、更新レートを上げると、同じ処理の遅れの間に何回分も届く（次の図）。

本文の割り込みと gnss_poll をホストで 1 ビットの時間ごとに動かし、通信の速さ・更新レート・処理の遅れを変えた 260 通りで、最大の埋まりが式の値と一致すること、RB_SIZE を 512 B（例の 0.3 s）と 2048 B（5 Hz）にすれば捨てるバイトが 0 で、その半分では捨てることを確かめた。

DMA で受けるとき

1 バイトごとの割り込みは、9600 bit/s では 1 秒に 960 回で、1 回 2 µs（代表値）なら CPU の時間の 0.2 % である。115 200 bit/s では 1 秒に 11 520 回（2.3 %）になる。速い通信の速さでは、DMA の循環モードで受け、転送の半分完了・全部完了と、線が 1 文字分休んだことを知らせるアイドルライン検出の割り込みで、主のループに知らせる（組み込み通信シリーズ 4 章 6 節）。モジュールは 1 回分を送ると休むので、アイドルライン検出は、1 回分が届き終わったことを知らせる（文と文の間で休む製品では、文ごとに知らせる）。DMA は満杯でも止まらずに上書きするので、DMA の受信の場所も、この節の \(n(t_\mathrm{p})\) より大きくする。

下の図で、通信の速さ・更新レート・1 回のバイト数・処理の遅れ・リングバッファの大きさを変えて再生すると、リングバッファの埋まり方と、あふれる時刻を確かめられる。

3. 状態の管理 — 測位の品質と状態機械

測位の状態とデータの鮮度

12 章 6 節では、位置を、測位の品質が 1 以上で RMC の状態が A のときだけ使うとした。使う側は、それに加えて、位置がどの方法で求めたものか（どれだけ確かか）を知りたい。モジュールが今、位置を求めているか、求めているならどの方法で求めたかを表す値を、この章では測位の状態（Fix の種類）という。同じ時刻の GGA と RMC の 1 組（まとめ方は 4 節）の欄から、次の図のように決める。

2D は、衛星が 3 つしか使えないために、高さを決めた値に置いて緯度と経度だけを解いた位置で、高さは使えない（GSA の 2 番の欄が 2。12 章 2 節）。この章のコードは、衛星の数が 4 未満の単独の位置を 2D とみなす。測位の品質の 6（推測）は、衛星の電波が届かない間に受信機が前の位置と速さから進めた位置で、GNSS で求めた位置ではないので、この章では測位なしと同じに扱う（慣性センサと組み合わせる方法は 19 章）。

位置を求めた時刻から今までの時間を、その位置のデータの鮮度（年齢）という。文を受け終えた時点で、年齢はすでに位置の遅れ（例で 0.27 s）だけあり、新しい組が届かない間は増え続ける。その間に機器は動く（100 km/h なら 1 秒に 28 m）ので、年齢が上限（例の値 2.5 s。1 Hz で 1 組の抜けまでを許す）を超えた位置は使わない。年齢は、組を受け終えたマイコンの時刻から測る（1PPS の時刻から測る方法は 4 節）。GGA の 13 番の欄の、補正の情報の古さ（16 章 3 節）とは別のものである。

状態機械 — 下がるのはすぐ、上がるのは続いてから

組ごとの測位の状態をそのまま使うと、境目の近くでは 1 秒ごとに入れ替わる。また、位置が出た直後の位置は、誤差が大きいことが多い（13 章 5 節）。さらに、文が届かなくなったことは、組が来ないので、組の値からは分からない。そこで、測位の状態を状態機械（組み込み通信シリーズ 5 章 1 節）で管理し、組がそろうことと時間切れをイベントにする（次の図）。

悪い状態へは 1 組で移り、良い状態へは 3 組（例の値）待つのは、悪い位置を使い続ける害のほうが、良い位置を 2 秒待つ害より大きいからである。文なし（3 s。例の値）は、モジュールの電源・通信の速さ・配線の不具合を表すので、5 節の手順で立て直す。

#define UP_N        3                    /* 良い種類が何回続いたら上がるか（例の値） */
#define AGE_MAX_MS  2500u                /* 位置の年齢の上限 [ms]（例の値: 1 Hz で 1 回の抜けまで） */
#define LOST_MS     3000u                /* 正しい文がこれだけ来なければ文なし [ms]（例の値） */

enum fix_state { FS_NODATA, FS_NOFIX, FS_2D, FS_3D, FS_DGNSS, FS_FLOAT, FS_FIXED };   /* 後ほど良い */
struct fixsm {
    enum fix_state st, cand;             /* 今の状態・上がる先の候補 */
    int ncand;                           /* 今の状態より良い種類が続いた回数 */
    uint32_t t_fix, t_ok;                /* 位置のある組・正しい文を最後に受けた時刻 [ms] */
};

enum fix_state fix_kind(const struct gga *g, char status)   /* 1 組の測位の種類 */
{
    if (status != 'A' || !g->has_pos) return FS_NOFIX;      /* RMC が V か、位置の欄が空 */
    switch (g->quality) {
    case 1:  return g->nsat >= 4 ? FS_3D : FS_2D;
    case 2:  return FS_DGNSS;
    case 5:  return FS_FLOAT;
    case 4:  return FS_FIXED;
    default: return FS_NOFIX;            /* 0（なし）と 6（推測。19 章） */
    }
}

void fix_epoch(struct fixsm *s, enum fix_state k, uint32_t now)   /* 組がそろうたびに呼ぶ */
{
    if (k >= FS_2D) s->t_fix = now;
    if (k <= s->st) {                    /* 下がるのはすぐ（同じなら、続いた回数を 0 に戻す） */
        s->st = k; s->ncand = 0;
    } else {                             /* 上がるのは UP_N 回続いてから（続いた中の最も悪い種類へ） */
        s->cand = (s->ncand == 0 || k < s->cand) ? k : s->cand;
        if (++s->ncand >= UP_N) { s->st = s->cand; s->ncand = 0; }
    }
}

void fix_tick(struct fixsm *s, uint32_t now)   /* 主のループから何度も呼ぶ（時間切れ） */
{
    if (now - s->t_ok > LOST_MS) { s->st = FS_NODATA; s->ncand = 0; }
    else if (s->st >= FS_2D && now - s->t_fix > AGE_MAX_MS) { s->st = FS_NOFIX; s->ncand = 0; }
}

RTK のフィックスとフロート（17 章）が交互に来るときは、続いた 3 回の中で最も悪いフロートへ移る。時刻の差を uint32_t の引き算で比べるので、時刻のカウンタが一周しても正しい（組み込み通信シリーズ 5 章 3 節）。文なしから測位なしへ戻すのは、正しい文を受けたとき（4 節の gnss_poll）である。

使ってよいか

状態機械が 3D 以上にいても、その組の位置を使ってよいとは限らない。HDOP が大きいと誤差が大きく（HDOP 2.0 なら、7 章の UERE 3.99 m で水平の DRMS は 8.0 m）、チェックサムが見逃す誤り（12 章 3 節の、66.6 km ずれても合う緯度）は、値の範囲を確かめても見つからない。そこで、組ごとに次の順で確かめる（しきい値は例の値で、使い方に合わせて決める）。

#define NSAT_MIN    5                    /* 衛星の数の下限（例の値） */
#define HDOP_MAX_C  200                  /* HDOP × 100 の上限（例の値: 2.0） */
#define V_MAX       50.0f                /* 前の位置からの飛びを許す速さ [m/s]（例の値） */
#define JUMP_M      30.0f                /* 飛びの余裕 [m]（例の値） */

enum use_why { USE_OK, USE_STATE, USE_SAT, USE_HDOP, USE_JUMP };
struct ref { int ok, njump; int32_t lat, lon; uint32_t t; };   /* 最後に使った位置とその時刻 */

enum use_why fix_judge(const struct fixsm *s, const struct gga *g, struct ref *r, uint32_t now)
{
    if (s->st < FS_3D) return USE_STATE;                 /* 状態機械が 3D まで上がっていない */
    if (g->nsat < NSAT_MIN) return USE_SAT;
    if (g->hdop_c < 0 || g->hdop_c > HDOP_MAX_C) return USE_HDOP;
    if (r->ok) {                                         /* 前の位置からの飛び（12 章 3 節の見逃しに備える） */
        float dn = (float)((int64_t)g->lat - r->lat) * 0.0111195f;   /* 1e-7 度 → m（南北） */
        float de = (float)((int64_t)g->lon - r->lon) * 0.0111195f * cosf((float)g->lat * 1.745329e-9f);
        float lim = V_MAX * (float)(now - r->t) / 1000.0f + JUMP_M;
        if (dn * dn + de * de > lim * lim && ++r->njump < 3) return USE_JUMP;   /* 3 回続けば受け入れる */
    }
    r->ok = 1; r->njump = 0; r->lat = g->lat; r->lon = g->lon; r->t = now;
    return USE_OK;
}

飛びは、最後に使った位置からの距離が、許す速さ × 経った時間 + 余裕を超えるかで決める（許す速さは、13 章 4 節の動きのモデルの上限と同じ考え方で選ぶ）。経った時間が長いほど許す距離が延びるので、トンネルを出た後の位置も使える。最後に使った位置そのものが誤っていたときに使えなくならないよう、3 回続けて飛んだら、飛んだ先を受け入れる。1e-7 度の南北の長さ 1.11 cm は、地球を半径 6371 km の球とした値で、飛びを見るには十分である。差は小さい数なので、float でも 1 cm より細かく計算できる（12 章 5 節で足りなかったのは、大きな値の刻みだった）。次の図は、ある走行の例で、組の値と、状態機械の状態と、判断を並べたものである。

下の図で、衛星の数・HDOP・補正の種類・補正の情報の古さを、時間を進めながら変えると、状態機械がどの状態にいて、位置を使うかどうかを確かめられる。

4. 時刻とデータをそろえる

同じ時刻の文を 1 組にする

位置と時刻を使うには、GGA の位置・品質と、RMC の日付・状態を組み合わせる（日付は RMC にしか無い。12 章 6 節）。受信機が同じ時刻に求めた結果を書いた文の組をエポックといい、この章では 3 節から単に組と呼んでいる。GGA と RMC には時刻の欄（12 章 5 節の t_ms）があるので、その値が同じ 2 つを 1 組にする。GSA・GSV などには時刻の欄が無いので、組の区切りには使わない（次の図）。

そろった組は、その場で次に渡す（GSV などを待たないので、位置の遅れが短い）。RMC を数値に直す nmea_rmc は、12 章 5 節の nmea_gga と同じ形（時刻・状態・日付の欄を読む）なので、宣言だけを載せた。どちらも、中身のカンマを書き換えてから文の種類を確かめる（12 章 4 節の nmea_split）ので、どちらの文かは、書き換える前に is_type で見分ける。

#define EP_GGA  1u
#define EP_RMC  2u
#define T_U_MS  1000                     /* 更新の間隔 [ms]（例の 1 Hz） */

struct rmc { int32_t t_ms; char status; int32_t date; };   /* 時刻・状態（A・V）・日付 ddmmyy（無ければ −1） */
struct epoch {
    int32_t t_ms;                        /* この組の時刻（UTC の 0 時からの ms）。初めは −1 */
    unsigned have;                       /* 受けた文（EP_GGA・EP_RMC の和） */
    struct gga g;                        /* GGA の値（12 章 5 節） */
    struct rmc r;                        /* RMC の値 */
};
uint32_t n_part, n_gap;                  /* そろわなかった組・時刻の飛び */
void epoch_done(const struct epoch *e, uint32_t now);   /* そろった組を渡す先（下） */
int nmea_rmc(char *body, struct rmc *r);   /* RMC の中身を数値に直す。RMC でなければ 0 */

static int is_type(const char *b, const char *ty)   /* 中身の頭が「話者 ID の 2 文字・ty・カンマ」か */
{ return b[0] && b[1] && strncmp(b + 2, ty, 3) == 0 && b[5] == ','; }

void epoch_feed(struct epoch *e, char *body, uint32_t now)   /* チェックサムの合った文ごとに呼ぶ */
{
    struct gga g; struct rmc r;
    int32_t t; unsigned bit;
    if (is_type(body, "GGA") && nmea_gga(body, &g)) { t = g.t_ms; bit = EP_GGA; }
    else if (is_type(body, "RMC") && nmea_rmc(body, &r)) { t = r.t_ms; bit = EP_RMC; }
    else return;                         /* GSA・GSV などは時刻の欄が無いので、組の区切りに使わない */
    if (t < 0) return;                   /* 時刻の欄が空の文はまとめられない */
    if (t != e->t_ms) {                  /* 新しい時刻: 前の組を閉じて、新しい組を始める */
        if (e->t_ms >= 0) {
            int32_t d = t - e->t_ms;
            if (e->have != (EP_GGA | EP_RMC)) n_part++;
            if (d != T_U_MS && d != T_U_MS - 86400000) n_gap++;   /* 0 時をまたぐときも見る */
        }
        e->t_ms = t; e->have = 0;
    }
    if (e->have & bit) return;           /* 同じ時刻の同じ文が 2 つ目: 捨てる */
    if (bit == EP_GGA) e->g = g; else e->r = r;
    e->have |= bit;
    if (e->have == (EP_GGA | EP_RMC)) epoch_done(e, now);
}

主のループから呼ぶ受信の関数は、12 章 4 節の gnss_poll の形のまま、チェックサムの合った文を組のまとめに渡す（13 章 2 節のバイナリのフレームも同じ線で受けるときは、gnss_poll を 13 章の形にし、nmea_char の中身を下の while の中身にする）。そろった組は、3 節の状態機械と判断を通して、使う側へ渡す。now_ms は 13 章 6 節と同じ、1 ms ごとに 1 増える時刻を返す仮に置く関数、use_epoch はこの章で仮に置く関数（組と判断を、記録・表示・制御の側へ渡す）である。

#define LEAPS   18                       /* GPS 時刻 − UTC [s]（書いた時点の値。14 章 1 節） */
static struct nmea_rx rx;                /* 12 章 4 節 */
uint32_t n_bad;                          /* 捨てた文の数（12 章 4 節） */
static struct epoch ep = { .t_ms = -1 }; /* 組の時刻は −1 から */
static struct fixsm sm;                  /* 初めは文なし（= 0） */
static struct ref ref;

void gnss_poll(void)                     /* 主のループから何度も呼ぶ */
{
    int c;
    uint32_t now = now_ms();
    while ((c = uart_read()) >= 0) {
        enum nmea_result res = nmea_feed(&rx, (char)c);
        if (res == NMEA_OK) {
            sm.t_ok = now;               /* 正しい文が届いている */
            if (sm.st == FS_NODATA) sm.st = FS_NOFIX;
            epoch_feed(&ep, rx.buf, now);
        } else if (res != NMEA_NONE) {
            n_bad++;                     /* 壊れた・切れた・長すぎる文 */
        }
    }
    fix_tick(&sm, now);
}

void epoch_done(const struct epoch *e, uint32_t now)   /* GGA と RMC がそろった組ごとに */
{
    fix_epoch(&sm, fix_kind(&e->g, e->r.status), now);
    enum use_why w = fix_judge(&sm, &e->g, &ref, now);
    use_epoch(e, sm.st, w);                            /* 位置を使うのは w が USE_OK のときだけ */
    if (e->t_ms % 1000 == 0 && sm.st >= FS_2D && e->r.date >= 0)
        pps_label(e, LEAPS);                           /* 秒の頭の組: 1PPS に名前を付ける（下） */
}

1PPS との対応

14 章 2 節では、パルスの後に届く文の時刻をそのパルスの名前にし、その付け方は、位置の遅れが 1 秒より十分短く、パルスと組が 1 つずつ届くときだけ正しいとした。これを、秒の頭の組がそろうたびに確かめる（次の図）。

14 章 3 節では、新しい捕獲値が来た印 g_cap_new を割り込みが立て、主の処理が読んで下ろすので、印の書き手が 2 つになる。ここでは、割り込みだけが捕獲値とパルスの数を書き、主のループは、読む前後で数が変わらないことで、2 つの値が同じパルスのものだと確かめる。timer_now は、捕獲と同じタイマのカウンタの今の値を返す、この章で仮に置く関数である。組の日付と時刻を GPS 時刻の ns に直す epoch_gnss_ns は、14 章 1 節の utc_to_gps を呼ぶだけなので、宣言だけを載せた。

#define F_TIM   10000000u                /* タイマの周波数 [Hz]（14 章 3 節の例） */
#define LAT_MAX (F_TIM / 2)              /* パルスから秒の頭の組がそろうまでの上限 0.5 s（例の値） */
static volatile uint32_t pps_cap, pps_n; /* 割り込みだけが書く: 最後の捕獲値・パルスの数 */
static uint32_t ep_n;                    /* 前に名前を付けようとしたときのパルスの数 */
static struct mclock mc;                 /* 14 章 3 節の時計 */
uint32_t n_nolabel, pps_late;            /* 名前を付けなかった組・遅れすぎの印 */
int64_t epoch_gnss_ns(const struct epoch *e, int leaps);   /* 組の日付と時刻（UTC）→ GPS 時刻 [ns] */

void pps_isr(void)                       /* 1PPS の捕獲の割り込み（14 章 3 節を、書き手が 1 つの形に） */
{
    pps_cap = timer_capture();           /* 捕獲値を書いてから */
    pps_n = pps_n + 1u;                  /* 数を進める */
}

void pps_label(const struct epoch *e, int leaps)
{
    uint32_t n, cap;
    do { n = pps_n; cap = pps_cap; } while (n != pps_n);   /* 読む間にパルスが来たら読み直す */
    uint32_t k = n - ep_n;               /* 前の組の後に来たパルスの数 */
    ep_n = n;
    if (k == 1 && timer_now() - cap >= LAT_MAX) pps_late = 1;   /* 遅れが 1 秒に近い: これからは付けない */
    if (k != 1 || pps_late) { n_nolabel++; return; }       /* パルスか組が抜けた・遅れすぎ */
    mclock_pps(&mc, cap, epoch_gnss_ns(e, leaps));          /* 14 章 3 節: そのパルスの時刻で合わせる */
}

負荷率が 100 % を超えて位置の遅れが増え続けると（13 章 3 節）、遅れが 1 秒を超える前に、パルスから 0.5 s を超えてそろう組が来るか、組の間にパルスが 2 つ来るので、誤った名前を付ける前に止まる。1 秒あたりの遅れの増え方を 0〜2 s の 201 通りに変えて、誤った名前が 1 つも付かないことを確かめた。遅れすぎの印が立ったら、負荷率を見直す（10 章 4 節・13 章 3 節）。

5. 電源の管理 — 起動・待機・バックアップ

起動から止めるまで

モジュールの電源は、主のループの中の、もう 1 つの状態機械で管理する。各段で待つ時間に上限を置き、時間切れのときの行き先を決めておく（次の図）。

入れるときは主の電源が先で信号が後、切るときは信号が先で電源が後にする（10 章 6 節の電源投入の順番）。文を待つ段は、3 節の状態機械が文なしから出ることで終わり、来なければ通信の速さを順に試す（13 章 3 節）。設定は、起動のたびに読み出して比べ、違えば送り直す（13 章 6 節）。測位を待つ上限は、そのときのスタートの種類の TTFF（5 章 5 節）より長くし、例ではウォームスタートの 30 s に余裕を足した 45 s とした。主の電源を切る前には、受信を止めて保つ情報を書き終える命令を送る（13 章 5 節）。切っていた時間がバックアップ電源の保持時間より短ければ、次はホットスタートになる（10 章 3 節）。

電池を長く持たせる — 起きる間隔の延長と方式の切り替え

屋内や地下では、何度起きて捕捉を試しても位置が出ない。13 章 5 節の周期的に起きる方式（60 s ごと）で、起きるたびに上限の 45 s まで捕捉を続けると、平均の電流は 35 mA × 45 s ÷ 60 s = 26 mA になり、位置が出るときの 1.32 mA の 20 倍になる。そこで、捕捉に失敗するたびに、次に起きるまでの間隔を 2 倍に延ばし、上限（例の値 30 分）で止める。これは、組み込み通信シリーズの、送り直しの間隔を延ばす指数バックオフ（5 章 5 節）と同じ考え方である。位置が出たら、初めの間隔に戻す。もう 1 つの工夫は、電池の残り（電池の電圧などから見積もる。電源と周辺の制御シリーズ 3 章 2 節）が減るほど、位置を出す間隔を延ばす方式に切り替えることである。2 つの工夫で電池の減りと記録を続けられる時間がどう変わるかを、13 章 5 節の式と例の値で計算して並べる。

6. 試験 — 記録した文を流して確かめる

記録の再生による試験

ここまでのコードが、壊れた文や途切れにどう応えるかを、実機を空の下に置くだけで確かめるのは難しい。誤りはまれにしか起きず、同じ条件を作り直せないからである。そこで、モジュールが出した文（または作った文）を、届いた時刻と一緒に記録しておき、ホストのコンピュータで、ファームウェアの解析の部分にそのまま流して、結果を期待の値と比べる。この試験を記録の再生による試験という。記録に誤りを書き足せば、まれな誤りを何度でも同じ形で作れる。

本文の C は、ハードウェアに触れる所を仮に置く関数にまとめてあるので、試験では、その中身を記録と試験の時計に置き換えるだけでよい。記録の 1 行は、時刻 [ms] と文、または時刻と PPS（パルスの立ち上がり）である。試験では、use_epoch が組の時刻・状態・判断を 1 行ずつ書き出し、mclock_pps が受け取った捕獲値と時刻を残す。

static uint32_t sim_ms;                      /* 試験の時計 [ms] */
static const char *feed;                     /* 割り込みに渡す残りのバイト */
uint32_t now_ms(void) { return sim_ms; }     /* 仮に置く関数の、試験での中身 */
uint32_t timer_now(void) { return sim_ms * 10000u; }       /* 10 MHz のタイマ */
uint32_t timer_capture(void) { return sim_ms * 10000u; }
int uart_hw_rx_ready(void) { return *feed != '\0'; }
uint8_t uart_hw_read(void) { return (uint8_t)*feed++; }
uint32_t uart_hw_rx_errors(void) { return 0; }

static void run_until(uint32_t t)            /* 1 ms ずつ時計を進め、10 ms ごとに主のループを回す */
{
    while (sim_ms < t)
        if (++sim_ms % 10 == 0) gnss_poll();
}

void replay(FILE *fp)                        /* 記録の 1 行は「時刻 [ms] 文」か「時刻 [ms] PPS」 */
{
    char line[200], s[200];
    unsigned long t;
    while (fgets(line, sizeof line, fp)) {
        if (sscanf(line, "%lu %190s", &t, s) != 2) continue;
        run_until((uint32_t)t);
        if (strcmp(s, "PPS") == 0) { pps_isr(); continue; }   /* 1PPS の立ち上がり */
        strcat(s, "\r\n");
        feed = s;
        gnss_rx_isr();                       /* 1 つの文を受けた割り込み */
    }
    run_until(sim_ms + 6000);                /* 最後の文の後の 6 s（時間切れを確かめる） */
}

誤りを混ぜた記録で確かめる

12 章の例の文（GPS の 7 文。東へ 10 m/s で動くとした）から Python で 60 s の記録を作り、誤りを混ぜて流した。期待の値は、同じ手順を Python で書いて求めた。

数えも、組ごとの状態と判断も、期待の値と一致した。1PPS に付けた 34 の名前は、どれもパルスの本当の秒と一致した。ただし、ホストの試験では、割り込みの時間、リングバッファの大きさ、タイマの捕獲は確かめられない（割り込みは記録の 1 行ごとに 1 回呼ぶ）。それらは、PC が同じ記録を本物の通信の速さで実機の受信の端子へ送り、1PPS をディジタルの出力の端子で出して、実機のファームウェアが出す結果と比べる HIL（組み込みテストシリーズ 15 章 1 節）で確かめる。HIL では、主のループをわざと遅らせて、n_drop と rb_max が 2 節の計算どおりかも確かめられる。

7. まとめ

項目内容
全体の構成・リングバッファ割り込み（UART の受信・1PPS の捕獲）は値を置くだけで、解析・状態の判断・記録は主のループ。両者は、リングバッファ（配列を輪のように使い、書く位置 head は割り込みだけ、読む位置 tail は主のループだけが進める受け渡しの場所。満杯なら新しいバイトを捨てて数え、rb_max で実機の埋まりを確かめる）と、割り込みだけが書く変数でつながる
