# 01. 電源と周辺制御の全体像 — 条件が決めること

> **この章で扱う問い.**
> 玄関の扉の開け閉めを知らせるセンサ、部屋を暖めるファンヒータ、机の上の測定器、屋外の気象計、車の中で使う記録計。どれもマイコンを内蔵し、センサで測り、LED やモータやヒータを動かしている。仕事は似ていても、電池で動くのか、家庭のコンセントにつながるのか、寒い屋外に置かれるのかによって、気をつけることと、マイコンでする制御は大きく変わる。このシリーズでは、機器が置かれる条件から出発して、電源・センサ・アクチュエータのまわりで何が起きるかを式と数値で確かめ、マイコンで何をすればよいかをコードまで組み立てる。
>
> この章では次の 3 つの問いに答える。
>
> 1. 機器の中では、何がどこからどこへ流れているのか。設計を始める前に、機器について何を書き出せばよいのか。
> 2. 電源と周辺のまわりで、マイコンは何を決めているのか。
> 3. 電池がどれだけもつか、電源が耐えられるかを、どう見積もるのか。マイコンが止まったときに危険にならないよう、何を決めておくのか。
>
> 答えの道具は、使用条件の 4 つの軸、マイコンが決める 4 つのこと、平均電流とピーク電流の式、そして安全な状態という考え方である。

> **このシリーズで前提とする知識.**
> C 言語、電圧・電流・抵抗とオームの法則、電力 = 電圧 × 電流、簡単な回路図の読み方（[組み込み回路シリーズ 01 章](../circuit/01_電圧電流抵抗.md)）、式の変形、マイコンでプログラムを動かしたことがある程度の経験。回路の中身（レギュレータ・MOSFET・モータドライバなど）は[組み込み回路シリーズ](../circuit/00_目次と学習の進め方.md)が詳しく扱っているので、このシリーズでは要点だけを書いてリンクする。

## 1. 機器の中を流れる電力・信号・熱

このシリーズでは、特定の仕事をするためにマイコンを内蔵した装置（組み込み機器）を、単に**機器**と呼ぶ。**マイコン**（マイクロコントローラ）は、CPU とメモリに、時間を数える回路やアナログの電圧を測る回路などを加えて、1 つのチップにまとめた部品である。マイコンはプログラムに従って、機器の中のほかの部品を動かす。

機器の部品は、マイコンのほかに、役割で 3 つに分けられる。

- **電源**: 機器に電力を渡すもの。電池・USB・AC アダプタ・家庭のコンセントの電源（商用電源）・車のバッテリーなどがある（02 章）。
- **センサ**: 温度・光・加速度・扉の開け閉めなど、外の世界の量や状態を、電圧やデジタルの値に変えてマイコンに伝える部品。
- **アクチュエータ**: マイコンの指示で、外の世界に働きかける部品。モータ、ヒータ、弁を動かすソレノイド、リレー、LED、ブザーなどがある。

マイコンの外にあって、マイコンにつながるセンサ・アクチュエータ・表示・通信の回路などを、まとめて**周辺**と呼ぶ。また、電源から電流を受け取って電力を使うものを、電源から見て**負荷**という。マイコンもセンサも負荷だが、モータやヒータのようなアクチュエータは、マイコンより何桁も大きな電流を使うことがあり、電源にとって大きな負荷になる。

部品の間を流れるものを、図に示す。

```fig
e01_block
```

図のように、部品の間を 3 つのものが流れている。

- **電力**: 電源から、電圧を一定にする回路（レギュレータ。05 章）を通って、マイコンとセンサへ流れる。アクチュエータは大きな電流や、マイコンより高い電圧を使うことが多いので、電源から直接、マイコンが入れたり切ったりするスイッチ（MOSFET やリレー。12 章）を通して電力を受け取る。
- **信号**: センサからマイコンへは測った値が、マイコンからスイッチへは「入れる・切る」の指示が流れる。マイコンは、センサの値を読み、決めた規則に従ってアクチュエータを動かす。
- **熱**: 部品が使った電力の多くは、その部品の中で熱になる。ヒータは熱を作るのが仕事だが、レギュレータ・スイッチ・モータ・マイコンも、使った電力の一部を熱にする。熱は部品から基板と筐体を通って周りの空気へ逃げ、逃げる速さより速く生まれると、部品の温度は上がり続ける（14 章）。

3 つの流れのうち、マイコンが直接扱うのは信号だけである。しかし、マイコンがアクチュエータを「いつ・どれだけ」動かすかで、電源から流れ出る電流と、機器の中で生まれる熱が決まる。つまり、周辺を制御するプログラムは、電力と熱の流れも制御している。このシリーズで扱うのは、この 3 つの流れをまとめて考えた制御である。

マイコンは、次の回路を使って周辺とやり取りする。どれもマイコンの中にある回路で、このシリーズでは「マイコンの周辺回路」と呼んで、マイコンの外の周辺と区別する。

- **GPIO**（汎用入出力）: プログラムで入力にも出力にもできるピン。入力にすると、ピンの電圧が H（電源の電圧に近い）か L（0 V に近い）かを読め、出力にすると H か L を出せる（回路は[組み込み回路シリーズ 19 章](../circuit/19_GPIO.md)）。
- **ADC**（A/D 変換器）: ピンに加わったアナログの電圧を測り、数値に変える回路（09 章）。
- **タイマ**: 一定の周期で刻む信号（クロック）を数えて、決めた時間がたったことを知らせたり、決めた周期と幅のパルスをピンに出したりする回路。
- **割り込み**: ピンの電圧の変化や、タイマが決めた時間を数え終えたことなどの出来事が起きたときに、実行中のプログラムを中断して、その出来事のために用意した関数（割り込みハンドラ）を実行し、終わったら元のプログラムに戻る仕組み。

```fig
e01_mcu
```

図の (a) のように、スイッチの状態は GPIO の入力で読み、状態が変わったことは割り込みで知る。アナログの電圧を出すセンサは ADC で読み、デジタルの値を出すセンサとは I2C や SPI などの通信の回路でやり取りする（08 章）。アクチュエータは、GPIO の出力でスイッチを入れ切りして動かす。タイマのパルスでスイッチを速く入れ切りすると、入れている時間の割合で、アクチュエータに加える平均の電力を細かく変えられる（この方法を PWM という。12・13 章）。

マイコンは、仕事が無い間、ほとんどの回路を止めて、小さな電流で待つことができる。このシリーズでは、これを「眠る」という（07 章）。(b) のように、割り込みを使えば、プログラムは出来事を待ち続けなくてよく、眠っているマイコンも、出来事が起きたときにだけ起きて処理できる。

## 2. 条件を書き出す — 電源・負荷・環境・使われ方

機器の回路やプログラムを考える前に、機器が置かれ、使われる条件を書き出す。この条件を、このシリーズでは**使用条件**と呼び、次の 4 つに分けて書き出す。この 4 つを**使用条件の 4 つの軸**という。

- 電源: 何から電力を得るか。電圧がどの範囲で変わるか、どれだけの電流を取り出せるか、途切れることがあるか（02 章）。
- 負荷: 何を動かすか。それぞれが平均でどれだけの電流を使い、瞬間には最大でどれだけの電流を使うか（4 節）。
- 環境: 温度と湿度の範囲、屋内か屋外か、配線の長さ、雷や電気のノイズ。
- 使われ方: いつも動いているか、ときどき起きて仕事をするか。何年使うか、電池を交換できるか。人がそばにいるか、止まったら何が起きるか。

```fig

```

例として、5 つの機器の使用条件を書き出す。値はどれも例で、製品によって違う。

| 機器 | 電源 | 負荷 | 環境 | 使われ方 |
|---|---|---|---|---|
| ドアの開閉センサ | コイン形のリチウム電池 CR2032 が 1 個（3 V、220 mAh 程度。代表値） | 扉に付けた磁石で開け閉めするスイッチ、無線の送信（送る瞬間に 10 mA 程度）、LED | 屋内（0〜40 °C） | ほとんど眠っていて、扉が動いたときと 1 分ごとに起きる。数年は電池を交換しない |
| 電気ファンヒータ | 商用電源（AC 100 V、50 Hz または 60 Hz） | ヒータ（1 kW 程度）、ファンのモータ、温度センサ | 屋内の床の上。ほこり | 冬の間、毎日数時間。人がそばにいて、人が部屋を離れても動き続けることがある |
| USB の測定器 | パソコンの USB（5 V） | センサ、表示、LED | 机の上 | 使うときだけ差す。いつ抜かれるか分からない |
| 屋外の気象計 | 太陽電池と、充電して使う電池 | 温度・湿度・風速のセンサ、無線 | 屋外（−20〜50 °C）。雨・結露・雷 | 何年も置いたまま。夜と曇りの日は、太陽電池から電力が来ない |
| 車の記録計 | 車の 12 V の電源 | マイコン、記録用のメモリ、表示 | 車内（夏は高温） | エンジンをかける瞬間に電源の電圧が下がるなど、電圧が大きく変わる（02 章） |

この表から、それぞれの機器で特に気をつけることを拾い出すと、次のようになる。

```fig

```

同じ「測って、何かを動かす」機器でも、条件が違えば、気をつけることがまったく違う。ドアの開閉センサでは、220 mAh ほどの電荷で何年動けるかが設計の中心になり（4 節）、無線を送る瞬間の電流で電池の電圧が下がることにも気をつける。ファンヒータでは電力の量の心配は無いが、感電と、ヒータの過熱が問題になる。USB の測定器では取り出せる電流の上限と抜き差し、気象計では温度と、太陽電池から入る電力と使う電力の釣り合い、車の記録計では電源の電圧の変動が問題になる。したがって、設計は、使用条件を書き出し、そこから気をつけることを導くことから始める。このシリーズの各章も、どの条件のときに何に気をつけるかを、4 つの軸で示す（6 節に地図をまとめる）。

ファンヒータのように商用電源につながる機器には、感電と火災の危険がある。商用電源から電気的に分けずに電力を取る回路（非絶縁の回路。02 章）では、マイコンの回路も商用電源と同じ電位になる。そのような回路に触れると感電し、PC やデバッガを直接つなぐと、つないだ機器が壊れたり、それに触れた人が感電したりする。このシリーズでは、通電中の回路に触れる作業を手順として扱わない。商用電源を扱う回路を作るときは、06 章と[筐体シリーズ 15 章](../enclosure/15_安全と規格.md)を読み、安全規格と法令（日本では電気用品安全法など）や、作業に必要な資格を確かめること。

## 3. マイコンが決めること — いつ・どれだけ・どの順で・失敗したら

使用条件を書き出したら、マイコンが電源と周辺について何を決めるのかを考える。マイコンが決めることは、次の 4 つにまとめられる。

1. いつ: いつ周辺の電源を入れ、いつ動かし、いつ眠るか。
2. どれだけ: アクチュエータにどれだけの電力を加えるか。電流をどこまで流してよいか。
3. どの順で: 複数の周辺を、どの順番で入れ、切るか。同時に動かしてよいか。
4. 失敗したら: センサが答えない、電源の電圧が下がった、温度が上がりすぎた、などのときにどうするか。

2 節の例の機器で、4 つの決めごとを図に示す。

```fig
e01_decide
```

- (a) いつ: ドアの開閉センサは、タイマで 1 分ごとに起きて電池の電圧を測って送り、扉が動いたときは、スイッチの変化を割り込みで受けて、すぐに起きて送る。それ以外の時間は眠っている。
- (b) どれだけ: ファンヒータは、ヒータを入れている時間の割合で、平均の電力を決める。10 秒のうち 3 秒だけ入れれば、1 kW のヒータの平均の電力は 1 kW × 3/10 = 300 W になる（AC のヒータを入れ切りする細かいやり方は 14 章）。
- (c) どの順で: ファンヒータは、ファンを回してからヒータを入れ、止めるときはヒータを先に切って、しばらくファンを回し続ける。ファンが止まったままヒータに電流を流すと、ヒータのまわりだけが熱くなりすぎるからである。
- (d) 失敗したら: 温度センサの値が、部屋ではありえない範囲（例: −20 °C 以下や 100 °C 以上）になったら、配線が切れたかセンサが壊れたとみなし、ヒータを切る。

この 4 つを、ファンヒータの制御のプログラムで確かめる。下の関数は、1 秒ごとにタイマの割り込みから呼ばれ、運転のスイッチ `run` と目標の温度 `target`（0.1 °C 単位）を受け取って、ヒータとファンを入れ切りする。`temp_read_c10()`・`heater_set()`・`fan_set()` は、この章で仮に置く関数で、実際のマイコンでは ADC で温度センサの電圧を読み、GPIO でスイッチを入れ切りする。状態の名前と移り方は、図の (c)・(d) と同じである。

```c
/* この章で仮に置く関数（実際のマイコンでは、ピンやセンサを操作する） */
bool temp_read_c10(int16_t *t);   /* 温度を 0.1 °C 単位で読む。読めなければ false */
void heater_set(bool on);         /* ヒータのスイッチを入れる・切る */
void fan_set(bool on);            /* ファンのモータを回す・止める */

enum { OFF, PREFAN, HEAT, COOL, FAULT };
static int st = OFF, sec, bad;    /* 状態、その状態に入ってからの秒数、続けて読めなかった回数 */

static void go(int s) { st = s; sec = 0; }

/* どれだけ: 目標との差 1 °C ごとに、10 秒のうち 1 秒ヒータを入れる（0〜10 秒） */
static int on_seconds(int diff_c10)
{
    int s = diff_c10 / 10;
    return s < 0 ? 0 : (s > 10 ? 10 : s);
}

/* いつ: 1 秒ごとにタイマの割り込みから呼ぶ。run は運転のスイッチ、target は目標 [0.1 °C] */
void heater_tick(bool run, int16_t target)
{
    int16_t t = 0;
    bool ok = temp_read_c10(&t) && t > -200 && t < 1000;   /* −20 °C 以下・100 °C 以上は故障とみなす */
    bad = ok ? 0 : bad + 1;
    sec++;
    switch (st) {
    case OFF:    if (run) { fan_set(true); go(PREFAN); } break;
    case PREFAN: if (!run) { fan_set(false); go(OFF); }
                 else if (sec >= 3) go(HEAT);                       /* どの順で: ファンを先に回す */
                 break;
    case HEAT:   if (bad >= 3) { heater_set(false); go(FAULT); }    /* 失敗したら: ヒータを切る */
                 else if (!run) { heater_set(false); go(COOL); }    /* どの順で: ヒータを先に切る */
                 else heater_set(ok && sec % 10 < on_seconds(target - t));
                 break;
    case COOL:   if (sec >= 30) { fan_set(false); go(OFF); } break; /* 余熱を逃がしてから止める */
    case FAULT:  if (sec >= 30) fan_set(false);
                 if (sec >= 30 && !run) go(OFF);                    /* 運転を切り直すまで再開しない */
                 break;
    }
}
```

- いつ: 1 秒ごとに呼ばれ、温度を読んで、その秒にヒータを入れるかどうかを決める。
- どれだけ: `HEAT` では、目標との差 1 °C ごとに、10 秒のうち 1 秒ヒータを入れる。差が 3 °C なら 10 秒のうち 3 秒で、平均の電力は図 (b) の 300 W になる。温度を読めなかった秒は、ヒータを入れない。
- どの順で: `PREFAN` でファンだけを 3 秒回してから `HEAT` に移る。運転を切ると、`HEAT` から `COOL` に移ってヒータを先に切り、30 秒たってからファンを止める。
- 失敗したら: 温度を 3 秒続けて読めないか、読めても範囲の外なら、`FAULT` に移ってヒータを切る。センサが元に戻っても、運転のスイッチを切り直すまでヒータを入れない。

起動の直後には `heater_set(false)` と `fan_set(false)` を呼んでおく。このコードは、仮に置いた関数をホストのコンピュータで差し替えて動かし、ヒータが入っている間はいつもファンも回っていること、目標との差に応じた秒数だけヒータが入ること、故障の後は運転を切り直すまでヒータが入らないことを確かめてある。

4 つの決めごとのうち、どれが重いかは使用条件で変わる。電池で動く機器では「いつ」と「どの順で」が、電池がどれだけもつかと、電池の電圧がどこまで下がるかを決める。商用電源でヒータを動かす機器では「失敗したら」が安全を決める。これを数と決まりで決めるために、次の 4 節で電流を数える道具を、5 節で失敗したときの行き先を用意する。

## 4. 平均電流とピーク電流

3 節の「いつ」と「どの順で」は、電源から流れ出る電流の形を決める。この節では、その電流を平均電流とピーク電流の 2 つの数で表し、電池がどれだけもつかと、電源の電圧が瞬間にどこまで下がるかを見積もる。例には、2 節のドアの開閉センサを使う。

### 電荷と容量

電流と時間の積を**電荷**という。電流 $`I`$ が時間 $`t`$ の間一定なら、流れた電荷は $`Q = I t`$ で、単位は C（クーロン）= A·s である。電流が時間とともに変わるときは、横軸を時間、縦軸を電流にしたグラフの下の面積が、流れた電荷になる。小さな電荷には µC（$`10^{-6}`$ C）を使う。mA × ms = µC なので、10 mA を 3 ms 流したときの電荷は 30 µC である。

電池から取り出せる電荷の量を、電池の**容量**という。電池の容量は、mAh（ミリアンペア時）で表すことが多い。1 mAh は 1 mA を 1 時間流したときの電荷で、

$$
1\ \text{mAh} = 10^{-3}\ \text{A} \times 3600\ \text{s} = 3.6\ \text{C}
$$

である。CR2032 の 220 mAh は 220 × 3.6 = 792 C にあたる。電池から実際に取り出せる電荷は、流す電流の大きさ・温度・どこまで電圧が下がってよいかで変わる（03 章）。この節では、電池に表示された容量で計算する。

### 間欠動作の電流

ドアの開閉センサは、ほとんどの時間を眠って過ごし、決めた時間ごとに短く起きて仕事をする。このように、短い時間だけ起きて仕事をし、それ以外の時間は眠る動かし方を**間欠動作**という。また、一定の周期で繰り返す動作で、1 周期のうち、ある状態（起きている状態や、ヒータを入れている状態）にある時間の割合を**デューティ比**という。3 節 (b) の「10 秒のうち 3 秒」は、デューティ比 0.3（30 %）である。

例のドアの開閉センサは、60 s の周期で、次の 3 つの段を繰り返すとする（電流と時間は例の値。代表値）。

| 段 | 電流 | 時間 | 電荷 = 電流 × 時間 |
|---|---|---|---|
| 処理（起きて電池の電圧を測り、送るデータを作る） | 3 mA | 4 ms | 12 µC |

### 平均電流を導く

電池がどれだけもつかは、時間あたりに電池から出ていく電荷で決まる。そこで、長さ $`T`$ の時間に流れた電荷を $`T`$ で割った値を**平均電流**といい、$`I_\mathrm{avg}`$ と書く。平均電流は、同じ時間に同じ電荷を運ぶ一定の電流である。

**方針**: 1 周期 $`T`$ を、電流が一定とみなせる区間に分け、区間ごとの電荷を足して、$`T`$ で割る。

**導出**: 1 周期を $`n`$ 個の区間に分け、区間 $`k`$（$`k = 1, 2, \ldots, n`$）の電流を $`I_k`$、長さを $`t_k`$ とする。区間の長さの和は周期に等しく、$`t_1 + t_2 + \cdots + t_n = T`$ である。区間 $`k`$ の電流は一定なので、そこで流れる電荷は $`I_k t_k`$ である。1 周期の電荷 $`Q`$ は、これを全部の区間について足して

$$
Q = I_1 t_1 + I_2 t_2 + \cdots + I_n t_n = \sum_{k=1}^{n} I_k t_k
$$

となる。平均電流 $`I_\mathrm{avg}`$ は、時間 $`T`$ の間に同じ電荷 $`Q`$ を運ぶ一定の電流なので、$`I_\mathrm{avg} \times T = Q`$ を満たす。両辺を $`T`$ で割って

$$
I_\mathrm{avg} = \frac{Q}{T} = \frac{1}{T} \sum_{k=1}^{n} I_k t_k
$$

となる ∎

例の値を入れる。µC ÷ s = µA なので、

$$
I_\mathrm{avg} = \frac{12\ \text{µC} + 30\ \text{µC} + 119.986\ \text{µC}}{60\ \text{s}} = \frac{161.986\ \text{µC}}{60\ \text{s}} \approx 2.70\ \text{µA}
$$

である。

### 2 つの状態に分ける — デューティ比の役割

平均電流が何で決まっているかを見るために、1 周期を「起きている」と「眠っている」の 2 つの状態に分ける。起きている時間を $`t_\mathrm{a}`$、その間の電流の平均を $`I_\mathrm{a}`$、眠っている間の電流を $`I_\mathrm{s}`$ とし、デューティ比を $`D = t_\mathrm{a}/T`$ とする。

**方針**: 上の式で区間を 2 つにし、眠りの電流の項と、起きている分の上乗せの項に分けて、$`D`$ で書き直す。

**導出**: 起きている間の電荷は $`I_\mathrm{a} t_\mathrm{a}`$、眠っている間（長さ $`T - t_\mathrm{a}`$）の電荷は $`I_\mathrm{s} (T - t_\mathrm{a})`$ なので、

$$
I_\mathrm{avg} = \frac{I_\mathrm{a} t_\mathrm{a} + I_\mathrm{s} (T - t_\mathrm{a})}{T}
$$

である。分子の $`I_\mathrm{s} (T - t_\mathrm{a})`$ を $`I_\mathrm{s} T - I_\mathrm{s} t_\mathrm{a}`$ と展開し、$`t_\mathrm{a}`$ を含む項をまとめると、分子は $`I_\mathrm{s} T + (I_\mathrm{a} - I_\mathrm{s})\, t_\mathrm{a}`$ になる。これを $`T`$ で割り、$`t_\mathrm{a}/T = D`$ とおいて

$$
I_\mathrm{avg} = I_\mathrm{s} + (I_\mathrm{a} - I_\mathrm{s})\, D
$$

となる ∎

例では、$`I_\mathrm{a}`$ = (12 + 30) µC ÷ 7 ms = 6 mA = 6000 µA、$`D`$ = 7 ms ÷ 60 s ≈ 1.167 × 10⁻⁴ で、$`I_\mathrm{avg}`$ = 2 + (6000 − 2) × 1.167 × 10⁻⁴ ≈ 2 + 0.70 = 2.70 µA と、上と同じ値になる。

第 1 項 $`I_\mathrm{s}`$ は眠りの電流そのもので、第 2 項は起きている分の上乗せであり、デューティ比に比例する。周期を 10 s にすると $`D`$ は 6 倍の 7 × 10⁻⁴ になり、第 2 項は 4.20 µA、平均電流は 6.20 µA になる。周期を 600 s にすると第 2 項は 0.07 µA で、平均電流は 2.07 µA と、ほとんど眠りの電流だけで決まる。したがって、平均電流を減らすには、2 つの項のどちらが大きいかを見て、大きいほうを減らす。上乗せが大きいなら、起きている時間を短くするか周期を長くし、眠りの電流が大きいなら、眠っている間に流れる電流を減らす（05・07 章）。

### 電池寿命

電池を新しくしてから、電池の電荷を使い切って機器が動けなくなるまでの時間を、**電池寿命**という。電池の容量を $`Q_\mathrm{bat}`$ とすると、電池は 1 秒あたり $`I_\mathrm{avg}`$ ずつ電荷を渡すので、使い切るまでの時間 $`t_\mathrm{life}`$ は

$$
t_\mathrm{life} = \frac{Q_\mathrm{bat}}{I_\mathrm{avg}}
$$

である。容量を mAh で、平均電流を mA で表せば、答えは時間（h）で出る。例の値では

$$
t_\mathrm{life} = \frac{220\ \text{mAh}}{2.70\ \text{µA}} = \frac{220 \times 10^{-3}\ \text{Ah}}{2.70 \times 10^{-6}\ \text{A}} \approx 81{,}500\ \text{h} \approx 9.3\ \text{年}
$$

となる。周期を 10 s にすると 4.1 年になる。実際の寿命は、これより短くなることが多い。取り出せる電荷が温度や電流で減ること、使わなくても電池の電荷が少しずつ減ること（自己放電。03 章）、電池の電圧が下がりきる前にマイコンが動けなくなること（03・04 章）による。

### ピーク電流

平均電流のほかに、電流が最も大きくなる瞬間の値も問題になる。この値を**ピーク電流**といい、$`I_\mathrm{pk}`$ と書く。例のドアの開閉センサの $`I_\mathrm{pk}`$ は送信の 10 mA で、平均電流 2.70 µA の約 3700 倍である。ピーク電流を生むのは、無線の送信のほか、モータの回り始め（13 章）や、周辺の電源を入れた瞬間にコンデンサを充電する電流（突入電流。05 章）などである。

平均電流が小さくても、ピーク電流が別に問題になるのは、電源が瞬間に渡せる電流に限りがあるからである。電池は、中に抵抗が直列に入っているようにふるまい、流す電流が大きいほど、端子の電圧が下がる（この抵抗を内部抵抗という。02・03 章）。端子の電圧が、マイコンが正しく動ける最低の電圧を下回ると、マイコンはリセットされ（実行を止めて、プログラムを最初からやり直すこと。05 章）、送信や測定は途中で終わる。USB や AC アダプタでは、取り出してよい電流の上限が決まっている（02 章）。

ピーク電流は、3 節の「どの順で」で変わる。扉が開いたとき、ドアの開閉センサが LED を 20 ms 点け（5 mA）、無線で知らせる（10 mA を 3 ms）とする。2 つを同時に始めると、重なった 3 ms の電流は 5 + 10 = 15 mA になる。LED を消してから送れば、ピーク電流は 10 mA にとどまる。どちらの順でも、流れる電荷は 5 mA × 20 ms + 10 mA × 3 ms = 130 µC で同じなので、平均電流は変わらない。

```fig
e01_overlap
```

図は、電流を流していないときの電池の電圧を 3.0 V、内部抵抗を 60 Ω、マイコンが正しく動ける最低の電圧を 2.2 V とした例である（どれも例の値）。新しい CR2032 を室温で使うときの内部抵抗は 10〜数十 Ω 程度のことが多いが、低温や、電池を使い切る間際には大きくなる（代表値。03 章）。端子の電圧の低下は電流 × 内部抵抗なので、同時に始めると 15 mA × 60 Ω = 0.9 V 下がって 2.1 V になり、2.2 V を下回ってマイコンがリセットされる。順に動かすと 10 mA × 60 Ω = 0.6 V の低下で、2.4 V にとどまる。

したがって、平均電流は電池がどれだけもつかを決め、ピーク電流は電源の電圧が瞬間にどこまで下がるかを決める。2 つは別の量なので、両方を見積もる。動作の順番は、平均電流を変えずにピーク電流を変えられる道具である。大きなコンデンサでピーク電流を電池から隠す方法と、電池の電圧が下がったときに正しく止まる方法は 04 章で、電源の電圧を見張る方法は 05 章で扱う。

## 5. 安全な状態という考え方

3 節の「失敗したら」で、ファンヒータは、温度センサが壊れたらヒータを切った。では、マイコン自身が止まったとき、リセットされたとき、電源が切れたとき、ヒータはどうなっているべきか。

マイコンが止まった、リセットされた、電源が切れた、故障が見つかったなど、正常に制御できないときに、アクチュエータがとるべき状態を、そのアクチュエータの**安全な状態**という。安全な状態は、人や物に危険が及ばず、そのまま放っておいても事態が悪くならない状態である。

```fig
e01_safe
```

図のとおり、安全な状態はアクチュエータごとに、使い方によって決める。ヒータは切り、モータは止める。弁は、水やガスを送る弁なら閉じる側、圧力を逃がす弁なら開く側が安全な状態である。電気錠は、人を閉じ込めないことが大事な扉なら開く側、盗難を防ぐことが大事な扉なら閉じる側になる。「電気を切る」がいつも安全な状態とは限らない。表示の LED のように、どちらでも危険の無いものもある。

安全な状態は決めるだけでなく、マイコンが動いていないときにもその状態になるようにしておく。マイコンが止まったりリセットされたりしている間は、プログラムは何もできないので、そのときのアクチュエータの状態は、回路と部品で決まる。

- リセットの間は、多くのマイコンで GPIO が入力になり、H も L も出さない。このとき、アクチュエータのスイッチの入力を抵抗で L（または H）に引いておけば、スイッチは決めた側になる。抵抗が無いと、スイッチの入力の電圧が定まらず、ヒータが入るかどうかは分からない（15 章）。
- 電源が切れたときの状態は、電気が切れるとばねで閉じる弁のように、部品の選び方で決まる。
- プログラムが止まったことは、ウォッチドッグ（決めた時間のうちにプログラムから合図が来ないと、マイコンをリセットする回路。15 章）で見つけ、リセットによって、アクチュエータを回路で決めた側に戻す。
- ヒータのように、安全な状態にならないと火災につながるものには、マイコンに頼らない保護（決めた温度で回路を切る部品など。14 章）も置く。プログラムの誤りやマイコンの故障、温度センサの故障は、プログラムだけでは防げないからである。

ヒータを入れている途中でプログラムが止まった場合を、抵抗が無いときとあるときで比べる。

```fig
e01_reset
```

プログラムが止まると、GPIO は最後に出していた H を出し続けるので、どちらの場合もヒータは入ったままになる。ウォッチドッグがマイコンをリセットすると、（多くのマイコンで）GPIO は入力になる。(a) 抵抗が無いと、リセットの間のスイッチの入力は定まらず、ヒータが入ったままのこともある。(b) 抵抗でスイッチの入力を L に引いておくと、リセットの間はヒータが切れる。プログラムが起動し直した後は、3 節で述べたとおり起動の直後に `heater_set(false)` を呼ぶので、ヒータは切れたままになる。ウォッチドッグが無ければ、プログラムが止まったままヒータは入り続け、残る守りはマイコンに頼らない保護だけになる。

まとめると、安全な状態は次の順に決める。(1) アクチュエータごとに、止まったときにとるべき状態を決める。(2) マイコンが動いていない間（リセット・電源が切れたとき）もその状態になるように、回路と部品を選ぶ。(3) マイコンは、異常を見つけたら、その状態へ移す（3 節の「失敗したら」）。(4) 危険の大きいものには、マイコンに頼らない保護も置く。リセットの間のピンの状態、ウォッチドッグ、故障したときに一部を止めて動き続ける方法は、15 章で詳しく扱う。

| 使用条件の 4 つの軸 | 電源・負荷・環境・使われ方。設計はこれを書き出すことから始める |
| マイコンが決める 4 つのこと | いつ・どれだけ・どの順で・失敗したら |
| 電荷・容量 | $`Q = I t`$（グラフの下の面積）。1 mAh = 3.6 C。容量は電池から取り出せる電荷 |

| 平均電流・電池寿命 | $`I_\mathrm{avg} = \frac{1}{T}\sum_k I_k t_k = I_\mathrm{s} + (I_\mathrm{a} - I_\mathrm{s}) D`$。電池寿命 $`t_\mathrm{life} = Q_\mathrm{bat}/I_\mathrm{avg}`$ |

| 安全な状態 | 正常に制御できないときにアクチュエータがとるべき状態。アクチュエータと使い方ごとに決め、マイコンが動いていない間は回路と部品で保証する |

この章で見た条件ごとの要点を、シリーズの軸（条件 → 気をつけること → マイコンでする制御）でまとめる。

| 条件 | 気をつけること | マイコンでする制御 |
|---|---|---|
| 電池で動く（例: ドアの開閉センサ） | 平均電流で電池寿命が、ピーク電流で電池の電圧の低下が決まる | 間欠動作で眠る時間を長くする。大きな動作を重ねない（4 節、04・07 章） |
| 商用電源でヒータを動かす（例: ファンヒータ） | 感電・火災、ヒータの過熱 | 異常を見つけたらヒータを切る。故障の後は自動で再開しない（3・5 節、06・14 章） |
| USB・AC アダプタで動く | 取り出せる電流の上限、抜き差し | 大きな動作を重ねず、ピーク電流を抑える（4 節、02・05 章） |
| 屋外・環境発電 | 温度、入る電力と使う電力の釣り合い | 使える電力に合わせて、起きる間隔を変える（02・03・16 章） |
| 車の電源 | 電源の電圧の大きな変動 | 電源の電圧を見張り、下がったら大きな動作を止める（02・05 章） |
| 止まると危険なアクチュエータがある | リセット・電源が切れたとき・プログラムが止まったとき | 安全な状態を決めて回路で保証し、ウォッチドッグで見張る（5 節、15 章） |
