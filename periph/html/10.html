Chapter 10

測り方を設計する — 周期・割り込み・FIFO・校正・故障の検出

この章で扱う問い. 08 章ではセンサのつなぎ方と電源の入れ切りを、09 章では ADC で 1 回の値を正しく測る方法を見た。この章では、測ることを時間の流れの中で設計する。いつ・どれだけの間隔で測るか、マイコンが起きる回数をどう減らすか、測ること自体が値をどうずらすか、部品ごとのずれをどう直すか、値の列をどうならすか、センサが壊れたことにどう気づくかを、マイコンでする制御として組み立てる。

この章では次の 3 つの問いに答える。

  1. 測る間隔は何で決まるのか。センサに見張らせて割り込みで起きる方法や、センサの中にためてまとめて読む方法で、マイコンの起きる回数と平均電流はどう変わるのか。
  2. 測るために流す電流がセンサを温めて値をずらすのは、どんなときか。部品ごとのずれと、温度によるずれは、どう測って直すのか。
  3. ノイズや、1 回だけ大きく外れた値や、急な変化が混じった値の列を、どのフィルタでならすのか。センサの断線・短絡・張り付きに、どう気づくのか。

答えの道具は、変化の速さと出来事の長さから決めるサンプリング周期、起きるたびの電荷を読む値の数で割る計算、平均の電力から求める温度の上昇、2 点校正の直線、3 つのフィルタのノイズの減り方と遅れ、そして値を使う前に行う妥当性の検査である。

この章で使う既出の用語（定義は各リンク先）. 機器・電源・センサ・アクチュエータ・マイコン・ADC・タイマ・クロック・割り込み・眠る（01 章 1 節）、電荷・平均電流・電池寿命（01 章 4 節）、安全な状態（01 章 5 節）、ノイズ・フラッシュメモリ（02 章 1 節）、低電池の判定・ヒステリシス（04 章 3 節）、レギュレータ・LDO（05 章 1 節）、RTC・深い眠り（07 章 1 節）、起床要因（07 章 2 節）、プルアップ抵抗（07 章 3 節）、起床の電荷・損益分岐の眠りの長さ（07 章 5 節）、デジタル出力（08 章 1 節）、I2C・アドレス・ACK・SPI（08 章 2 節）、バスの復旧（08 章 6 節）、LSB・ADC の値（09 章 1 節）、内部の基準電圧（09 章 2 節）、サーミスタ・B 定数・比率測定（09 章 3 節）、標本化時間（09 章 5 節）、標準偏差・平均化（09 章 6 節）

1. いつ測るか — 周期と出来事

センサの値は、決めた間隔で測るか、何かが起きたときに測る。決めた間隔で測るとき、1 回の測定から次の測定までの時間をサンプリング周期といい、\(T\) と書く（01 章 4 節の周期と同じ記号である）。09 章 5 節の標本化時間は、1 回の測定の中で ADC が電圧を取り込む時間で、サンプリング周期とは別のものである。

周期を決める 4 つのこと

  • 変わる速さ: 量が 1 秒あたり最大 \(S\) だけ変わるなら、続けて測った 2 つの値の間に、量は最大 \(S T\) 変わる。直前に測った値を今の値として使うと、これがそのまま誤差になる (a)。暖房で部屋の温度が 10 分に 3 °C 上がる（\(S\) = 0.005 °C/s）とき、この誤差を 0.1 °C 以下にするには \(T \le 0.1 \div 0.005 = 20\) s である。
  • 応える速さ: 値がしきい値を越えてから気づくまでに、最大で \(T\) 遅れる。決めた時間のうちに応える（ヒータを切るなど）なら、\(T\) をその時間より短くする。
  • 短い出来事: 測る時刻と時刻の間だけに起きて終わる出来事は、見逃す (b)。見逃す割合は下で求める。
  • 電力: 1 回の測定で使う電荷を \(Q_\mathrm{m}\) とすると、01 章 4 節の平均電流の式のとおり、平均電流は \(Q_\mathrm{m}/T\) だけ増える。起きてサーミスタの分圧（09 章 4 節）を 1 ms 動かして測り、計算して眠るまでを 2 µC とする（例の値）。\(T\) = 1 s なら平均電流は 2 µA 増え、07 章の深い眠りの電流の例（2 µA）と同じ大きさになる。60 s なら 0.033 µA しか増えない。

方針: 測る時刻を \(0, T, 2T, \ldots\) とし、長さ \(d\) の出来事は、周期の中のどこでも同じように始まる（始まる時刻に偏りが無い）とする。出来事の間に測る時刻が入るような始まりの範囲の長さを、\(T\) で割る。

導出: 出来事が時刻 \(s\)（\(0 \le s < T\)）に始まるとすると、出来事は \(s\) から \(s + d\) まで続く。\(d < T\) なら、この間に入りうる測る時刻は \(T\) だけで、入るのは \(s + d \ge T\)、つまり \(T - d \le s < T\) のときである。この範囲の長さは \(d\) なので、見つける確率は \(d/T\)、見逃す確率は \(1 - d/T\) である。\(d \ge T\) なら、長さ \(T\) 以上の間には測る時刻が必ず入るので、確率は 1 である ∎

扉が 2 秒だけ開いて閉じたとき、\(T\) = 10 s では 8 割を見逃す (c)。必ず見つけるには \(T \le 2\) s が要り、電力は 5 倍以上になる。このような出来事は、周期を縮めずに、出来事そのもので起こす（07 章 2 節の扉のスイッチ）。

このほか、センサ自身が変化に追いつく速さ（ケースに入ったサーミスタは数十秒かけて周りの温度に近づく）より速く測っても、新しいことは分からない。また、量に速く繰り返す変化（50 Hz のノイズや機械の振動）が含まれると、間隔をあけて測った値には、ありもしないゆっくりした変化が現れる（エイリアシング。ディジタル信号処理シリーズ 01 章 3 節）。そうした変化は、測る前に RC や平均化で取り除いておく（09 章 6 節）。

出来事で起こす — センサに見張らせる

デジタル出力のセンサ（08 章 1 節）の多くは、マイコンに知らせるための割り込みの出力（INT などと書くピン）を持ち、マイコンはこのピンの変化を起床要因（07 章 2 節）にできる。知らせる出来事の代表は 2 つある。

  • データレディ割り込み: センサが 1 回の測定を終え、新しい値を読めるようになったことを知らせる割り込み。マイコンは、測り終えるのを決めた時間待ったり、センサの状態のレジスタを何度も読んで確かめたりせずに、眠って待てる (b)。
  • しきい値割り込み: センサが自分で測り続け、値がマイコンの決めたしきい値を越えたときだけ知らせる割り込み。加速度センサの「動いたら知らせる」働き（08 章 3 節）や、温度が上限を越えたら知らせる働きがある。多くは、04 章 3 節のヒステリシスや「続けて何回越えたら」の設定を持ち、しきい値の近くで知らせが繰り返されるのを防げる。

物に付けて、持ち出されたら知らせる札の例で比べる。加速度センサは中で 10 Hz で測り、そのための電流は 3 µA、札のほかの部分の平均電流は 01 章 4 節の 2.70 µA とする（例の値）。(a) マイコンが 0.1 s ごとに起きてセンサの値を読み、動いたかを自分で判定すると、1 回の読み出しを 1 µC として 10 µA が加わり、平均電流は 15.7 µA、CR2032（220 mAh）の電池寿命は 1.6 年である。(c) しきい値割り込みにすると、マイコンは動いたときだけ起きるので 5.7 µA、4.4 年になる。センサは同じ 10 Hz で測っているので、気づくまでの遅れは変わらない。

データレディ割り込みには、もう 1 つ役目がある。センサが自分の時計で決まった周期ごとに測り続けるとき、マイコンが自分のタイマで同じ周期ごとに読むと、2 つの時計のずれのために、同じ値を 2 回読んだり、1 つ飛ばしたりする。センサの中の発振器の誤差は数 % あることがある（07 章 2 節）。

周期 40 ms（25 Hz）で、センサの時計が 1 % 速ければ、マイコンは 100 回に 1 回、つまり 4 s ごとに 1 つの値を読み落とす。データレディ割り込みで読めば、センサが測った値を 1 つずつ読める。

割り込みで起こす方法には、弱点もある。センサの電源が落ちて設定が消えた、配線が外れた、などのときも、割り込みは来ない。割り込みが来ないことは、何も起きていないことと区別できない。そこで、割り込みで待つセンサも、決めた間隔（例 1 時間）ごとに、設定のレジスタと状態を読んで確かめる（6 節）。

マイコンでする制御

  • 変わる速さ・応える速さ・短い出来事・電力から \(T\) の上限と下限を求め、条件を満たす中で長い \(T\) を選ぶ。普段は長く、何か起きた後は短く、と切り替えてもよい（08 章 3 節）。
  • \(T\) より短い出来事と「何か起きたら」は、周期を縮めずに、ピンやセンサのしきい値割り込みで起きる。センサが自分の時計で測り続けるときは、データレディ割り込みで読む。
  • しきい値割り込みで起きたら、値と状態のレジスタを読み（読むと割り込みの印が消えるものが多い）、次の出来事に備えて設定し直してから眠る。割り込みで待つセンサも、決めた間隔で確かめる。

2. センサの FIFO でまとめて読む

加速度で歩数を数える、振動の形を調べる、動きを記録する、といった用途では、センサが測った値を全部使う。センサが周期 40 ms（25 Hz）で測るとき、データレディ割り込みで 1 つずつ読むと、マイコンは 1 秒に 25 回起きる。起きるたびに、起床の電荷（07 章 5 節）と、読み出しの始めと終わり（I2C のアドレスやレジスタの番地を送る分）と、決まった処理の電荷がかかる。

そこで、センサの中にためておいて、まとめて読む。センサの中で、測った値を測った順にためておき、古いものから順に読み出させる記憶の場所を、センサの FIFO（First In, First Out）という。ためられる値の数（FIFO の深さ。\(M_\mathrm{max}\) と書く）は、数十〜数百のものが多い（代表値）。多くのセンサは、決めた数 \(M\) の値がたまったら割り込みで知らせる（データシートではウォーターマークと呼ぶことが多い）。

1 回にいくつ読むか

方針: マイコンが 1 回起きるのにかかる電荷を、起きるたびに決まってかかる分 \(Q_\mathrm{e}\)（起床の電荷・読み出しの始めと終わり・決まった処理。07 章 6 節の上乗せの電荷と同じ考え方）と、値 1 つを読むごとにかかる分 \(Q_\mathrm{r}\) に分ける。1 回に \(M\) 個ずつ読むときの、1 回の電荷を起きる間隔で割る。

導出: 1 回起きて \(M\) 個読むと、電荷は \(Q_\mathrm{e} + M Q_\mathrm{r}\) である。\(M\) 個がたまるのにかかる時間 \(M T\) ごとに起きるので、01 章 4 節の平均電流の式のとおり、読むために加わる平均電流は

\[ I_\mathrm{read} = \frac{Q_\mathrm{e} + M Q_\mathrm{r}}{M T} = \frac{Q_\mathrm{e}}{M T} + \frac{Q_\mathrm{r}}{T} \]

となる ∎

第 1 項は \(M\) に反比例して減るが、第 2 項は \(M\) によらない。2 つの項が等しくなる \(M^* = Q_\mathrm{e}/Q_\mathrm{r}\) より大きくしても、平均電流はほとんど減らない。値 1 つを 6 バイト（加速度の 3 つの軸を 16 ビットずつ）、\(Q_\mathrm{e}\) = 1.5 µC、マイコンが動く間の電流を 3 mA とする（例の値）。I2C の 400 kHz では 6 バイトに 54 個のクロック（135 µs）がかかり、プルアップ抵抗の分（08 章 5 節）を足して \(Q_\mathrm{r}\) = 0.59 µC、SPI の 8 MHz では 6 µs で \(Q_\mathrm{r}\) = 0.018 µC である。

I2C では、値を読む時間そのものが電荷の大部分を占め、FIFO の効きは 1/3 にとどまる（\(M\) = 27 は、下の「深さ・遅れ・時刻」で求める上限の例である）。SPI では、起きるたびの決まった電荷が大部分なので、27 個ずつ読むと 1/20 になる。どちらでも、起きる間隔が延びた分、07 章 5 節の損益分岐の眠りの長さを超えれば、より深い段階で眠れる。

深さ・遅れ・時刻

  • あふれ: マイコンは、無線の送信やフラッシュメモリの消去の間、割り込みにすぐ応えられないことがある。その時間の最大を \(t_\mathrm{d}\) とすると、その間にも \(t_\mathrm{d}/T\) 個がたまるので、\(M + t_\mathrm{d}/T \le M_\mathrm{max}\) が要る。深さ 32、\(t_\mathrm{d}\) = 0.2 s なら \(M \le 32 - 5 = 27\) である。あふれると、新しい値が捨てられるか、古い値から上書きされる（設定で選ぶ）。
  • 遅れ: たまった値のうち最も古いものは、測ってから \(M T\) たって読まれる（27 個なら 1.08 s）。すぐ応えるべき出来事は、FIFO と並べて、1 節のしきい値割り込みで知る。
  • 時刻: FIFO の値には、測った時刻が付いていないことが多い。読んだ時刻から \(T\) ずつさかのぼって時刻を付けるが、センサの時計の誤差がたまる。長い間（例 1000 個）に読んだ数と RTC の時刻から、本当の周期を求めて使う。

マイコンでする制御

  • センサを自分の時計で測り続ける設定にし、FIFO と、\(M\) 個たまったら知らせる割り込みを使う。割り込みで起きたら、たまった数を読み、番地が自動で進む読み出しで 1 回の通信にまとめて読む。
  • \(M\) は、\(M^*\)、深さと \(t_\mathrm{d}\) から決まる上限、許せる遅れ \(M T\) から決める。\(Q_\mathrm{r}\) が大きい（I2C で遅い）なら、SPI や速いクロックを先に考える。
  • 読むたびに、あふれの印を確かめる。あふれていたら回数を記録し、時刻を付け直す。

3. 自己発熱と測る間隔

測るためにセンサに電流を流すと、その電力はセンサの中で熱になる。この熱でセンサ自身が温まることを、自己発熱という。温度を測るセンサは周りより高い温度を読み、湿度のように温度で値が変わる量も、ずれて読める。

どれだけ温まるかを表すために、この節では、電力 1 mW を加え続けたときに、センサが周りより何 °C 高くなるかを \(k_\mathrm{th}\) [°C/mW] と書く。熱が逃げる道の通りにくさを表す量で、14 章 1 節で熱抵抗として扱う（センサの自己発熱は組み込み回路シリーズ 10 章 5 節も参照）。部品の大きさ、基板への取り付け方、風で大きく変わる。サーミスタのデータシートには、その逆数（1 °C 上げるのに要る電力）が熱放散定数として書かれていることが多い。以下、基板に載せた小さなサーミスタの例として \(k_\mathrm{th}\) = 1 °C/mW を使う（例の値）。この章では、サンプリング周期に \(T\) を使うので、温度は \(\theta\)、温度の上昇は \(\Delta\theta\) と書く（09 章 3 節の絶対温度 \(T\) とは別の記号である）。

流しっぱなしと、測るときだけ流す

09 章 3 節のサーミスタの分圧（固定抵抗 10 kΩ、電源 3.0 V）では、サーミスタの電力は、サーミスタの抵抗が固定抵抗と等しい 25 °C で最も大きく、\((1.5\ \text{V})^2 \div 10\ \text{k}\Omega\) = 225 µW である（0 °C で 173 µW、50 °C で 186 µW）。分圧を流しっぱなしにすると、温度は \(\Delta\theta = k_\mathrm{th} P\) = 1 × 0.225 = 0.23 °C 上がったところで落ち着き、そのまま誤差になる。

09 章 4 節のとおり、分圧に \(t_\mathrm{on}\) の間だけ電流を流して、周期 \(T\) ごとに測るときの、温度の上昇の平均を求める。

方針: 逃げる熱の速さ（1 秒あたりに逃げる熱、つまり電力）は、温度の上昇に比例するとする（\(k_\mathrm{th}\) の決め方から、上昇が \(\Delta\theta\) のとき \(\Delta\theta / k_\mathrm{th}\)）。温度の動きが周期ごとに同じ形を繰り返すようになった後は、周期の始めと終わりで温度が同じなので、1 周期に入る熱と逃げる熱が等しい。これを式にする。

導出: 1 周期に入る熱は \(P t_\mathrm{on}\) である。時刻 \(t\) の上昇を \(\Delta\theta(t)\) とすると、1 周期に逃げる熱は \(\Delta\theta(t)/k_\mathrm{th}\) を 1 周期にわたって足したもの、つまり 1 周期の上昇の平均 \(\overline{\Delta\theta}\) を使って \(\overline{\Delta\theta}\, T / k_\mathrm{th}\) である。2 つが等しいので \(P t_\mathrm{on} = \overline{\Delta\theta}\, T/k_\mathrm{th}\)、両辺に \(k_\mathrm{th}/T\) を掛けて

\[ \overline{\Delta\theta} = k_\mathrm{th} \frac{P\, t_\mathrm{on}}{T} \]

となる ∎

右辺の \(P t_\mathrm{on}/T\) は平均の電力なので、上昇の平均は、平均の電力で流しっぱなしにしたときと同じになる。この式は、温度の上がり方の速さによらない（速さで変わるのは、周期の中での上下の幅だけである）。1 ms ずつ 60 s ごとに測ると 3.75 × 10⁻⁶ °C、1 s ごとでも 2.25 × 10⁻⁴ °C で、どちらも無視できる。1 ms の間の上昇も、センサが温まるのに時間がかかるので、\(k_\mathrm{th} P\) のごく一部にとどまる。測るときだけ流すことは、電流を減らすだけでなく、自己発熱も消す。

機器自身の熱

センサ自身よりも大きいことが多いのは、同じ基板の上のマイコン・レギュレータ・LED・無線が出す熱である。USB で動き、マイコンが起きたまま（3.3 V・10 mA で 33 mW）、LED を 5 V から抵抗を通して 5 mA で点け（25 mW）、5 V から 3.3 V を LDO で作る（15 mA で 25.5 mW）機器では、合わせて 84 mW が基板の上で熱になる。基板と筐体の中から周りへの \(k_\mathrm{th}\) を 0.05 °C/mW（例の値）とすると、基板に載せた温度センサは周りより約 4.2 °C 高く読む。マイコンを測る間以外は眠らせ、LED を消して、合わせて 5 mW に減らせば（例の値）、0.25 °C になる。測る間隔を短くしてマイコンや無線を長く起こしておくことは、電力だけでなく、この誤差も増やす（機器の発熱は 14 章 6 節）。

湿度センサでは、この誤差がさらに大きく効く。相対湿度は、空気中の水蒸気の量を、その温度で含める量の上限で割ったもので、上限は 25 °C 付近で 1 °C あたり約 6 % 増える（Magnus の近似式で計算した値）。周りが 25 °C・50 % のとき、センサが 1 °C 高いと 47.1 %、4 °C 高いと 39.5 % と読む。

マイコンでする制御

  • 分圧やセンサの電流は、測るときだけ流す（09 章 4 節）。流しっぱなしにするしかないセンサは、\(k_\mathrm{th} P\) を見積もり、4 節の校正の中で差し引く。
  • 長く眠った後、無線の送信・LED・モータを動かす前に測る。それらの後に測るなら、温度が戻るまで待つ。測る間隔と、マイコン・無線の起きている時間の割合を、電力だけでなく発熱からも決める。温度・湿度のセンサは、熱を出す部品から離して置く（基板の熱は基板シリーズ 18 章）。
  • 作った機器で、普段の動き方のときと、ほかの部分をすべて止めたときの読みの差を測り、機器の熱による誤差を確かめる。

4. 校正と温度補正

09 章 3 節で見たとおり、固定抵抗とサーミスタの許容差 1 % は、それぞれ 25 °C で 0.26 °C の誤差になる。このような誤差は、同じ機器では何回測っても同じだけずれるので、平均化（09 章 6 節）でも 5 節のフィルタでも減らない。機器ごとに測って直す。

2 点校正

本当の値が分かっているもの（基準）を測り、読みとのずれから、読みを直す式の係数を決めることを、校正という。読みを \(x\)、本当の値を \(y\) とし、両者が直線の関係 \(x = g y + o\) にあるとする。\(o\) は本当の値が 0 のときの読みで、これをオフセットという。\(g\) は本当の値が 1 だけ変わったときの読みの変わり方で、これをゲインという。誤差の無いセンサでは \(g = 1\)、\(o = 0\) である。読みから本当の値を求める式は、\(x = g y + o\) を \(y\) について解いて \(y = (x - o)/g\)、つまり \(y = a x + b\)（\(a = 1/g\)、\(b = -o/g\)）の形になる。

方針: 本当の値 \(y_1\)・\(y_2\) が分かっている 2 つの点で読み \(x_1\)・\(x_2\) を測り、直線 \(y = a x + b\) が 2 つの点を通るように \(a\) と \(b\) を決める。2 つの点で決めるこの方法を 2 点校正という。

導出: 2 つの点を通るので、\(y_1 = a x_1 + b\) と \(y_2 = a x_2 + b\) が成り立つ。2 つ目の式から 1 つ目の式を引くと、\(b\) が消えて \(y_2 - y_1 = a (x_2 - x_1)\) となる。\(x_1 \ne x_2\) なので両辺を \(x_2 - x_1\) で割って \(a\) が求まり、それを 1 つ目の式に入れて \(b\) について解くと

\[ a = \frac{y_2 - y_1}{x_2 - x_1}, \qquad b = y_1 - a x_1 \]

となる ∎

例として、09 章 3 節のサーミスタで、固定抵抗が +1 %、\(R_{25}\) が −1 %、B 定数が +1 % ずれた部品に当たったとする（どれも許容差の中）。マイコンが表どおりの値で計算した温度は、0 °C で 0.21 °C、25 °C で 25.52 °C、40 °C で 40.73 °C、80 °C で 81.38 °C と、高い温度ほど大きくずれる。0 °C（氷水）と 40 °C（基準の温度計で測った湯）の 2 点で校正すると、\(a\) = 0.9871、\(b\) = −0.203 °C となる。

校正の後の誤差は、0〜40 °C の間で 0.016 °C 以下になる。2 点の外では直線を延ばして使うことになり、80 °C で 0.13 °C、−20 °C で 0.05 °C と誤差が増える。25 °C の 1 点だけでオフセットを合わせると（\(a = 1\) のまま）、0〜40 °C で 0.31 °C、80 °C で 0.87 °C が残る。したがって、2 つの点は使う範囲の両端に置く。基準そのものの誤差（例: 基準の温度計の ±0.1 °C）は、校正では減らせず、そのまま残る。

デジタル出力のセンサの多くは、工場で校正され、直す計算をセンサの中で行う（08 章 1 節）。直す式の係数をセンサのレジスタに残し、マイコンに計算させるセンサもある（09 章 2 節の、工場で測った内部の基準電圧の値も同じ考え方である）。その場合、マイコンは電源を入れた後に係数を 1 回読み、データシートの式で直す。

温度補正

センサの読みは、測りたい量のほかに、センサ自身の温度でも変わることがある。温度を測って、温度によるずれを直すことを、温度補正という。例として、ひずみゲージ（引っ張られると抵抗が変わる素子）で重さを測るはかりのオフセットが、25 °C で合わせた後、温度で \(o(\theta)\) だけ動くとする（例の値で、5 °C で −36.0 g、40 °C で +32.3 g、その間は少し曲がる）。2 点校正と同じ考え方で、何も載せない状態で 5 °C と 40 °C のオフセットを測り、温度係数 \(c = \{o(40) - o(5)\}/(40 - 5)\) = 1.95 g/°C を求めて、読みから \(o(5) + c(\theta - 5)\) を引く。

5〜40 °C の間で最大 36 g あったずれは 3.1 g 以下になり、−10 °C では 7.5 g が残る。ゲインも温度で変わるなら、同じ方法で直す。直すのに使う温度は、そのときのセンサ自身の温度でなければならない。温度センサとひずみゲージが離れている、日が当たって温度が速く変わっている、3 節の自己発熱がある、といった場合は、温度の差がそのまま誤差になる。

校正の値を保存する

校正の値は、機器ごとに製造の検査で測って決め、その機器のフラッシュメモリ（02 章 1 節）に書く。05 章 5 節のとおり、書きかけで止まっても前の値が残るように、2 か所に交互に書き、書いた順の番号と、誤りを調べる値（CRC など。組み込み通信シリーズ 03 章 5 節）を付ける。起動したら両方を調べ、正しいもののうち新しいほうを使う。どちらも正しくなければ、表どおりの値（\(a = 1\)、\(b = 0\)）で動き、「校正されていない」ことを記録して知らせる。壊れた係数で、正しそうな値を出し続けないためである。整数で計算するマイコンでは、\(a\) を \(2^{16}\) 倍した整数で持つ（stdint.h を使う）。

typedef struct {
    int32_t a_q16;   /* 傾き a を 2^16 倍した整数（a = 1 なら 65536） */
    int32_t b;       /* 切片 b [0.01 °C] */
} cal_t;

/* 読み x [0.01 °C] を a x + b に直す（丸めて返す） */
int32_t cal_apply(const cal_t *c, int32_t x)
{
    int64_t p = (int64_t)c->a_q16 * x;             /* a x の 2^16 倍 */
    p = (p >= 0) ? (p + 32768) / 65536 : (p - 32768) / 65536;   /* 丸めて 2^16 で割る */
    return (int32_t)(p + c->b);
}

掛け算を 64 ビットで行うので、\(a x\) が 32 ビットに収まる範囲なら桁あふれしない。丸めは、負の数でも 0 から遠い向きにそろえた。テストでは、ホストのコンピュータで、\(a\) = 0.5〜2、\(x\) = ±2²⁴ の乱数 20 万組について、浮動小数点で計算した値との差が 0.5 以下であること、上の例の 2 点から求めた係数で 0.21 °C が 0.00 °C、40.73 °C が 40.00 °C に直ることを確かめた（アドレスと未定義動作の検査付き）。

マイコンでする制御

  • 製造の検査で、使う範囲の両端の 2 点を測って \(a\)・\(b\) を求め、番号と CRC を付けて 2 か所に書く。温度補正が要るなら、2 つの温度でも測る。
  • 起動したら校正の値を調べ、だめなら表どおりの値で動いて、校正されていないことを知らせる。
  • 測った値は、校正で直してから、5 節のフィルタと 6 節の比較に渡す。温度補正には、同じ時刻に測ったセンサの近くの温度を使う。

5. フィルタ — 移動平均・中央値・一次の IIR

校正で直した値の列にも、測るたびに無関係に変わるノイズが残る。ほかに、無線の送信やモータの起動の瞬間に乗ったノイズや、通信の誤りで、1 回だけ大きく外れた値が混じる。これを、この章ではとび値という。一方で、温度が上がり始めた、はかりに物が載った、といった本当の変化もある。09 章 6 節の平均化は、1 回の測定の中で続けて何回も測るものだった。この節では、周期 \(T\) ごとに 1 つずつ得られる値の列をならすフィルタを扱う。測る回数は増えないが、その代わり、本当の変化に遅れて追いつくようになる。

この節では、\(n\) 回目の値（フィルタの入力）を \(x[n]\)、フィルタの出力を \(y[n]\) と書く（4 節の \(x\)・\(y\) とは別の量である）。比べる 3 つのフィルタを定義する。

  • 移動平均: 直近の \(N\) 個の値の平均 \(y[n] = (x[n] + x[n-1] + \cdots + x[n-N+1])/N\)。
  • 中央値フィルタ: 直近の \(N\) 個（奇数）を大きさの順に並べたときの真ん中の値（中央値。統計シリーズ 02 章 2 節）を出力にする。
  • 一次 IIR フィルタ（指数移動平均とも呼ぶ。名前の理由は下で見る）: 1 つ前の出力から、新しい値に向かって、差の割合 \(\alpha\)（\(0 < \alpha \le 1\)）だけ近づける。
\[ y[n] = y[n-1] + \alpha\,(x[n] - y[n-1]) \]

IIR は、1 つの入力の影響が出力に限りなく長く残ることを表す言葉である（ディジタル信号処理シリーズ 07 章 1 節）。ディジタル信号処理シリーズ 07 章 2 節の \(y[n] = a y[n-1] + (1 - a) x[n]\) は、同じ式を \(a = 1 - \alpha\) で書いたものである（周波数での性質はそちらで扱う）。

ノイズ・とび値・段差への応え方

3 つのフィルタに、ノイズ、1 回だけのとび値、段差（値がある時刻から一定量だけ変わる変化）を入れた結果を並べる。

ノイズの減り方を求める。移動平均は、\(N\) 個の無関係なノイズの平均なので、09 章 6 節と同じく標準偏差が \(\sigma/\sqrt{N}\) になる。一次 IIR フィルタは次のとおりである。

方針: 出力を、過去の入力に重みを掛けた和の形に書き直し、09 章 6 節と同じく、無関係なノイズの和の 2 乗の平均が、各項の重みの 2 乗 × \(\sigma^2\) の和になることを使う。

導出: フィルタが十分長く動いた後を考える。式を \(y[n] = \alpha x[n] + (1 - \alpha)\, y[n-1]\) と並べ替え、\(y[n-1]\) に同じ式を入れることを繰り返すと、\(y[n] = \alpha x[n] + \alpha(1-\alpha)\, x[n-1] + \alpha(1-\alpha)^2 x[n-2] + \cdots\) となる。\(j\) 個前の値の重みは \(\alpha(1-\alpha)^j\) で、古いものほど \(1 - \alpha\) 倍ずつ（指数的に）小さくなる。指数移動平均と呼ぶのはこのためである。出力のノイズは、各回のノイズ \(e[n-j]\) に重みを掛けた和である。これを 2 乗すると、\(e[n-j]\,e[n-k]\) の積に重みの積を掛けた項が並ぶ。09 章 6 節と同じく、\(j \ne k\) の積は平均が 0 になり、\(j = k\) の項だけが \(\sigma^2\) × 重みの 2 乗として残るので、

\[ \sigma_y^2 = \alpha^2 \sigma^2 \sum_{j=0}^{\infty} (1-\alpha)^{2j} = \frac{\alpha^2 \sigma^2}{1 - (1-\alpha)^2} = \frac{\alpha}{2 - \alpha}\, \sigma^2 \]

となる（2 つ目の等号は、公比 \((1-\alpha)^2 < 1\) の等比級数の和、3 つ目は分母を \(1 - (1 - 2\alpha + \alpha^2) = \alpha(2 - \alpha)\) と計算した）。したがって \(\sigma_y = \sigma \sqrt{\alpha/(2 - \alpha)}\) である ∎

段差への応え方も求める。入力が時刻 0 から一定の値 \(x\) になったとき、出力との差 \(e[n] = x - y[n]\) は、式の両辺を \(x\) から引いて \(e[n] = (1 - \alpha)\, e[n-1]\) となるので、1 回ごとに \(1 - \alpha\) 倍に縮む。差が 1 割になるのは \((1-\alpha)^m = 0.1\) の \(m = \ln 0.1/\ln(1-\alpha)\) 回後で、\(\alpha\) = 1/8 なら 17.2 回（18 回目）である。移動平均は、新しい値が \(N\) 個たまった所でちょうど追いつく直線になり、9 割に届くのは新しい値が \(0.9 N\) 個以上たまった回である。

フィルタノイズ（標準偏差）とび値（大きさ 1）段差の 9 割まで
移動平均（\(N\) = 8）\(\sigma/\sqrt{8}\) = 0.35 σ1/8 が 8 回続く8 回
移動平均（\(N\) = 15）0.26 σ1/15 が 15 回続く14 回
一次 IIR（\(\alpha\) = 1/8）\(\sqrt{1/15}\) = 0.26 σ1/8 から 7/8 倍ずつ減る18 回
中央値（3 個）0.67 σ（乱数で求めた値）消える（2 回続くと残る）2 回
中央値 3 個 → 一次 IIR（1/8）0.27 σ（同）消える19 回

表から 3 つのことが分かる。1 つ目に、移動平均と一次 IIR は、ノイズを減らすほど段差に遅れる。同じ 0.26 σ まで減らすと、9 割まで移動平均で 14 回、一次 IIR で 18 回かかる。一次 IIR は 1 つの値しか覚えなくてよいが、追いつく最後の部分が長く尾を引く（99 % まで 35 回）。2 つ目に、どちらもとび値を消せず、薄く広げるだけである。3 つ目に、中央値フィルタは、ノイズはあまり減らさないが、1 回だけのとび値を消し、段差には 1 回遅れるだけで追いつく。したがって、とび値の混じる値の列は、まず 3 個の中央値でとび値を除き、その後に一次 IIR か移動平均でノイズをならす。遅れの許せる時間から、\(\alpha\) や \(N\) を決める。\(T\) = 1 s で 9 割まで 20 s 以内なら \(\alpha\) = 1/8 である。

整数で作る

一次 IIR を整数で作るとき、\(\alpha = 1/2^k\) にすると、掛け算が \(2^k\) での割り算（シフト）で済む。ところが、出力を値の単位の整数のまま持って y += (x - y) / 8 と書くと、\(x - y\) が 8 より小さくなった所で増えなくなり、出力は入力の手前 7 で止まる。\(2^k - 1\) までの不感帯ができる（ディジタル信号処理シリーズ 09 章 4 節）。0.01 °C の単位なら、0.07 °C 手前で止まる。

そこで、状態を出力の \(2^k\) 倍で持ち、下の \(k\) ビットを小数部として残す。式の両辺を \(2^k\) 倍すると、状態 \(A = 2^k y\) の更新は \(A \leftarrow A + x - y\) になる。出力 \(y\) には \(A/2^k\) を丸めた値を使い、同じ値を更新にも使う。入力が一定なら、更新が止まるのは出力が入力と等しいときだけなので、出力は入力にちょうど追いつく。また、状態は入力と出力の差を足し続けたもので、限られた範囲にとどまるので、差の合計を回数で割った値は 0 に近づく。つまり、長い間の出力の平均は入力の平均に一致し、丸めの偏りが残らない。3 個の中央値と合わせたコードを示す（stdbool.h・stdint.h を使う）。

typedef struct {
    int32_t acc;          /* 出力の 2^k 倍（下の k ビットが小数部） */
    uint8_t k;            /* α = 1/2^k（k は 1〜10） */
    bool started;
} ema_t;

/* acc / 2^k を最も近い整数に丸める（ちょうど半分は 0 から遠い向き）。
   負の数の右シフトは C では処理系定義なので、割り算を使う */
static int32_t ema_out(const ema_t *f)
{
    int32_t d = (int32_t)1 << f->k, h = d / 2;
    return (f->acc >= 0) ? (f->acc + h) / d : (f->acc - h) / d;
}

/* x: 新しい値（|x| < 2^20。例 0.01 °C 単位）。戻り値: 出力 */
int32_t ema_update(ema_t *f, int32_t x)
{
    if (!f->started) {                  /* 最初の値から始める */
        f->acc = x * ((int32_t)1 << f->k);
        f->started = true;
    } else {
        f->acc += x - ema_out(f);       /* y += (x − y)/2^k の両辺を 2^k 倍した式 */
    }
    return ema_out(f);
}

static int32_t med3(int32_t a, int32_t b, int32_t c)
{
    if (a > b) { int32_t t = a; a = b; b = t; }   /* a ≤ b にする */
    if (b > c) b = c;                              /* b = min(b, c) */
    return (a > b) ? a : b;                        /* max(a, min(b, c)) */
}

typedef struct { int32_t v[3]; uint8_t n, i; } med3_t;   /* 直近の 3 つ */

int32_t med3_update(med3_t *m, int32_t x)
{
    m->v[m->i] = x;
    m->i = (uint8_t)((m->i + 1u) % 3u);
    if (m->n < 3u && ++m->n < 3u)
        return x;                       /* 3 つたまるまでは、そのまま通す */
    return med3(m->v[0], m->v[1], m->v[2]);
}

測るたびに ema_update(&f, med3_update(&m, x)) と呼ぶ。最初の値で状態を始めるのは、0 から立ち上がるのを待たないためである。\(|x| < 2^{20}\)、\(k \le 10\) なら、状態は \(2^{30}\) 程度までで、32 ビットに収まる。テストでは、ホストのコンピュータで、\(k\) = 1〜10 のそれぞれで、一定の入力に上からも下からも近づけて出力がちょうどその値になること、±(2²⁰ − 1) を交互に入れても桁があふれないこと、ノイズのある入力 40 万個の出力の平均と入力の平均の差が 0.001 LSB 未満であること、段差の応答が浮動小数点の計算と 1 以内で一致すること、中央値が 3 つの値のすべての並び（27 通り）で正しいことを確かめた（アドレスと未定義動作の検査付き）。小数部を持たない書き方では、0 から 1000 への段差で、\(k\) = 3 なら 993、\(k\) = 6 なら 937 で止まった。

フィルタの遅れは、そのまま判断の遅れになる。しきい値で警報を出す・ヒータを切るといった判断に使う値は、遅れの短いもの（中央値だけを通した値など）にするか、遅れを見込んでしきい値を決める（14 章）。また、フィルタは故障の兆しも隠すので、故障の検査はフィルタの前の値で行う（6 節）。

マイコンでする制御

  • とび値は 3 個の中央値で除き、ノイズは一次 IIR（\(\alpha = 1/2^k\)）か移動平均でならす。\(k\) や \(N\) は、許せる遅れから決める。
  • 一次 IIR は、状態に \(k\) ビットの小数部を持たせ、丸めた出力を更新にも使う。桁あふれの範囲を確かめる。
  • 判断に使う値の遅れを見積もる。急いで応える判断には、遅れの短い値を使う。

下の図で、ノイズの大きさ、とび値の割合と大きさ、段差の大きさを入れた値の列を作り、移動平均の数、中央値の数、一次 IIR の \(k\) を変えると、それぞれの出力と、残ったノイズ・とび値の影響・段差に追いつくまでの回数が表示される。「もう一度（別の乱数で）」で乱数を替えられる。

6. センサの故障を見つける

ここまでの校正とフィルタは、センサが正しく動いていることを前提にしていた。実際には、線が切れる、コネクタがゆるむ、水が入って短絡する、センサが測るのをやめる、といった故障が起きる。故障したセンサの値は、正しそうに見えることがあり、フィルタを通すとさらに見分けにくくなる。そこで、測った値を使う前に、その値がありうるものかを、範囲・変わり方・ほかのセンサとの関係で調べる。これを妥当性の検査という。

故障の種類と、見つける規則

  • 断線と短絡: 09 章 3 節の比率測定のサーミスタでは、サーミスタの線が切れると ADC の値は最大の 4095 近くに、つなぎ目が GND に触れると 0 近くになる。使う温度の範囲（−40〜125 °C）は ADC の値の 215〜3937 にあたるので、その外の値は故障を疑う（09 章 3 節のコードが範囲の外を温度にしないのは、このためである）。故障が範囲の外に出るように、固定抵抗と測る範囲を決めておく。
  • 通信の失敗: デジタル出力のセンサが答えない（ACK が無い・時間の上限を超える）、誤りを調べる値が合わない、製品の ID が違う（08 章 2・6 節）。
  • 張り付き: 値が動かなくなる。センサが電源の落ち込みで初めの状態に戻って測るのをやめた、データを出す回路が止まった、などで起きる。ノイズがあれば値は少しずつ動くので、同じ値が長く続いたら疑う。ただし、ノイズが小さいと正常でも同じ値が続く。ノイズの標準偏差が 1 LSB なら、最も出やすい値の出る確率は 0.4 程度で、30 回続けて同じ値になる確率は \(0.4^{30} \approx 10^{-12}\) である。0.2 LSB では、ほとんどいつも同じ値が出て、1 s ごとに測ると、本当の値によっては数分に 1 回、30 回続く（乱数で試した値）。ノイズが 1/2 LSB より小さいセンサでは、値ではなく、データレディ割り込みや、測った回数を数えるレジスタが進むことで確かめるか、センサの自己診断の機能（マイコンの指示で、中の素子に決まった刺激を加えて出力が変わるかを見るもの）を使う。
  • 急変: 1 回の間に、ありえないほど大きく変わる。部屋の温度が 1 s で 1 °C 変わることは無いので、続けて測った値の差が、25 °C 付近で 1 °C にあたる 40 を超えたら外れとする。1 回だけならとび値で、5 節の中央値が除く。続けて起きるなら、コネクタの接触不良を疑う。
  • ほかのセンサとの比較: 同じ量を測る 2 つのセンサの差が、許せる幅を長く超える。上の規則は、範囲の中でゆっくりずれていく故障や、正しそうな値で止まった故障を見つけられない。それらは比較で見つける。2 つでは、どちらが正しいかは分からない。3 つあれば中央値を使える。ヒータを入れ続けているのに温度が上がらない、のような物理の関係との比較もある（14 章）。

続けて外れたら確定する

1 回の外れで故障と決めると、1 回だけのノイズで故障になる。04 章 3 節の低電池の判定と同じく、続けて \(K\) 回外れたときに故障と確定する（04 章 3 節では \(N\) と書いた回数である）。外れが無関係に確率 \(r\) で起きるなら、続けて \(K\) 回外れる確率は \(r^K\) に下がる。その代わり、故障してから確定するまで \(K T\) かかる。確定する前でも、範囲の外の値と通信に失敗した値は使わない。

検査は、フィルタの前の値で行う。サーミスタの線が切れると、ADC の値はすぐに 4095 になる。ADC の値を一次 IIR（\(\alpha\) = 1/8）に通していると、出力は 18 回ほどかけてゆっくり 4095 に近づき、温度がだんだん下がっていくように見える。フィルタの後の値で調べると、本当の温度の変化と区別できない。

故障と確定したら、そのセンサの値を使わない。最後の正しい値を使い続けるのは、決めた短い時間だけにする。その値で動かしているアクチュエータは、安全な状態（01 章 5 節）へ移す。温度センサが壊れたら、ヒータを切る（01 章 3 節の例）。そのうえで、バスの復旧（08 章 6 節）やセンサの電源の入れ直し（08 章 3 節）で戻るかを試し、戻ったら設定を書き直して、検査が続けて通るまで値を使わない。故障の種類・時刻・回数を記録して知らせる。一部のセンサを使わずに動き続ける方法（縮退運転）は、15 章 5 節で扱う。

マイコンでする制御

次のコードは、09 章 3 節のサーミスタの ADC の値を、フィルタに渡す前に調べる。範囲・通信・急変は \(K\) = 3 回続いたら、張り付きは 30 回続いたら、故障と確定する（stdbool.h・stdint.h を使う。値はどれも例の値）。

typedef enum { SF_OK, SF_COMM, SF_RANGE, SF_JUMP, SF_STUCK } sf_t;

#define RAW_LO     215u   /* これより小さい: 短絡を疑う（125 °C より高い） */
#define RAW_HI    3937u   /* これより大きい: 断線を疑う（−40 °C より低い） */
#define JUMP_MAX    40u   /* 1 回の間にありえない変化（25 °C 付近で約 1 °C） */
#define STUCK_N     30u   /* 前と同じ値がこの回数続いたら張り付き */
#define K_CONFIRM    3u   /* 続けてこの回数外れたら故障と確定する */

typedef struct {
    uint16_t prev;        /* 前に読めた範囲の中の値 */
    bool     have_prev;
    uint8_t  same, bad;   /* 前と同じ値が続いた回数、続けて外れた回数 */
    sf_t     fault;       /* 確定した故障（SF_OK なら故障なし） */
} sens_chk_t;

static uint8_t inc(uint8_t n) { return (n < 255u) ? (uint8_t)(n + 1u) : n; }
static unsigned dif(uint16_t a, uint16_t b) { return (a > b) ? (unsigned)(a - b) : (unsigned)(b - a); }

/* ok: 通信が成功したか、raw: ADC の値。戻り値: この値をフィルタに渡してよいか */
bool sens_check(sens_chk_t *c, bool ok, uint16_t raw)
{
    sf_t why = SF_OK;
    if (!ok) {
        why = SF_COMM;
    } else if (raw < RAW_LO || raw > RAW_HI) {
        why = SF_RANGE;
    } else {                                   /* 範囲の中の値だけで、変化を調べる */
        if (c->have_prev && dif(raw, c->prev) > JUMP_MAX)
            why = SF_JUMP;
        c->same = (c->have_prev && raw == c->prev) ? inc(c->same) : 0u;
        if (c->same >= STUCK_N)
            why = SF_STUCK;
        c->prev = raw;
        c->have_prev = true;
    }
    c->bad = (why == SF_OK) ? 0u : inc(c->bad);
    if (c->fault == SF_OK && (c->bad >= K_CONFIRM || why == SF_STUCK))
        c->fault = why;                        /* 確定したら、直すまで戻さない */
    /* 急変した値は渡す（1 回だけなら 5 節の中央値が除く） */
    return c->fault == SF_OK && (why == SF_OK || why == SF_JUMP);
}

前の値は、範囲の中の値だけで更新する。範囲の外の値で更新すると、次の正しい値が急変として数えられるからである。1 回だけのとび値は、とび値とその次の値の 2 回の急変になるが、\(K\) = 3 なので確定しない。確定した故障は、センサを戻して検査をやり直すまで（構造体を 0 にするまで）消さない。テストでは、ホストのコンピュータで、ノイズ 1 LSB の正しい値 100 万個で故障にならないこと、断線・短絡・無応答・接触不良（1 回おきの急変）は外れ始めて 3 回目に、張り付きは前と同じ値が 30 回続いた所（止まってから 31 個目の値）で確定すること、1 回だけの範囲の外の値やとび値では確定しないこと、範囲の外の値をフィルタに渡さないことを確かめた（アドレスと未定義動作の検査付き）。ほかのセンサとの比較は、2 つのセンサの値がどちらもこの検査を通った後に、校正した単位で行う。

下の図で、故障の種類（断線・短絡・張り付き・接触不良・ゆっくりしたずれ）と、ノイズの大きさ、急変のしきい値、張り付きの回数、続けて外れる回数、ほかのセンサとの比較の有無を変えると、ADC の値の列と、故障に気づくまでの時間、正しい間の誤った警報が表示される。
