# 16. マイコンで実装する — 周期・量子化・固定小数点

> **この章で扱う問い.**
> 10・11 章では、PID の 1 回分の計算を C の関数 `pid_step()` にした。15 章では、それをサンプリング周期 $`T_\mathrm{s}`$ ごとに計算すると、ループにどれだけの遅れが加わり、差分の近似で何が変わるかを調べた。この章では、その関数を実際のマイコンに載せるときに起きることを扱う。
>
> この章では次の 3 つの問いに答える。
>
> 1. 決めた周期で確実に計算するには、どうするのか。計算を始める時刻の揺らぎと、測ってから出すまでの時間は、応答をどれだけ変えるのか。
> 2. 操作量そのものを計算する形と、操作量の増分を計算する形は、飽和や切り替えのときにどう違うのか。ADC と PWM の段の細かさは、制御量をどう揺らすのか。
> 3. 浮動小数点の演算の回路を持たないマイコンで、整数だけで PID を計算するには、数の桁をどう決めるのか。起動・停止・異常のときと、試験と調整のときに、制御のプログラムは何をするのか。
>
> 答えの道具は、測る・計算する・出すの時刻を並べたタイミング図、2 つの計算の形の差の式、出力の段ごとに行き着く温度と ADC の段を同じ目盛に並べた図、固定小数点の数の並びと積の桁合わせ、そしてループを閉じたまま正弦波を足して一巡伝達関数を測る方法である。

## 1. 制御周期を守る — タイマ割り込みと揺らぎ

10 章 6 節の `control_tick()` は、モータの角度を測り、PID で電圧を計算して出す関数で、1 ms ごとに呼ぶことを前提にしていた。測る・計算する・出すの 1 回を決めた間隔で繰り返すとき、その間隔を**制御周期**という。1 つのループでは測る間隔と出す間隔が同じなので、制御周期は 15 章 1 節のサンプリング周期 $`T_\mathrm{s}`$ と同じ値である（14 章 4 節のカスケード制御のように、ループごとに制御周期が違うこともある）。この節では、10 章 6 節の例（モータの角度の PID。$`K_\mathrm{P}`$ = 0.84 V/rad、$`T_\mathrm{I}`$ = 0.168 s、$`T_\mathrm{D}`$ = 0.0238 s、$`N`$ = 10、目標値の重み $`b`$ = 0.5、$`T_\mathrm{s}`$ = 1 ms）を使う。連続時間で見たこのループのゲイン交差角周波数は 27.8 rad/s、位相余裕は 58.8° である。

### 周期の作り方 — 待つのではなく、時計で起こす

決めた間隔で計算を繰り返す方法を 4 つ並べる。

```fig
e16_ways
```

- (a) 計算の後で決まった時間だけ待つ（`for (;;) { control_tick(r); delay_ms(1); }`）: 1 回の繰り返しは、待つ 1 ms に計算の時間を足した長さになり、計算の時間が回ごとに違えば、周期も回ごとに違う。計算に 0.3 ms かかると周期は 1.3 ms になり、コードの中の $`T_\mathrm{s}`$（`dt` = 1 ms）と合わない。I の分は 1 回ごとに 1 ms 分の面積しか足さないので、1 s あたりの増え方が 1/1.3 になり、積分時間を 1.3 倍にしたのと同じになる。D の分は 1.3 ms の間の変化を 1 ms で割るので、微分時間を 1.3 倍にしたのと同じになる。$`b`$ = 1 で目標を 1 rad 変えると、行き過ぎ量は 29.4 % から 21.1 % に、2 % 整定時間は 0.396 s から 0.543 s に変わる。設計したものとは別の制御器になる。
- (b) タイマ割り込み: タイマが 1 ms ごとに割り込みを起こし、その処理の中で計算する。周期はタイマの時計で決まり、計算の時間によらない。処理の始まりは、ほかの割り込みを処理している間や、割り込みを禁じている間だけ遅れる（[OS シリーズ 18 章 6 節](../freertos/18_割り込みとの境界.md#割り込みレイテンシ)）。
- (c) RTOS の優先度の高いタスク: 前回起きる予定だった時刻から数えて 1 ms 後まで待つ関数（FreeRTOS の `vTaskDelayUntil()`）でタスクを起こす。待つ時刻を前回の予定から数えるので、ずれはたまらない（[OS シリーズ 8 章 4 節](../freertos/08_ティックとタイムスライス.md#vtaskdelayuntil-は誤差が累積しない)）。起きる時刻は、ほかのタスクや割り込みの分だけ、(b) より大きく揺れる。
- (d) 測る時刻と出す時刻をタイマに決めさせる: タイマの合図で ADC が変換を始めるようにし（その機能を持つマイコンが多い）、PWM には書き込んだ値を周期の区切りで反映させる（15 章 1 節）。計算を周期の中のいつ行っても、次の区切りまでに終われば、測る時刻と出す時刻はタイマの時計どおりになる。

実際に測る時刻や出す時刻が、決めた時刻 $`kT_\mathrm{s}`$ からずれることを**揺らぎ**（**ジッタ**）という。(a) は周期そのものがずれていく。(b)・(c) は周期は平均で正しいが、始まる時刻が回ごとに揺らぐ。(d) は、測る時刻と出す時刻の揺らぎを、タイマの時計の精度まで小さくする。

### 計算遅れ — 次の周期の頭で出す

15 章 1 節の、測ってから出すまでの時間 $`L_\mathrm{c}`$ を**計算遅れ**という。15 章 2 節のとおり、計算遅れと零次ホールドは、位相余裕を約 $`(180°/\pi)\,\omega_\mathrm{gc}(L_\mathrm{c} + T_\mathrm{s}/2)`$ 減らす。出す時刻の決め方 (A)（計算が終わりしだい出す）と (B)（次の周期の頭で出す）を、時刻を並べて比べる。

```fig
e16_order
```

| | (A) 計算が終わりしだい出す | (B) 次の周期の頭で出す |
|---|---|---|
| 計算遅れ $`L_\mathrm{c}`$ | 計算の時間（例 0.2〜0.4 ms）。回ごとに大きく違う | 平均でちょうど $`T_\mathrm{s}`$。始まりの揺らぎの差の分だけ揺れる |
| 出す時刻 | 始まりの揺らぎと計算の時間の揺れが重なる | 次の割り込みの始め（(d) ならタイマの区切り） |
| 位相余裕（$`T_\mathrm{s}`$ = 1 ms） | 57.6°（$`L_\mathrm{c}`$ = 0.2 ms） | 56.3° |
| 位相余裕（$`T_\mathrm{s}`$ = 10 ms） | 48.3°（$`L_\mathrm{c}`$ = 0.3 ms） | 32.4° |

位相余裕は、15 章 5 節の方法（対象を零次ホールドで離散化し、$`z = e^{j\omega T_\mathrm{s}}`$ で一巡伝達関数を求める）で求めた厳密な値である。1 ms で計算するなら、(B) にしても位相余裕は (A) より 1.3° 減るだけである。(B) では、計算遅れが平均でちょうど 1 周期なので、対象のモデルに $`z^{-1}`$ を 1 つ掛けるだけで、遅れを含めたループを表せる（15 章 5 節）。計算の時間が分岐やほかの割り込みで変わっても、1 周期の中に収まる限り、出す時刻は変わらない。(d) のように測る時刻と出す時刻をタイマに決めさせれば、計算遅れはちょうど 1 周期になる。そこで、余裕に困らないループは (B) にする。15 章 6 節の電流のループ（$`\omega_\mathrm{gc}`$ = 5000 rad/s、$`T_\mathrm{s}`$ = 50 µs）のように $`\omega_\mathrm{gc}T_\mathrm{s}`$ が大きいループでは、(B) の 21.5° の減りが大きすぎるので、(A) にして、計算を短く、回ごとに同じ長さにする（その割り込みの優先度を最も高くし、割り込みを禁じる処理を短くする。[OS シリーズ 18 章 3 節](../freertos/18_割り込みとの境界.md#割り込み優先度-最も事故が多い設定)）。

次のコードは、(B) の出し方で、11 章 4 節の `pid_step()`（アンチワインドアップ付き）を 1 ms ごとのタイマ割り込みから呼ぶ（`stdint.h` を使う）。始めに 10 章 6 節の `pid_start(&pid, read_angle())` を呼んでから、割り込みを許す。

```c
float read_angle(void);                  /* 10 章 6 節と同じ、仮に置く関数（角度 [rad]） */
void set_voltage(float v);               /* 同じく（電圧 [V]） */
uint32_t timer_count(void);              /* 1 µs ごとに 1 増えるタイマの値（この章で仮に置く関数） */

#define TS_US 1000u                      /* 制御周期 [µs] */
static pid_ctl_t pid = { .kp = 0.84f, .ti = 0.168f, .td = 0.0238f, .n = 10.0f, .b = 0.5f,
                         .dt = 0.001f, .umin = -12.0f, .umax = 12.0f };
volatile float target;                   /* 目標値 [rad]（ほかの処理が書き換える） */
static float u_next;                     /* 次の周期の頭で出す電圧 */
volatile uint32_t t_max, overrun;        /* かかった時間の最大 [µs]、間に合わなかった回数 */

void timer_isr(void)                     /* タイマが 1 ms ごとに起こす割り込みの処理 */
{
    uint32_t t0 = timer_count();
    set_voltage(u_next);                 /* 1. 前の周期に計算した電圧を出す */
    float y = read_angle();              /* 2. 測る */
    u_next = pid_step(&pid, target, y);  /* 3. 計算する（出すのは次の周期の頭） */
    uint32_t took = timer_count() - t0;  /* 符号なしの引き算は、タイマが一周しても正しい */
    if (took > t_max) t_max = took;
    if (took >= TS_US) overrun++;        /* 次の割り込みに間に合わなかった */
}
```

このコードは、書き込んだ値がすぐに反映される PWM を前提にしている。PWM が書き込んだ値を周期の区切りで反映させる設定なら、`set_voltage()` は計算の直後に呼ぶ（割り込みの始めに呼ぶと、反映は 2 周期後になる）。`t_max` と `overrun` は 6 節のログに残し、`overrun` が増え続けるなら異常として扱う（5 節）。周期の中に、通信などほかの仕事と合わせて間に合うかは、最も長くかかる場合の時間で確かめる（[OS シリーズ 20 章 8 節](../freertos/20_リアルタイム性の解析.md#wcet-最悪実行時間-をどう求めるか)）。テストでは、ホストのコンピュータで本文のコードをコンパイルし（`gcc -std=c99`、アドレスと未定義動作の検査付き）、仮に置く関数をモータの角度の模型（電圧を 1 ms の間保って厳密に進める）とタイマの値の模型につないだ。目標を 1 rad 変えて 1 s に負荷トルク 0.01 N·m を加えると、ずれの最大は 1.062 rad で、Python で同じ条件を計算した値と一致した。タイマの値が途中で一周しても `t_max` が正しいこと、計算が 1 周期を越えると `overrun` が増えることも確かめた。

### 揺らぎの影響

揺らぎは、測った値と、D の分の計算に誤差を入れる。

**方針**: 測る時刻が、決めた時刻 $`kT_\mathrm{s}`$ から $`\delta_k`$ だけずれたとする。$`\delta_k`$ は小さいとして、制御量 $`y`$ を $`kT_\mathrm{s}`$ のまわりで 1 次までのテイラー展開で近づける（2 章 5 節の線形化と同じ考え方）。D の分は、続く 2 回の値の差を $`T_\mathrm{s}`$ で割るので、その 2 回の本当の間隔と比べる。

**導出**: $`y(kT_\mathrm{s} + \delta_k) \approx y(kT_\mathrm{s}) + \dot y(kT_\mathrm{s})\,\delta_k`$ なので、測った値の誤差は $`\dot y\,\delta_k`$ で、制御量の変わる速さに比例する。また、続く 2 回の本当の間隔は $`T_\mathrm{s} + \delta_k - \delta_{k-1}`$ なので、差 $`y[k] - y[k-1]`$ を $`T_\mathrm{s}`$ で割った値は、その間の本当の変わる速さの $`1 + (\delta_k - \delta_{k-1})/T_\mathrm{s}`$ 倍である ∎

目標を 1 rad 変えたときのモータの角速度は最大 9.3 rad/s なので、0.1 ms の揺らぎによる誤差は最大 0.93 mrad で、角度の 0.1 % に満たない。D の分の倍率のずれ $`(\delta_k - \delta_{k-1})/T_\mathrm{s}`$ は、揺らぎが周期の数十 % あると大きいが、不完全微分（10 章 6 節）がそれをならす。角周波数 $`\omega`$ で揺れる成分にとって、$`\dot y`$ は振幅の $`\omega`$ 倍なので、誤差の割合はおよそ $`\omega\delta`$ である。ゲイン交差角周波数のあたりで $`\omega_\mathrm{gc}\delta`$ が小さければ、揺らぎはほとんど効かない。処理の始まりが、決めた時刻から 0〜周期の 20 %・40 % の間で回ごとにでたらめに遅れるとして、負荷トルクによるずれの最大を数値計算で比べる（(A) の計算の時間は 0.2〜0.4 ms）。

```fig
e16_jitter
```

1 ms では、揺らぎを 40 % にしても、ずれの最大はほとんど変わらない（(A) で 1.055 rad から 1.056 rad、(B) は 1.062 rad のまま）。制御周期を 10 ms に延ばすと、(A) と (B) の差（平均の計算遅れの差。1.123 rad と 1.332 rad）は大きくなるが、揺らぎで変わる分は 1 % 以下で、乱数によって増えることも減ることもある。揺らぎで困るのは、次の 3 つの場合である。

1. 揺らぎで計算が周期に間に合わなくなる。1 周期が飛ぶと、その回の操作量は 2 周期の間保たれ、次の回の D の分は 2 周期分の変化を 1 周期で割る。
2. 速く変わる信号を測る。PWM に合わせて上下するモータの電流を、ON の真ん中の時刻に測るつもりで測るとき（[電源と周辺の制御シリーズ 13 章 2 節](../periph/13_モータを回す.md#電流のリップル)）、測る時刻がずれれば、測った値は電流の傾き × ずれだけ違う。
3. 速いループで、揺らぎが周期の大きな割合になる（電流のループの 50 µs に、5 µs の揺らぎは 10 %）。

どれも (d) のように、測る時刻と出す時刻をタイマに決めさせれば避けられる。揺らぎがどれだけあるかは、周期ごとの時刻を記録して分布で見る（[組み込みテストシリーズ 14 章 3 節](../embtest/14_タイミングとリアルタイム性.md#ジッタを見る-一発でなく分布で)）。

下の図で、周期の作り方、出す時刻（(A)・(B)）、制御周期、計算の時間、揺らぎの大きさを変えると、始めの数周期のタイミング図（決めた時刻・測る時刻・計算・出す時刻）と、目標を 1 rad 変えて 1 s に負荷トルクを加えたときの角度と電圧が、連続時間で計算した応答と重ねて表示される。

## 2. 離散 PID のコード — 位置形と速度形

10 章 6 節と 11 章 4 節のコードが周期ごとに計算していることを、15 章 1 節の書き方（$`k`$ 回目の値に $`[k]`$ を付ける）で書く。$`u_\mathrm{c}`$ は制御器が計算した操作量、$`u`$ は範囲 $`u_\mathrm{min}`$〜$`u_\mathrm{max}`$ に収めて実際に出す操作量である（11 章 4 節）。

$$
u_\mathrm{P}[k] = K_\mathrm{P}\bigl(b\,r[k] - y[k]\bigr), \qquad u_\mathrm{D}[k] = a\,u_\mathrm{D}[k-1] - aK_\mathrm{P}N\bigl(y[k] - y[k-1]\bigr), \qquad a = \frac{T_\mathrm{D}}{T_\mathrm{D} + NT_\mathrm{s}}
$$

$$
u_\mathrm{c}[k] = u_\mathrm{P}[k] + u_\mathrm{I}[k] + u_\mathrm{D}[k], \qquad u_\mathrm{I}[k+1] = u_\mathrm{I}[k] + \frac{K_\mathrm{P}T_\mathrm{s}}{T_\mathrm{I}}\,e[k]
$$

I の分は前進差分、D の分は後退差分である（15 章 4 節）。このように、周期ごとに操作量そのものを計算する形を**位置形**という（操作量を、弁の開きやモータの電圧のような「位置」として出すことからの名前）。位置形は、I の分 $`u_\mathrm{I}`$ をためておき、毎回それに P と D の分を足す。

### 増分を計算する — 速度形

ためた I の分を使わずに、前の回の操作量からの増分を計算することもできる。

**方針**: 位置形の $`u_\mathrm{c}[k]`$ の式から、1 回前の $`u_\mathrm{c}[k-1]`$ の式を引く。I の分の差は、I の分の式から 1 回分の増分になる。

**導出**: P と D の分の和を $`u_\mathrm{PD}[k] = u_\mathrm{P}[k] + u_\mathrm{D}[k]`$ と書くと、$`u_\mathrm{c}[k] - u_\mathrm{c}[k-1] = \{u_\mathrm{PD}[k] - u_\mathrm{PD}[k-1]\} + \{u_\mathrm{I}[k] - u_\mathrm{I}[k-1]\}`$ である。I の分の式で $`k`$ を $`k - 1`$ に置き換えると、$`u_\mathrm{I}[k] - u_\mathrm{I}[k-1] = (K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I})\,e[k-1]`$ である。したがって

$$
\Delta u[k] = \bigl\{u_\mathrm{PD}[k] - u_\mathrm{PD}[k-1]\bigr\} + \frac{K_\mathrm{P}T_\mathrm{s}}{T_\mathrm{I}}\,e[k-1], \qquad u_\mathrm{c}[k] = u_\mathrm{c}[k-1] + \Delta u[k]
$$

となる ∎

増分 $`\Delta u[k]`$ を計算して、前の回の操作量に足す形を**速度形**という（操作量の変わる速さを計算することからの名前）。速度形は I の分をためず、前の回の操作量そのものを覚えておく。

```fig
e16_forms
```

範囲の外に出なければ、2 つの形は、数の丸めを除いて同じ操作量を出す（モータの角度の例で、float で計算した差は最大 8 × 10⁻⁷ V）。違いが出るのは、範囲で切ったときである。

### 範囲で切ると — 速度形は逆算の T_t = T_s と同じ

速度形で、範囲に収めた $`u[k-1]`$ に増分を足すことにする（$`u[k] = \min(\max(u[k-1] + \Delta u[k], u_\mathrm{min}), u_\mathrm{max})`$）。範囲の外へ向かう増分は、毎回捨てられるので、ワインドアップは起きない。これを 11 章 4 節のアンチワインドアップと比べる。

**方針**: 11 章 4 節のバックカリキュレーションの I の分の式を、周期ごとの式で書き、$`T_\mathrm{t} = T_\mathrm{s}`$ とおく。次の回の $`u_\mathrm{c}[k+1]`$ を求めて、速度形の式と比べる。

**導出**: 11 章 4 節のコードの I の分は $`u_\mathrm{I}[k+1] = u_\mathrm{I}[k] + (K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I})\,e[k] + (T_\mathrm{s}/T_\mathrm{t})(u[k] - u_\mathrm{c}[k])`$ である。$`T_\mathrm{t} = T_\mathrm{s}`$ とおき、$`u_\mathrm{c}[k] = u_\mathrm{PD}[k] + u_\mathrm{I}[k]`$ を入れると、$`u_\mathrm{I}[k]`$ が消えて $`u_\mathrm{I}[k+1] = u[k] - u_\mathrm{PD}[k] + (K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I})\,e[k]`$ になる。したがって

$$
u_\mathrm{c}[k+1] = u_\mathrm{PD}[k+1] + u_\mathrm{I}[k+1] = u[k] + \bigl\{u_\mathrm{PD}[k+1] - u_\mathrm{PD}[k]\bigr\} + \frac{K_\mathrm{P}T_\mathrm{s}}{T_\mathrm{I}}\,e[k]
$$

で、範囲に収めた $`u[k]`$ に増分 $`\Delta u[k+1]`$ を足す速度形の式と同じである ∎

速度形は、張り付いている間、I の分を 1 周期ごとに、出している操作量に合わせ直すのと同じである。11 章 4 節の温度の板（PI 10 W/K・160 s、ヒータ 0〜80 W、1 s ごと）で、25 °C で落ち着いている板の目標値を 60 °C に変えて比べる。

```fig
e16_sat
```

速度形は 44 s で 80 W から下がり始め、飽和から最も早く抜ける（クランプは 178 s）。その代わり、目標に近づくのが遅く、±0.5 K に入るのは 573 s（クランプ 387 s、$`T_\mathrm{t}`$ = 80 s のバックカリキュレーション 430 s、対策なし 851 s）である。張り付いている間に、温度が上がって P の分が減るたびに、その減りがそのまま操作量を下げるからである。

### 速度形の使いどころと落とし穴

- 今の操作量から始められる。前の回の操作量を、今出ている値にしておけば、始めた回の操作量は跳ねない。手動から自動に切り替えるときも、11 章 5 節の `pid_manual()` のような I の分の決め直しが要らない。
- 増分で動く操作端に、そのまま渡せる。周期ごとに決めた数だけ進めるステッピングモータや、開け閉めの時間で開きを変える弁では、増分が出す量そのものである。
- I 動作が無いと、範囲で切った分が戻らない。モータの角度の PD（$`K_\mathrm{P}`$ = 0.84 V/rad、$`T_\mathrm{D}`$ = 0.0238 s、$`b`$ = 1）で目標を 20 rad 変えると、始めの増分 16.8 V のうち 12 V を越えた 4.8 V が捨てられ、その分 $`u_\mathrm{PD}`$ との関係がずれたまま残る。角度は 4.8 ÷ 0.84 = 5.71 rad 手前の 14.29 rad で止まる。

```fig
e16_velpd
```

I 動作があれば、残ったずれは I の分が消すので、速度形の PID（$`T_\mathrm{I}`$ = 0.168 s を足す）は 20 rad に届き、行き過ぎも 1.65 rad と、クランプの位置形の 4.40 rad より小さい。速度形は、I 動作を含む制御器に使う。

次のコードは、11 章 4 節の `pid_ctl_t` に 3 つの値（`float u1, pd1, e1;`。1 回前の操作量・P と D の分の和・偏差）を足し、11 章 4 節の `pid_pd()` と `clampf()` を使って速度形を計算する。

```c
/* 速度形を始めるときに 1 回呼ぶ。u: そのとき出ている操作量（止まっていれば 0） */
void pid_start_vel(pid_ctl_t *c, float r, float y, float u)
{
    pid_start(c, y);                          /* 10 章 6 節: D の分を 0、y1 = y */
    c->pd1 = pid_pd(c, r, y);                 /* 増分の基準にする P と D の分 */
    c->e1 = 0.0f;
    c->u1 = clampf(u, c->umin, c->umax);      /* この値から跳ねずに続ける */
}

/* 速度形の 1 回分。T_s ごとに呼ぶ。戻り値: 対象に出す操作量 */
float pid_step_vel(pid_ctl_t *c, float r, float y)
{
    float pd = pid_pd(c, r, y);               /* P と D の分（11 章 4 節） */
    float du = pd - c->pd1;                   /* P と D の分の増分 */
    if (c->ti > 0.0f)
        du += c->kp * c->dt / c->ti * c->e1;  /* I の分の増分（前の回の偏差。位置形と同じ） */
    c->pd1 = pd;
    c->e1 = r - y;
    c->u1 = clampf(c->u1 + du, c->umin, c->umax);   /* 範囲に収めた値を次の回の基準にする */
    return c->u1;
}
```

テストでは、範囲の外に出ない間は 11 章の位置形と同じ操作量になること、温度の板の模型で、速度形の操作量が $`T_\mathrm{t} = T_\mathrm{s}`$ のバックカリキュレーションの位置形と 0.0001 W 以内で一致し、上の 44 s・573 s とクランプの 387 s が Python の計算と一致すること、PD の速度形が 5.714 rad 手前で止まること、3 V を出している所から始めると始めの回の操作量が 3 V のままであることを確かめた（アドレスと未定義動作の検査付き）。

## 3. 量子化 — ADC と PWM の分解能

ループの中で、連続な値が飛び飛びの値に変わる所が 2 つある。ADC は電圧を $`2^n`$ 段のどれかの整数にし、PWM は操作量を、タイマが 1 周期を数える段（例 3200 段。[電源と周辺の制御シリーズ 13 章 2 節](../periph/13_モータを回す.md#周波数を選ぶ)）のどれかにする。連続な値を、決まった幅の段のどれかに丸めることを**量子化**といい、丸めた値と元の値の差を**量子化誤差**という（[電源と周辺の制御シリーズ 9 章 1 節](../periph/09_アナログ値を正しく測る.md#標本化と量子化)と同じ意味で、1 段の幅を LSB と書く）。四捨五入で丸めれば、量子化誤差は ±1/2 LSB の中にある。

この節では、11 章 3 節の温度の板の PI 制御（$`K_\mathrm{P}`$ = 10 W/K、$`T_\mathrm{I}`$ = 160 s、1 s ごと）を例にする。温度は 0〜102.4 °C の範囲を ADC の値に比例するように測り（例の値。サーミスタでは、1 LSB にあたる温度が温度で変わる。[電源と周辺の制御シリーズ 9 章 3 節](../periph/09_アナログ値を正しく測る.md#サーミスタ)）、ヒータの電力は 0〜80 W を PWM の段で出すとする。60 °C で落ち着いている板の周りの温度が、200 s に 25 °C から 23 °C に下がり、保つのに要る電力が 28 W から 29.6 W に増える場面で比べる。

```fig

```

### 止まれる段があるか — リミットサイクル

PI 制御が落ち着くには、I の分が止まらなければならない。量子化があると、それが難しくなる。

**方針**: 出力が 1 つの段にとどまって落ち着いた状態を考える。そのときの温度が、偏差の読みが 0 になる範囲に入るかを調べる。入らなければ I の分は止まれない。

**導出**: 出力の段の値を $`u_j`$（間隔 $`\Delta u`$）とする。出力が $`u_j`$ にとどまれば、温度は周りの温度に $`Ku_j`$ を足した値に落ち着く（$`K`$ = 1.25 K/W）ので、隣の段とは $`K\Delta u`$ 違う。I の分が止まるのは偏差の読みが 0 のとき、つまり温度が、目標を中心とする幅 1 LSB（ADC の 1 段の幅 $`\Delta y`$）の範囲にあるときである。段どうしの温度の間隔 $`K\Delta u`$ が $`\Delta y`$ 以下なら、少なくとも 1 つの段の温度がこの範囲に入る。$`K\Delta u`$ が $`\Delta y`$ より大きければ、どの段の温度も範囲に入らないことがある。そのときは、どの段にとどまっても偏差の読みは 0 にならないので、I の分は動き続け、出力は 1 つの段にとどまれない ∎

ADC が十分に細かければ（$`\Delta y`$ が 0 に近ければ）、保つのに要るちょうど 29.6 W の段が無い限り、出力は止まれず、要る値をはさむ 2 つの段を行き来する。量子化のような非線形な要素のために、目標値と外乱が一定でも、決まった振れ幅と周期で続く振動を**リミットサイクル**という（ディジタルフィルタの丸めで起きるリミットサイクルは [DSP シリーズ 9 章 4 節](../dsp/09_実装構造と数値的注意点.md#b-丸め誤差の蓄積とリミットサイクル)）。

```fig
e16_limit
```

- (a) PWM 8 ビット（0.3125 W。$`K\Delta u`$ = 0.39 K）、ADC は十分に細かい: 出力は 29.375 W と 29.6875 W を行き来し、上の段にいる時間の割合 $`D`$ は 0.72（平均 29.6 W）、往復の周期 $`T_\mathrm{w}`$ は約 106 s である。温度の揺れの幅は 0.017 K で、[電源と周辺の制御シリーズ 14 章 4 節](../periph/14_熱を扱う.md#交流の-1-周期を単位に入れ切りする)で、窓の中でまとめて入れ切りしたときの式 $`D(1 - D)K\Delta u\,T_\mathrm{w}/T`$（$`T`$ = 500 s。1 段分の電力 $`\Delta u`$ を入れ切りしているとみなす）の 0.017 K と一致する。往復の周期が熱時定数よりずっと短いので、揺れは小さい。
- (b) ADC 10 ビット（0.1 K）、PWM は十分に細かい: 出力はどの値にもとどまれるが、読みが 60.0 °C の間は偏差 0 で I の分が止まり、温度は ±0.05 K の範囲の中を、要る電力とのわずかな差でゆっくり動く。範囲の端を越えて読みが 1 LSB 変わると、P の分が 1 W 跳ね、読みがむだ時間 20 s の間戻らないので I の分も動く。その動きで温度の行き着く先が反対側の端を越えるので、約 1000 s の周期で往復し続ける。温度の揺れの幅は 0.10 K で、ADC の 1 LSB とほぼ同じである。
- (c) (a) と同じ PWM 8 ビットで、丸めた端数を次の回に持ち越す（下の対策 2）: 往復の周期が約 4 s に縮み、温度の揺れの幅は 0.0008 K になる。
- (d) PID（10 章 5 節の $`K_\mathrm{P}`$ = 24 W/K・$`T_\mathrm{I}`$ = 40 s・$`T_\mathrm{D}`$ = 10 s、$`N`$ = 10）で ADC 10 ビット: 測定値の微分は、読みの 1 LSB の段差を $`aK_\mathrm{P}N`$ × 0.1 K = 12 W の山にする（$`a`$ = 0.5）。ヒータの電力は 15〜46 W の間で跳ね、温度の揺れの幅は 0.22 K になる。

揺れの大きさは、ADC の 1 LSB と、出力の 2 つの段の往復で生じる揺れの、大きい方でほぼ決まる。片方だけを細かくしても、もう片方が粗ければ揺れは残る（ADC 12 ビット・PWM 8 ビットで 0.040 K）。対策は次のとおりである。

1. 粗い方の段を細かくする。ADC は、速く測って平均すると、ノイズのある信号では細かくできる（[電源と周辺の制御シリーズ 9 章 6 節](../periph/09_アナログ値を正しく測る.md#オーバーサンプリング)）。
2. 出力の端数を持ち越す。出したい値に前の回の端数を足してから丸め、丸めで捨てた分を次の回に足す。出力は周期ごとに隣の段と行き来し、平均が出したい値に等しくなる。[電源と周辺の制御シリーズ 14 章 4 節](../periph/14_熱を扱う.md#マイコンでする制御-3)の `cycle_on()` と同じ考え方である。往復が速いほど、対象がならす。
3. D 動作は、$`N`$ を小さくするか使わない（10 章 6 節）。PI で足りる対象なら PI にする（11 章 6 節）。

偏差の読みが小さい間は積分しないという方法もあるが、止めた範囲の分だけ偏差が残り、出力の段が粗いと P の分による往復は残る。

## 4. 固定小数点で計算する

10・11 章の `pid_step()` は、float（単精度の浮動小数点）で計算した。浮動小数点の演算の回路を持たないマイコンでは、float の足し算や掛け算を、整数の命令を組み合わせたライブラリで行うので、整数の演算の何十倍もの時間がかかることがある（マイコンとコンパイラで違う）。ADC の値も PWM の設定値も整数なので、整数のまま計算できれば速い。

整数を、決めた 2 のべきで割った値とみなして小数を表す方法を**固定小数点**という（[DSP シリーズ 9 章](../dsp/09_実装構造と数値的注意点.md)の始めにも説明がある）。符号付きの整数 $`X`$ で実数 $`x = X/2^f`$ を表すとき、$`f`$ を小数部のビット数という。符号のビットを含めた整数部のビット数 $`m`$ と合わせて、この表し方を Qm.f と書く方法を **Q 形式**という（$`m`$ に符号のビットを含めない流儀もあり、そのときは同じものを Q15.16 と書くので、資料ごとに確かめる）。32 ビットの整数を Q16.16 で使えば、刻みは $`2^{-16}`$ = 1.53 × 10⁻⁵、表せる範囲は −32768 以上 32768 未満である。

```fig
e16_qfmt
```

### 桁の決め方と、係数の誤差

信号ごとに、とりうる最大の大きさから整数部のビット数を決め、残りを小数部にする。モータの角度の PID では、角度（目標を含めて例えば ±20 rad）、電圧（±12 V）、途中の P・I・D の分のどれも ±32768 よりずっと小さいので、すべて Q16.16 にできる。係数も Q16.16 の整数に丸める。

| 係数（$`T_\mathrm{s}`$ = 1 ms） | 値 | Q16.16 の整数 | 戻した値との差 | $`T_\mathrm{s}`$ = 0.1 ms の値 | その差 |
|---|---|---|---|---|---|
| $`K_\mathrm{P}`$ | 0.84 | 55050 | −0.0004 % | 0.84 | −0.0004 % |
| $`a = T_\mathrm{D}/(T_\mathrm{D} + NT_\mathrm{s})`$ | 0.704142 | 46147 | +0.0008 % | 0.959677 | −0.0007 % |
| $`aK_\mathrm{P}N`$ | 5.91479 | 387632 | +0.00003 % | 8.06129 | +0.00005 % |
| $`K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I}`$ | 0.005 | 328 | +0.098 % | 0.0005 | +0.71 % |

15 章 6 節で予告したとおり、$`T_\mathrm{s}`$ を短くするほど、1 周期の I の分の係数 $`K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I}`$ は小さくなり、少ないビットでは割合として粗くしか表せない。$`a`$ は 1 に近づき、$`1 - a`$（D の分が 1 周期で減る割合）の誤差が効くようになる。小さな係数だけ小数部を多くした形で持つと、この誤差は減らせる。

### 掛け算の後の桁合わせと丸め

**方針**: 小数部 $`f`$ ビットの 2 つの数 $`x = X/2^f`$ と $`c = C/2^f`$ の積を、同じ形の整数 $`Z`$ で表す。

**導出**: $`xc = XC/2^{2f}`$ である。$`Z = xc \cdot 2^f`$ とおくと $`Z = XC/2^f`$ になる。$`X`$ と $`C`$ が 32 ビットなら、積 $`XC`$ は 64 ビットに収まるので、64 ビットで掛けてから $`2^f`$ で割る（右へ $`f`$ ビットずらす）。割った端数を四捨五入するには、割る前に $`2^{f-1}`$ を足す（負の数は、符号を外して同じことをしてから符号を戻す）∎

右へずらすだけ（切り捨て）だと、結果は平均で 1/2 LSB ずつ小さい側にずれ、何度も足し込む I の分では、その偏りがたまる。C の符号付きの整数を右へずらすとき、負の数の結果は処理系によって違う（C の規格で決まっていない）ので、上の方法で負の数も同じ規則で丸める。

### 1 LSB に満たない増分 — I の分が止まる

I の分の 1 回の増分は $`K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I}`$ × 偏差で、係数が小さいので、増分も小さい。

**方針**: 係数 $`K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I}`$ を $`k_\mathrm{I}`$ と書く。増分 $`k_\mathrm{I}e`$ を小数部 $`f`$ ビットの整数に丸めたものが 0 になる偏差の範囲を求める。

**導出**: 増分を小数部 $`f`$ ビットの整数にすると、$`k_\mathrm{I}e \cdot 2^f`$ を四捨五入した値である。これが 0 になるのは $`|k_\mathrm{I}e \cdot 2^f| < 1/2`$、つまり

$$
|e| < \frac{2^{-f}}{2k_\mathrm{I}}
$$

のときである ∎

$`k_\mathrm{I}`$ = 0.005 なら、この範囲は 1 LSB（$`2^{-f}`$）の 100 倍で、$`f`$ = 16 で 1.5 mrad、$`f`$ = 8 で 0.39 rad である。偏差がこれより小さくなると I の分は動かないので、負荷トルクを支える 1 V を出し切れず、偏差が残る（$`f`$ = 16 で 0.68 mrad、12 で 11.6 mrad、8 で 0.27 rad）。対策は、I の分だけ小数部を多くしてためることである。下のコードでは、積 $`k_\mathrm{I}e`$（小数部 $`2f`$ = 32 ビット）を右へずらさずに 64 ビットの整数に足していく。こうすると、無視される偏差は 1/2 LSB 未満になる。

### 桁あふれと飽和演算

計算の結果が、その形で表せる範囲を越えることを**桁あふれ**という。C の符号付きの整数の桁あふれは、動作が決まっていない（未定義の動作）。多くのマイコンでは、2 の補数の下のビットだけが残り、最大の正の値の次が最小の負の値になる（一周する）。結果を範囲の端の値で置き換える演算を**飽和演算**という（そのための命令を持つマイコンもある）。

Q5.27（$`f`$ = 27、範囲は ±16）で目標を 20 rad にすると、目標が表せない。一周すると、目標は 20 − 32 = −12 rad になり、モータは逆へ回って −12 rad で止まる。飽和演算なら、目標は 16 rad で止まり、向きは正しい。どちらも正しくないので、整数部のビット数は、とりうる最大の値から決める（この例では $`f`$ = 26 以下）。飽和演算は、決めた範囲を越える思いがけない値が来たときに、向きの逆転のような大きな誤りを防ぐ守りである。


| | float（単精度） | Q16.16（32 ビットの整数） |
|---|---|---|
| 刻み | 値の約 6 × 10⁻⁸ 倍（1 の付近で 1.2 × 10⁻⁷） | どの値でも 1.5 × 10⁻⁵ |
| 範囲 | 約 ±3.4 × 10³⁸ | ±32768 |
| 桁あふれ | ふつうは起きない | 範囲を設計し、飽和演算で守る |
| 小さな増分 | 大きな値に足すと消える（I の分が 1 V なら、6 × 10⁻⁸ V 未満の増分） | 上の式の範囲の偏差で消える（64 ビットでためれば 1/2 LSB 未満） |
| 浮動小数点の回路が無いマイコンでの速さ | 遅い | 速い |

次のコードは、11 章 4 節の PID（クランプのアンチワインドアップ）を Q16.16 の整数で計算する（`stdint.h` を使う）。まず積と丸めと飽和の部品である。

```c
typedef int32_t q16_t;                         /* Q16.16: 実数 × 2^16 の整数 */
#define QF 16                                  /* 小数部のビット数 */

static int64_t rshift_round(int64_t v, int s)  /* v ÷ 2^s を四捨五入（負の数も 0 から遠い方へ） */
{
    int64_t h = (int64_t)1 << (s - 1);
    return v >= 0 ? (v + h) >> s : -((h - v) >> s);
}
static q16_t sat32(int64_t v)                  /* 飽和演算: int32 の範囲の外なら端の値にする */
{
    return v > INT32_MAX ? INT32_MAX : (v < INT32_MIN ? INT32_MIN : (q16_t)v);
}
static q16_t qmul(q16_t a, q16_t b)            /* Q16.16 どうしの積 */
{
    return sat32(rshift_round((int64_t)a * b, QF));
}
```

PID の 1 回分は次のとおりで、係数は上の表のように前もって整数にしておく（`umin`・`umax` は ±12 V を Q16.16 にした ±786432）。

```c
typedef struct {
    q16_t kp, b, a, akn, ki;  /* K_P、b、a、a·K_P·N、K_P·T_s/T_I（どれも Q16.16） */
    q16_t umin, umax;         /* 操作量の範囲 */
    int64_t i;                /* I の分（小数部 32 ビット: 1 LSB に満たない増分も捨てない） */
    q16_t d, y1;              /* D の分、1 回前の測った値 */
} pid_q16_t;

void pid_q16_start(pid_q16_t *c, q16_t y)
{
    c->i = 0;  c->d = 0;  c->y1 = y;
}

/* T_s ごとに 1 回呼ぶ。r・y・戻り値は Q16.16 */
q16_t pid_q16_step(pid_q16_t *c, q16_t r, q16_t y)
{
    q16_t e = sat32((int64_t)r - y);
    c->d = sat32((int64_t)qmul(c->a, c->d) - qmul(c->akn, sat32((int64_t)y - c->y1)));
    c->y1 = y;
    q16_t pd = sat32((int64_t)qmul(c->kp, sat32((int64_t)qmul(c->b, r) - y)) + c->d);
    int64_t uc = (int64_t)pd + rshift_round(c->i, QF);    /* I の分を Q16.16 に戻して足す */
    q16_t u = uc > c->umax ? c->umax : (uc < c->umin ? c->umin : (q16_t)uc);
    if (!((uc > c->umax && e > 0) || (uc < c->umin && e < 0)))
        c->i += (int64_t)c->ki * e;                       /* 積は小数部 32 ビット。ずらさずにためる */
    return u;
}
```

I の分を 64 ビットにしたので、32 ビットのマイコンでは 64 ビットの足し算が 1 回増える。2 のべきの定数で割る代わりの右へのずらしは、どのマイコンでも速い。テストでは、丸めが正と負で同じ規則になること、積が範囲を越えると端の値になること、係数の整数が上の表と同じであることを確かめた。さらに、モータの角度の模型（1 ms ごと、10 章 6 節と同じく測った瞬間に出す）につないで、目標を 1 rad 変えて 1 s に負荷トルクを加え、角度が 11 章の float のコードと最大 0.64 mrad しか違わず、5 s 後の偏差が 0.002 mrad であること、I の分を Q16.16 のまま丸めてためると偏差が 0.68 mrad 残ることを確かめた（アドレスと未定義動作の検査付き）。

下の図で、小数部のビット数、I の分のため方（Q16.16 のまま丸める・64 ビットでためる）、丸め方（四捨五入・切り捨て）、桁あふれのときの扱い（一周する・飽和演算）、動かし方（1 rad と負荷トルク・20 rad）を変えると、整数で計算した角度と電圧が float の結果と重ねて表示され、差の大きさと、32 ビットの中の整数部と小数部の分け方が表示される。

## 5. 起動・停止・異常のときの扱い

1〜4 節のコードは、制御が動き続けている間の 1 回分の計算だった。実際の機器では、電源を入れた直後、止めるとき、センサが壊れたときにも、制御のプログラムが何をするかを決めておく。制御器の運転の状態を、停止・自動・手動・異常の 4 つに分け、状態ごとに出す操作量と、状態を移るときにすることを決める。

```fig
e16_modes
```

### 始めるとき

- 測った値が使えるようになるまで（センサが動き出し、フィルタが落ち着くまで）、出力は安全な値（モータなら 0 V、ヒータなら 0 W）にしておく。リセットの間のピンは [電源と周辺の制御シリーズ 15 章 1 節](../periph/15_異常に備える.md#リセットの間のピンの状態)の方法で安全な側に引いておく。
- `pid_start()` で、D の分を 0 にし、1 回前の測った値を今の測った値にする。1 回前の値が 0 のままだと、始めの回の D の分が $`-aK_\mathrm{P}N`$ × 今の測った値になる。
- I の分を、今の操作量から跳ねずに続くように決める（11 章 5 節の $`u_\mathrm{I} = u - u_\mathrm{P} - u_\mathrm{D}`$）。I の分を 0 にすると、目標値の重み $`b`$ が 1 でない PID は、目標の位置で止まっていても $`u_\mathrm{P} = K_\mathrm{P}(b - 1)r`$ を出す。

```fig
e16_start
```

図の (a) は、2 rad で止まっているモータの角度を、目標 2 rad のまま PID で保ち始めた場合である。1 回前の値が 0 のままだと、始めの回の電圧は −12 V に張り付き、角度は 0.84 rad まで戻される。`pid_start()` だけで I の分を 0 にすると、$`K_\mathrm{P}(b - 1)r`$ = −0.84 V から始まり、1.12 rad まで動く。I の分を今の電圧 0 V に合わせると、動かない。止まっている所から新しい目標へ動かすときも、目標をいったん測った値とみなして I の分を合わせてから目標を変えれば、目標の段差に対する応答は 10 章で設計したとおりになる。目標を測った値からゆっくり本来の値へ動かせば、操作量の大きな跳ねと飽和を避けられる（11 章 5 節）。

### 止めるとき

出力を安全な値にし、PID の計算をやめる。止まっている間に I の分をためない。もう一度始めるときは、上の手順をやり直す。モータを 0 V にして惰性で止めるか、ブレーキをかけるかは、[電源と周辺の制御シリーズ 13 章 3 節](../periph/13_モータを回す.md#止め方-惰性-短絡ブレーキ-回生)で決める。

### 異常のとき

次のことが起きたら異常と決める。

- センサの値が範囲の外、変化の速さがありえない、読めない回が続く（[電源と周辺の制御シリーズ 10 章 6 節](../periph/10_測り方を設計する.md#センサの故障を見つける)）。浮動小数点で計算するなら、値が数でない（NaN）ことも調べる。NaN が一度 I の分に入ると、I の分はずっと NaN のままになる。
- 計算が周期に間に合わない回が続く（1 節の `overrun`）。
- 操作量が上限に張り付いたまま、制御量が決まった時間動かない（モータの拘束。[電源と周辺の制御シリーズ 13 章 4 節](../periph/13_モータを回す.md#拘束の検出)。ヒータは [14 章 5 節](../periph/14_熱を扱う.md#センサがはがれても最大の出力にしない)）。

異常と決めたら、出力を安全な値にし、I の分をためず、異常の種類と時刻を記録して、人が原因を直すまで自動では戻らない（[電源と周辺の制御シリーズ 15 章 5 節](../periph/15_異常に備える.md#故障を見つけて縮退する)）。図の (b) は、温度の板を PI で 60 °C に保っている 600 s に、NTC サーミスタの線が切れて、読みが −40 °C（最も冷たい側）になった場合である。異常を見つけないと、偏差が 100 K に見え、ヒータは 80 W のまま、板は 124.5 °C に向かう。読みが範囲の外であることが 3 回続いたら異常と決めると、602 s にヒータを切る。プログラムが止まったときに備えるウォッチドッグは、制御の計算が正しく回った周期にだけ合図を送るようにする（[電源と周辺の制御シリーズ 15 章 4 節](../periph/15_異常に備える.md#ウォッチドッグと安全な停止)）。

次のコードは、4 つの状態を、11 章 4・5 節の `pid_step()` と `pid_manual()` で扱う（`math.h`・`stdbool.h`・`stdint.h` を使う）。利用者が求めた状態を `req` に書くと、次の周期から移る。

```c
typedef enum { CTL_STOP, CTL_AUTO, CTL_MANUAL, CTL_FAULT } ctl_mode_t;
typedef struct {
    pid_ctl_t pid;               /* 11 章のアンチワインドアップ付きの PID */
    ctl_mode_t mode, req;        /* 今の状態と、求められた状態 */
    float u, u_man, u_safe;      /* 出している操作量、手動の操作量、安全な操作量 */
    uint8_t bad;                 /* 続けて読めなかった回数 */
} ctl_t;

/* 制御周期ごとに呼ぶ。ok: 読みが検査を通ったか。戻り値: 出す操作量 */
float ctl_tick(ctl_t *s, float r, float y, bool ok)
{
    if (!ok || !isfinite(y)) {                    /* 読めない回は計算しない */
        if (++s->bad >= 3)
            s->mode = CTL_FAULT;                  /* 3 回続いたら異常と決める */
        if (s->mode == CTL_FAULT)
            s->u = s->u_safe;
        return s->u;                              /* それまでは前の値を保つ */
    }
    s->bad = 0;
    if (s->mode != CTL_FAULT && s->req != s->mode) {
        if (s->mode == CTL_STOP) {                /* 止まっていた所から始める */
            pid_start(&s->pid, y);                /* D の分と y1 を整える */
            pid_manual(&s->pid, y, y, s->u);      /* 目標を y とみなして I の分を合わせる */
        }
        s->mode = s->req;                         /* 手動 ⇄ 自動は 11 章 5 節で跳ねない */
    }
    if (s->mode == CTL_AUTO)
        s->u = pid_step(&s->pid, r, y);
    else if (s->mode == CTL_MANUAL)
        s->u = pid_manual(&s->pid, r, y, s->u_man);
    else
        s->u = s->u_safe;                         /* 停止と異常 */
    return s->u;
}
```

異常から戻すには、原因を直した後に、別の関数で `mode` を停止にする。テストでは、温度の板の模型で、停止から自動に移ると 80 W から温め始めること、600 s に読みが範囲の外になると 602 s に異常と決めてヒータを切り、板が 60 °C を越えないこと（決めないと 124.5 °C）、手動 30 W から自動に移った周期の操作量が 30 W のままであること、2 rad で止まっているモータを目標 2 rad で始めても動かないこと、1 回だけ読めない回や NaN では前の操作量を保って I の分を変えないこと、異常からは自動に戻らないことを確かめた。

## 6. 試験と調整の道具 — ログ・ステップ試験・周波数応答の測定

実際の機器で、制御が設計どおりに動いているかを確かめ、調整する道具をまとめる。どれも、制御周期ごとの値を記録することから始まる。

### ログ — 周期ごとの値を残す

周期ごとに、目標値 $`r`$・測った値 $`y`$・計算した操作量 $`u_\mathrm{c}`$・出した操作量 $`u`$ と、運転の状態、計算にかかった時間を記録する。1 ms ごとに 4 つの float（16 バイト）を残すと 1 s で 16 kB になり、115200 bps の UART（1 s に約 11.5 kB）では送り切れない。そこで、RAM のリングバッファに最後の一定の時間分を上書きしながら残し、目標値を変えた・異常が起きたなどのきっかけの前後を、後でゆっくり送る。

```fig
e16_log
```

### ステップ試験

- 手動の状態で操作量を段差で変え、ステップ応答から 3 章 5 節の方法でモデル（$`K`$・$`T`$・$`L`$）を求める。積分を含む対象（モータの角度）は止まらずに動いていくので、短い時間だけにする。
- 自動の状態で目標値を段差で変え、ログの応答を、同じ制御器のコードとモデルをホストのコンピュータで動かした結果と重ねる。違いがあれば、モデルの値か、実装（周期・計算遅れ・飽和・量子化）を疑う。

### 正弦波を足して周波数応答を測る

8 章 6 節の周波数掃引は、対象に直接正弦波を入れた。積分を含む対象や、ほかの機器とつながっていて止められない対象では、ループを開けない。そこで、ループを閉じたまま、制御器の出す操作量に正弦波 $`d`$ を足して測る。

**方針**: 目標値を一定にし、制御器が計算した $`u_\mathrm{c}`$ に $`d`$ を足した $`u = u_\mathrm{c} + d`$ を対象に出す。ログの $`u_\mathrm{c}`$ と $`u`$ から、角周波数 $`\omega`$ の成分を 8 章 6 節と同じく正弦波を掛けた平均で求め、その比をとる。

**導出**: 目標値が一定なら、動作点からのずれについて、$`u_\mathrm{c}`$ は測った値に制御器を掛けて符号を変えたもので、$`U_\mathrm{c} = -CY`$ である。測った値は、対象に出した $`u`$ から決まり、$`Y = PU`$ である。2 つを合わせると $`U_\mathrm{c} = -PC\,U`$ なので

$$
P(j\omega)C(j\omega) = -\frac{U_\mathrm{c}(j\omega)}{U(j\omega)}
$$

である。同じく $`P(j\omega) = Y(j\omega)/U(j\omega)`$ である ∎

ログの値は周期ごとの値なので、測れるのは、計算遅れと零次ホールドを含めた、実際に動いているループの一巡伝達関数（15 章 5 節の $`z = e^{j\omega T_\mathrm{s}}`$ の値）である。

```fig
e16_inject
```

1 節の (B) の出し方のモータの角度で、振幅 0.2 V の正弦波を足して測ると、28 rad/s で $`|PC|`$ = 0.996、位相 −123.7° で、位相余裕 56.3° と読める。厳密な値との差は、どの角周波数でも 0.3 % と 0.2° 以内である。振幅は、操作量が範囲を越えず、制御量の揺れが運転を乱さない大きさにする（この例では角度が最大 0.29 rad 揺れる）。次のコードは、1 節の `timer_isr()` の 3. を `u_next = test_step(target, y);` に置き換えて、正弦波を足し、周期ごとに記録する（`math.h` を使う）。

```c
typedef struct { float r, y, uc, u; } log_rec_t;   /* 1 周期分の記録 */
#define LOG_N 1024u
log_rec_t log_buf[LOG_N];               /* 最後の LOG_N 周期分を残す（リングバッファ） */
volatile uint32_t log_k;                /* 書いた回数。log_k % LOG_N が次に書く場所 */
volatile float inj_amp, inj_w;          /* 足す正弦波の振幅 [V] と角周波数 [rad/s] */
static float inj_ph;                    /* 正弦波の位相 [rad] */

float test_step(float r, float y)
{
    float uc = pid_step(&pid, r, y);                       /* 制御器が出す操作量 u_c */
    float u = clampf(uc + inj_amp * sinf(inj_ph), pid.umin, pid.umax);   /* d を足す */
    inj_ph += inj_w * pid.dt;
    if (inj_ph >= 6.2831853f)
        inj_ph -= 6.2831853f;
    log_buf[log_k % LOG_N] = (log_rec_t){ r, y, uc, u };   /* 周期ごとに記録する */
    log_k++;
    return u;
}
```

テストでは、モータの角度の模型につないで 10・28・100 rad/s で記録し、記録の最後の 3 周期（1024 個に収まる数）から求めた $`-U_\mathrm{c}/U`$ が、厳密な値と 1 % と 0.5° 以内で一致することを確かめた。

### ホストで模型と一緒に動かす試験

この章と 10・11 章のテストのように、制御のコードをそのままホストのコンピュータでコンパイルし、対象の模型とつないで動かす試験は、実機より速く、飽和・センサの故障・桁あふれのような、実機で起こしにくい場合も繰り返し試せる。次に、マイコンの上でコードを動かし、対象だけを模型にした装置（HIL。[組み込みテストシリーズ 15 章 1 節](../embtest/15_HILハードウェアインザループ.md#hil-とは何か)）で、周期と計算遅れを含めて確かめる。最後に実機で、小さな段差と小さな正弦波から試す。

## 7. まとめ

| 項目 | 内容 |
|---|---|
| 制御周期 | 測る・計算する・出すを繰り返す間隔。1 つのループではサンプリング周期 $`T_\mathrm{s}`$ と同じ。待つのではなく、タイマ割り込みか、前の予定から数えて待つタスクで作る。計算の後で待つと周期が延び、積分時間と微分時間が変わる（1.3 ms で 1.3 倍） |
| 揺らぎ（ジッタ） | 測る時刻・出す時刻が決めた時刻からずれること。測った値に $`\dot y\,\delta`$ の誤差、D の分に $`(\delta_k - \delta_{k-1})/T_\mathrm{s}`$ の倍率のずれ。$`\omega_\mathrm{gc}\delta`$ が小さければほとんど効かない（1 ms なら 40 % でも、ずれの最大はほとんど変わらない）。タイマに測る時刻と出す時刻を決めさせると避けられる |
| 計算遅れ | 測ってから出すまでの時間 $`L_\mathrm{c}`$。前の周期の値を次の割り込みで出すと平均でちょうど $`T_\mathrm{s}`$ になり、$`z^{-1}`$ で表せる（1 ms のモータの角度で位相余裕 57.6° → 56.3°）。タイマに測る時刻と出す時刻を決めさせると揺れない |
| 位置形・速度形 | 周期ごとに操作量そのものを計算する形／増分 $`\{u_\mathrm{PD}[k] - u_\mathrm{PD}[k-1]\} + (K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I})e[k-1]`$ を前の操作量に足す形。範囲に収めた値に足す速度形は、$`T_\mathrm{t} = T_\mathrm{s}`$ のバックカリキュレーションと同じ。今の操作量から跳ねずに始められるが、I 動作が無いと範囲で切った分が残る（PD で 5.71 rad） |
| 量子化・量子化誤差 | 連続な値を決まった幅の段に丸めること／丸めた値と元の値の差（四捨五入で ±1/2 LSB） |
| リミットサイクル | 非線形な要素のために、目標値と外乱が一定でも続く決まった振れ幅の振動。出力の段の温度の間隔 $`K\Delta u`$ が ADC の 1 LSB より大きいと止まれる段が無いことがある。揺れは ADC の 1 LSB と、2 つの段の往復の揺れ $`D(1 - D)K\Delta u\,T_\mathrm{w}/T`$ の大きい方。端数の持ち越しで小さくなる |
| 固定小数点・Q 形式 | 整数を決めた 2 のべきで割った値とみなす数の表し方／$`x = X/2^f`$ を Qm.f と書く方法。積は 64 ビットで求め、$`f`$ ビット右へずらして四捨五入する |
| I の分の止まり | 増分が丸めで 0 になる偏差 $`|e| < 2^{-f}/(2K_\mathrm{P}T_\mathrm{s}/T_\mathrm{I})`$。Q16.16、1 ms で 1.5 mrad。I の分だけ小数部を多くして 64 ビットでためる |
| 桁あふれ・飽和演算 | 結果が表せる範囲を越えること（C の符号付き整数では未定義の動作。多くは一周して符号が変わる）／範囲を越えた結果を端の値にする演算。整数部のビット数は最大の値から決める |
| 起動・停止・異常 | 使える読みまで安全な出力。`pid_start()` と、I の分を今の操作量に合わせる。異常（範囲の外・NaN・周期に遅れる・張り付いて動かない）では安全な出力にし、記録し、自動では戻らない |
| 試験の道具 | 周期ごとのログ（リングバッファ）、手動と自動のステップ試験、操作量に正弦波を足して $`-U_\mathrm{c}/U`$ で一巡伝達関数を測る方法、ホストの模型 → HIL → 実機の順の試験 |

この章では、PID を決めた周期で確実に計算し、整数でも桁が足りるようにし、起動・異常・試験のときの扱いを決めた。ここまでの章では、制御器は測った 1 つの制御量だけを見ていた。次章からは、対象の中の複数の量（位置と速度、電流と角速度）をまとめて状態として扱い、すべての状態を使って制御器を決める方法に進む。
