IoT / Embedded Security

動いて理解する IoT セキュリティ

このテーマには 2 つのありがちな失敗があります。一般論だけ知っている——「Root of Trust が重要」と言えるが、目の前の SoC でどう実現するか分からない。データシートだけ読んでいる——「AES アクセラレータがある」と言えるが、それが何を守るのか分かっていない。この全23章は、その両方を埋めます。前半（01〜16章）でベンダに依存しない一般論——脅威、規制、RoT、セキュアブート、鍵の保管、分離、物理攻撃、ライフサイクル、通信——を、後半（17〜23章）でArm・ST・NXP・Espressif・Nordic・Silicon Labs・TI・Microchip・Renesas・Infineonが「その一般論をどの機能で実現しているか」を対応づけます。全章に触って動かせるデモ（LIVE・計 27 点）と、概念を図で示す SVG 図版 107 点を埋め込みました。

第 I 部 — 前提

「攻撃者が現物を手に持てる」という前提の重さと、それを法的義務に変えつつある規制。

CH 01なぜ難しいのか試行回数の制限も監視も効かない。守るのは「割に合わない」まで。▶ LIVE CH 02脅威モデリングと攻撃者の分類誰から、何を、いくらまで守るか。STRIDE と攻撃ツリー。▶ LIVE ×2 CH 03規制と認証の地図CRA・RED・PSTI・IEC 62443・PSA・SESIP。投資判断は法律で決まる。▶ LIVE

第 II 部 — ハードウェアの信頼の基点

全体の背骨。この 5 つは、どのベンダの SoC でも同じ名前で出てきます。

CH 04Root of Trust「信じるしかないもの」を最小にして、ハードウェアに固定する。▶ LIVE ×2 CH 05セキュアブート核心は「公開鍵を OTP のハッシュと照合する」こと。飛ばすと無意味。▶ LIVE CH 06鍵の保管OTP・PUF・鍵ラッピング。CPU に平文の鍵を見せない。▶ LIVE CH 07分離TrustZone・MPU・TEE。鍵を「使えるが読めない」形にする。▶ LIVE CH 08暗号エンジンと乱数乱数が全部の土台。ここが弱いと他が無意味になる。▶ LIVE ×2

第 III 部 — 物理攻撃

数万円の機材でできることと、専用ラボが要ること。線を引くために知っておく。

CH 09サイドチャネル攻撃16 バイトを 1 バイトずつ独立に破れる。2¹²⁸ → 4096。▶ LIVE CH 10フォールトインジェクション電圧をひと突きすると if 文が飛ぶ。保護機能そのものが狙われる。▶ LIVE CH 11ファームウェア抽出攻撃はここから始まる。最も費用対効果の高い対策。▶ LIVE

第 IV 部 — ライフサイクル

工場から廃棄まで。「機器ごとに違う鍵」が最大の防御になります。

CH 12デバイス ID とプロビジョニング工場でどう鍵を入れるか。実は一番難しい部分。▶ LIVE CH 13セキュア OTA署名検証だけでは古い脆弱な版に戻される。ロールバック防止。▶ LIVE CH 14ライフサイクル状態と廃棄RMA のジレンマ、暗号消去、所有権移転。▶ LIVE

第 V 部 — ソフトウェアと通信

セキュアブートは、正規に署名された脆弱なコードを止めません。

CH 15ソフトウェア防御と脆弱性管理メモリ安全・ファジング・SBOM。CRA が要求するのはここ。▶ LIVE CH 16通信のセキュリティ「つながらないから証明書検証を切った」——最も多い失敗。▶ LIVE

第 VI 部 — 各社 SoC の実装

前半の概念が、各社でどう呼ばれ、どの機能に対応するか。

CH 17ArmTrustZone-M・PSA・TF-M。各社の機能はこの上に載る。▶ LIVE CH 18STMicroelectronics — STM32GTZC・製品状態・SAES・SFI。世代差が大きい。▶ LIVE CH 19NXP — i.MX RT / LPC / KinetisPUF・HAB/AHAB・PRINCE・EdgeLock。▶ LIVE CH 20Espressif — ESP32 系機能はある。問題は「有効化されないまま出荷される」こと。▶ LIVE CH 21Nordic・SiLabs・TI・Microchip・Renesas・Infineon各社の設計思想の違い。共通の方向性。▶ LIVE CH 22セキュアエレメントと TPMいつ使い、いつ使わないか。全部入れるのは間違い。▶ LIVE CH 23選定指針とチェックリスト要件から機能へ、機能から品種へ。基板を起こす前に通す。▶ LIVE ×2
