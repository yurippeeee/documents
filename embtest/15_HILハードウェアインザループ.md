# 15. HIL — ハードウェア・イン・ザ・ループ

> **この章のゴール.**
>
> 実機（ハードウェア）を回路の輪の中に置いたまま、**周囲の世界を PC で模擬**して自動テストする
> HIL という枠組みを理解すること。センサ・アクチュエータ・通信相手を偽物（フェイク）に置き換え、
> 再現可能なシナリオを繰り返し流す作り方をつかむ。

## 1. HIL とは何か

3〜14 章の技（電流観測、信号注入、偽センサ、無線スキャン、レイテンシ測定）を**一つの自動テスト装置に束ねた**ものが HIL である。

**HIL（Hardware-in-the-Loop、ハードウェア・イン・ザ・ループ）** とは、テスト対象の実機はそのまま動かし、その**周囲の環境**（センサが感じる世界、アクチュエータがつながる負荷、通信相手）を PC やハードで**模擬（シミュレート）**して、閉じた輪の中で自動テストする方式である。「実機に、偽物の世界を見せて反応を測る」仕組み。


対して、実機を使わずファーム全体を PC 上で走らせる **SIL（Software-in-the-Loop）** もあるが、本書はブラックボックス＝実機主体なので HIL を扱う。

## 2. なぜ HIL が要るのか

- **再現性**: 「気温 −20 ℃、電圧降下、センサ故障」を手で作るのは大変。模擬なら**ボタン一つで何度でも**同じ状況を作れる（2 章の再現性）
- **異常系・危険系**: 実際に高温にしたり短絡させたりせずに、センサが異常値を返す状況を安全に作れる
- **自動化と回帰**: 生成 AI がコードを直すたびに、同じ数百シナリオを**一晩で自動実行**して壊れていないか確かめる（18 章の CI と直結）
- **境界とレア条件**: めったに起きない組み合わせを狙って作れる

## 3. 何を模擬するか — 世界を偽物に

HIL 装置は、実機の各インタフェースに「偽物の相手」をつなぐ。これまでの章の技がそのまま部品になる。

| 実機の口 | 模擬するもの | 使う技（章） |
|---|---|---|
| アナログ入力（センサ） | 温度・圧力などの**偽の電圧**を DAC で与える | 7 章 |
| デジタルセンサ（I²C/SPI） | **偽センサ**として任意の値を返す | 6 章 |
| GPIO/割り込み | ボタン・アラーム・エッジを注入 | 4 章 |
| アクチュエータ出力 | モータ/LED の**負荷を模擬**し、出力を観測 | 3・4 章 |
| 無線・ネットワーク相手 | **偽のペア機器／偽サーバ** | 10・11 章 |
| 電源 | 電圧降下・瞬断を**プログラマブル電源**で | 3 章 |

## 4. HIL 装置の骨格

最小構成は「模擬役のハード＋それを操る PC＋観測系」。

- **模擬・注入ハード**: DAC/ADC/GPIO を持つマイコンボード（自作可、19 章）や計測器。「偽センサ」「偽負荷」を担う
- **観測ハード**: 電流計（PPK2、3 章）、ロジアナ／オシロ（4 章）、sniffer（9・11 章）
- **オーケストレータ（PC）**: シナリオを順に実行し、模擬を設定し、観測を集め、判定する（18 章のハーネス）
- **タイムライン**: 「t=0 で起動 → t=1s で温度異常を注入 → t=1.5s までに警報が出るか」のように、**時刻付きの筋書き**で動かす

```python
# HIL シナリオの疑似コード（オーケストレータ視点）
psu.set_voltage(3.3);   dut.power_on()
fake_temp.set_celsius(25);  wait(1.0)
assert obs.current_state() == "IDLE"          # 平常
fake_temp.set_celsius(85)                      # 異常注入（偽センサ）
assert obs.wait_for("ALARM", timeout=0.5)     # 0.5s 以内に警報（オラクル＋デッドライン, 14 章）
```

## 5. スケールと安全

- **半自動から始める**: 最初は手動＋一部自動でよい。効くと分かった所から機械化する
- **安全設計**: 実機が誤って危険動作（高電流・発熱）をしても装置と人が安全なよう、電流制限・ヒューズ・非常停止を入れる
- **多数機の並行**: 同じ HIL を並べて統計を取る（個体ばらつき、2 章）
- **「模擬 ≠ 現実」**: 偽物は現実の一面しか再現しない。HIL で通っても、最後は本物の環境で確かめる（8 章のグレーボックスと同じ戒め）

## 6. 何をオラクルにするか

- 各シナリオで、状態遷移・出力・タイミングが**時刻付きの期待どおり**
- 異常注入（センサ故障、電圧降下）から**規定の安全動作・回復**をする
- 何百シナリオを**繰り返しても同じ結果**（再現性・回帰）
- 個体をまたいで**ばらつきが許容内**
