## 1. なぜ自作するのか

市販の計測器・アナライザは強力だが、**高価**だったり、**独自プロトコルに未対応**だったり、**自動化に組み込みにくい**ことがある。組み込みテストでは、数百円〜数千円のマイコンと少しのコードで、驚くほど実用的な注入・観測ツールが作れる。「作る／買う」は費用対効果で決める。

## 2. 作る／買うの判断

| 状況 | 寄せ方 |
|---|---|
| 標準プロトコル・高精度・高速が要る | **買う**（ロジアナ、PPK2、オシロ、SDR） |
| 独自プロトコル・特殊な注入・自動化に密結合 | **作る**（マイコン＋スクリプト） |
| 一度きり・探索段階 | まず**既存の糊付け**（3 節） |
| 繰り返す・チームで共有 | **作って**ハーネス（[18 章](18_テスト自動化ハーネスを作る.md#ハーネスを設計する)）に組み込む |

原則: **観測・解析はホストのソフトで**、**リアルタイムな注入・タイミングはマイコンで**分担すると相性がよい。

## 3. 既存ツールを糊で束ねる — 最小の自作

いちばん安上がりな「自作」は、既存ツールを Python で繋ぐこと。

- **CLI をラップ**: `sigrok-cli`（ロジアナ）、`rtl_433`（SDR）、`nmap` を `subprocess` で呼び、出力を解析
- **ファイルを解析**: pcap（`pyshark`/`scapy`）、VCD（波形）、CSV(電流)を読んで判定に使う
- **API を束ねる**: `bleak`＋`ppk2-api`＋`pyvisa` を一つのスクリプトで協調させ、刺激と観測を同時に

これだけで「BLE で書き込みながら電流を録画し、同時にコンソールも監視する」といった多点同時テストが組める。

## 4. マイコンを注入・観測エージェントにする

安価なマイコン（RP2040、ESP32、STM32、FPGA なら iCE40 等）を、PC の手足として使う。**PC はミリ秒でしか動けないが、マイコンはマイクロ秒で正確に動ける**——この役割分担が肝。

- **信号注入器**: GPIO でエッジ・パルス列・タイミングを正確に生成（[04 章](04_デジタル信号の観測.md)）、DAC で偽アナログ（[07 章](07_アナログ周辺とセンサ.md)）、PWM
- **偽センサ／偽バス**: I²C/SPI スレーブを演じて任意の値を返す（[06 章](06_I2CとSPI.md#能動テスト②-周辺-ic-になりすます-偽センサ)）。PIO（RP2040）や FPGA なら難しいタイミングも
- **観測器**: 高速 GPIO サンプリング、割り込みでイベント時刻を記録、ADC で電圧監視
- **PC との口**: USB シリアルで簡単なコマンド（`SET DAC 1200`, `PULSE 3 10us`, `READ?`）を受ける——ホストのハーネス（[18 章](18_テスト自動化ハーネスを作る.md#三層に分ける-抽象化が命)）から叩ける

```
# ホスト側から自作エージェントを叩く（シリアルの簡単プロトコル）
agent.write(b"FAKE_TEMP 850\n")      # 偽 I2C センサに 85.0℃ を返させる
agent.write(b"TRIG?\n"); t = agent.readline()   # 警報 GPIO の立ち上がり時刻を回収
```

## 5. ホスト側の解析ツール

観測データを「意味」に変えるソフトも自作価値が高い。

- **独自プロトコルのデコーダ**: sigrok の**プロトコルデコーダを自作**（Python）して、独自バス／UART コマンドを PulseView で解読
- **波形・ログ解析**: レイテンシのヒストグラム（[14 章](14_タイミングとリアルタイム性.md#レイテンシとジッタを可視化する)）、電流の状態分類（[03 章](03_電源と消費電流から状態を読む.md)）、差分ビット抽出（[12 章](12_サブGHzとSDR.md#変調を解く-生の電波から意味へ)）を numpy で
- **簡易 GUI/可視化**: matplotlib やブラウザで、ウォーターフォール・状態遷移・傾向を描く

## 6. 設計の勘所

- **単純なテキストプロトコル**でホスト⇔エージェントを繋ぐ（デバッグしやすい、行指向）
- **時刻を持たせる**: エージェント側でイベント時刻を打つと、PC の揺れ（[14 章](14_タイミングとリアルタイム性.md#正しい値-だけでは足りない)）を避けられる
- **決定性**: 乱数を使うファザは**シード固定**で再現可能に（[02 章](02_テスト設計の土台.md)・[16 章](16_ファジングと堅牢性.md)）
- **小さく始める**: 1 機能ずつ。効いたらハーネス（[18 章](18_テスト自動化ハーネスを作る.md)）へ昇格
- **文書化**: コマンド表と配線図を残す（次の人＝未来の自分のため）

## 7. 何を大事にするか

- 足りない道具を**安価に**埋め、**自動化に組み込める**
- 注入・観測が**正確な時刻**を持ち、**再現可能**
- 独自プロトコルを**自分でデコード**できる
- 作ったものが**ハーネスから叩ける**共通の口を持つ

## この章のポイント

- 既製品で届かない所は、安いマイコン＋スクリプトで**自作**する。「作る／買う」は費用対効果で
