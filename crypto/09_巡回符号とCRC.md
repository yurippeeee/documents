## 1. 巡回符号 — 「ずらしても符号語」という構造

[07 章](07_線形符号.md#定義)の線形符号は、符号語どうしの XOR がまた符号語になる符号だった。この節では、それに「符号語をずらしても符号語」という条件を加えた**巡回符号**を扱う。この条件があると、符号語を 1 つの多項式の倍数として表せるようになり、符号化と検査が多項式の割り算になる。CRC はこの仕組みを使っている。

### 多項式表現

この章では[04 章 1 節](04_多項式と既約多項式.md#gf-2-係数の多項式)と同じく、ビット列の左端を最高次の係数、右端を定数項とする。長さ$`n`$のビット列$`c_{n-1}c_{n-2}\cdots c_1c_0`$は多項式

$$
c(x) = c_{n-1}x^{n-1} + c_{n-2}x^{n-2} + \cdots + c_1x + c_0
$$

と同じものである。$`c_i`$は$`x^i`$の係数で、添字$`i`$をビットの**位置**と呼ぶ（右端が位置 0）。

### 巡回シフト

長さ$`n`$のビット列の**巡回シフト**とは、左端のビットを右端へ回し、残りを 1 つずつ左へずらす操作である:

$$
c_{n-1}c_{n-2}\cdots c_1c_0 \;\longmapsto\; c_{n-2}\cdots c_1c_0c_{n-1}
$$

```fig
e09_rotate
```

$`n`$回繰り返すと元に戻る。右へ 1 つずらす操作は、左へ$`n-1`$回ずらすのと同じである。

線形符号$`C`$で、どの符号語を巡回シフトしても符号語になるものを**巡回符号**という。左へ 1 回ずらして閉じていれば、何回ずらしても、右へずらしても閉じているので、向きや回数を区別する必要はない。

### 巡回シフトは「x を掛けて x^n + 1 で割った余り」

$`x`$を掛けると各項の次数が 1 上がるので、ビット列は 1 ビット左にずれ、右端に 0 が入る（[05 章 2 節](05_拡大体GF2m.md#乗算-xtime-の繰り返し)の xtime と同じ）。左端のビットは$`x^n`$の項としてはみ出す。はみ出した項を右端に戻すのが、$`x^n + 1`$で割った余りを取る操作である。

**方針**: $`x\,c(x)`$を書き、$`x^n`$を$`x^n + 1`$で割った余りが 1 であることを使って、はみ出した項を定数項に置き換える。

**導出**: $`c(x)`$に$`x`$を掛けると

$$
x\,c(x) = c_{n-1}x^{n} + c_{n-2}x^{n-1} + \cdots + c_1x^2 + c_0x
$$

である。$`x^n = 1\cdot(x^n+1) + 1`$なので$`x^n \equiv 1 \pmod{x^n+1}`$であり、最高次の項$`c_{n-1}x^n`$は定数項$`c_{n-1}`$に置き換わる:

$$
x\,c(x) \bmod (x^n+1) = c_{n-2}x^{n-1} + \cdots + c_1x^2 + c_0x + c_{n-1}
$$

係数を並べると$`c_{n-2}\cdots c_1c_0c_{n-1}`$で、1 回巡回シフトしたものになっている ∎

```fig
e09_xshift
```

$`\mathrm{GF}(2)`$では$`-1 = 1`$なので、$`x^n - 1`$と$`x^n + 1`$は同じ多項式である。教科書によっては$`x^n - 1`$と書くが、この章では$`x^n+1`$と書く。

ビット列を回すという操作が、$`x`$を掛けて余りを取るという多項式の計算に置き換わった。これにより、多項式の割り算や因数分解の性質を符号の解析に使えるようになる。

### 生成多項式

**定理**: 0 以外の符号語を含む長さ$`n`$の巡回符号$`C`$について、0 でない符号語のうち次数が最小のものを$`g(x)`$とする。このとき$`g`$は$`x^n + 1`$を割り切り、

$$
C = \{\, u(x)\,g(x) \;:\; u = 0 \text{ または } \deg u < n - \deg g \,\}
$$

である。この$`g`$を$`C`$の**生成多項式**、掛ける側の$`u`$を**情報多項式**という。

次数が最小の 0 でない符号語は 1 つしかない。2 つあれば、その和は最高次の項が消えて次数がより小さい 0 でない符号語になるからである。

**方針**: まず「$`g`$の倍数を$`x^n+1`$で割った余りは符号語」という補題を示す。それを使って、(i) $`g`$の倍数で次数が$`n`$未満のものは符号語、(ii) 符号語はすべて$`g`$の倍数、(iii) $`g`$は$`x^n+1`$を割り切る、の 3 つを示す。

**補題**: 任意の多項式$`a`$について、$`a\,g`$を$`x^n + 1`$で割った余りは符号語である。

$`g`$は符号語で、$`x`$を掛けて$`x^n+1`$で割った余りを取ると 1 回巡回シフトしたものになるので、また符号語である。これを$`j`$回繰り返すと、$`x^j g \bmod (x^n+1)`$も符号語である（途中で余りを取ってもよいことは[04 章 2 節](04_多項式と既約多項式.md#合同式の記法)）。
$`a\,g`$は、$`a`$の係数が 1 の項$`x^j`$について$`x^j g`$を足したものである。余りを取ってから足しても結果は同じなので、$`a\,g \bmod (x^n+1)`$は符号語の和であり、線形性より符号語である ∎

**(i)** $`\deg(u g) < n`$なら、$`u g`$を$`x^n+1`$で割った余りは$`u g`$自身なので、補題より$`u g`$は符号語である。

**(ii)** 符号語$`c`$を$`g`$で割って$`c = q g + r`$（$`r = 0`$または$`\deg r < \deg g`$）とする。$`\deg(qg) \leq \deg c < n`$なので (i) より$`qg`$は符号語であり、$`r = c + qg`$は符号語の和として符号語である。
$`g`$は 0 でない符号語のうち次数が最小だったので、$`\deg r < \deg g`$の符号語$`r`$は 0 しかない。よって$`c = qg`$である。

**(iii)** $`x^n + 1`$を$`g`$で割って$`x^n + 1 = q'g + r'`$とする。この式から$`q'g = 1\cdot(x^n + 1) + r'`$で、$`\deg r' < \deg g < n`$なので、$`r'`$は$`q'g`$を$`x^n+1`$で割った余りである。補題より$`r'`$は符号語であり、(ii) と同じ理由で$`r' = 0`$、すなわち$`g`$は$`x^n+1`$を割り切る ∎

**情報ビットの数**: $`u`$は 0 か次数$`n - \deg g`$未満の多項式なので、係数の選び方は$`2^{n-\deg g}`$通りある。異なる$`u_1, u_2`$からは異なる符号語ができる。$`u_1 g = u_2 g`$なら$`(u_1+u_2)g = 0`$で、0 でない多項式どうしの積は 0 にならない（[04 章 1 節](04_多項式と既約多項式.md#乗算)の次数の性質）ので$`u_1 + u_2 = 0`$だからである。
したがって符号語は$`2^{n-\deg g}`$個で$`k = n - \deg g`$、つまり$`\deg g = n - k`$は検査ビットの数である。

### 例: 長さ 7 の巡回符号とハミング符号

$`x^7+1`$は次のように因数分解できる（右辺を展開すると確かめられる）:

$$
x^7 + 1 = (x+1)(x^3+x+1)(x^3+x^2+1)
$$

$`g = x^3+x+1`$（ビット列`1011`）は$`x^7+1`$を割り切るので、長さ 7 の巡回符号の生成多項式になる。$`\deg g = 3`$なので$`k = 4`$で、$`(7,4)`$符号である。16 個の符号語$`u(x)g(x)`$を、巡回シフトで移り合うものごとにまとめると次のようになる。

どの符号語も、巡回シフトを繰り返すと同じ組の中を回り、組の外へは出ない。0 でない符号語の重みの最小は 3（$`g`$自身など）なので、[07 章 1 節](07_線形符号.md#最小距離は-0-でない符号語の最小の重み)より$`d_{\min} = 3`$である。

**ハミング符号との関係**: 長さ 7 のビット列$`y`$が符号語かどうかは、(i) と (ii) より$`y \bmod g`$が 0 かどうかで判定できる。余りを取ってから足しても結果は同じなので

$$
y \bmod g = \sum_{i \,:\, y_i = 1} \left( x^i \bmod g \right)
$$

である（和は$`y`$の 1 が立つ位置$`i`$についての XOR）。$`x^i \bmod g`$（$`i = 6, \dots, 0`$）を 3 ビットの縦の列にして並べると、次の表になる。

### 巡回符号が実装に有利な理由

[07 章 2 節](07_線形符号.md#生成行列-g-符号化の装置)の一般の線形符号では、符号化に$`k \times n`$個の成分を持つ生成行列$`G`$が要った。巡回符号なら、$`n - k + 1`$ビットの生成多項式$`g`$を 1 本持てばよい。
符号化も検査も多項式の割り算なので、シフトレジスタと XOR で実装でき、ハードウェアでは少ないゲートで作れる（5 節）。

## 2. CRC の手順

CRC は、データの後ろに「生成多項式$`g`$で割った余り」を付けて、全体を$`g`$の倍数にしてから送る方式である。受信者は、受け取ったビット列が$`g`$で割り切れるかどうかで誤りを検出する。

### 符号化（送信側）

データを$`k`$ビット、生成多項式$`g(x)`$の次数を$`r`$とする。送るビット列（符号語）の長さは$`n = k + r`$である。この章の$`r`$は次数を表し、余りの多項式は大文字$`R(x)`$で書く。

1. データのビット列を多項式$`m(x)`$と見なす。
2. $`x^r`$を掛ける。ビット列では、データの後ろに 0 を$`r`$個並べることに当たる。
3. $`x^r m(x)`$を$`g(x)`$で割った余り$`R(x)`$を求める。$`\deg R < r`$なので、$`R`$は$`r`$ビットで書ける。
4. 送信する符号語を$`T(x) = x^r m(x) + R(x)`$とする。ビット列では、データの後ろに余りの$`r`$ビットを付けたものである。

$$
\boxed{T(x) = x^r m(x) + R(x), \qquad R(x) = x^r m(x) \bmod g(x)}
$$

```fig
e09_frame
```

$`T`$の前半にはデータがそのまま現れるので、CRC は[07 章 2 節](07_線形符号.md#組織符号形式-系統形式)の組織符号である。後ろに付けた$`r`$ビットを**検査ビット**と呼ぶ。

### T は必ず g で割り切れる

**方針**: 手順 3 の割り算の結果を式に書き、$`T`$の式に代入する。

**導出**: 割り算の結果を$`x^r m(x) = q(x)g(x) + R(x)`$と書く。これを$`T`$の式に代入すると

$$
T(x) = x^rm(x) + R(x) = q(x)g(x) + R(x) + R(x) = q(x)g(x)
$$

である。$`\mathrm{GF}(2)`$では$`R + R = 0`$だからである。よって$`T(x)`$は$`g(x)`$で割り切れる ∎

整数なら割り切れる形にするには余りを引く必要があるが、$`\mathrm{GF}(2)`$では引き算と足し算が同じなので、余りをそのまま後ろに付けるだけで済む。
1 節の言葉で言えば$`T = q\,g`$で、商$`q`$が情報多項式に当たる。CRC は、同じ$`g`$の倍数を「データが前半にそのまま現れる形」で作る方法である。

### CRC は短縮巡回符号

$`k`$ビットのデータすべてについて$`T`$を作ると、異なるデータからは異なる$`T`$ができ（$`T`$の前半がデータそのもの）、どの$`T`$も$`g`$の倍数で次数が$`n`$未満である。$`g`$の倍数で次数が$`n`$未満の多項式$`q\,g`$（$`q = 0`$または$`\deg q < k`$）も$`2^k`$個しかないので、$`T`$全体は「$`g`$の倍数で次数が$`n`$未満のもの全体」と一致する。これは 1 節の定理の形と同じである。

ただし 1 節の巡回符号では$`g`$が$`x^n+1`$を割り切る必要があった。CRC ではデータの長さ$`k`$が用途ごとに変わり、$`n`$をそのように選ぶとは限らない。
$`g`$が$`x^L+1`$を割り切る長さ$`L`$（4 節 (b) で**周期**として調べる）を 1 つ取ると、長さ$`L`$の巡回符号ができる。データが$`L - r`$ビットより短いときは、データの前に 0 を補って長さ$`L`$の符号語を作り、補った 0 は送らない。前に付けた 0 は多項式の値を変えないので、送る部分は上の手順で作った$`T`$そのものである。
これは[08 章 4 節](08_ハミング符号.md#ecc-メモリ-短縮した拡張ハミング符号)の**短縮符号**（一部の情報ビットを常に 0 として送らない符号）であり、CRC は巡回符号を短縮した**短縮巡回符号**である。$`g`$で割り切れるかどうかで検査するという仕組みは、そのまま使える。


### 検査（受信側）

受信者は受け取ったビット列$`T'(x)`$を$`g(x)`$で割り、余りが 0 なら誤り無し、0 でなければ誤り有りと判定する。
反転した位置に 1 が立ったビット列を**誤りパターン**$`E(x)`$とすると（[07 章 4 節](07_線形符号.md#シンドローム-誤りの-指紋)）、$`T'(x) = T(x) + E(x)`$である。$`T`$は$`g`$で割り切れ、余りを取ってから足しても結果は同じなので

$$
T'(x) \bmod g(x) = E(x) \bmod g(x)
$$

である。

```fig
e09_check
```

[07 章 4 節](07_線形符号.md#シンドローム-誤りの-指紋)のシンドロームと同じく、**余りは送ったデータによらず、誤りパターンだけで決まる**。したがって

$$
\text{CRC が誤りを見逃す} \iff E(x) \neq 0 \text{ かつ } E(x) \text{ が } g(x) \text{ の倍数}
$$

であり、どんな誤りを検出できるかは、どんな$`E(x)`$が$`g(x)`$で割り切れるかという問題になる。4 節でこれを調べる。

## 3. 手計算の実例

## 4. CRC の検出能力 — どんな誤りを見逃さないか

$`g(x)`$の次数を$`r`$とする。2 節より、CRC が誤りを見逃すのは、誤りパターン$`E(x)`$が 0 でない$`g`$の倍数のときだけである。誤りの起き方を次のように分け、それぞれ$`E`$が$`g`$の倍数にならない条件を調べる。

```fig
e09_errpat
```

### 準備: x のべきを取り除く補題

**補題**: $`g`$の定数項が 1 なら、$`g`$が$`x^i A(x)`$を割り切るとき、$`g`$は$`A(x)`$を割り切る。

**方針**: $`i = 1`$の場合を、拡張ユークリッドの互除法で得られる等式で示す。$`i \geq 2`$の場合はそれを$`i`$回繰り返せばよい。

**導出**:
- $`\gcd(g, x) = 1`$である。$`x`$を割り切る多項式は$`1`$と$`x`$だけで（$`x = d\,e`$と書くと次数の和が 1 なので、$`d`$は次数 0 の$`1`$か、$`e = 1`$となる$`x`$自身）、定数項が 1 の$`g`$は$`x`$で割り切れない（[04 章 3 節](04_多項式と既約多項式.md#判定法-低次の場合)）からである。
- 拡張ユークリッドの互除法（[04 章 5 節](04_多項式と既約多項式.md#最大公約多項式とユークリッドの互除法)）より、$`u\,g + v\,x = 1`$となる多項式$`u, v`$がある。
- 両辺に$`A`$を掛けると$`A = u A g + v\,(xA)`$である。$`g`$が$`xA`$を割り切るなら、右辺の 2 項はどちらも$`g`$で割り切れるので、$`A`$も$`g`$で割り切れる。
- $`g`$が$`x^iA = x\,(x^{i-1}A)`$を割り切るなら、上の議論で$`g`$は$`x^{i-1}A`$を割り切る。これを$`i`$回繰り返すと$`g`$は$`A`$を割り切る ∎

**例**: $`g = x^3+x+1`$なら$`g = x\,(x^2+1) + 1`$なので、$`u = 1`$、$`v = x^2+1`$とすれば$`u\,g + v\,x = (x^3+x+1) + (x^3+x) = 1`$である。

実用の生成多項式はどれも定数項が 1 なので、以下ではそれを仮定する。

### (a) すべての 1 ビット誤り

1 ビット誤りは$`E(x) = x^i`$である。$`g`$が$`x^i = x^i \cdot 1`$を割り切るとすると、補題（$`A = 1`$）より$`g`$は 1 を割り切ることになるが、$`\deg g = r \geq 1`$なのでありえない。

**→ 1 ビット誤りは必ず検出される。**

### (b) すべての 2 ビット誤り

$`E(x) = x^i + x^j = x^i(1 + x^{j-i})`$（$`i<j`$）である。補題より、$`g`$が$`E`$を割り切るなら$`g`$は$`1 + x^{j-i}`$を割り切る。

$`g`$が$`1+x^L`$を割り切る最小の正の整数$`L`$を$`g`$の**周期**という。$`g`$が$`1 + x^L`$を割り切ることは$`x^L \equiv 1 \pmod g`$と同じなので、周期は$`g`$を法とする$`x`$の位数（[04 章 4 節](04_多項式と既約多項式.md#原始多項式-既約よりさらに強い条件)）である。

**$`g`$が$`1 + x^a`$を割り切るのは、$`a`$が周期$`L`$の倍数のときに限る。**

**方針**: [03 章 3 節](03_有限体GFp.md#原始元の個数)の段階 2 と同じく、$`a`$を$`L`$で割った余りに注目する。

**導出**: $`a = qL + s`$（$`0 \le s < L`$）と書くと、$`x^a = (x^L)^q\, x^s \equiv 1^q \cdot x^s = x^s \pmod g`$である。$`0 < s < L`$なら、$`L`$が最小であることから$`x^s \not\equiv 1`$である。よって$`x^a \equiv 1 \iff s = 0 \iff a`$は$`L`$の倍数 ∎

したがって$`0 < j - i < L`$なら$`g`$は$`1 + x^{j-i}`$を割り切らず、その 2 ビット誤りは検出される。符号語の長さを$`n`$とすると$`j - i \leq n - 1`$なので、**$`n \leq L`$ならすべての 2 ビット誤りを検出できる**。
逆に$`n > L`$なら、位置 0 と位置$`L`$の 2 ビット誤り$`E = x^L + 1`$は$`g`$の倍数なので見逃す。

```fig
e09_period
```

周期の値は、生成多項式の形で決まる。
- **$`g`$が次数$`r`$の原始多項式**なら、定義より$`L = 2^r - 1`$である。CRC-32 の多項式は原始多項式で、$`L = 2^{32}-1 \approx 4.3 \times 10^9`$ビット（約 512 MiB）まで 2 ビット誤りを必ず検出する。
- **$`g = (x+1)p(x)`$で、$`p`$が次数$`r-1`$の原始多項式**なら、$`L = 2^{r-1} - 1`$である。CRC-16 の 2 種類（下の表）はこの形で、$`L = 2^{15}-1 = 32767`$ビットまで 2 ビット誤りを必ず検出する。

後者の理由を示す。

**方針**: 「$`g`$が$`1 + x^a`$を割り切る」と「$`p`$が$`1 + x^a`$を割り切る」が同じであることを示す。後者は、$`p`$の周期$`2^{r-1}-1`$の倍数の$`a`$でちょうど起きる。

**導出**: $`g`$が割り切れば、その因数の$`p`$も割り切る。逆に$`p`$が割り切るとして、$`1 + x^a = p\,h`$と書く。$`x = 1`$を代入すると、左辺は$`1 + 1 = 0`$、右辺は$`p(1)\,h(1)`$である。$`p`$は次数 2 以上の既約多項式なので$`x+1`$で割り切れず、[04 章 3 節](04_多項式と既約多項式.md#判定法-低次の場合)より$`p(1) = 1`$である。したがって$`h(1) = 0`$で、$`h`$は$`x+1`$で割り切れ、$`h = (x+1)h'`$と書ける。すると$`1 + x^a = (x+1)p\,h' = g\,h'`$となり、$`g`$も割り切る ∎

### (c) すべての奇数個の誤り

**定理**: $`g(x)`$が$`x+1`$を因数に持つなら、奇数個のビット誤りを必ず検出する。

**方針**: 係数 1 の項を奇数個持つ$`E`$は$`x+1`$で割り切れないことを、[04 章 3 節](04_多項式と既約多項式.md#判定法-低次の場合)の判定（項の個数が偶数 ⇔ $`x+1`$で割り切れる）で示す。$`g`$が$`x+1`$の倍数なら、$`g`$の倍数もすべて$`x+1`$の倍数である。

**導出**: $`E`$の項の個数が奇数なら、04 章の判定より$`E`$は$`x+1`$で割り切れない。一方$`g = (x+1)h`$なので、$`E`$が$`g`$の倍数$`E = gq`$なら$`E = (x+1)(hq)`$は$`x+1`$で割り切れる。矛盾するので$`E`$は$`g`$の倍数でない ∎

**→ $`g`$が$`x+1`$を因数に持てば、奇数個の誤りはすべて検出される。**

### (d) 長さ r 以下のバースト誤り

**バースト誤り**とは、連続する区間の中で起きる誤りである。区間の長さ$`b`$は最初の誤りから最後の誤りまでを数えるので、両端は必ず誤りで、中は誤っていてもいなくてもよい。長さ$`b`$のバーストは

$$
E(x) = x^i \cdot B(x), \qquad B(x) = x^{b-1} + (\text{中間の項}) + 1
$$

と書ける。$`x^i`$はバーストの右端の位置$`i`$を表す。$`B`$は両端が誤りなので最高次$`x^{b-1}`$と定数項の係数が 1 で、$`\deg B = b - 1`$である。

```fig
e09_burst
```

**$`b \leq r`$のとき**: 補題より、$`g`$が$`E`$を割り切るなら$`g`$は$`B`$を割り切る。ところが 0 でない$`g`$の倍数は次数が$`r`$以上であり、$`B \neq 0`$で$`\deg B = b-1 < r`$なので、$`B`$は$`g`$の倍数ではない。よって$`E`$は$`g`$の倍数でない ∎

**→ 長さ$`r`$以下のバースト誤りはすべて検出される。**

これが CRC の最大の強みである。実際の通信では、各ビットが独立に誤るより、電気的なノイズやディスクの傷、無線の電波の落ち込みで連続した数ビットがまとめて壊れることが多い。CRC-32 なら長さ 32 ビット以下のバーストはすべて検出される。

### (e) 長さ r+1 以上のバースト

バーストの両端は 1 に決まっているので、中間の$`b - 2`$ビットの$`2^{b-2}`$通りがすべて同じ確率で起きるとして、見逃す割合を求める。

**方針**: 見逃すのは$`B`$が$`g`$の倍数のときなので、$`B = g\,q`$となる$`B`$の個数を、$`q`$の個数として数える。

**導出**: $`B = g\,q`$とすると、$`\deg q = (b-1) - r`$である。積の最高次の係数は最高次どうしの積、定数項は定数項どうしの積なので、$`B`$と$`g`$の両端が 1 であることから、$`q`$も最高次と定数項が 1 でなければならない。逆にそのような$`q`$なら、$`g\,q`$は両端が 1 で長さ$`b`$のバーストの形になる。
- $`b = r+1`$なら$`\deg q = 0`$で、$`q = 1`$の 1 通りしかない（$`B = g`$）。見逃す割合は$`1/2^{r-1} = 2^{-(r-1)}`$である。
- $`b \geq r+2`$なら$`\deg q = b-1-r \geq 1`$で、最高次と定数項を除く$`b-2-r`$個の係数が自由なので$`2^{b-2-r}`$通りある。見逃す割合は$`2^{b-2-r}/2^{b-2} = 2^{-r}`$である ∎

```fig

```

CRC-32 なら、長さ 34 ビット以上のバーストを見逃す割合は$`2^{-32} \approx 2.3\times10^{-10}`$である。

### 標準的な生成多項式

生成多項式は、最高次$`x^r`$の係数（必ず 1）を省いた下位$`r`$ビットを 16 進で書くのが慣例である。たとえば CRC-32 の 0x04C11DB7 は、[04 章](04_多項式と既約多項式.md#実務で使われる既約多項式)で最高次まで含めて書いた 0x104C11DB7 と同じ多項式である。

| 名前 | $`r`$ | 生成多項式（16 進） | $`x+1`$を因数に持つか | 周期$`L`$ | 主な用途 |
|---|---|---|---|---|---|
| CRC-8 | 8 | 0x07 | 持つ | 127 | SMBus、センサ |
| CRC-16-IBM | 16 | 0x8005 | 持つ | 32767 | Modbus、USB |
| CRC-16-CCITT | 16 | 0x1021 | 持つ | 32767 | X.25、Bluetooth、SD カード |
| **CRC-32** | 32 | **0x04C11DB7** | 持たない（原始多項式） | $`2^{32}-1`$ | **Ethernet、ZIP、PNG、gzip** |
| CRC-32C | 32 | 0x1EDC6F41 | 持つ | $`2^{31}-1`$ | iSCSI、ext4、Btrfs（CPU 命令あり） |
| CRC-64 | 64 | 0x42F0E1EBA9EA3693 | 持つ | 約$`8.6\times10^{9}`$ | XZ、ストレージ |

CRC-8、2 種類の CRC-16、CRC-32C は、$`x+1`$と原始多項式の積の形なので、(b) と (c) の両方の保証がある。**CRC-32（Ethernet などで使う 0x04C11DB7）は既約多項式なので$`x+1`$を因数に持たず**、奇数個の誤りの検出は保証されない。その代わり原始多項式なので、(b) の 2 ビット誤りを非常に長い符号語まで保証する。
CRC-64 は$`x+1`$を 2 個含み、残りも複数の既約多項式の積で、(b) の 2 つの形のどちらでもない。表の周期は計算機で$`x`$の位数を求めた値である。

## 5. 実装 — シフトレジスタと表引き

### 筆算をレジスタで行う

3 節の筆算の各段で見ているのは、「今の余り$`r`$ビット」と「次に下ろす 1 ビット」だけである。そこで$`r`$ビットを入れる箱（**レジスタ**）を 1 つ用意し、1 ビットずつ次の操作を繰り返す。1 回の操作を**クロック**という。

1. レジスタ全体を 1 ビット左にずらし、右端に入力の次のビットを入れる。
2. 左端からはみ出したビットが 1 なら、$`g`$の下位$`r`$ビット（最高次の 1 を除いたもの）をレジスタに XOR する。

入力は筆算と同じく、データの後ろに 0 を$`r`$個並べた$`k + r`$ビットである。

**方針**: 入力の先頭から$`t`$ビットを多項式と見たものを$`P_t`$とし、$`t`$クロック後のレジスタが$`P_t \bmod g`$であることを、$`t`$を 1 つずつ増やして示す。

**導出**: $`t = 0`$ではレジスタも$`P_0`$も 0 である。次の入力ビットを$`b`$とすると$`P_{t+1} = x P_t + b`$で、途中で余りを取ってよいので

$$
P_{t+1} \bmod g = \bigl(x\,(P_t \bmod g) + b\bigr) \bmod g
$$

である。$`P_t \bmod g`$は次数$`r`$未満なので、$`x`$を掛けて$`b`$を足した括弧の中は次数$`r`$以下である。その$`x^r`$の係数（はみ出したビット）が 1 なら$`g`$を 1 回 XOR すれば次数が$`r`$未満になり、0 ならそのままでよい。これが 1. と 2. の操作である ∎

全$`k+r`$ビットを入れ終えると、レジスタは$`P_{k+r} \bmod g = x^r m(x) \bmod g = R(x)`$になる。3 節の例で確かめると、レジスタの値は筆算の各段の余りと一致する。

```fig
e09_regsteps
```

### 0 を付け足さずに済ませる

上の方法では、データの後の 0 を入れる$`r`$クロックが余分にかかる。データのビットを右端から入れる代わりに、**左端からはみ出すビットに XOR する**と、この$`r`$クロックが要らなくなる。実際の回路やプログラムはこの形である。

1. レジスタの左端のビットと、データの次のビットの XOR を取る。これを**帰還ビット**$`f`$とする。
2. レジスタを 1 ビット左にずらし、右端に 0 を入れる。
3. $`f = 1`$なら、$`g`$の下位$`r`$ビットをレジスタに XOR する。

**方針**: データの先頭から$`t`$ビットを多項式と見たものを$`M_t`$とし、$`t`$クロック後のレジスタが$`x^r M_t \bmod g`$であることを示す。データ$`k`$ビットを入れ終えた時点で、レジスタは$`x^r m(x) \bmod g = R(x)`$になる。

**導出**: 次のデータビットを$`b`$とすると$`M_{t+1} = x M_t + b`$なので、$`x^r M_{t+1} = x\,(x^r M_t) + b\,x^r`$であり

$$
x^r M_{t+1} \bmod g = \bigl(x\,(x^rM_t \bmod g) + b\,x^r\bigr) \bmod g
$$

である。右辺の括弧の中は次数$`r`$以下で、その$`x^r`$の係数は「左端からはみ出したビット」と$`b`$の XOR、つまり帰還ビット$`f`$である。$`f = 1`$なら$`g`$を 1 回 XOR すれば次数が$`r`$未満になる。これが 1.〜3. の操作である ∎

$`g = x^3+x+1`$のときの回路と、データ`1101`を入れたときの動きを次に示す。4 クロックで余り`001`が得られ、3 節の筆算と一致する。

### C 言語のビットごとの実装

C 言語で書く。記号の意味: `^` は XOR、`<<`/`>>` は左/右シフト、`&` はビットごとの AND、`data[i]` は$`i`$番目の入力バイト、`? :` は「条件 ? 真のとき : 偽のとき」。
CRC-32 の生成多項式（$`r = 32`$）を使い、上の「0 を付け足さない」方法を 32 ビットのレジスタ`crc`で行う。

```c
uint32_t crc32_plain(const uint8_t *data, size_t len) {
    uint32_t crc = 0;                       // レジスタ（最初は 0）
    for (size_t i = 0; i < len; i++) {
        crc ^= (uint32_t)data[i] << 24;     // 入力の 8 ビットを左端の 8 ビットに XOR
        for (int b = 0; b < 8; b++) {
            crc = (crc & 0x80000000)        // 左端のビットが 1 なら
                ? (crc << 1) ^ 0x04C11DB7   // ずらして g の下位 32 ビットを XOR
                : (crc << 1);               // 0 ならずらすだけ
        }
    }
    return crc;                             // 余り R
}
```

- 0x04C11DB7 は 4 節の表のとおり最高次$`x^{32}`$を省いた表記で、$`g`$の下位 32 ビットそのものである。`crc << 1`で 32 ビットからあふれた左端の 1 が$`x^{32}`$の項に当たり、それと合わせて$`g`$全体を XOR したことになる。
- 帰還ビットを 1 ビットずつ作る代わりに、入力の 8 ビットをまとめて左端の 8 ビットに XOR している。各入力ビットはちょうどレジスタの左端に来たときに判定に使われ、XOR は順番を入れ替えても結果が変わらないので、1 ビットずつ XOR するのと同じ結果になる。

`"123456789"`（9 バイト）に対して、この関数は 0x89A1897F を返す。実際に使われている CRC-32 はこれと違う値になる。その理由は 6 節で扱う。

### テーブル駆動（実用の定番）

1 バイト（8 クロック）分の処理を、表引き 1 回で済ませる。

```c
uint32_t table[256];
void make_table(void) {
    for (int i = 0; i < 256; i++) {
        uint32_t c = (uint32_t)i << 24;
        for (int b = 0; b < 8; b++)
            c = (c & 0x80000000) ? (c << 1) ^ 0x04C11DB7 : (c << 1);
        table[i] = c;
    }
}

uint32_t crc32_plain_table(const uint8_t *data, size_t len) {
    uint32_t crc = 0;
    for (size_t i = 0; i < len; i++)
        crc = (crc << 8) ^ table[((crc >> 24) ^ data[i]) & 0xFF];
    return crc;
}
```

**なぜ表にできるのか**: 入力バイトを左端の 8 ビットに XOR した後の 8 クロックで、「左端が 1 か」の判定に使われるのは、そのときの左端 8 ビットだけである。右側の 24 ビットは 8 ビット左にずれるだけで、左端に届く前に 8 クロックが終わるので判定には関わらない。
したがって 8 クロックの結果は、「右側の 24 ビットを 8 ビット左にずらしたもの」と「左端 8 ビットの値だけから決まる 32 ビット」の XOR になる。後者を左端 8 ビットの 256 通りについて前もって計算したのが`table`である。

```fig
e09_table
```

### ハードウェア命令

- **CRC-32C**: Intel/AMD の `CRC32` 命令、ARM の `CRC32C` 系命令で計算できる
- **任意の poly**: キャリーレス乗算の命令 `PCLMULQDQ`（[04 章 1 節](04_多項式と既約多項式.md#乗算)）を使うと、毎秒数 GB の速度で計算できる

### 線形性

ここまでの計算は XOR とシフトだけでできている。このことから、6 節と 7 節で使う次の性質が成り立つ。上の`crc32_plain`のように、レジスタを 0 から始めて余りをそのまま返す CRC を**素の CRC**と呼び、その値を$`\mathrm{CRC}_0(a)`$と書く。同じ長さのデータ$`a, b`$について

$$
\mathrm{CRC}_0(a \oplus b) = \mathrm{CRC}_0(a)\oplus\mathrm{CRC}_0(b)
$$

である。$`\mathrm{CRC}_0(a)`$は$`x^r a(x) \bmod g`$で、余りを取ってから足しても結果は同じ（$`(A + B) \bmod g = (A \bmod g) + (B \bmod g)`$）だからである。

## 6. 実装パラメータ — 同じ多項式でも値が合わない理由

同じ「CRC-32」でも、次の 5 つのパラメータが違うと値が一致しない。

| パラメータ | 意味 | CRC-32 (Ethernet) の値 |
|---|---|---|
| **poly** | 生成多項式（最高次を省いた 16 進） | 0x04C11DB7 |
| **init** | 計算を始めるときのレジスタの値 | 0xFFFFFFFF |
| **refin** | 入力の各バイトのビット順を反転して処理するか | true |
| **refout** | 最後にレジスタのビット順を反転して出力するか | true |
| **xorout** | 最後に XOR する値 | 0xFFFFFFFF |

5 節の`crc32_plain`は、init = 0、refin = refout = false、xorout = 0 の場合である。以下、init と xorout が何を防ぐか、refin と refout が何をしているかを順に見る。

### init — 先頭に増えた 0 を見えるようにする

init = 0 の素の CRC では、データの先頭に 0 が何個付いても余りが変わらない。多項式として先頭の 0 は係数 0 の高次の項で、何も足していないのと同じだからである。
通信では同期がずれて 0 のバイトが余分に入ったり抜けたりすることがあり、これを検出したい。init を 0 以外にすると、先頭の 0 を処理するたびにレジスタの中身が変わるので、0 の個数が結果に反映される。

```fig
e09_init
```

CRC-32 でも、init = 0 なら 2 バイトのデータ`12 34`（16 進）と、先頭に 0 を 2 バイト付けた`00 00 12 34`の値は同じ（0x77951E50）になる。init = 0xFFFFFFFF なら 2 つは違う値になる。

**init は決まった値を XOR するのと同じ**: レジスタの操作は XOR とシフトだけなので、初期値$`I`$から始めた結果は、「初期値 0 からデータを処理した結果」と「初期値$`I`$から同じ長さの 0 だけのデータを処理した結果」の XOR になる。後者はデータの長さだけで決まる。
つまり同じ長さのデータについては、init は素の CRC の値に決まった値を XOR するだけである。受信側も同じ値を XOR するので、誤りを見逃す条件（4 節）は init = 0 のときと変わらない。

### refin・refout — ビットを送る順番に合わせる

Ethernet などのシリアル通信では、1 バイトを最下位ビットから順に送る。CRC を送る順番どおりのビット列で計算するため、各バイトのビット順を反転してから処理し（refin）、最後のレジスタもビット順を反転して出力する（refout）。

```fig
e09_reflect
```

ビット順を反転したデータで計算する代わりに、レジスタの向きを逆にしても同じ計算になる。「左端」が「右端」に、「左シフト」が「右シフト」に、生成多項式もビット順を逆にした 0xEDB88320 になり、次のように書ける。

```c
uint32_t crc32_ethernet(const uint8_t *data, size_t len) {
    uint32_t crc = 0xFFFFFFFF;              // init
    for (size_t i = 0; i < len; i++) {
        crc ^= data[i];                     // 右端の 8 ビットに入力（ビット順の反転を兼ねる）
        for (int b = 0; b < 8; b++) {
            crc = (crc & 1)
                ? (crc >> 1) ^ 0xEDB88320   // 右端が 1 なら、反転した g を XOR
                : (crc >> 1);
        }
    }
    return crc ^ 0xFFFFFFFF;                // xorout
}
```

### xorout — 末尾に増えた 0 を見えるようにする

2 節の検査では、受信者は受け取ったビット列全体（データと検査ビット）を$`g`$で割り、余りが 0 かを見た。送った符号語$`T`$は$`g`$の倍数なので、その後ろに 0 が付け足されても（$`x^jT`$も$`g`$の倍数）余りは 0 のままで、増えた 0 に気づけない。init はデータの先頭に効くだけなので、これは防げない。
検査ビットに xorout を XOR してから送ると、全体を割った余りは 0 ではなく、データによらない決まった値になる。後ろに 0 が増えるとこの値が変わるので、増えた 0 を検出できる。

```fig
e09_xorout
```

受信側は、全体の余りがこの決まった値になるかを見ればよい。たとえば CRC-32 の関数で、データとその CRC 値（4 バイトを下位バイトから順に付けたもの）をまとめて計算し直すと、データによらず 0x2144DF1C になる。
xorout も、同じ長さのデータには決まった値を XOR するだけなので、誤りを見逃す条件（4 節）は変わらない。

### 実装ごとの値の違い

`"123456789"`に対して、5 節の`crc32_plain`は 0x89A1897F、init と xorout だけを加えたもの（refin = refout = false。**CRC-32/BZIP2** と呼ばれる変種）は 0xFC891918、上の`crc32_ethernet`は 0xCBF43926 を返す。3 つとも同じ生成多項式で割っているが、値はすべて違う。
教科書どおりの割り算だけで実装すると、既存のシステムと値が合わない。実装するときは、この 5 つのパラメータを必ず確認する。

## 7. CRC の限界 — 「改ざん検知」には使えない

CRC は偶然に起きた誤りを検出するためのもので、悪意のある改ざんは防げない。理由は 2 つある。

**(1) 線形性**: 5 節のとおり、素の CRC は$`\mathrm{CRC}_0(a \oplus b) = \mathrm{CRC}_0(a)\oplus\mathrm{CRC}_0(b)`$を満たす。init と xorout があっても、6 節のとおり同じ長さのデータには決まった値$`K`$を XOR するだけである（refin と refout はビットの並べ替えなので、XOR の関係を崩さない）。

**方針**: パラメータ付きの CRC を$`\mathrm{CRC}(a) = L(a) \oplus K`$と書く。$`L`$は XOR について線形な計算（$`L(a \oplus b) = L(a) \oplus L(b)`$）で、$`K`$は長さだけで決まる値である。改ざん前後の差を取ると$`K`$が打ち消し合うことを使う。

**導出**: データ$`m`$の一部を、反転したい位置に 1 が立ったビット列$`\Delta`$で書き換えて$`m \oplus \Delta`$にすると

$$
\mathrm{CRC}(m \oplus \Delta) \oplus \mathrm{CRC}(m) = L(m) \oplus L(\Delta) \oplus K \oplus L(m) \oplus K = L(\Delta)
$$

である。$`L(0\cdots0) = 0`$なので$`\mathrm{CRC}(0\cdots0) = K`$であり、$`L(\Delta) = \mathrm{CRC}(\Delta) \oplus \mathrm{CRC}(0\cdots0)`$と書ける。よって

$$
\mathrm{CRC}(m \oplus \Delta) = \mathrm{CRC}(m) \oplus \underbrace{\mathrm{CRC}(\Delta) \oplus \mathrm{CRC}(0\cdots0)}_{m \text{ を含まない}} \qquad \blacksquare
$$

攻撃者は、元のデータ$`m`$の中身を知らなくても、自分が加える変更$`\Delta`$とデータの長さだけから下線部を計算し、元の CRC 値に XOR して辻褄を合わせられる。

```fig

```

下の図で元のデータと書き換え後のデータを入れると、$`\Delta`$から計算した補正値で CRC が合わせられる様子が表示される。

**(2) 鍵が無い**: 生成多項式は公開された仕様なので、誰でも正しい CRC を計算できる。攻撃者の知らない秘密の値（鍵）が計算に入っていない。データを丸ごと差し替えて、CRC を計算し直すこともできる。

改ざんを検知するには、[18 章](18_ハッシュ・MAC・デジタル署名.md)の暗号学的ハッシュ関数（SHA-256 など）や、鍵を使う MAC（HMAC など）を使う。「チェックサムが合っているから改ざんされていない」とは言えない。

**歴史的な事故**: 無線 LAN の旧規格 WEP は、データに CRC-32 を付けてから、RC4 というストリーム暗号で暗号化していた。RC4 は鍵から作ったビット列を平文に XOR するだけの方式である（[13 章](13_ストリーム暗号とLFSR.md)）。
暗号化が XOR なので、暗号文のビットを反転すると、復号した平文の同じビットが反転する。CRC も (1) のとおり XOR について線形なので、反転に応じた CRC の変化分も暗号文に XOR で足し込める。

```fig
e09_wep
```

この 2 つが組み合わさって、暗号文のまま任意のビットを改ざんし、CRC まで合わせることができた。これが WEP が破られた原因の 1 つである。

## 8. まとめ

| 項目 | 内容 |
|---|---|
| 巡回符号 | 巡回シフトで閉じた線形符号。シフトは$`x`$を掛けて$`x^n+1`$で割った余り |
| 生成多項式 | 符号語はすべて$`g`$の倍数。$`g`$は$`x^n+1`$を割り切り、$`\deg g = n-k`$ |
| CRC の原理 | $`T(x) = x^rm(x) + [x^rm(x)\bmod g(x)]`$は必ず$`g`$で割り切れる |
| 検査 | 受信語を$`g`$で割り、余りが 0 なら誤り無し。余りは誤りパターンだけで決まる |
| 見逃す条件 | 誤りパターン$`E(x)`$が 0 でない$`g(x)`$の倍数のときだけ |
| 強み | 長さ$`r`$以下のバースト誤りをすべて検出。2 ビット誤りは周期まで、奇数個は$`x+1`$があれば検出 |
| 実装 | シフトレジスタと XOR、テーブル駆動、CPU 命令 |
| 注意 | 5 つのパラメータ（poly/init/refin/refout/xorout）を合わせないと値が合わない |
| 限界 | 線形で鍵も無いので、改ざん検知には使えない |

CRC は検出に特化していた。同じ巡回符号の枠組みで訂正までできるように設計したのが、次章の BCH 符号である。
鍵になるのは、生成多項式の根を有限体$`\mathrm{GF}(2^m)`$の中で指定するという考え方で、[05 章](05_拡大体GF2m.md)で作った拡大体がここで使われる。
