Chapter 05

拡大体 GF(2^m) — 1 バイトが 1 つの「数」になる世界

この章の位置づけ. 03 章では整数を素数\(p\)で割った余りの世界として\(\mathrm{GF}(p)\)を作った。 04 章では多項式の世界と、そこでの「素数」にあたる既約多項式を用意した。 この章では同じ論法を多項式に適用して\(\mathrm{GF}(2^m)\)を作る。

材料「素数」で割るできる体
03 章整数\(\mathbb{Z}\)素数\(p\)\(\mathrm{GF}(p)\)
本章多項式\(\mathrm{GF}(2)[x]\)次数\(m\)の既約多項式\(f\)\(\mathrm{GF}(2^m)\)

\(m = 8\)とすると、1 バイト（8 ビット）が 1 個の要素になり、バイトどうしの四則演算が自由にできる。AES やリード・ソロモン符号はこの体の上で計算する。

この章で使う既出の用語（定義は各リンク先）. 拡張ユークリッドの互除法（01 章 4 節）、繰り返し二乗法（01 章 6 節）、 群・巡回群・生成元・要素の位数・ラグランジュの定理とその帰結（02 章 1 節）、零因子（02 章 2 節）、体・標数（02 章 3 節）、XOR（02 章 4 節）、 原始元・離散対数（03 章 3 節）、要素数は\(p^m\)に限ること（03 章 5 節）、 \(\mathrm{GF}(2)\)係数の多項式・次数・ビット列での表し方・足し算（XOR）と掛け算（04 章 1 節）、多項式の除算と合同式\(\equiv \pmod f\)（04 章 2 節）、既約多項式・因数・多項式の 16 進表現（04 章 3 節）、原始多項式（04 章 4 節）、最大公約多項式と互除法（04 章 5 節）

1. 構成 — 既約多項式で割った余りの世界

定義

次数\(m\)の既約多項式\(f\)を 1 つ選ぶ。\(\mathrm{GF}(2)\)係数の多項式を\(f\)で割ると、余りは\(0\)か、次数が\(m\)未満の多項式である（04 章 2 節）。逆に、次数\(m\)未満の多項式を\(f\)で割ると、商は\(0\)で、自分自身が余りになる。 \(\mathrm{GF}(2^m)\)の要素は、この余りとして現れる多項式、すなわち次数\(m\)未満の多項式

\[ a_{m-1}x^{m-1} + \cdots + a_1 x + a_0, \qquad a_i \in \{0,1\} \]

の全体である（係数がすべて 0 の\(0\)も含む）。係数\(m\)個がそれぞれ 0 か 1 なので、要素数は\(2^m\)個である。係数を最高次から並べると\(m\)ビットのビット列になる。

足し算と掛け算 — 多項式として計算し、f で割った余りに直す

演算は、多項式として計算してから\(f\)で割った余りを取る。

  • 足し算は係数ごとの XOR である（04 章 1 節）。次数が上がらないので、\(f\)で割る必要は無い。
  • 掛け算は分配法則で展開し、同じ次数の項を XOR でまとめる（04 章 1 節）。次数が\(m\)以上になりうるので、\(f\)で割った余りに直す。

\(m = 3\)、\(f = x^3+x+1\)で、\(a = x^2+x+1\)（ビット\(111\)）と\(b = x^2+1\)（ビット\(101\)）の和\(a + b\)と積\(a \cdot b\)を計算する。

掛け算の結果\(x^4+x^3+x+1\)（ビット\(11011\)）を\(f\)（ビット\(1011\)）で割る:

余りは\(110\)なので、この世界では\((x^2+x+1)(x^2+1) = x^2+x\)である。この筆算は04 章 5 節のステップ 1 と同じものである。

こうして決めた足し算と掛け算について、体の条件（02 章 3 節）のうち次のものは多項式の計算から引き継がれる。

  • 閉じている: 足し算の結果は次数\(m\)未満のまま、掛け算の結果は余りに直すので、どちらも要素の集合の外に出ない。
  • 結合律・交換律・分配律: 多項式の計算で成り立つ。途中で余りに置き換えてもよいので（04 章 2 節）、どの順で余りを取っても結果は変わらない。
  • 単位元と足し算の逆元: 足し算の単位元は\(0\)、掛け算の単位元は\(1\)である。\(a + a = 0\)なので、足し算の逆元は\(a\)自身である。

残る条件は、0 以外のすべての要素が掛け算の逆元を持つことである。

なぜ体になるのか（逆元の存在）

方針: 整数で「\(p\)が素数なら\(\gcd(a, p) = 1\)、したがって拡張ユークリッドの互除法で逆元が作れる」と示したのと同じ流れをたどる（下の図の上の段）。既約性を使うのは\(\gcd(a, f) = 1\)を示す 1 か所だけである。

導出: \(a \neq 0\)、\(\deg a < m\)とし、\(d = \gcd(a, f)\)とおく。 \(d\)は\(f\)の因数なので\(f = d h\)と書ける。\(f\)は既約なので、\(d\)と\(h\)のどちらかは次数 0、つまり定数\(1\)である（\(\mathrm{GF}(2)\)係数で 0 でない定数は\(1\)だけである）。 \(h = 1\)なら\(d = f\)だが、\(d\)は\(a\)も割り切るので、\(a = f q\)（\(q \neq 0\)）と書けることになる。すると\(\deg a = \deg f + \deg q \geq m\)となり（04 章 1 節の次数の性質）、\(\deg a < m\)に反する。よって\(d = 1\)、すなわち

\[ \gcd(a, f) = 1 \]

04 章 5 節の拡張ユークリッドの互除法により、次を満たす多項式\(u, v\)が求まる:

\[ a\,u + f\,v = 1 \]

\(f v\)は\(f\)で割り切れるので、\(f\)で割った余りを取ると消えて\(a u \equiv 1 \pmod f\)となる。\(u\)を\(f\)で割った余りが\(a\)の逆元である ∎

例: \(f = x^3+x+1\)、\(a = x^2+x\)（ビット\(110\)）。04 章 5 節のステップ 2 は、\(f\)（ビット\(1011\)）を\(a\)で割る次の筆算であった:

商は\(11 = x+1\)、余りは\(1\)なので、この筆算は\(x^3+x+1 = (x+1)(x^2+x) + 1\)を表している（左辺は\(f\)）。\((x+1)(x^2+x)\)を左辺に移項すると、普通の計算どおり符号が変わって

\[ f - (x+1)(x^2+x) = 1 \]

となる。\(\mathrm{GF}(2)\)係数の多項式では\(-1 = 1\)なので引き算は足し算と同じであり（04 章 1 節）、これは

\[ f + (x^2+x)(x+1) = 1 \]

とも書ける。符号を変え忘れたのではなく、標数 2 では\(-\)と\(+\)が同じ意味になるので、どちらで書いても同じ式である。実際に展開すると\((x^2+x)(x+1) = x^3 + x\)で、\(f + x^3 + x = (x^3 + x + 1) + (x^3 + x) = 1\)と確かめられる。 \(f\)は\(f\)で割り切れるので\((x^2+x)(x+1) \equiv 1 \pmod f\)であり、\(x^2+x\)（ビット\(110\)）の逆元は\(x+1\)（ビット\(011\)）である。

可約な多項式では体にならない

たとえば\(f = x^2 = x \cdot x\)で割った余りの世界では\(x \cdot x \equiv 0\)なのに\(x \neq 0\)で、\(x\)は零因子（02 章 2 節）である。 もし\(x\)に逆元\(u\)があれば、\(x \cdot x \equiv 0\)の両辺に\(u\)を掛けて\(x \equiv 0\)となり矛盾する。したがって\(x\)は逆元を持たない。 既約な\(x^2+x+1\)で割った場合と、掛け算の表を並べて比べる。

原始多項式である必要はない

体になるために使ったのは「\(f\)が既約」ということだけで、原始多項式（04 章 4 節）である必要はない。 原始多項式かどうかで変わるのは、要素\(x\)自身が原始元になるか（\(x\)のべき乗で 0 以外の全要素を巡るか）だけである。ここでの\(x\)は、多項式\(x\)を\(f\)で割った余りとしての要素で、\(m\)ビットで書くと\(0\cdots 010\)である。

たとえば既約だが原始でない\(f = x^4+x^3+x^2+x+1\)で割った余りの世界も、要素数 16 の体になる。04 章 4 節で計算したとおり\(x^5 \equiv 1\)なので、要素\(x\)の位数は 5 で、原始元ではない。 一方、要素\(x+1\)のべき乗を順に計算すると、15 乗で初めて 1 に戻り、その間に 0 以外の 15 個がすべて現れる（下の図の右）。\(x+1\)がこの体の原始元である。

2 節では、既約多項式であれば何でも使える計算（多項式のままビット演算で計算する方法）を AES の体で示す。3 節では要素\(x\)が原始元になる原始多項式を選び、\(x\)のべき乗だけで全要素を書き出す。実用でも、要素\(x\)をそのまま原始元に使えて便利なので、原始多項式を選ぶことが多い。

2. 既約多項式の計算 — AES の GF(2^8) をビット演算で計算する

\(m = 8\)とすると要素は 0x00〜0xFF の 256 個になり、1 バイトが 1 個の要素になる。実務で使われる\(\mathrm{GF}(2^8)\)は主に次の 2 つで、どちらも既約多項式だが、原始多項式かどうかが違う。この節では、原始多項式ではない 0x11B を使う AES を例に、既約多項式でさえあれば使える計算方法を示す。原始多項式 0x11D では、さらに対数表を使う方法がある（3 節）。表の右端の計算方法の違いは原始かどうかから来るのではなく、秘密の値を扱うかどうかから来る（3 節の「暗号では対数表を使わない理由」）。

用途多項式16 進原始多項式か実務での主な計算方法
リード・ソロモン符号（QR コードなど）\(x^8+x^4+x^3+x^2+1\)0x11Dはい対数表（3 節）
AES\(x^8+x^4+x^3+x+1\)0x11Bいいえxtime（この節）

AES は\(f = x^8 + x^4 + x^3 + x + 1\)（0x11B）を使う。各バイトの第\(i\)ビット（最下位ビットを第 0 ビットとする）を\(x^i\)の係数と見て、バイトを次数 7 以下の多項式として扱う。 以下では、足し算・掛け算・割り算を多項式の計算のまま（ビット演算で）行う。この方法は\(f\)が既約でありさえすれば使え、原始多項式かどうかは関係ない。

加算

係数ごとの\(\mathrm{GF}(2)\)の足し算なので、ビットごとの XOR である。\(f\)で割る必要は無い（次数が 8 以上にならない）。

例: \(\texttt{0x57} + \texttt{0x83} = 01010111_2 \oplus 10000011_2 = 11010100_2 = \texttt{0xD4}\)。

乗算 — xtime の繰り返し

\(x\)倍（xtime）: \(x\)を掛けると各項の次数が 1 上がるので、ビット列では 1 ビット左シフトになる。 最上位ビット（\(x^7\)の係数）が 0 なら、シフトした結果は 8 ビットに収まり、これで終わる。 最上位ビットが 1 だった場合は\(x^8\)の項が生じ、8 ビットからあふれる。\(f = x^8 + (x^4+x^3+x+1)\)なので、\(x^8\)を\(f\)で割ると商が\(1\)、余りが\(x^4+x^3+x+1\)であり

\[ x^8 \equiv x^4+x^3+x+1 \pmod f \]

である。そこで、あふれた\(x^8\)を捨てる代わりに\(x^4+x^3+x+1\)、つまり 0x1B を XOR で足す。0x1B は 0x11B の下位 8 ビットである。

例 1: \(\texttt{0x57} \times \texttt{0x02}\)。\(\texttt{0x57} = 01010111_2\)は最上位ビットが 0 なので、左シフトするだけで\(\texttt{0xAE}\)。

例 2: \(\texttt{0xAE} \times \texttt{0x02}\)。\(\texttt{0xAE} = 10101110_2\)は最上位ビットが 1 なので、左シフトして下位 8 ビットを取った\(\texttt{0x5C}\)に 0x1B を XOR して\(\texttt{0x5C} \oplus \texttt{0x1B} = \texttt{0x47}\)。

uint8_t xtime(uint8_t a) {
    return (a << 1) ^ ((a & 0x80) ? 0x1B : 0x00);
}

uint8_tに入れた時点で 9 ビット目は捨てられるので、コードでは XOR 0x1B だけを書けばよい。

一般の乗算は、片方をビットに分解し、xtime の繰り返しと XOR で組み立てる。 例 3: \(\texttt{0x57} \times \texttt{0x13}\)。\(\texttt{0x13} = 00010011_2\)は多項式\(x^4 + x + 1\)で、\(\texttt{0x10} \oplus \texttt{0x02} \oplus \texttt{0x01}\)と分けられる。分配法則により

\[ \texttt{0x57} \times \texttt{0x13} = (\texttt{0x57} \times \texttt{0x10}) \oplus (\texttt{0x57} \times \texttt{0x02}) \oplus (\texttt{0x57} \times \texttt{0x01}) \]

である。\(\texttt{0x02}\)は\(x\)、\(\texttt{0x10}\)は\(x^4\)なので、\(\texttt{0x57} \times \texttt{0x02}\)は xtime 1 回、\(\texttt{0x57} \times \texttt{0x10}\)は xtime 4 回で求まる。下の図のように上から順に xtime を繰り返し、\(\texttt{0x13}\)のビットが 1 の行（\(i = 0, 1, 4\)）だけを XOR する。

よって\(\texttt{0x57} \times \texttt{0x13} = \texttt{0x07} \oplus \texttt{0xAE} \oplus \texttt{0x57} = \texttt{0xFE}\)である。

このやり方では、XOR で足し込む回数が掛ける数のビットの 1 の個数で変わる（0x13 なら 3 回、0xFF なら 8 回、0x01 なら 1 回）。xtime も、あふれるかどうかで 0x1B を足すかが変わる。つまり計算の手順が値ごとに変わる。これが問題になる場合は 3 節の「暗号では対数表を使わない理由」で、その対処は 3 節の最後の「定数時間の乗算」で扱う。

AES の MixColumns でバイトに 0x02 や 0x03 を掛ける操作は、この\(\mathrm{GF}(2^8)\)上の掛け算である（14 章）。

下の図で a と b を変えると、a に xtime を繰り返した列と、b のビットが 1 で XOR する行、掛け算の結果が表示される。

割り算 — 逆元を求めて掛ける

\(a \div b = a \times b^{-1}\)なので、逆元\(b^{-1}\)が求まれば割り算は掛け算になる。逆元の求め方は 2 つある。

方法 1: 拡張ユークリッドの互除法。1 節の「なぜ体になるのか」と同じ計算で、\(b \cdot u + f \cdot v = 1\)となる\(u\)を求めれば\(u = b^{-1}\)である。

方法 2: 254 乗する。

方針: 0 以外の 255 個の要素は掛け算について群になる。その群の中で\(b^{255} = 1\)が成り立つことを使い、\(b^{254}\)が逆元になることを示す。

導出: 1 節で示したとおりこの集合は体なので、0 以外の 255 個の要素は掛け算について群（位数 255）をなす。0 でない要素どうしの積は 0 にならず（体には零因子が無い。02 章 3 節）、逆元も 1 節で示したとおり存在するからである。 ラグランジュの定理の帰結（02 章 1 節）から、群の任意の要素\(b\)について\(b^{255} = 1\)である。\(b^{255} = b \cdot b^{254}\)なので

\[ b \cdot b^{254} = 1 \quad\Longrightarrow\quad b^{-1} = b^{254} \]

である ∎

\(b^{254}\)は繰り返し二乗法（01 章 6 節）で計算する。\(254 = 11111110_2 = 128+64+32+16+8+4+2\)なので、\(b\)を 2 乗していって\(b^2, b^4, \dots, b^{128}\)の 7 個を作り（2 乗 7 回）、それらを全部掛ける（掛け算 6 回）。

例: \(b = \texttt{0x53}\)（14 章の S-box の計算例と同じ値）。下の図の上の段が 2 乗の列、下の段がそれを左から順に掛けた途中の値である。

7 個を掛け合わせると\(b^{254} = \texttt{0xCA}\)になる。確かめると\(\texttt{0x53} \times \texttt{0xCA} = \texttt{0x01}\)である。

例（割り算）: \(\texttt{0xFE} \div \texttt{0x13}\)。上と同じ計算で\(\texttt{0x13}^{-1} = \texttt{0x13}^{254} = \texttt{0x4B}\)なので、\(\texttt{0xFE} \times \texttt{0x4B} = \texttt{0x57}\)。乗算の例 3（\(\texttt{0x57} \times \texttt{0x13} = \texttt{0xFE}\)）と一致する。

方法 1 は割り算の繰り返し回数が値ごとに変わるが、方法 2 は値によらず 2 乗 7 回と掛け算 6 回で固定である。AES の S-box はこの逆元から作られる（14 章）。

下の図で b を変えると、2 乗の列と、それを掛け合わせた途中の値、逆元\(b^{-1} = b^{254}\)が表示される。a を入れると\(a \div b = a \times b^{-1}\)も計算する（b を 13 にすると上の割り算の例になる）。

3. 原始多項式の計算 — GF(2^3) を手で作る

2 節では、要素を多項式（ビット列）のまま計算した。\(f\)が原始多項式なら、要素\(x\)のべき乗で 0 以外のすべての要素を書けるので、掛け算を指数の足し算に置き換えられる。小さい体で全要素を書き出して確かめる。

\(m = 3\)、\(f = x^3 + x + 1\)（04 章 3 節で既約と確認済み。原始多項式であることは下のべき表で確かめる）を使う。

1 節の定義どおり、この体の要素は次数 2 以下の多項式 8 個である:

多項式\(0\)\(1\)\(x\)\(x+1\)\(x^2\)\(x^2+1\)\(x^2+x\)\(x^2+x+1\)
ビット000001010011100101110111

生成元 α によるべき表現

要素 x を掛けていく: 要素\(x\)（ビット\(010\)）を何度も掛けてみる。\(x \cdot x = x^2\)は次数 2 なのでそのまま要素である。次の\(x^2 \cdot x = x^3\)は次数 3 なので、\(f\)で割った余りに直す:

余りは\(011\)、つまり\(x + 1\)である。したがってこの体の中では、要素\(x\)を 3 回掛けた結果は要素\(x+1\)に等しい。

\(x\)に\(\alpha\)という名前を付ける: ここで記号の問題が起きる。\(x\)は、\(f(x) = x^3 + x + 1\)のように多項式の変数（値を代入する文字）としても使っている。そのまま「\(x^3 = x + 1\)」と書くと、\(x\)を求める方程式のように見えてしまう。 そこで、この体の 1 つの要素である\(x\)（ビット\(010\)）を、\(\alpha\)という名前で呼ぶ。\(\alpha\)は変数ではなく、ビット\(010\)という決まった要素の名前である。以後、多項式の変数としての\(x\)と、要素としての\(\alpha\)を区別して書く。 名前を変えただけなので、要素はすべて\(x\)を\(\alpha\)に書き換えて表せる。たとえばビット\(011\)の要素は\(\alpha + 1\)、ビット\(110\)の要素は\(\alpha^2 + \alpha\)である。上の筆算の結果は

\[ \alpha^3 = \alpha + 1 \]

と書ける。これは方程式ではなく、要素どうしの等式（「ビット\(010\)を 3 回掛けるとビット\(011\)になる」）である。

複素数の\(i\)との比較: これは実数から複素数を作るときの\(i\)と同じ考え方である。\(x^2 + 1 = 0\)を満たす実数は無いが、「\(i^2 = -1\)を満たす新しい数\(i\)」を加えて、\(a + bi\)の形の数の世界を作る。 ここでも、\(\mathrm{GF}(2)\)には\(f(x) = x^3 + x + 1 = 0\)を満たす数（0 と 1 を入れても\(f(0) = f(1) = 1\)）は無いが、\(f\)で割った余りの世界を作ると、その中の要素\(\alpha\)を\(f\)に代入して

\[ f(\alpha) = \alpha^3 + \alpha + 1 = \underbrace{(\alpha + 1)}_{\alpha^3} + \alpha + 1 = (\alpha + \alpha) + (1 + 1) = 0 + 0 = 0 \]

となる。\(\alpha^3\)を\(\alpha + 1\)に置き換えると、\(\alpha\)と\(1\)がそれぞれ 2 個ずつになり、係数は\(\mathrm{GF}(2)\)なので\(1 + 1 = 0\)で両方とも消える。普通の数なら\(2\alpha + 2\)で 0 にならないが、ここでは「2」が 0 である。 ビット列で確かめると、\(\alpha^3 = 011\)、\(\alpha = 010\)、\(1 = 001\)で、\(011 \oplus 010 \oplus 001 = 000\)である。\(\alpha\)はこの体の中での\(f\)の根であり、体の要素は\(a_2\alpha^2 + a_1\alpha + a_0\)（\(a_i \in \{0, 1\}\)）の形で書ける。\(a + bi\)で複素数を書くのと同じである。

この関係を使うと、\(\alpha\)のべき乗は「1 つ前に\(\alpha\)を掛け、\(\alpha^3\)が出たら\(\alpha+1\)に置き換える」ことで順に求まる:

べき計算多項式表現ビット10 進
\(\alpha^0\)—\(1\)0011
\(\alpha^1\)—\(\alpha\)0102
\(\alpha^2\)—\(\alpha^2\)1004
\(\alpha^3\)\(\alpha^3 = \alpha+1\)\(\alpha+1\)0113

\(\alpha^7 = 1\)で一周し、\(\alpha^1\)から\(\alpha^7\)までに 0 以外の 7 個の要素がすべて 1 回ずつ現れる。\(\alpha\)の位数は 7 で、\(\alpha\)は原始元である。これは\(f\)が原始多項式（04 章 4 節）であることの言い換えである。

下の図で既約多項式を選ぶと、同じように\(\alpha = x\)のべき乗を順に計算した表が表示される。\(x^3+x+1\)、\(x^3+x^2+1\)、\(x^4+x+1\)は原始多項式なので 0 以外の全要素を巡る。\(x^4+x^3+x^2+x+1\)は既約だが原始でないので、\(\alpha^5 = 1\)で一周してしまい、15 個のうち 5 個しか現れない（それでも 1 節のとおり体にはなっている）。

演算の実例

加算はビット列の XOR: \(\alpha^3 + \alpha^5 = 011 \oplus 111 = 100 = \alpha^2\)

乗算は指数の足し算: \(\alpha^3 \cdot \alpha^5 = \alpha^8 = \alpha^7 \cdot \alpha = \alpha\)。\(\alpha^7 = 1\)なので、指数は 7 で割った余りだけを見ればよい。 多項式で直接計算しても一致する: \((\alpha+1)(\alpha^2+\alpha+1) = \alpha^3+1 = (\alpha+1)+1 = \alpha\)

逆元: \(a\)の逆元とは、\(a\)に掛けると\(1\)になる要素のことである。この体では\(1 = \alpha^7\)（表の最後の行）なので、\(\alpha^3\)に掛けて\(\alpha^7\)になる\(\alpha^k\)を探せばよい。掛け算は指数の足し算なので\(3 + k = 7\)、つまり\(k = 7 - 3 = 4\)で、\(\alpha^3\)の逆元は\(\alpha^4\)である。 検算すると\(\alpha^3 \cdot \alpha^4 = \alpha^7 = 1\)。円の図で言えば、\(\alpha^3\)から 1（\(\alpha^0 = \alpha^7\)）まで残り何歩かを数えることに当たる（下の図の内側の矢印）。一般に\(\alpha^i\)の逆元は\(\alpha^{7-i}\)である。 1 節の例で求めた「\(110\)の逆元は\(011\)」は、表では「\(\alpha^4\)の逆元は\(\alpha^3\)」であり、一致している。

除算は逆元を掛けること: \(\alpha^5 / \alpha^3 = \alpha^5 \cdot \alpha^4 = \alpha^9 = \alpha^2\)

対数表による実装

掛け算のたびに多項式を展開して\(f\)で割るのは手間がかかる。そこで上のべき表を、2 つの向きに引ける表にしておく。

  • 対数表: ビット列 → 指数\(i\)（ビット列が\(\alpha^i\)のどれかを引く）。この\(i\)は、\(\alpha\)を底とする離散対数（03 章 3 節）である。0 は\(\alpha\)のべき乗で表せないので、表に入れず別扱いにする。
  • 逆対数表: 指数\(i\) → ビット列（\(\alpha^i\)が何かを引く）。

\(\mathrm{GF}(2^3)\)、\(f = x^3+x+1\)の場合、上のべき表を並べ替えると次の 2 枚になる。10 進はビット列を数として読んだもので、プログラムでは配列の添字に使う。

例 1（掛け算）: \(110 \times 111\)

  1. 対数表を引く: \(110 \to 4\)、\(111 \to 5\)。
  2. 指数を足して 7 で割った余りを取る: \(4 + 5 = 9\)、\(9 - 7 = 2\)。
  3. 逆対数表を引く: \(2 \to 100\)。

よって\(110 \times 111 = 100\)である。多項式で確かめると\((\alpha^2+\alpha)(\alpha^2+\alpha+1) = \alpha^4 + \alpha = (\alpha^2 + \alpha) + \alpha = \alpha^2\)で、ビット列\(100\)と一致する。

例 2（割り算）: \(011 \div 101\)

  1. 対数表を引く: \(011 \to 3\)、\(101 \to 6\)。
  2. 指数を引いて 7 で割った余りを取る: \(3 - 6 = -3\)、\(-3 + 7 = 4\)。
  3. 逆対数表を引く: \(4 \to 110\)。

よって\(011 \div 101 = 110\)である。検算として\(110 \times 101\)を表で計算すると\(4 + 6 = 10 \to 3 \to 011\)に戻る。

例 3（逆元）: \(101\)の逆元は、指数\(6\)から\(7 - 6 = 1\)を求めて逆対数表で\(1 \to 010\)。\(101 \times 010\)を表で計算すると\(6 + 1 = 7 \to 0 \to 001\)で、確かに 1 になる。

0 が入る掛け算は表を引かずに 0 を返す。足し算は表を使わず、ビット列の XOR のままでよい。

C 言語で書くと、表は 2 つの配列になる:

const uint8_t LOG[8] = { 0, 0, 1, 3, 2, 6, 4, 5 };  /* LOG[0] は使わない */
const uint8_t EXP[7] = { 1, 2, 4, 3, 6, 7, 5 };

uint8_t gf8_mul(uint8_t a, uint8_t b) {
    if (a == 0 || b == 0) return 0;
    return EXP[(LOG[a] + LOG[b]) % 7];
}

掛け算が「対数表を 2 回引いて足し算し、逆対数表を引く」に変わるのは、\(\log(ab) = \log a + \log b\)で掛け算を足し算にするのと同じ考え方である。 \(\mathrm{GF}(2^8)\)なら指数を 255 で割った余りを使い、対数表（添字 0〜255 の 256 項。添字 0 は使わない）と逆対数表（指数 0〜254 の 255 項）の 2 枚で済む。リード・ソロモン符号（11 章）の実装でよく使われる。

03 章の GF(4) の正体

03 章 5 節で演算表だけを与えた\(\mathrm{GF}(4) = \{0, 1, \alpha, \beta\}\)は、\(m = 2\)、\(f = x^2+x+1\)で作った体である。 要素は\(0, 1, x, x+1\)の 4 個で、\(\mathrm{GF}(2^3)\)と同じく要素\(x\)を\(\alpha\)と呼ぶ（体が違うので、\(\mathrm{GF}(2^3)\)の\(\alpha\)とは別の要素である）。\(x^2\)を\(f\)で割った余りは\(x+1\)なので\(\alpha^2 = \alpha + 1\)であり、残りの要素\(\alpha + 1\)が 03 章の\(\beta\)である。 さらに\(\alpha^3 = \alpha \cdot \alpha^2 = \alpha(\alpha+1) = \alpha^2 + \alpha = (\alpha + 1) + \alpha = 1\)なので、\(\alpha\)のべきは\(\alpha^0, \alpha^1, \alpha^2\)の 3 個で一周し、0 以外の 3 個の要素をすべて巡る。\(\alpha\)の位数は 3 で、\(\alpha\)は原始元である。つまり\(x^2+x+1\)は、この節の\(x^3+x+1\)と同じく原始多項式（04 章 4 節）である。

4 つの要素の対応をまとめると次のようになる。ビットは\(\mathrm{GF}(2^3)\)と同じく係数を並べたもの（左が\(\alpha\)の係数、右が定数項）である。

乗算は\(\alpha^2 = \alpha + 1\)と\(1 + 1 = 0\)だけを使って計算する。03 章の乗算表の 3 つの欄は次のとおりである。

  • \(\alpha \cdot \alpha = \alpha^2 = \alpha + 1 = \beta\)（ビットで\(10 \times 10 = 11\)）
  • \(\alpha \cdot \beta = \alpha(\alpha + 1) = \alpha^2 + \alpha = (\alpha+1) + \alpha = 1\)（\(10 \times 11 = 01\)）

実務の例 — リード・ソロモン（QR コード）の GF(2^8)

2 節と同じく、\(m = 8\)で 1 バイトが 1 個の要素になる。QR コードは\(f = x^8+x^4+x^3+x^2+1\)（0x11D）を使い、\(\alpha = x\)（ビット\(00000010\)、16 進で 0x02）のべき乗で、\(\mathrm{GF}(2^3)\)と同じように対数表・逆対数表を作る。

逆対数表の作り方: \(\alpha^0 = \texttt{0x01}\)から始めて、\(\alpha\)（0x02）を 1 回ずつ掛けていく。\(x\)を掛けるとビット列は 1 ビット左シフトになり、最上位ビットからあふれた\(x^8\)は\(x^8 \equiv x^4+x^3+x^2+1 \pmod f\)、つまり 0x1D に置き換える（0x1D は 0x11D の下位 8 ビット）。2 節の xtime と同じ操作で、足す定数が 0x1B から 0x1D に変わっただけである。

\(i\)0123456789101112
\(\alpha^i\)01020408102040801D3A74E8CD

\(\alpha^7 = \texttt{0x80}\)までは左シフトだけで、\(\alpha^8\)で初めてあふれて 0x1D になる。\(\alpha^9 = \texttt{0x1D} \times \texttt{0x02} = \texttt{0x3A}\)、…と続けて\(\alpha^{254}\)まで 255 個を書き出すと、0x01〜0xFF がちょうど 1 回ずつ現れ、次の\(\alpha^{255}\)で 0x01 に戻る。したがって 0x11D は原始多項式であり、\(\alpha\)（0x02）は原始元である。対数表は、この逆対数表を逆引きにしたものである。

例（掛け算）: \(\texttt{0x12} \times \texttt{0x34}\)

  1. 対数表を引く: \(\log \texttt{0x12} = 224\)、\(\log \texttt{0x34} = 106\)。
  2. 指数を足して 255 で割った余りを取る: \(224 + 106 = 330\)、\(330 - 255 = 75\)。
  3. 逆対数表を引く: \(\alpha^{75} = \texttt{0x0F}\)。

例（逆元）: \(\texttt{0x12} = \alpha^{224}\)の逆元は\(\alpha^{255 - 224} = \alpha^{31} = \texttt{0xC0}\)である（\(\alpha^{224} \cdot \alpha^{31} = \alpha^{255} = 1\)）。

掛け算は表を 3 回（対数表 2 回、逆対数表 1 回）、逆元は 2 回引いて指数を足し引きするだけで済み、多項式の展開も\(f\)での割り算も要らない。

暗号では対数表を使わない理由

AES の体でも対数表は作れる: 2 節の AES の体（0x11B）で、1 から始めて\(x\)（0x02）を掛け続けると、51 回で 1 に戻る（位数 51）。0 以外の 255 個のうち 51 個しか現れないので、0x02 は対数表の底にできない。これが「0x11B は原始多項式ではない」ということの中身である。 しかし体には必ず原始元があり（4 節の定理 2）、AES の体では\(x + 1\)（0x03）が位数 255 の原始元である。

0x03 を底にすると\(\log \texttt{0x57} = 98\)、\(\log \texttt{0x13} = 14\)なので、\(98 + 14 = 112\)を逆対数表で引いて\(\texttt{0x57} \times \texttt{0x13} = \texttt{0xFE}\)となり、2 節の xtime の結果と一致する。 したがって、対数表を使うかどうかは多項式が原始かどうかでは決まらない。決めるのは、秘密の値を扱うかどうかである。

表を引く時間から鍵が漏れる: CPU は、最近読んだメモリの内容をキャッシュと呼ばれる小さく速い記憶に置いておき、同じ場所をもう一度読むときはそこから速く読む。キャッシュに無い場所を読むと、遅いメモリ本体まで取りに行くので時間がかかる。 表の参照はメモリアクセスであり、読む番地は「表の先頭 + 引く値」で決まる。引く値が秘密のデータ（鍵や、鍵と混ぜた値）から決まると、その番地がキャッシュに載っているかどうかで計算時間が変わる。暗号ではこの時間差を測って鍵を推定する攻撃（キャッシュタイミング攻撃）がある。 表引きでもこの漏れは防げる。毎回 256 項を全部読み、欲しい 1 項だけをマスク（全ビットが 1 か全ビットが 0 の値。AND を取ると、残すか 0 にするかを分岐なしで選べる）で残せば、読む番地が値によらなくなる。ただし掛け算 1 回で表を 3 回（対数表 2 回、逆対数表 1 回）引くので約 768 回の読み出しになり、対数を持たない 0 の扱いもマスクで書く必要がある。シフトと XOR なら 8 回ずつで済むので、暗号では表を使わずに計算する。

定数時間の乗算

シフトと XOR でも、2 節の乗算で見たとおり素直に書くと手順が値ごとに変わる。素直に書いた掛け算は次のようになる:

uint8_t gf_mul(uint8_t a, uint8_t b) {
    uint8_t r = 0;
    while (b) {                 /* b が 0 になったら終わる */
        if (b & 1) r ^= a;      /* b の最下位ビットが 1 のときだけ足す */
        a = xtime(a);           /* xtime の中でも、最上位ビットで 0x1B を足すかが変わる */
        b >>= 1;
    }
    return r;
}

繰り返しの回数（\(b\)の最上位の 1 の位置で決まる）、足す回数（\(b\)の 1 のビットの数）、0x1B を足す回数が、どれも値で変わる。秘密の値を掛けると、かかる時間からその値の手がかりが漏れうる。 そこで、値によらず同じ命令を同じ回数だけ実行するように書く。このような書き方を定数時間（constant-time）の実装という。まず xtime の? :（値によって分岐しうる）を、分岐の無い形にする:

uint8_t xtime_ct(uint8_t a) {
    return (uint8_t)((a << 1) ^ (0x1B & -(a >> 7)));  /* 最上位ビットが 1 なら 0x1B、0 なら 0 */
}

a >> 7は最上位ビット（0 か 1）で、-(a >> 7)は 0 か全ビット 1 になるので、0x1B との AND で「0x1B か 0」が分岐なしで選ばれる。

一般の乗算も、ビットが 1 のときだけ足すのではなく、8 ビットすべてについて毎回 xtime と XOR を行い、足すかどうかをマスクで選ぶ:

uint8_t gf_mul_ct(uint8_t a, uint8_t b) {
    uint8_t r = 0;
    for (int i = 0; i < 8; i++) {          /* 回数は常に 8 回 */
        r ^= a & -(b & 1);                 /* b の最下位ビットが 1 なら a を、0 なら 0 を足す */
        a = xtime_ct(a);
        b >>= 1;
    }
    return r;
}

ビットが 0 のときも「0 を XOR する」ので、どの値でも同じ命令列を同じ回数だけ実行する。2 節の例 3 の 0x57 × 0x13 も 0x57 × 0x01 も、8 回の xtime と 8 回の XOR になる（下の図）。

この書き方は原始多項式でもそのまま使え、変わるのはあふれたときに足す定数だけである（0x11D なら 0x1B の代わりに 0x1D）。

下の図で a と b を変えると、2 つの実装が各周回で実行する操作と、すべての b について素直な実装が実行する操作の数が表示される。

AES の MixColumns で掛ける定数は 0x02 と 0x03 だけで、\(\times\texttt{0x02}\)は xtime 1 回、\(\times\texttt{0x03} = \times\texttt{0x02} \oplus \times\texttt{0x01}\)は xtime 1 回と XOR 1 回で済む。定数は公開された値なので、それで手順が変わっても秘密は漏れない（漏れてはいけないのは、掛けられる側の状態のバイトである）。 S-box（逆元とアフィン変換）をソフトウェアで 256 項の表として引く実装にも同じ問題があるため、CPU の AES 専用命令を使うか、表を使わずビット演算だけで S-box を計算する実装が使われる。

4. 有限体の一般論（まとめの定理）

ここまでの構成を一般化した定理を挙げる。定理 1〜3 は証明が長いので、本シリーズでは事実として引用し、ここまでに作った体で実例を確かめる。

定理 1（存在と一意性）: 任意の素数\(p\)と正整数\(m\)に対し、要素数\(p^m\)の有限体が存在し、同型を除いて一意である。 存在は、次数\(m\)の既約多項式が必ず存在することから、1 節と同じ構成（係数を\(\mathrm{GF}(p)\)にする）で示される。要素数が\(p^m\)の形に限ることは03 章 5 節で示した。

「同型」とは、要素どうしの 1 対 1 の対応で、足し算と掛け算の結果も対応するもののことである。「同型を除いて一意」とは、どの既約多項式を選んでも、要素の名前が変わるだけで演算の構造は同じ体ができるという意味である。 たとえば\(\mathrm{GF}(2^3)\)は\(x^3+x+1\)で作っても\(x^3+x^2+1\)で作っても同じ構造になる。\(x^3+x^2+1\)で作った体の中で、ビット\(011\)の要素（\(x+1\)の余り）を\(\gamma\)と書くと、\(\gamma^3 + \gamma + 1 = 0\)が成り立つ。つまり\(\gamma\)は、3 節の\(\alpha\)と同じく\(x^3+x+1\)の根である。そこで\(\alpha^k\)に\(\gamma^k\)を対応させると、掛け算は指数の足し算なので対応が保たれ、足し算の結果も対応する（下の図。たとえば\(\alpha + 1 = \alpha^3\)に対して\(\gamma + 1 = \gamma^3\)）。

ただしビット列の値は多項式ごとに異なるので、AES（0x11B）と QR コード（0x11D）のように、同じシステム内では同じ多項式を使う必要がある。

定理 2（乗法群は巡回群）: \(\mathrm{GF}(p^m)\)の 0 以外の要素は、掛け算について位数\(p^m - 1\)の巡回群をなす。すなわち原始元が存在し、0 以外のすべての要素がその累乗で書ける。 3 節で\(\alpha\)の累乗が 7 個すべてを巡ったのはこの例である。ただし\(\alpha = x\)自身が原始元になるのは、\(f\)が原始多項式のときに限る。原始多項式でない場合も原始元は存在し、1 節の\(x^4+x^3+x^2+x+1\)の体では\(x+1\)が、3 節で見た AES の体では 0x03 が原始元である。

系: 0 以外の任意の要素\(a\)について

\[ a^{p^m-1} = 1, \qquad \text{よって} \quad a^{-1} = a^{p^m-2} \]

この系は定理 2 を使わなくても示せる。0 以外の要素は掛け算について要素数\(p^m - 1\)の群をなすので、02 章のラグランジュの定理の帰結から\(a^{p^m-1} = 1\)である。 \(\mathrm{GF}(2^8)\)なら\(a^{-1} = a^{254}\)で、AES の S-box はこの逆元を使う（14 章）。

定理 3（部分体）: 体\(F\)の部分集合で、同じ演算でそれ自身も体になっているものを\(F\)の部分体という。 \(\mathrm{GF}(p^m)\)が\(\mathrm{GF}(p^n)\)を部分体として含むのは、\(n\)が\(m\)を割り切るときに限る。 たとえば\(\mathrm{GF}(2^8)\)は\(\mathrm{GF}(2)\)、\(\mathrm{GF}(2^2)\)、\(\mathrm{GF}(2^4)\)を含むが、\(\mathrm{GF}(2^3)\)は含まない。AES の体で実際に調べると、下の図の色の付いたバイトがそれぞれ部分体になっている。たとえば\(\{\texttt{00}, \texttt{01}, \texttt{BC}, \texttt{BD}\}\)は、\(\texttt{BC} + \texttt{BD} = \texttt{01}\)、\(\texttt{BC} \cdot \texttt{BC} = \texttt{BD}\)、\(\texttt{BC} \cdot \texttt{BD} = \texttt{01}\)のように足し算と掛け算で閉じていて、03 章の\(\mathrm{GF}(4)\)と同じ演算表になる（\(\texttt{BC}\)が\(\alpha\)、\(\texttt{BD}\)が\(\beta\)に当たる）。

\(\mathrm{GF}(2^3)\)を含まないことは、ラグランジュの定理からも確かめられる。\(\mathrm{GF}(2^3)\)の 0 以外の 7 個は掛け算で群をなすので、もし\(\mathrm{GF}(2^8)\)の中にあれば、0 以外の 255 個がなす群の部分群になり、7 が 255 を割り切るはずである。しかし\(255 = 3 \times 5 \times 17\)は 7 で割り切れない。

定理 4（フロベニウス）: 標数\(p\)の体では、任意の要素\(a, b\)について

\[ (a + b)^p = a^p + b^p \]

方針: 左辺を二項定理で展開する。展開の係数は二項係数\(\binom{p}{k} = \dfrac{p!}{k!\,(p-k)!}\)（\(p\)個から\(k\)個を選ぶ選び方の数で、整数）である。両端以外の係数が\(p\)の倍数になることを示す。標数\(p\)の体では、1 を\(p\)個足すと 0 なので、係数が\(p\)の倍数の項は消える。

例: \(p = 2\)なら\((a+b)^2 = a^2 + 2ab + b^2\)で、\(2ab = ab + ab = 0\)なので\((a+b)^2 = a^2 + b^2\)。

下の図は\((a+b)^n\)の係数を\(n = 0\)〜\(7\)について並べたもので、\(n\)が素数の行では両端以外がすべて\(n\)の倍数になっている。\(n = 4, 6\)のように素数でない行では、そうならない係数がある。

導出: 二項定理より\((a+b)^p = \sum_{k=0}^{p} \binom{p}{k} a^k b^{p-k}\)。\(0 < k < p\)のとき、二項係数の式の分母を払うと

\[ \binom{p}{k} \cdot k!\,(p-k)! = p! \]

である。右辺は\(p\)を因数に持つ。左辺の\(k!\,(p-k)!\)は\(p\)より小さい数の積であり、\(p\)は素数（02 章 3 節より標数は素数）なので、\(k!\,(p-k)!\)は\(p\)を因数に持たない。素数\(p\)が積を割り切るなら、\(p\)はどれかの因数を割り切るので、\(p\)は\(\binom{p}{k}\)を割り切る。 よってその項は\(a^k b^{p-k}\)を\(p\)の倍数個足したものであり、標数\(p\)では 0 になって消える。残るのは\(k = 0\)と\(k = p\)の項\(b^p\)と\(a^p\)だけである ∎

標数 2 では「2 乗すると各項が別々に 2 乗される」。この性質は BCH 符号の共役根（10 章）で使う。
