# 17. ディフィー・ヘルマンと楕円曲線暗号

> **「鍵を共有していない 2 人が、盗聴されている回線だけで秘密を共有できるか?」**
>
> 常識的には不可能に見える。やりとりは全部聞かれているのだから。
> ところが 1976 年、ディフィーとヘルマンはこれが**できる**ことを示した。
> 暗号史における最大の転換点である。
>
> そして 1985 年、その仕組みを「$`\bmod p`$の掛け算」から「**楕円曲線上の点の足し算**」に
> 移植することで、同じ安全性を保ったまま鍵長を 1/10 程度（128 ビット安全なら 3072 → 256 ビット）に縮められることが分かった。
> 今日の HTTPS、Signal、Bitcoin、パスキー——すべて楕円曲線で動いている。

> **この章で使う既出の用語（定義は各リンク先）.**
> $`a \bmod p`$（演算）と$`a \equiv b \pmod p`$（関係）の 2 つの書き方（[01 章 §1](01_合同算術とユークリッドの互除法.md#合同とは-時計の算数)）、$`\mathrm{GF}(p)`$（[03 章](03_有限体GFp.md#gf-p-の構成と演算表)）、$`\mathrm{GF}(2^m)`$（[05 章](05_拡大体GF2m.md)）、Pollard ρ・Index Calculus（[15 章 §5](15_数論の道具.md#離散対数問題-dlp)）、位数（[02 章 §1](02_群・環・体.md#群-group)）、単位元（[02 章 §1](02_群・環・体.md#群-group)）、標数（[02 章 §3](02_群・環・体.md#体-field)）、結合律（[02 章 §1](02_群・環・体.md#群-group)）、逆元（[02 章 §1](02_群・環・体.md#群-group)）、閉性（[02 章 §1](02_群・環・体.md#群-group)）、原始元（[03 章 §3](03_有限体GFp.md#原始元-生成元-と離散対数)）、離散対数（[03 章 §3](03_有限体GFp.md#原始元-生成元-と離散対数)）、原始根（[15 章 §4](15_数論の道具.md#位数と原始根)）、RSA（[16 章](16_RSA.md)）

## 1. ディフィー・ヘルマン鍵交換 (DH)

### 手順

公開パラメータ: 大きな素数$`p`$、その原始根$`g`$（どちらも公開。盗聴者も知っている）

| ステップ | Alice | 回線を流れるもの | Bob |
|---|---|---|---|
| 1 | 秘密$`a`$を選ぶ | | 秘密$`b`$を選ぶ |
| 2 | $`A = g^a \bmod p`$ を計算 | $`A \longrightarrow`$ | |
| 3 | | $`\longleftarrow B`$ | $`B = g^b \bmod p`$ を計算 |
| 4 | $`K = B^a \bmod p`$ | | $`K = A^b \bmod p`$ |

### なぜ同じ鍵になるのか

$$
B^a \equiv (g^b)^a = g^{ab} = (g^a)^b \equiv A^b \pmod p
$$

**指数法則だけ** ✓ 両者とも$`K = g^{ab} \bmod p`$に到達する ∎

### なぜ盗聴者に分からないのか

盗聴者が知っているのは$`p, g, A=g^a, B=g^b`$。
$`K = g^{ab}`$を求めるには$`a`$または$`b`$が必要——つまり**離散対数問題**（[15 章](15_数論の道具.md#離散対数問題-dlp)）を解く必要がある。

> **鍵が「回線を流れていない」ことに注目してほしい.**
> 共有された$`K = g^{ab}`$は、**どちらの端末でも計算されたが、一度も送信されていない**。
> 送られたのは$`g^a`$と$`g^b`$だけで、そこから$`g^{ab}`$を作るのは（DH 仮定の下で）困難である。
>
> 絵の具のたとえで言うとこうなる（手順の表と 1 対 1 に対応する）:
> 1. 公開の色$`g`$を全員が持っている
> 2. Alice は秘密の色$`a`$を$`g`$に混ぜた色$`A`$を送り、Bob は秘密の色$`b`$を$`g`$に混ぜた色$`B`$を送る（送るのはこの 2 つだけ）
> 3. Alice は受け取った$`B`$に自分の$`a`$を混ぜ、Bob は受け取った$`A`$に自分の$`b`$を混ぜる。どちらも「$`g + a + b`$」の色になる
>
> 盗聴者は$`g, A, B`$を見ているが、混ざった絵の具から元の色$`a`$や$`b`$を分離できないので、$`g + a + b`$を作れない。
> 「混ぜるのは簡単、分けるのは困難」という絵の具の性質を、DH は「べき乗は簡単、離散対数は困難」で実現している。

### 中間者攻撃 — DH 単独では防げない

Mallory が Alice と Bob の間に入り、それぞれと別々に DH を実行すると:
- Alice ↔ Mallory で鍵$`K_1`$
- Mallory ↔ Bob で鍵$`K_2`$

Mallory は全通信を復号・再暗号化して中継できる。両者は気づかない。

> **DH は「秘密の共有」はできるが「相手が誰か」は保証しない.**
> だから実際の TLS では、DH に**証明書による認証**（[18 章](18_ハッシュ・MAC・デジタル署名.md#証明書チェーン-pki)）を組み合わせる。
> 「暗号化されている」と「相手が本物である」は別問題——これはセキュリティ設計の基本である。

### 前方秘匿性 (Forward Secrecy)

サーバは「自分が本物であること」を示すために、証明書に対応する秘密鍵を何年も使い続ける（これを**長期秘密鍵**という。§1 の$`a, b`$とは別物）。
昔の TLS では、この長期鍵で暗号化した値を送って共有鍵を決めていたため、長期鍵が後日漏れると、録音しておいた過去の通信がすべて復号できた。

これに対し、毎回**使い捨ての**$`a, b`$を乱数で作り、通信が終わったら捨てる DH を **DHE / ECDHE**（E = Ephemeral、一時的）という。
長期秘密鍵は相手の認証（署名）にだけ使い、共有鍵$`K`$の計算には関わらない。
だから長期秘密鍵が将来漏れても、**過去の通信は復号できない**（$`K`$を作るのに必要な$`a, b`$はもう存在しない）。この性質を**前方秘匿性**という。
TLS 1.3 では ECDHE が**必須**になった。

## 2. 楕円曲線 — 「点の足し算」で群を作る

### 定義

体$`K`$上の楕円曲線（標数 2,3 でない場合のワイエルシュトラス形）:

$$
E: y^2 = x^3 + ax + b, \qquad 4a^3+27b^2 \neq 0
$$

条件$`4a^3+27b^2\neq0`$は、3 次式$`x^3 + ax + b = 0`$が重根（同じ値の根が 2 つ以上）を持たないための条件である。
重根があると曲線に尖った点や自分自身と交わる点（**特異点**）ができ、そこでは接線が 1 本に定まらないので、下で定義する加法が壊れる。

曲線上の点$`(x, y)`$全体に、**無限遠点**と呼ぶ特別な点$`\mathcal{O}`$を 1 つ加えた集合を考える。
$`\mathcal{O}`$は座標を持たない約束上の点で、「すべての垂直な直線（$`x = `$定数）が通る点」と考える。
下の加法で、垂直な直線を引いたときの「3 つ目の交点」の役を担い、足し算の 0（単位元）になる。

### 加法の定義（幾何的に）

曲線は$`y^2 = \cdots`$の形なので$`x`$軸に関して対称で、$`P = (x, y)`$が曲線上なら$`(x, -y)`$も曲線上にある。この点を$`-P`$と書く。

2 点$`P, Q`$に対し:
1. $`P`$と$`Q`$を通る直線を引く（$`P = Q`$のときは$`P`$での接線）
2. その直線は曲線と**もう 1 点**で交わる（3 次曲線と直線の交点は重複を込めて 3 つ）
3. その交点を$`x`$軸に関して折り返した点を$`P+Q`$と定める

ただし$`Q = -P`$のときは直線が垂直になり、曲線上の 3 つ目の交点は無い。この場合は 3 つ目の交点を$`\mathcal{O}`$とみなし、$`P + (-P) = \mathcal{O}`$と定める。
また$`P + \mathcal{O} = P`$と定める（$`P`$と$`\mathcal{O}`$を通る「直線」は$`P`$を通る垂直線で、3 つ目の交点は$`-P`$、折り返すと$`P`$）。

> **なぜこれが「足し算」なのか.** 一見すると恣意的な規則だが、
> この演算は**群の公理をすべて満たす**（[02 章](02_群・環・体.md#例で確かめる)）:
> - 閉性 ✓（交点は必ず曲線上）
> - 単位元 ✓（無限遠点$`\mathcal{O}`$）
> - 逆元 ✓（$`x`$軸対称の点$`-P`$。$`P + (-P) = \mathcal{O}`$）
> - 結合律 ✓（$`(P+Q)+R = P+(Q+R)`$。下の代数的な公式を使って両辺を展開すれば確かめられるが長い計算になるので、ここでは事実として使う）
> - 可換 ✓（直線の引き方は順序に依らない）
>
> **群になっている**からこそ、[02 章](02_群・環・体.md#位数と巡回群)以降の群論の道具（位数、生成元、ラグランジュ）が全部使える。
> そして「べき乗」の代わりに「**スカラー倍**$`kP = P+P+\cdots+P`$」を考えれば、
> DH と同じ構造がそのまま成立する。

### 加法の公式（代数的に）

$`P=(x_1,y_1)`$、$`Q=(x_2,y_2)`$、$`P+Q=(x_3,y_3)`$とすると:

**傾き**:

$$
\lambda = \begin{cases}
\dfrac{y_2-y_1}{x_2-x_1} & (P \neq Q)\\[8pt]
\dfrac{3x_1^2+a}{2y_1} & (P = Q,\ \text{接線})
\end{cases}
$$

（接線の傾きは、曲線の式$`y^2 = x^3 + ax + b`$の両辺を$`x`$で微分した$`2y \frac{dy}{dx} = 3x^2 + a`$から$`\frac{dy}{dx} = \frac{3x^2 + a}{2y}`$。）

**座標**:

$$
x_3 = \lambda^2 - x_1 - x_2, \qquad y_3 = \lambda(x_1 - x_3) - y_1
$$

**導出（$`x_3`$の式）**: 直線$`y = \lambda(x-x_1)+y_1`$を曲線の式に代入:

$$
(\lambda(x-x_1)+y_1)^2 = x^3+ax+b
$$

左辺を展開すると$`\lambda^2 x^2 + (\text{$x$ の 1 次以下の項})`$。右辺に移項して整理すると

$$
x^3 - \lambda^2 x^2 + (\cdots)x + (\cdots) = 0
$$

という$`x`$の 3 次方程式になる（$`x^2`$の項は左辺の$`\lambda^2 x^2`$からしか出ない）。
3 次方程式$`x^3 + c_2 x^2 + c_1 x + c_0 = 0`$の 3 根を$`r_1, r_2, r_3`$とすると$`(x - r_1)(x - r_2)(x - r_3)`$を展開して$`x^2`$の係数を比べれば$`r_1 + r_2 + r_3 = -c_2`$（解と係数の関係）。
いまの方程式の 3 根は「直線と曲線の 3 つの交点の$`x`$座標」で、そのうち 2 つは$`x_1, x_2`$（$`P,Q`$）。3 つ目を$`x_3`$とおくと

$$
x_1+x_2+x_3 = \lambda^2 \Longrightarrow x_3 = \lambda^2-x_1-x_2
$$

$`x`$軸で折り返しても$`x`$座標は変わらないので、これがそのまま$`P+Q`$の$`x`$座標 ∎
（$`y_3`$は、3 つ目の交点の$`y`$座標$`\lambda(x_3 - x_1) + y_1`$の符号を反転したもの。）

> **重要: この公式には割り算（$`\lambda`$の分母）が現れる.**
> だから**係数を体から取る必要がある**——[02 章](02_群・環・体.md)・[03 章](03_有限体GFp.md#gf-p-の限界-なぜ次章が必要か)で「体でなければ困る」と述べた理由がここでも生きる。
> 実際には$`\mathrm{GF}(p)`$（$`p`$は 256 ビット程度の素数）や$`\mathrm{GF}(2^m)`$を使い、
> 割り算は**逆元の掛け算**（[01 章](01_合同算術とユークリッドの互除法.md)の拡張ユークリッド、または$`a^{p-2}`$）で実行する。

## 3. 楕円曲線上の離散対数 (ECDLP)

### 問題

曲線上の点$`G`$（**ベースポイント**）を 1 つ決めておく。$`G`$の位数、すなわち$`nG = \mathcal{O}`$となる最小の$`n`$を以下$`n`$と書く
（曲線の設計時に$`n`$が大きな素数になるよう選ぶ。$`G`$のスカラー倍は$`G, 2G, \dots, nG = \mathcal{O}`$の$`n`$個を巡る）。

**ECDLP**: $`G`$と$`Q = kG`$（$`1 \le k < n`$）が与えられたとき、$`k`$を求めよ。

- **$`k \to kG`$**: 繰り返し二乗法と同じ要領で、$`k`$の 2 進表示に沿って「2 倍する」と「$`G`$を足す」を繰り返す（ダブル・アンド・アッド）。$`O(\log k)`$回の点演算——高速
- **$`Q \to k`$**: 最良でも約$`\sqrt n`$回の点演算（Pollard ρ。[15 章](15_数論の道具.md#離散対数問題-dlp)の表の汎用アルゴリズム）——$`n \approx 2^{256}`$なら$`2^{128}`$回で実質不可能

### なぜ RSA/DH より鍵が短くて済むのか

> **[15 章](15_数論の道具.md#難しさの非対称性)で触れた決定的な違い.**
> $`\mathbb{Z}_p^\ast`$（$`\{1,\dots,p-1\}`$の掛け算の群。記法は[02 章 §1 例 4](02_群・環・体.md#例で確かめる)）上の離散対数には **Index Calculus** という準指数時間アルゴリズムが効く。
> これは「小さな素数の積に分解できる数（滑らかな数）」を集めて連立方程式を作る手法だが、
> **楕円曲線の点には『素因数分解』に相当する概念が無い**ため適用できない。
>
> 結果として、楕円曲線を攻撃する最良手段は汎用の$`O(\sqrt n)`$アルゴリズムだけ。
> 安全性$`2^{128}`$を得るには$`n \approx 2^{256}`$、つまり**256 ビットで十分**。
> 一方 RSA は Index Calculus 系（GNFS）があるため 3072 ビット必要になる。

## 4. 楕円曲線暗号の応用

### ECDH（鍵交換）

DH の$`g^a`$を$`aG`$に置き換えるだけ:

| | Alice | Bob |
|---|---|---|
| 秘密 | $`d_A`$ | $`d_B`$ |
| 公開 | $`Q_A = d_AG`$ | $`Q_B = d_BG`$ |
| 共有鍵 | $`d_AQ_B = d_Ad_BG`$ | $`d_BQ_A = d_Ad_BG`$ ✓ |

### ECDSA（署名）

署名するのは、メッセージをハッシュ関数（[18 章](18_ハッシュ・MAC・デジタル署名.md)。任意長のデータを固定長の値に潰す関数）で$`n`$未満の整数にした$`z`$である。
以下の$`k^{-1}, s^{-1}`$は法$`n`$での逆元、計算はすべて$`\bmod n`$。
（§1 の大文字$`K`$は共有鍵だったが、ここからの小文字$`k`$は署名ごとの乱数で、別物である。）

署名（秘密鍵$`d`$、メッセージのハッシュ値$`z`$）:
1. 乱数$`k`$（$`1 \le k < n`$）を選び、$`(x_1,y_1) = kG`$
2. $`r = x_1 \bmod n`$
3. $`s = k^{-1}(z + rd) \bmod n`$
4. 署名 = $`(r,s)`$

検証（公開鍵$`Q = dG`$）:
1. $`u_1 = z s^{-1} \bmod n`$、$`u_2 = r s^{-1} \bmod n`$
2. $`(x_1,y_1) = u_1G + u_2Q`$
3. $`x_1 \bmod n = r`$ なら有効

**検証が通る理由**:

$$
u_1G+u_2Q = zs^{-1}G + rs^{-1}dG = s^{-1}(z+rd)G = s^{-1}\cdot sk G = kG \checkmark
$$

（$`s = k^{-1}(z+rd)`$より$`z+rd = sk`$。）

> **ECDSA の乱数$`k`$は絶対に再利用してはいけない.**
> 同じ$`k`$で 2 つのメッセージ$`z_1,z_2`$に署名すると、$`r`$が同じになり:
>
> $$s_1 - s_2 = k^{-1}(z_1-z_2) \Longrightarrow k = \frac{z_1-z_2}{s_1-s_2}$$
>
> $`k`$が分かれば$`d = r^{-1}(sk - z)`$で**秘密鍵が完全に露出する**。
>
> **実際の事故**:
> - **2010 年、ソニー PlayStation 3**: ECDSA の$`k`$を定数にしていたため、
>   マスター署名鍵が抽出され、任意のソフトが実行可能になった
> - **2013 年、Android の Bitcoin ウォレット**: 乱数生成器の不具合で$`k`$が衝突し、資金が盗まれた
>
> 対策として、$`k`$を秘密鍵とメッセージから決定論的に導出する **RFC 6979** や、
> 設計段階でこの問題を回避した **EdDSA (Ed25519)** が推奨される。

### 代表的な曲線

| 曲線 | ビット | 用途 |
|---|---|---|
| P-256 (secp256r1) | 256 | TLS、政府標準 |
| **Curve25519** | 255 | Signal、WireGuard、TLS 1.3、SSH |
| secp256k1 | 256 | **Bitcoin、Ethereum** |
| Ed25519 | 255 | 署名（EdDSA）、SSH、Git のコミット署名 |

> **Curve25519 が支持される理由.**
> 設計者 Daniel J. Bernstein が、**実装ミスを起こしにくい**ことを最優先に設計した:
> - すべての入力値に対して安全。相手が「曲線上にない点」を送ってきたとき、検査せずに計算すると別の弱い曲線上の計算になって秘密鍵が漏れる**無効曲線攻撃**があるが、Curve25519 は$`x`$座標だけで計算する設計で、どんな入力でもこの攻撃が成立しない
> - 分岐やテーブル参照が不要 → **タイミング攻撃に本質的に強い**
> - パラメータの選定根拠が完全に公開されている（NIST 曲線には「定数の出所が不明」という批判がある）
>
> **「理論的に安全」だけでなく「実装しても壊れにくい」ことを設計目標にする**——
> 現代の暗号設計の重要な潮流である。

## 5. まとめ

| 項目 | DH（$`\mathbb{Z}_p^\ast`$） | ECDH（楕円曲線） |
|---|---|---|
| 群 | 乗法群、位数$`p-1`$ | 点の加法群、位数$`n`$ |
| 演算 | $`g^a \bmod p`$ | $`aG`$（スカラー倍） |
| 困難性 | DLP | ECDLP |
| 攻撃法 | Index Calculus（準指数） | Pollard ρ のみ（$`O(\sqrt n)`$） |
| 128 ビット安全の鍵長 | 3072 ビット | **256 ビット** |
