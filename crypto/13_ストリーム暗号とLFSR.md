# 13. ストリーム暗号と LFSR — GF(2) 上の漸化式

> **ワンタイムパッドの夢と現実.**
> [12 章](12_暗号の基礎概念と古典暗号.md#ワンタイムパッド-唯一の完全な暗号)で「ワンタイムパッドは完全に安全だが、鍵が長すぎて使えない」と分かった。
>
> ならば——**短い鍵から、長い「ランダムに見える」列を作れないか?**
>
> これがストリーム暗号の発想である。短い種（鍵）から擬似乱数列を生成し、それを平文と XOR する。
> 安全性は「その擬似乱数列が本物のランダムと区別できないこと」に懸かっている。
>
> この章では、その最も基本的な生成器である **LFSR** を扱う。
> LFSR は$`\mathrm{GF}(2)`$上の漸化式そのものであり、**[04 章](04_多項式と既約多項式.md#実務で使われる既約多項式)・[05 章](05_拡大体GF2m.md#構成-既約多項式で割った余りの世界)の多項式論が直接使われる**。
> そして——重要なことに——**LFSR 単独では暗号として破れる**。その理由も導出する。

> **この章で使う既出の用語（定義は各リンク先）.**
> 位数（[02 章 §1](02_群・環・体.md#群-group)）、多項式（[03 章 §5](03_有限体GFp.md#gf-p-の限界-なぜ次章が必要か)）、シンドローム（[07 章 §4](07_線形符号.md#シンドローム-誤りの-指紋)）、線形符号（[07 章 §1](07_線形符号.md#定義)）

## 1. ストリーム暗号の枠組み

平文をビット列$`P_0, P_1, P_2, \dots`$、暗号文を$`C_0, C_1, \dots`$とし、

$$
C_i = P_i \oplus Z_i
$$

とする。$`Z_0, Z_1, \dots`$は**鍵ストリーム**と呼ぶビット列で、秘密の鍵$`K`$から生成器で作る。
復号は同じ$`Z_i`$をもう一度 XOR するだけ（$`C_i \oplus Z_i = P_i \oplus Z_i \oplus Z_i = P_i`$）。

**必須の要件**: **同じ鍵ストリームを 2 度使ってはならない**（[12 章](12_暗号の基礎概念と古典暗号.md#ワンタイムパッド-唯一の完全な暗号)のワンタイムパッド再利用問題と同じ）。
そのため実用の生成器は、秘密の鍵$`K`$と、メッセージごとに変える公開値 **IV（初期化ベクトル、ノンスとも）** の 2 つを入力に取り、
$`(K, \mathrm{IV})`$の組から鍵ストリームを作る。$`K`$が同じでも IV が違えば別の鍵ストリームになる。
本章で扱う LFSR では、$`K`$と IV を混ぜたものを**初期状態**（§2）として入れる。

## 2. LFSR (線形帰還シフトレジスタ)

### 構造

LFSR（Linear Feedback Shift Register）は、$`L`$個のビットを入れた箱（レジスタ）と、それを毎クロック更新する規則からなる。
「クロック」とは 1 回の更新操作のことで、時刻$`n`$の状態から時刻$`n+1`$の状態を作る。

出力されるビット列を$`s_0, s_1, s_2, \dots`$と書く。最初の$`L`$ビット$`s_0, \dots, s_{L-1}`$が**初期状態**（利用者が与える）で、
それ以降は次の**漸化式**で決まる:

$$
\boxed{s_{n+L} = c_1 s_{n+L-1} \oplus c_2 s_{n+L-2} \oplus \cdots \oplus c_L s_n}
$$

$`c_1, \dots, c_L \in \{0,1\}`$は固定の定数で、$`c_i = 1`$の位置を**タップ**という（XOR に参加するビットの位置）。

時刻$`n`$のレジスタの中身（**状態**）は、直近の$`L`$ビット$`s_n, s_{n+1}, \dots, s_{n+L-1}`$である。1 クロックで起きることは:
1. 一番古いビット$`s_n`$を出力する
2. 漸化式で新しいビット$`s_{n+L}`$を計算し、レジスタに入れる
3. 状態は$`s_{n+1}, \dots, s_{n+L}`$になる（全体が 1 つずれる。これが「シフト」）

本章では状態を**左が新しい・右が古い**順に並べた文字列で書く: 時刻$`n`$の状態 = $`s_{n+L-1} \cdots s_{n+1} s_n`$。
右端が出力されるビット、左端に新しいビットが入る。

### 特性多項式

タップの構成を多項式で表す:

$$
f(x) = x^L + c_1x^{L-1} + \cdots + c_{L-1}x + c_L
$$

これを**特性多項式**（または帰還多項式）という。$`x^L`$の係数は常に 1、$`x^{L-i}`$の係数が漸化式の$`c_i`$である。

> **周期は特性多項式で決まる.**
> 状態は$`2^L`$通りしかないので、出力列はいつか必ず繰り返す。繰り返しの長さを**周期**という
> （すべて 0 の状態は 0 しか出さないので除いて考える。すると最長でも$`2^L - 1`$）。
>
> 漸化式$`s_{n+L} = c_1 s_{n+L-1} \oplus \cdots \oplus c_L s_n`$は、多項式の言葉では
> 「$`x^L`$を$`c_1 x^{L-1} + \cdots + c_L`$に置き換える」すなわち$`x^L \equiv c_1 x^{L-1} + \cdots + c_L \pmod{f(x)}`$という規則と同じ形をしている
> （[05 章](05_拡大体GF2m.md#生成元-α-によるべき表現)で$`\alpha^3 = \alpha + 1`$を使って$`\alpha`$のべきを次々に書き換えたのと同じ操作）。
> このため、出力列の$`n`$番目は「$`x^n`$を$`f(x)`$で割った余り」で決まり、
> $`x^N \equiv 1 \pmod{f(x)}`$となる最小の$`N`$で列が元に戻る。この$`N`$を**$`f`$の位数**という
> （[02 章](02_群・環・体.md#要素の位数-単位元になるまでに要素を何個並べるか)の「要素の位数」を、$`f`$で割った余りの世界の要素$`x`$に適用したもの）。
>
> | $`f(x)`$の性質 | 周期 |
> |---|---|
> | 可約 | 短くなる（初期状態によっても変わる） |
> | 既約だが原始でない | $`f`$の位数（$`2^L-1`$の約数だが$`2^L-1`$未満） |
> | **原始多項式** | **$`2^L-1`$（最大）**。$`x`$のべきが 0 以外の全要素を巡る（[04 章](04_多項式と既約多項式.md#原始多項式-既約よりさらに強い条件)の原始多項式の定義そのもの） |
>
> 原始多項式を使ったときの出力を **M 系列 (maximal length sequence)** という。
> 「$`x^n`$の余りが全$`2^L - 1`$個の非零要素を巡る」ことと「レジスタの状態が全$`2^L-1`$通り（全 0 以外）を巡る」ことは、
> 上の対応により同じことである。

### 実例: L=4, f(x) = x⁴+x+1（原始多項式）

$`f(x) = x^4 + 0\cdot x^3 + 0 \cdot x^2 + 1 \cdot x + 1`$なので$`c_1 = 0, c_2 = 0, c_3 = 1, c_4 = 1`$。漸化式は

$$
s_{n+4} = c_3 s_{n+1} \oplus c_4 s_n = s_{n+1} \oplus s_n
$$

初期状態を$`s_3 s_2 s_1 s_0 = 1000`$（$`s_3 = 1`$、他は 0）とする。各時刻で、右端のビットを出力し、$`s_{n+1} \oplus s_n`$（右から 2 番目と右端の XOR）を左端に入れる:

| 時刻$`n`$ | 状態 $`s_{n+3}s_{n+2}s_{n+1}s_n`$ | 新ビット $`s_{n+4} = s_{n+1} \oplus s_n`$ | 出力 $`s_n`$ |
|---|---|---|---|
| 0 | 1000 | $`0 \oplus 0 = 0`$ | 0 |
| 1 | 0100 | $`0 \oplus 0 = 0`$ | 0 |
| 2 | 0010 | $`1 \oplus 0 = 1`$ | 0 |
| 3 | 1001 | $`0 \oplus 1 = 1`$ | 1 |
| 4 | 1100 | $`0 \oplus 0 = 0`$ | 0 |
| 5 | 0110 | $`1 \oplus 0 = 1`$ | 0 |
| 6 | 1011 | $`1 \oplus 1 = 0`$ | 1 |
| 7 | 0101 | $`0 \oplus 1 = 1`$ | 1 |
| 8 | 1010 | $`1 \oplus 0 = 1`$ | 0 |
| 9 | 1101 | $`0 \oplus 1 = 1`$ | 1 |
| 10 | 1110 | $`1 \oplus 0 = 1`$ | 0 |
| 11 | 1111 | $`1 \oplus 1 = 0`$ | 1 |
| 12 | 0111 | $`1 \oplus 1 = 0`$ | 1 |
| 13 | 0011 | $`1 \oplus 1 = 0`$ | 1 |
| 14 | 0001 | $`0 \oplus 1 = 1`$ | 1 |
| 15 | 1000 | | |

たとえば時刻 2 → 3: 状態 0010 の右端$`s_2 = 0`$を出力し、新ビット$`s_6 = s_3 \oplus s_2 = 1 \oplus 0 = 1`$を左端に入れて$`1001`$。

時刻 15 で初期状態 1000 に戻った。15 回の更新（$`2^4-1`$）で一周 = **最長周期** ✓
出力列は$`s_0 \dots s_{14} = 000100110101111`$で、1 が 8 個、0 が 7 個。

### M 系列の統計的性質

1 周期（$`N = 2^L-1`$ビット）の中で:
- **1 の個数**: $`2^{L-1}`$個、**0 の個数**: $`2^{L-1}-1`$個（ほぼ半々。上の例では 8 個と 7 個）
- **自己相関**: 列を$`d`$ビット（$`1 \le d \le N-1`$）ずらしたものと元の列を、1 周期分の各位置で比べる。
  「一致した位置の数 − 不一致の位置の数」が、どの$`d`$でも常に$`-1`$になる（ずらさなければ$`N`$）。
  つまり、ずらすとほぼ無相関に見える
- **連（ラン）の分布**: 同じ値が続く区間を**連**という（上の例の$`000\,1\,00\,11\,0\,1\,0\,1111`$は 8 個の連）。
  長さ$`k`$の連の個数は、連の総数の約$`2^{-k}`$（半分が長さ 1、1/4 が長さ 2、…）

> **これらは「ランダムに見える」ための良い性質である.**
> だから M 系列は**通信の同期、GPS の測距符号、レーダー、スペクトラム拡散**で広く使われる。
> たとえば GPS 衛星が送る測距用の符号（C/A コード）は、長さ 1023 の M 系列 2 本を XOR して作る（この作り方の符号を Gold 符号という。
> 衛星ごとに違う組み合わせを使っても互いに相関が小さいので、同時に受信して分離できる）。
>
> **ただし「統計的にランダムに見える」ことと「暗号的に安全」は全く別物**である。次節でそれを見る。

## 3. LFSR はなぜ暗号として使えないのか

### 出力 2L ビットからの復元

**定理**: 長さ$`L`$の LFSR の出力を**連続$`2L`$ビット**観測すれば、
その LFSR の構成（タップ$`c_1, \dots, c_L`$と状態）が完全に決定できる。

**なぜか**: 観測した$`2L`$ビットを$`s_0, \dots, s_{2L-1}`$とする。漸化式を$`n = 0, 1, \dots, L-1`$について書くと

$$
\begin{aligned}
s_{L} &= c_1 s_{L-1} \oplus \cdots \oplus c_L s_0\\
s_{L+1} &= c_1 s_{L} \oplus \cdots \oplus c_L s_1\\
&\vdots\\
s_{2L-1} &= c_1 s_{2L-2} \oplus \cdots \oplus c_L s_{L-1}
\end{aligned}
$$

1 本の式には連続する$`L+1`$ビットが現れ、$`L`$本目の式の最後のビットが$`s_{2L-1}`$。だから$`2L`$ビットあれば$`L`$本の式が立つ。
未知数は$`c_1,\dots,c_L`$の$`L`$個で、式は$`c_i`$について線形（$`s`$は既知の 0/1）なので、
[03 章](03_有限体GFp.md#gf-p-上の線形代数-誤り訂正の道具)の掃き出し法（$`\mathrm{GF}(2)`$上）で解ける。
状態は最初の$`L`$ビット$`s_0, \dots, s_{L-1}`$そのもの。

計算量は掃き出し法で$`O(L^3)`$。**バーレカンプ・マッシー法**という専用アルゴリズムなら$`O(L^2)`$で、しかも$`L`$を知らなくても
「観測列を生成する最短の LFSR」を見つけてくれる。

> **[11 章](11_リードソロモン符号.md#バーレカンプ-マッシー法)と同じアルゴリズムがここに出てくる.**
> RS 符号の復号では「シンドロームを生成する最短 LFSR を求める」ためにバーレカンプ・マッシー法を使った。
> ここでは攻撃者が「鍵ストリームを生成する LFSR を求める」ために同じ手法を使う。
>
> **符号理論では味方、暗号では敵**——同じ数学が立場によって役割を変える好例である。

### 帰結

$`L = 128`$の LFSR でも、**256 ビット観測されれば終わり**。
既知平文攻撃（平文と暗号文のペアが少しでも手に入る状況。$`Z_i = C_i \oplus P_i`$で鍵ストリームが分かる）で、以後の鍵ストリームがすべて再現される。

**根本原因は「線形性」**。線形な仕組みは連立方程式で解ける。

## 4. 非線形化の工夫

LFSR を使いつつ線形性を壊す手法:

| 手法 | 内容 | 例 |
|---|---|---|
| **非線形結合** | 複数 LFSR の出力を非線形関数（AND を含む式）で混ぜる | Geffe 生成器（3 本の LFSR を$`z = a b \oplus (1 \oplus b) c`$で混ぜる） |
| **非線形フィルタ** | 1 つの LFSR の状態から何ビットか取り出し、非線形関数に通す | Crypto-1 |
| **不規則クロック** | ある LFSR の出力で別の LFSR を進めるかどうかを決める | **A5/1**（GSM）、Shrinking 生成器（LFSR A の出力が 1 のときだけ LFSR B の出力を採用） |
| **メモリ付き** | LFSR の出力を整数として足し、繰り上がりを内部に持ち越す | Summation 生成器 |

> **しかし、これらも多くが破られている.**
> - **A5/1**（GSM 携帯電話）: 3 個の LFSR を不規則クロックで動かす。
>   2000 年代に実時間で破られ、現在は**レインボーテーブル**（鍵と出力の対応を事前に大量計算して表にし、観測した出力から表引きで鍵を逆引きする手法）で数秒で解読される
> - **E0**（Bluetooth）: 4 個の LFSR + メモリ。総当たりなら$`2^{128}`$のところ、既知の攻撃は$`2^{38}`$程度の演算で済む
> - **Crypto-1**（Mifare Classic 交通カード）: 48 ビット LFSR + 非線形フィルタ。完全に破られた
>
> 有効な攻撃は主に 2 つ。
> - **相関攻撃**: 最終出力が、中の 1 本の LFSR の出力と確率$`p \neq 1/2`$で一致するとする。
>   その LFSR の初期状態だけを総当たり（$`2^{L_1}`$通り）し、それぞれの出力列と観測列の一致率を測れば、正しい候補だけ$`p`$に近い値を示す。
>   全体を一度に総当たりする（$`2^{L_1 + L_2 + L_3}`$）代わりに、1 本ずつ切り離して攻撃できる。
> - **代数的攻撃**: 非線形関数を多変数の連立方程式として書き下し、解く。

## 5. 現代のストリーム暗号

LFSR ベースを離れた設計が主流:

| 暗号 | 構造 | 用途 |
|---|---|---|
| **ChaCha20** | ARX（加算・回転・XOR。回転はビット列を循環的にずらす操作で、はみ出したビットを反対側に戻す）| TLS、WireGuard、Linux の乱数 |
| **Salsa20** | ChaCha の前身 | — |
| **Trivium** | 3 個の非線形シフトレジスタ | 軽量用途（eSTREAM という欧州の選定プロジェクトで採択） |
| **Grain** | LFSR + NFSR（帰還に AND を含む非線形シフトレジスタ） | IoT 向け |
| RC4 | 状態配列の交換 | **廃止**（偏りが発見され TLS から除外） |

> **ChaCha20 が現代の標準である.**
> 加算・ビット回転・XOR という単純な演算だけで構成され、
> - **ソフトウェアで高速**（AES の専用命令が無い環境では AES より速い）
> - **タイミング攻撃に強い**（テーブル参照が無いのでキャッシュ経由の情報漏洩が起きない）
>
> モバイル端末の HTTPS では ChaCha20-Poly1305 が広く使われている。

| 項目 | 内容 |
|---|---|
| ストリーム暗号 | $`C = P \oplus Z`$、$`Z`$は鍵から生成 |
| LFSR | $`\mathrm{GF}(2)`$上の線形漸化式 |
| 最長周期の条件 | **特性多項式が原始多項式**（[04 章](04_多項式と既約多項式.md#原始多項式-既約よりさらに強い条件)・[05 章](05_拡大体GF2m.md#生成元-α-によるべき表現)） |
| M 系列の用途 | 通信同期、GPS、レーダー（暗号以外では現役） |
| **暗号としての致命傷** | **線形なので $`2L`$ ビットで完全に解読される** |
| 現代の主流 | ChaCha20（ARX 構造） |
