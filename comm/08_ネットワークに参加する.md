# 08. ネットワークに参加する — ARP・DHCP・DNS・NAT

> **この章で扱う問い.**
> 07 章では、データが層ごとのヘッダに包まれて宛先まで運ばれる様子を見た。そこでは、宛先の IP アドレスと、リンク層で渡す相手の MAC アドレスは分かっているものとしていた。しかし、電源を入れた直後の機器は、自分の IP アドレスも、サーバの IP アドレスも、隣の機器の MAC アドレスも知らない。
>
> この章では次の 3 つの問いに答える。
>
> 1. 機器は、宛先が自分と同じネットワークの中にいるかをどう判断し、まず誰に渡すのか。
> 2. 自分のアドレス、サーバのアドレス、渡す相手の MAC アドレスを、機器はどう手に入れるのか。
> 3. 家庭や会社のネットワークの中にいる機器へ、外のサーバからはなぜ接続できないのか。機器の側では何をすればよいのか。
>
> 答えの道具は、アドレスとネットマスクの AND、問い合わせて答えをもらう 3 つのプロトコル（ARP・DHCP・DNS）、そして NAT の変換表とその保持時間である。

## 1. 同じネットワークの中と外

家庭のネットワークを例に、機器が最初のパケットを送るまでに何を知っていなければならないかを整理する。この節と次の節では、機器は自分の IP アドレスと、この節で定義するネットマスクとデフォルトゲートウェイを、すでに知っているものとする。それらを機器が手に入れる方法は 3 節で扱う。

```fig
e08_lan
```

図の機器（192.168.1.23）と PC（192.168.1.40）は、同じ Wi-Fi のアクセスポイント（09 章）または同じ Ethernet につながっている。リンク層のフレームは、このように同じリンクにつながった機器の間でしか届かない（07 章 2 節）。そのため、機器は PC にはフレームを直接届けられるが、インターネットの先のサーバ（203.0.113.10）には直接届けられない。サーバへ送るときは、フレームをいったんルータに渡し、ルータが IP の宛先を見てその先へ運ぶ（07 章 3 節）。

したがって機器は、パケットを送るたびに、宛先が同じリンクにいるかどうかを判断しなければならない。この判断には、IP アドレスの上位のビットを使う。

IPv4 アドレスの 32 ビットのうち、上位の決まった数のビットが等しい機器の集まりを**サブネット**といい、その上位の部分を**ネットワーク部**という。ネットワークを管理する人（家庭ではルータの設定）は、1 つのリンクにつながる機器に、ネットワーク部が等しいアドレスを割り当てる。だから機器は、宛先のネットワーク部が自分と等しければ、宛先は同じリンクにいると判断できる。

ネットワーク部の長さは、上位のそのビット数だけ 1 を並べ、残りを 0 にした 32 ビットの値で表す。この値を**ネットマスク**（マスク）という。ネットワーク部のビット数を**プレフィックス長**といい、アドレスの後ろに `/24` のように書く。192.168.1.23/24 は「アドレスは 192.168.1.23、上位 24 ビットがネットワーク部」を表し、ネットマスクは 255.255.255.0 である。よく使うプレフィックス長の実例を示す。

| プレフィックス長 | ネットマスク | 16 進 | サブネットの中のアドレスの数 |
|---|---|---|---|
| /8 | 255.0.0.0 | 0xFF000000 | $`2^{24}`$ = 16,777,216 |
| /16 | 255.255.0.0 | 0xFFFF0000 | $`2^{16}`$ = 65,536 |
| /24 | 255.255.255.0 | 0xFFFFFF00 | $`2^{8}`$ = 256 |
| /26 | 255.255.255.192 | 0xFFFFFFC0 | $`2^{6}`$ = 64 |
| /30 | 255.255.255.252 | 0xFFFFFFFC | $`2^{2}`$ = 4 |

プレフィックス長が n なら、ネットワーク部の後ろに残る 32 − n ビットの組み合わせの数だけ、つまり $`2^{32-n}`$ 個のアドレスが 1 つのサブネットに入る。

### ネットワーク部を比べる — マスクとの AND

宛先が同じサブネットにいるかは、2 つのアドレスのネットワーク部を比べれば分かる。ネットワーク部だけを取り出すのに、ネットマスクとのビットごとの AND を使う。

**方針**: どのビット x についても x AND 1 = x、x AND 0 = 0 であることから、アドレスとマスクの AND が「ネットワーク部はそのまま、残りのビットは 0」の値になることを示す。そのうえで、2 つのアドレスのネットワーク部が等しいことと、AND の結果が等しいことが同じだと導く。

**導出**: アドレス a の第 i ビット（i = 31 が最上位）を $`a_i`$、マスク m の第 i ビットを $`m_i`$ とし、プレフィックス長を n とする。m は上位 n ビット（i = 31, …, 32 − n）が 1、残りが 0 である。AND はビットごとの演算なので、a AND m の第 i ビットは $`a_i`$ AND $`m_i`$ である。上位 n ビットでは $`m_i = 1`$ なので $`a_i`$ AND 1 = $`a_i`$、残りのビットでは $`m_i = 0`$ なので $`a_i`$ AND 0 = 0 となる。つまり a AND m は、a のネットワーク部をそのまま残し、残りのビットをすべて 0 にした値である。

もう 1 つのアドレス b についても、b AND m は b のネットワーク部と、すべて 0 のビットからなる。残りのビットはどちらも 0 で常に等しいので、a AND m と b AND m が等しいのは、上位 n ビット、つまりネットワーク部が等しいときであり、そのときに限る。したがって

$$
\text{a と b が同じサブネットにある} \iff (a \;\mathrm{AND}\; m) = (b \;\mathrm{AND}\; m)
$$

である ∎

実際の値で計算すると次のようになる。

```fig
e08_and
```

上の段の /24 では、PC の 192.168.1.40 は AND の結果が自分と同じ 192.168.1.0 なので同じサブネット、サーバの 203.0.113.10 は 203.0.113.0 なので外である。下の段のように、同じ 192.168.1.23 でもマスクが /26 なら、192.168.1.100 は外になる。4 つ目の数の上位 2 ビットまでがネットワーク部に入り、23（0b0001_0111）では 00、100（0b0110_0100）では 01 と異なるからである。アドレスの見た目が似ていても、中か外かはマスクで決まる。

C で書くと次のようになる。アドレスは 32 ビットの数として持ち、最初の数（192）を上位 8 ビットに置く。

```c
#define IP4(a, b, c, d) (((uint32_t)(a) << 24) | ((uint32_t)(b) << 16) | ((uint32_t)(c) << 8) | (uint32_t)(d))

/* プレフィックス長 n（0〜32）からネットマスクを作る */
static uint32_t prefix_to_mask(unsigned n)
{
    if (n == 0) return 0;                  /* 32 ビットずらすのは C では未定義なので分ける */
    if (n > 32) n = 32;
    return 0xFFFFFFFFu << (32 - n);        /* 上位 n ビットが 1 */
}

/* a と b が、マスク m のもとで同じサブネットにあるか（ネットワーク部が等しいか） */
static bool same_subnet(uint32_t a, uint32_t b, uint32_t m)
{
    return (a & m) == (b & m);
}

/* 宛先 dst へ送るとき、リンク層で次に渡す相手の IP アドレス（その MAC アドレスを 2 節の方法で調べる） */
static uint32_t next_hop(uint32_t me, uint32_t mask, uint32_t gw, uint32_t dst)
{
    return same_subnet(me, dst, mask) ? dst : gw;
}
/* IP4(192,168,1,23) は 0xC0A80117。prefix_to_mask(26) は 0xFFFFFFC0。
   same_subnet(IP4(192,168,1,23), IP4(192,168,1,100), prefix_to_mask(26)) は false */
```

TCP/IP スタックによっては、アドレスをネットワークバイトオーダ（03 章 6 節）のバイトの並びのまま 32 ビットの変数に入れている。その場合も、マスクを同じ並びで持っていれば判定の結果は変わらない。AND と比較はビットごとの演算なので、a と m のバイトを同じように並べ替えても、結果のバイトが同じように並べ替わるだけだからである。ただし、上の `prefix_to_mask` が作るマスクは数としての並びなので、そのような変数と組み合わせるときは、マスクもネットワークバイトオーダに直してから使う。

### 外の宛先はデフォルトゲートウェイへ

宛先が同じサブネットにないとき、機器はパケットを、同じサブネットにいるルータに渡す。このために設定しておくルータの IP アドレスを**デフォルトゲートウェイ**という（「ほかに当てはまる道が無いときに使う出口」という意味）。名前は似ているが、01 章 1 節のゲートウェイ（異なる通信方式の間を取り次ぐ機器）とは別の用語である。初期のインターネットの文書で、ルータをゲートウェイと呼んでいた名残である。デフォルトゲートウェイは、自分と同じサブネットの中になければならない。そうでなければ、デフォルトゲートウェイにもフレームを直接届けられないからである。

上の `next_hop` は、この判断をそのまま書いたものである。宛先が同じサブネットにあれば宛先そのものを、なければデフォルトゲートウェイを返す。どちらの場合も、機器はリンク層のフレームの宛先に、返された相手の MAC アドレスを書かなければならない。IP アドレスから MAC アドレスを知る方法が、次の ARP である。

## 2. ARP — IP アドレスから MAC アドレスを知る

1 節で、次に渡す相手の IP アドレスが決まった。しかし Ethernet や Wi-Fi のフレームの宛先には、IP アドレスではなく MAC アドレスを書く（07 章 2 節）。相手の MAC アドレスを知らなければ、リンクにつながる全員に問い合わせるしかない。

リンクにつながるすべての機器に同時に届けることを**ブロードキャスト**という。Ethernet と Wi-Fi では、宛先の MAC アドレスを FF:FF:FF:FF:FF:FF（48 ビットすべて 1）にしたフレームを、同じリンクのすべての機器が受け取る。IP にもブロードキャストのアドレスがある。255.255.255.255 は自分のリンクの全員を、ネットワーク部の後ろをすべて 1 にしたアドレス（192.168.1.0/24 なら 192.168.1.255）はそのサブネットの全員を表す。ルータは、ふつうの設定ではブロードキャストを外のネットワークへ転送しないので、ブロードキャストが届くのはリンクの中だけである。

サブネットのアドレスのうち、ネットワーク部の後ろがすべて 0 のもの（192.168.1.0）はサブネットそのものを表し、すべて 1 のもの（192.168.1.255）はブロードキャストに使う。どちらも機器には割り当てないので、/24 のサブネットで機器に割り当てられるのは 256 − 2 = 254 個である。

**ARP**（Address Resolution Protocol、RFC 826）は、IP アドレスから MAC アドレスを知るためのプロトコルである。機器がデフォルトゲートウェイ 192.168.1.1 の MAC アドレスを知る手順を図に示す。図の MAC アドレスは、文書の例のために予約された範囲（RFC 7042）のものである。

```fig
e08_arp_seq
```

1. 機器は「192.168.1.1 を持っている機器は、MAC アドレスを教えてほしい」という ARP の要求を、ブロードキャストで送る。
2. リンクのすべての機器が要求を受け取る。尋ねられた IP アドレスを持たない機器（図の PC）は捨てる。
3. 192.168.1.1 を持つルータだけが、自分の MAC アドレスを入れた ARP の応答を、要求した機器あてに返す。ルータは同時に、要求に入っていた機器の IP アドレスと MAC アドレスの組を覚える。直後に機器へ送るものがあることが多いからである。

ARP の要求と応答は、IP のパケットには入れず、EtherType 0x0806 の Ethernet フレームのデータとして直接運ぶ（07 章 2 節）。中身は次の 28 バイトである。

```fig
e08_arp_bytes
```

### ARP キャッシュ

パケットを送るたびに問い合わせると、そのたびに 1 往復の待ち時間と、リンクの全員が受け取るブロードキャストが増える。そこで機器は、得た IP アドレスと MAC アドレスの組を表に記録しておき、しばらくの間はそれを使う。この表を **ARP キャッシュ**という。記録には期限があり、期限が切れたら問い合わせ直す。同じ IP アドレスが、機器の入れ替えなどで別の MAC アドレスに変わることがあるからである。期限の長さは実装によって違い、数十秒から数十分まで幅がある。答えを待つ間、送ろうとしたパケットは保留されるが、小さな TCP/IP スタックでは保留できるパケットの数が少ない（設定による）。

### 外の宛先では、ゲートウェイの MAC アドレスを聞く

宛先がインターネットの先のサーバでも、ARP で聞くのはデフォルトゲートウェイの MAC アドレスである。3 つの場合を比べる。

```fig
e08_arp_mac
```

外の宛先へのフレームでは、宛先の MAC アドレスはルータのもの、その中の IP パケットの宛先 IP アドレスはサーバのものになる。ルータはフレームを受け取ると、IP の宛先を見て次の区間へ送り、そのときリンク層のヘッダを付け替える。IP の宛先は最後まで変わらないが、MAC アドレスは区間ごとに変わる。図の (c) のようにサーバの IP アドレスで ARP の要求を出しても、サーバは同じリンクにいないので、答えは返ってこない。

ARP には、答えた相手が本物かどうかを確かめる仕組みが無い。同じリンクにいる悪意のある機器が偽の応答を返すと、機器はその機器にフレームを渡してしまう（ARP スプーフィング）。そのため、通信の中身は TLS（12 章）で暗号化し、相手を確かめる。
